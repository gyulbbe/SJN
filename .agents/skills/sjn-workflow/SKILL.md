# SJN 프로젝트 작업과 참고 문서 유지

프로젝트 루트는 이 스킬 폴더에서 `../../../`다. 아래 문서는 개발자가 필요한 구조와 제약을 빠르게 찾기 위한 현재 상태 요약이다. 상세 DDL·사용법은 문서에 연결된 원문에서 확인한다.

## 작업 전에 읽을 문서

| 작업 내용 | 먼저 읽을 참고 문서 |
| --- | --- |
| 스키마·마이그레이션·인증·권한·소유권·자재 버전·자산 참조 | [DB](references/database.md) |
| 실행 명령·환경변수·Cloudflare 바인딩·R2 키/이미지 경로·OAuth 연결·빌드/배포 | [개발 환경](references/development-environment.md) |
| 사용자 기능·화면·Before/After·시안·자재·렌더링·내보내기·AI 역할·코드 구조 | [프로젝트 설명](references/project-overview.md) |

작업과 관련된 문서만 읽는다. 저장 흐름이나 AI 연결처럼 여러 영역에 걸친 변경은 해당 문서를 함께 읽는다. 단순 스타일 수정처럼 참고 문서가 설명하는 동작을 바꾸지 않는 작업에는 문서를 억지로 수정하지 않는다.

## 진행 방법

1. 관련 참고 문서를 읽고 연결된 코드·마이그레이션·설정에서 이번 작업의 실제 동작을 확인한다. 문서와 코드가 충돌하면 현재 소스를 조사하여 사실과 의도된 요구사항을 구분한다. 오래된 안내를 근거로 이미 바뀐 동작을 되돌리지 않는다.
2. 사용자가 요청한 범위의 작업을 수행한다. 문서 유지 자체가 운영 DB 적용, 배포, 권한 변경 또는 실제 AI 호출을 추가로 허용하는 것은 아니다.
3. 구현·설정·기능이 달라졌다면 같은 작업에서 영향을 받는 참고 문서를 갱신한다. 테이블·권한은 DB 문서, 변수·명령·바인딩·R2 경로는 환경 문서, 기능·화면·모델 역할·구조는 프로젝트 설명을 고친다. 관련 영역이 둘 이상이면 모두 맞춘다.
4. 오래된 문장을 현재 설명으로 교체하고 근거 파일 링크와 확인 기준을 함께 수정한다. 전체 SQL이나 긴 상세 문서를 중복 복사하거나, 작업마다 변경 이력을 추가하지 않는다. 요약이 가리키는 상세 가이드도 이번 변경으로 사실이 달라졌다면 해당 부분을 함께 맞춘다.
5. 문서의 링크·명령·이름·경로가 현재 소스와 일치하는지 확인한다. 문서만 수정한 작업에 앱 전체 테스트를 의무화하지 않는다. 코드 변경이 있는 경우 해당 기능에 필요한 검증을 수행한다.

## 기록 기준

- 소스에서 확인한 설정, 예시 값, 실제 원격 확인 결과를 구분한다. 코드에 구현되었다는 이유로 운영 연결·마이그레이션·배포가 완료됐다고 쓰지 않는다.
- 현재 원격 상태를 확인하지 않았다면 미확인으로 적는다. 과거 테스트의 날짜·모의 응답 여부를 유지하며 새로운 검증 결과로 표현하지 않는다.
- 실제 `.env`·`.dev.vars`의 비밀값이나 토큰·OAuth secret·사용자 정보를 문서에 복사하지 않는다. 변수 이름과 빈 예시, 바인딩 이름만 기록한다.
- 자료를 읽는 범위와 공개 범위, R2 객체 키와 브라우저 URL, 로컬 저장과 원격 AI 호출을 각각 구분한다.
- 문서 갱신을 위해 별도 백업·정리 보고서·감시 프로그램을 만들지 않는다. 갱신은 AI가 관련 개발 작업을 수행할 때 적용하는 절차다.

## 완료 확인

관련 참고 문서의 설명이 최종 코드와 맞고, 모든 상대 링크가 해석되며, 예시 값이 실제 운영 값으로 잘못 표시되지 않아야 한다. 새로 확인하지 못한 운영 상태는 미확인으로 유지한다. 최종 답변에는 사용자가 요청한 작업 결과, 관련 문서 갱신 여부와 검증 결과를 간단히 알린다.
