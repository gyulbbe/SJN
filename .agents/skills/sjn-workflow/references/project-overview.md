# 프로젝트 설명

> 확인 기준: 2026-09-18 저장소의 현재 소스. 기능이 구현된 상태와 실제 운영 적용 상태는 별개다. 운영 연결 상태는 [개발 환경](development-environment.md)의 구분을 따른다.

## 목적과 이용자

공간미리(SJN)는 사진 또는 치수로 준비한 공간에 타일·제품을 배치하고 여러 인테리어 시안을 비교하는 한국어 웹 앱이다. 화면은 React/Next.js, 편집 상태는 Zustand, 공간 표현·이미지 출력은 Three.js를 사용한다. Cloudflare 배포는 현재 vinext 빌드 경로를 사용한다.

개발·운영 모두 메인과 공용 자재 목록·상세·검색을 로그인 없이 볼 수 있다. `/try`에서는 빈 공간을 만들고 자재 검색·배치·속성 조절·견적·시안 비교를 이용한다. 사진·AI·정식 저장·출력은 로그인이 필요하다. 일반 회원은 본인 프로젝트를 생성·편집하고 공용 자재를 사용한다. 관리자는 공용 자재·기준 분류·회원 역할/상태를 관리하며, 전용 화면에서 다른 회원의 프로젝트를 검색·조회·편집할 수 있다. 소유권은 유지하고 관리자 행위를 감사 기록에 남긴다. 기존 IndexedDB 자료와 계정별 복구본은 보존하고 게스트 체험과 섞지 않는다.

| 화면 | 역할 |
| --- | --- |
| `/` | 공개 메인·로그인/회원가입·체험 시작; 로그인 후 본인 프로젝트 목록과 기본 공간·사진 기반 시작 |
| `/try` | 같은 탭의 임시 빈 공간과 기본 자재 검색·배치; 로그인 후 본인 프로젝트로 저장 |
| `/projects/[id]` | Before/After 편집, 시안 관리·비교, 자재 적용, 내보내기 |
| `/materials` | 로그인 없이 보는 현재 활성 공용 자재 목록·상세·검색 |
| `/login` | 로그인 / 회원가입: 아이디·비밀번호 로그인과 회원가입, 설정된 경우 Google로 계속하기; 취소·실패·정지·재시도 상태를 필요한 때만 안내하며 로그인된 회원은 내 프로젝트로 이동하고 체험 복귀는 `/try`에서 저장을 이어감 |
| `/admin/materials` | 관리자 자재 등록·버전 수정·비활성화 |
| `/admin/catalog` | 관리자 하위 카테고리·색상·브랜드·재질·마감 관리 |
| `/admin/users` | 회원 이름·이메일·ID 검색, 역할·상태 필터, 관리자 승격/강등·계정 정지/해제 |
| `/admin/projects` | 회원 프로젝트 검색·조회·전용 편집; 소유권 유지·감사·revision 충돌 확인 |
| `/reconstruction-performance` | Gemma·브라우저 MoGe·전체 재구성의 성능 확인 화면 |

화면 진입점은 [App Router](../../../../src/app/), 접근 규칙은 [DB 문서](database.md)와 [인증·공개 범위 상세](../../../../docs/database-design.md)를 참고한다. 옛 `/reconstruction-lab` 주소는 현재 성능 확인 화면으로 이동한다.

## 핵심 화면과 반응형 UI

메인과 공개 자재 라이브러리는 [공통 탐색](../../../../src/components/workspace-nav.tsx)을 사용한다. 데스크톱은 왼쪽 메뉴와 가운데 정렬한 본문, 620px 이하에서는 열고 닫는 모바일 메뉴를 제공한다. 메뉴에서 계정·로그아웃과 권한에 맞는 관리자 화면에 접근하며 메인 상단 중복 관리자 메뉴는 표시하지 않는다. [공통 스타일](../../../../src/app/studio.css)은 따뜻한 중립색·민트색과 읽기 쉬운 글자 대비를 적용하며 캔버스의 재질·조명·출력 이미지에는 영향을 주지 않는다.

공개 자재 화면은 관리자 분류 폼과 별도 스타일을 사용한다. 검색·종류, 사이즈·색상·표면 분류 버튼과 펼침 패널, 결과 개수와 조건 초기화, 불러오는 중·등록 없음·검색 결과 없음·오류를 구분한다. 이미지 실패에도 카드 공간을 유지하고 자재 상세는 키보드로 닫은 뒤 열었던 카드에 초점을 돌려준다.

편집기의 왼쪽 자재·중앙 공간·오른쪽 견적/속성 배치는 유지한다. 1100px 이하에서는 기존 패널을 열어 사용하는 방식으로 공간을 확보하고 1280px 이하의 보조 작업은 더보기에서 연다. 620px 이하에서는 상단 도구를 두 줄로 정돈한다. 견적/편집 속성 바로가기는 같은 패널의 스크롤만 이동하여 입력값과 펼침 상태를 유지한다. 모바일 터치 영역과 키보드 포커스를 제공하며 동작 감소 설정을 따른다. 로그인 팝업은 화면 중앙에 표시하고 X·Escape로 닫으면 이전 초점으로 돌아간다.

[로그인 팝업](../../../../src/components/guest/login-prompt.tsx)·[독립 로그인 페이지](../../../../src/app/login/page.tsx)·[로그인이 필요한 화면](../../../../src/components/app-provider.tsx)은 제목 **로그인 / 회원가입** 아래 공통 [아이디 로그인 폼](../../../../src/components/auth/credential-auth-form.tsx)을 사용한다. 로그인/회원가입 전환, 아이디(영문·숫자·밑줄 4~20자)·비밀번호(8자 이상)·가입 시 비밀번호 확인을 받고 성공하면 Google 복귀와 같은 주소(`/` 또는 `/try?resume=1`)로 전체 이동한다. 서버에 Google 설정이 있으면 **또는** 아래에 로컬 Google G 표시를 넣은 **Google로 계속하기** 버튼을 함께 둔다. 비밀번호 찾기는 없다. 기본 화면에는 중복 가입·기능 설명, 장식 아이콘, **체험 계속하기** 버튼을 두지 않는다. 오류·취소·정지·만료·초안 보존 실패와 재시도는 해당 상태에서만 표시하고, 연결 확인·진행 상태는 접근성 안내를 유지한다. 독립 로그인 페이지는 메인 또는 체험으로 돌아가는 링크를 제공한다. UI 간소화는 OAuth 요청·복귀 경로, 권한 검사, 체험 초안 보존·로그인 후 저장, 계정 변경 보호를 바꾸지 않는다.

화면별 변경 내용과 5가지 너비의 비교 캡처·검증 범위는 [UI 검증 문서](../../../../docs/ui-studio-verification.md)에 정리한다.

## 주요 작업 흐름

### 공간과 시안

- 체험 초안은 `sessionStorage`에 같은 탭 범위로 임시 보관하여 새로고침·Google 로그인 이동 뒤 이어간다. 탭을 닫으면 사라질 수 있으며 서버 저장 완료를 의미하지 않는다. 로그인 성공 후 본인 D1/R2 프로젝트로 저장하고 실패하면 초안을 유지한다. 체험에서도 최대 5개 시안 추가·복제·비교, 빈 Before/After 보기, 우측 견적·수량·단가와 타일 시공 설정·밝기/색감·그림자·겹침 순서·제품 잠금/복제를 편집한다. 우측 공간 크기 변경·벽 구조 편집도 허용한다. 표시된 상단 공간 둘러보기·AI 보정·저장·공간 크기·내보내기는 로그인 안내로 연결한다. 사진 업로드/재구성과 모든 다운로드·정식 계정 저장·관리자 기능의 인증은 유지한다. 체험 시안 미리보기는 메모리에서만 생성하고 IndexedDB 캐시는 읽거나 쓰거나 삭제하지 않는다.

- 기본 공간은 가로·깊이·높이로 빈 방을 만든다. 사진으로 비교 공간을 만드는 경우 참고 사진에서 편집 가능한 Before 초안을 추정하고 같은 카메라의 빈 After에서 새 디자인을 시작한다. 자동 초안은 실측 결과나 실제 상품 형상 복원이 아니다.
- Before 보정과 After 편집을 분리한다. 공간 크기 변경은 공통 공간과 시안에 반영하며, 비교는 동일한 구도를 사용한다.
- 속성 패널의 슬라이더(타일 방향·시작점·줄눈·명암 보존, 밝기와 색감, 제품 배율·크기·회전, 그림자)는 옆 숫자 칸에 직접 입력할 수 있다. Enter·포커스 이동 시 슬라이더와 같은 범위·간격으로 맞춰 한 번의 편집으로 적용하고, 빈 값·Escape는 되돌리며 위·아래 방향키(Shift는 10칸)로 바로 조절한다. 근거: [range-input](../../../../src/lib/range-input.ts).
- 속성 패널의 **시공 설정 전체 적용**은 선택한 면의 배열·방향·가로/세로 시작점·줄눈 색상/폭·원본 명암 보존을 현재 편집 중인 장면의 모든 벽·바닥에 복사한다. 면마다 고른 타일 자재와 무늬 변형(seed)은 유지하며 한 번의 편집으로 기록되어 Ctrl+Z로 되돌린다. 근거: [tile-settings](../../../../src/lib/tile-settings.ts).
- 공간 둘러보기의 90° 회전·확대·이동은 공통 시점만 저장하고 장면·견적·편집 이력은 바꾸지 않는다. D1 저장 실패 뒤에는 추가 회전에도 오류와 재시도 버튼을 유지한다. 사용자가 시점 저장을 재시도하면 최신 각도를 저장하며, 실패 중 서버에 있던 시점은 덮어쓰지 않는다.
- 편집 변경은 상단 실행 취소·다시 실행 버튼 또는 `Ctrl+Z`·`Ctrl+Y`로 되돌리고 복원한다. 버튼에 마우스를 올리면 단축키를 표시한다. `Ctrl+Shift+Z`와 Mac의 `Cmd` 조합도 지원한다. 현재 Before 또는 선택한 After 시안의 이력을 사용하며, 새 편집을 하면 다시 실행 기록이 비워진다. 선택한 제품은 Delete(Mac은 delete/Backspace)로 삭제하고 선택한 면은 적용한 타일을 초기화한다. 속성 패널의 제품 삭제·타일 초기화 버튼과 같은 편집이라 Ctrl+Z로 되돌리며, 잠긴 제품·초안·Before/비교 보기 중에는 동작하지 않는다. 입력창은 브라우저의 텍스트 실행 취소를 유지하고, 한글 조합·팝업·드래그 중에는 프로젝트 이력을 변경하지 않는다.
- 프로젝트마다 시안을 최대 5개 만들고 최대 5개를 비교한다. 공통 Before와 독립적인 After·자재 설정·편집 이력을 유지한다. 시안 생성·복제·전환 자체가 AI 추론을 실행하지 않는다.
- 자재 수량·금액은 현재 시안의 After를 기준으로 계산한다. 기본 공간은 설정 치수, 사진에서 불확실한 시공 면적은 사용자의 입력을 사용한다. 세금·공임·현장 여유분을 자동 가산하지 않는다.

### 관리자와 접근 보호

관리자 회원 목록은 25개씩 표시하고 현재 역할·상태를 확인한 뒤 변경한다. 자기 정지와 마지막 활성 관리자 해제/정지는 막는다. 정지 시 기존 세션이 삭제되고 새 로그인도 거부된다. 역할/상태 변경, 관리자 프로젝트 조회·편집과 관련 자료 접근은 서버 감사 기록에 남는다.

관리자 타인 프로젝트 편집은 본인 프로젝트 편집과 범위를 분리한다. 관계없는 개인 자산·자재, 타인 프로젝트 삭제·복제·소유권 이전은 제공하지 않는다. 저장은 동일 revision 기반 충돌 검사를 쓰며 강등·정지 후 기존 창/캐시로 계속 접근할 수 없다. 세션이 만료되면 편집기를 숨기고 로그인 안내를 표시하며 본인 계정의 미저장 IndexedDB 복구본은 보존한다.

관리자가 다른 회원의 프로젝트를 편집할 때 초안·미리보기와 사진 재분석 관측은 현재 탭의 메모리에서만 유지한다. 계정 복구본·시안 미리보기와 Gemma·DeepLab·MoGe의 사진 파생 IndexedDB 캐시는 읽거나 쓰지 않고 서버 진단 아카이브도 만들지 않으며, 재분석은 실행별 `transient` 정책을 전달한다. 공통 모델 파일 캐시와 본인 프로젝트의 일반 저장·복구 정책은 유지한다. 저장 실패한 관리자 초안은 탭을 닫으면 복구할 수 없다는 안내를 표시한다.

근거: [관리자 서버](../../../../src/lib/admin/), [DB 계약](database.md). 기본 실행은 [개발 환경](development-environment.md)의 vinext 3000·로컬 D1/R2·Google 로그인을 따른다.

### 자재와 이미지

- 타일은 텍스처·규격·줄눈과 시공 패턴을, 제품은 방향 이미지·실제 크기·배치 기준점을 사용한다. 목록 표시는 제품 정면을 우선하고 없으면 첫 사진, 타일은 첫 텍스처를 사용한다.
- 여러 장이 찍힌 타일 사진은 [한 장 선택·정면 보정](../../../../src/components/materials/image-preparer.tsx)에서 기본 **사각형**으로 드래그해 감싸고(안쪽 이동·모서리 크기 조절·퍼센트 입력) 타일 규격 비율 고정을 기본으로 한다. 기울어진 사진은 **네 점** 모드로 모서리를 맞추며, 두 방식 모두 규격 비율 PNG로 원본을 보존한 새 텍스처를 만든다. 근거: [crop-rect](../../../../src/lib/crop-rect.ts).
- 사진 입력은 모두 버튼 선택과 끌어 놓기를 지원한다. 홈 시작 카드·직접 편집 줄·비교 창·재구성 테스트는 한 장만 받고(여러 장은 안내 후 거절), 자재 폼 텍스처·제품 이미지는 여러 장을 한꺼번에 받는다(목록 합계 100장). 공통 검사는 `src/lib/file-drop.ts`, 끌어 놓기 처리는 `src/components/use-file-drop.ts`이며, 올릴 수 없는 곳의 드롭은 `AppProvider`가 막는다([이미지 올리기 규칙](../../../../docs/material-images.md)).
- 제품 사진은 배경 제거 결과를 비교한 뒤 선택한 사진에 적용할 수 있다. 360° 입체화는 TripoSR로 모형을 만들고 원하는 각도의 이미지를 추가·수정한다. 저장한 입체 데이터를 다시 열 때는 재추론 없이 각도를 편집한다. 새 입체화는 조명 보정(사진 명암 대신 재질 기본색 + 시점 조명, `원본 색` 선택 가능)·자동 수평 맞춤(확실할 때만)·형상 정리(GPU 격자 256, 떠 있는 조각 제거, Taubin 스무딩)·입력 가장자리 정리를 적용하고, 사진 방향에서 40° 넘게 돌리면 부정확할 수 있다고 안내한다. 과거 각도는 `원본 색`으로 열린다([제품 입체 품질](../../../../docs/product3d-editor.md)).
- 공개 자재 API는 현재 활성 공용 버전의 표시·배치 DTO와 직접 표시하는 이미지만 반환한다. 원본 사진·개인 자재·메시·입체화 원본 참조·전체 자재 payload는 공개하지 않는다. 배치 DTO에는 현재 등록된 단가·판매 단위·박스 규격과 실제 버전 ID·규격·줄눈·방향·기준점을 유지하여 로그인 후 동일 자재로 저장할 수 있다.
- 최종 자재 등록·수정 때 이미지와 선택 값을 확정한다. 자재 버전은 불변이며 과거 프로젝트는 당시 버전을 유지한다.
- 공개 자재 목록과 편집기 자재 패널은 현재 제품 종류·탭의 자재 값으로 [사이즈·색상·표면(마감) 분류](../../../../src/components/materials/material-facets.tsx)를 만든다. 상단 분류 버튼(선택 개수 표시)을 누르면 아래에 한 번에 하나의 패널이 펼쳐지고 버튼 재클릭·Escape로 닫힌다. 편집기에서는 Escape가 자재 서랍까지 닫지 않는다. 색상·표면은 체크박스 목록, 사이즈는 표 형태 셀이며 `600X1200`처럼 타일은 가로X세로, 제품은 0보다 큰 가로X세로X깊이를 가로·세로·깊이 내림차순으로 보인다. 같은 항목에서는 하나라도, 항목끼리는 모두 일치하는 자재를 표시하고 현재 범위에 없는 선택은 무시한다. 서버 API는 바꾸지 않고 받은 자재 값으로 브라우저에서 거른다.
- 하위 카테고리·속성은 관리자가 등록한 값의 ID로 선택한다. 목록 스크롤과 부분 검색(`그레 → 그레이`), 방향키·Enter로 선택하며 검색어는 값으로 저장하지 않는다. Tab으로 다른 필드로 이동하거나 Escape를 누르면 목록을 닫는다. 브랜드·하위 카테고리는 단일, 색상·재질·마감은 복수 선택이다.
- 사진 분석으로 만든 유사 모형은 프로젝트용 내부 자원이며 공개 카탈로그 상품으로 자동 등록하지 않는다.

근거: [자재 컴포넌트](../../../../src/components/materials/), [분류 계약](../../../../src/lib/catalog/contract.ts), [검색 필터](../../../../src/lib/catalog/facets.ts). 상세: [이미지 정책](../../../../docs/material-images.md), [배경 제거](../../../../docs/ai-background-removal.md), [360° 편집](../../../../docs/product3d-editor.md). 저장·공개 조건은 [DB](database.md), 파일 경로는 [개발 환경](development-environment.md)에 둔다.

### 내보내기

일반 PNG/JPG 내보내기는 현재 시안이나 Before/After 비교를 렌더링하며 편집 도구를 이미지에 포함하지 않는다. FLUX 비교는 현재 After의 동일 PNG를 기준으로 4B·9B를 사용자가 각각 실행하고 결과를 미리 본 뒤 PNG로 다운로드한다. 결과는 내보내기 창에서 관리하며 프로젝트 장면을 자동 교체하지 않는다. 사진처럼 보여도 실제 현장 촬영본은 아니다.

근거: [AI 내보내기 UI](../../../../src/components/editor/ai-export.tsx), [FLUX 계약](../../../../src/lib/ai-export/contract.ts), [서버 경로](../../../../src/app/api/export/photoreal/route.ts). 상세: [FLUX 비교](../../../../docs/flux-export.md).

프로젝트 v3는 공통 공간과 독립 시안을 저장한다. 이미지 Blob을 문서에 복제하지 않고 자산 ID로 참조하며, 원본·파생 자료·편집 이력에 필요한 자산을 보존한다. 현재 정식 저장은 메타데이터·권한·참조를 D1에, 프로젝트 스냅샷·파일을 비공개 R2에 둔다. [게스트 세션](../../../../src/lib/guest/session.ts)은 별도 `sessionStorage` 임시 초안과 메모리 이미지로 동작하며 D1/R2 쓰기와 계정 저장소 초기화를 하지 않는다. IndexedDB는 본인 미저장 복구본·자산·시안·AI 단계 캐시에만 사용한다. 진단 로그는 별도 D1/R2 아카이브에서 본인 계정만 조회한다. 과거 로컬 자료를 읽기·쓰기·자동 업로드·삭제하지 않으며 로컬 저장 구현은 데이터 형식 회귀를 위한 테스트 전용으로만 남긴다.

기존 문서 정규화와 참조 보존 규칙을 바꿀 때는 [DB 문서](database.md)도 읽는다. 화면·기능·AI 역할·시안 한도·코드 책임이 바뀌면 이 문서를 갱신하고, 연결 주소·모델 호스팅·환경 설정까지 바뀌면 [개발 환경](development-environment.md)도 함께 갱신한다.
