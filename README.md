# 공간미리

내 사진과 직접 등록한 자재로 작업하는 한국어 인테리어 시뮬레이터입니다. 기본값은 **로컬 모드**입니다. 계정, API 키, Supabase 또는 외부 AI 연결 없이 실행됩니다.

사진 없이도 **기본 공간으로 시작**을 누르고 가로·깊이·높이를 입력하면 그 비율의 빈 방에서 편집할 수 있습니다. 기본값은 **2.4 × 2.4 × 2.4m**이며 실측 확인 전의 설정값입니다. Three.js가 벽 3면·바닥·천장 배경과 원근을 함께 만들고, 등록한 타일 규격과 제품 크기를 적용합니다. 도기·거울·문·창이나 예시 상품은 자동 추가하지 않습니다. Before와 After 모두 빈 공간으로 시작하고 After를 편집합니다. 이전 사진 합성은 **기존 사진 위에 직접 편집하기 → 사진 위에 직접 편집**에 따로 있습니다. 기존 저장 프로젝트는 유지합니다.

**사진으로 비교 공간 만들기**에서는 기존 공간 사진과 치수로 Before 초안을 재구성하고, 동일한 구도의 빈 After에서 새 디자인을 시작합니다. 생성 직후 After 편집 화면이 열립니다. Before 확인·보정은 필요할 때 하고, 우측 자재 수량·금액은 현재 시안의 After에 적용한 자재만 집계합니다. 실제 제품을 복원하는 대신 수정 가능한 유사 모형을 사용합니다. [재구성 Before / After 사용법](docs/reconstructed-comparison.md)

[Cloudflare 배포와 main 자동 배포 안내](docs/cloudflare-deployment.md)

## 실행

Node.js 22.13 이상을 권장합니다. 프로젝트 폴더에서:

```powershell
npm install
npm run dev
```

http://127.0.0.1:3000 에 접속합니다. 사진과 프로젝트는 이 주소의 **브라우저 IndexedDB**에 저장됩니다. `localhost`와 `127.0.0.1`, 포트, 브라우저 프로필이 다르면 다른 저장 공간입니다. 네트워크를 통한 외부 서버 저장이나 백업이 아닙니다. 최초 의존성 설치 후 로컬 실행에 외부 API 연결은 필요하지 않습니다.

```powershell
npm run build
npm run start
```

## 사용할 수 있는 기능

- 사진과 치수로 기존 공간 Before 재구성, 참고 사진·초안 보정, 기본 모형 추가 및 등록 제품 교체, 동일 카메라의 빈 After 시작과 비교. Before는 일반 자재 목록과 After 자재 집계에서 분리합니다.
- 사진 업로드, 프로젝트 생성·열기·이름 변경·복제·삭제, 지연 자동 저장, 명시적 저장 및 새로고침 복원.
- 기본 공간의 가로·깊이(0.5–20m)·높이(1–6m) 입력, 빈 방 미리보기, 편집 중 공간 크기 변경. 타일 반복·제품 원근 크기·자재 시공 면적을 같은 설정 치수로 계산합니다.
- 개인 자재와 공용 자재 목록, 검색·카테고리·공개 범위 필터, 등록·버전 수정·복제·비활성화·복구. 기본 예시 상품은 자동으로 생성하지 않습니다.
- JPG/PNG/WebP 바이트 형식·용량·해상도 확인(25MB, 40MP), EXIF 방향 정리, 원본과 미리보기 분리. 타일용 텍스처와 홍보 사진 분리.
- 타일 한 장의 네 점 자르기·정면 보정, 여러 무늬 변형, 실제 mm 크기의 반복, 격자·반장 엇갈림, 방향·시작점·줄눈·명암 보존.
- **벽 타일 → 등록한 자재**처럼 자재를 누르면 사진에서 벽/바닥을 자동으로 찾아 적용합니다. 처음 찾은 면과 마스크는 저장되며 다음 자재 변경에는 분석을 반복하지 않습니다. 적용 위치에서 전체/개별 면을 고를 수 있습니다.
- 기본 벽·바닥은 고정하고 자재만 적용·변경·해제합니다. 수동 면 생성·경계/원근점·브러시·레이어 목록은 제공하지 않습니다. 화면 이동·줌은 유지합니다.
- 방향별 2D 제품 이미지와 기준점, 이동·크기·평면 회전·복제·잠금·앞뒤 순서·접지 그림자. 제품 속성에서 제품만 삭제할 수 있습니다. 자재 등록의 이미지 자르기와 제품 배경 지우기는 유지합니다.
- 전체 및 선택 자재의 노출·대비·채도·따뜻함, Before/After 버튼, 드래그 비교.
- 편집 도구를 제외한 After 및 좌우 비교 PNG/JPG, 전체 긴 변 최대 4096px(원본/GPU 한도 적용).
- 우측 **자재 수량·금액**에서 현재 시안의 After에 적용된 타일·제품을 집계합니다. 면별 시공 면적, 타일 자동/수동 구매 수량, 판매 단위·단가·포장을 시안별로 수정하고 비교 카드에서도 금액을 확인합니다. 세금·공임·추가 비용·할인·자동 여유분을 가산하지 않습니다. 기존 견적서 작성·인쇄 화면은 제거했습니다.

## 사진으로 기존 공간과 새 디자인 비교

홈의 **사진으로 비교 공간 만들기** → 사진·가로·깊이·높이 입력 → **자동 초안 만들기** → 빈 After에서 새 디자인 꾸미기 순서로 진행합니다. Before는 상단 버튼으로 비교하고, 필요하면 **기존 공간 수정**에서 보정한 뒤 상단 **After**로 돌아옵니다. 분석이 어려우면 **분석 없이 직접 구성**을 사용할 수 있습니다. **기존 공간 수정**은 After를 유지하고, **공간 크기** 변경은 양쪽에 함께 적용합니다. 참고 사진은 별도로 열며 비교 화면은 두 재구성 장면을 같은 각도로 표시합니다.

자동 초안은 전체·좌우 반전 사진과 모호한 기구의 확대 영역을 실제로 다시 분석합니다. 창·거울의 원본 디테일, 세면대 하부장, 상부 도장·하부 타일 구간과 줄눈을 보존하도록 개선했습니다. 기존 재구성은 **기존 공간 수정 → 초안 보정 → 사진 다시 분석**으로 갱신할 수 있습니다. After와 자재 설정은 유지되며, 결과는 사진을 참고한 편집 가능한 추정입니다. [재구성 안내](docs/reconstructed-comparison.md).

## 시안을 여러 개 만들고 비교하기

편집기 상단 **시안 관리**에서 새 시안을 만들거나 현재 구성을 복사합니다. 프로젝트마다 최대 **5개**를 저장하며, 최대 **5개**를 골라 **선택한 시안 비교**로 함께 볼 수 있습니다.

- **새 시안**은 공통 기준 공간의 빈 조합으로 시작합니다. **복제**는 자동 저장 전 조작까지 확정해 최신 타일·제품·색감·자재 수량·가격 설정을 가져옵니다. 원본 시안은 유지합니다.
- 비교 카드의 **이 시안 편집**으로 수정하고 **시안 비교로 돌아가기**를 누르면 기존 선택을 유지한 최신 결과가 보입니다. 비교에서 제외하는 것은 삭제가 아닙니다.
- **확대·이동 동기화**는 기본으로 켜져 있고 **모두 화면 맞춤**으로 초기화합니다. 모바일은 세로 스크롤로 모든 선택 시안을 볼 수 있습니다.
- Before/After는 **공통 Before와 현재 시안**을 비교합니다. 다중 시안 비교는 서로 다른 After를 보여줍니다.
- **공간 크기**는 Before와 모든 시안에 함께 적용합니다. 일반 실행 취소는 현재 시안 또는 Before 안에서만 동작하며, 치수 변경은 **크기 변경 직전 전체 복원**으로 되돌립니다. 이 복원은 이후 생성·삭제한 시안과 자재 수량·가격 변경도 함께 되돌립니다.

[다중 시안 구조·검증 결과](docs/designs-verification.md) · [5개 한도 변경](docs/five-design-limit.md)

## 빠른 작업 순서

1. **기본 공간으로 시작** 또는 **새 프로젝트**에서 가로·깊이·높이를 입력하고 **공간 만들기**를 누릅니다. 나중에 상단 **공간 크기**로 다시 변경할 수 있습니다. 사진을 Before로 준비하려면 **사진으로 비교 공간 만들기**를 선택하거나 사진을 홈으로 끌어 놓습니다. **내 자재 등록하기** 또는 홈의 **자재 라이브러리**에서 타일이나 제품을 등록합니다.
2. 왼쪽 **벽 타일** 또는 **바닥 타일**을 고른 뒤 원하는 자재를 누릅니다. 지정된 면이 없으면 브라우저가 사진을 분석해 자동으로 적용합니다. 사진은 외부로 전송하지 않습니다.
3. **적용 위치**에서 전체/개별 벽 또는 바닥을 고릅니다. 설정한 공간 크기에 맞춰 타일이 반복됩니다. **타일 적용 해제**는 자재만 제거하며 벽·바닥은 유지합니다.
4. 위생도기 탭에서 제품을 눌러 배치합니다. 화면에서 제품을 선택해 위치·크기·설치 면·방향을 바꾸거나 **제품 삭제**를 누릅니다. 잠긴 제품은 먼저 잠금을 해제합니다.
5. Before/After로 비교하고 내보냅니다. Ctrl+Z 실행 취소, Ctrl+Shift+Z 다시 실행, Ctrl+S 저장을 지원합니다.
6. 오른쪽 **자재 수량·금액**에서 사용 면적·구매 수량·단가를 확인하고 수정합니다. 숫자는 Enter 또는 포커스 이동으로 확정됩니다. 수동 구매 수량은 면적이 변해도 유지되며 자동 계산값이 함께 표시됩니다. 비교 카드의 **자재 보기**는 해당 시안의 읽기 전용 상세를 엽니다. [자재 집계와 검증](docs/material-usage.md)을 참고하세요.

## 구조와 저장 계약

`src/lib/types.ts`의 직렬화 가능한 문서와 자산 ID가 공통 계약입니다. React/Zustand 편집기, Three.js 렌더러, IndexedDB/Supabase 저장소를 분리했습니다. 렌더러는 `RenderSnapshot`과 자산 reader만 받습니다.

사진 좌표는 방향 정리 후 `[0,1]`, 면은 mm, 화면 줌/이동은 별도 좌표입니다. 면의 역호모그래피로 타일과 줄눈을 함께 반복합니다. 원본 색을 반투명하게 덮지 않고 새 자재 위에 저주파 명암만 적용합니다. 선택 테두리는 SVG 오버레이라 이미지 출력에 들어가지 않습니다.

- `editRevision`: 확정 편집/undo/redo 때 증가합니다. Before/After·선택·줌으로 바뀌지 않습니다.
- `storageRevision`: 트랜잭션의 조건부 저장으로 증가합니다. 오래된 저장 응답은 최신 편집을 덮어쓰지 않습니다.
- v3 문서는 공통 `shared`와 독립적인 `designs`를 저장합니다. 각 시안은 장면·자재 설정과 최근 50개 undo/redo 기록을 가지고 Before 기록은 따로 관리합니다. Blob은 복제하지 않고 자산 ID를 참조합니다. v1/v2는 읽을 때 메모리에서만 변환하고 다음 조건부 저장 성공 때 v3를 기록합니다. 이전 치수의 이력은 별도 프로젝트로 복원할 수 있게 보존합니다.
- 자재 버전은 불변이며 기존 프로젝트는 사용 당시 버전을 유지합니다. 비활성화해도 기존 합성은 유지됩니다.
- 선택적인 `materialUsage`는 면별 수동 면적, 배치별 불변 가격·포장 스냅샷, 타일 수동 구매 수량만 저장합니다. 자동 수량과 합계는 장면에서 계산합니다. 시안 복사는 참조 ID를 변환한 깊은 복사이며 개별 실행 취소·공통 크기 변경 복원에 포함됩니다. `renderRevision`은 시각 변경에만 증가해 가격 수정으로 이미지를 다시 합성하지 않습니다. 기존 `quote`는 보관하고 정확하게 연결되는 수동 값만 읽기 시 메모리에서 이관합니다.
- 새 기본 공간은 선택 필드인 `Scene.room`에 정수 mm 치수와 생성 버전을 저장합니다. 기존 사진·고정 배경 프로젝트에는 자동으로 이 필드를 추가하거나 장면을 변경하지 않습니다. 크기 변경은 새 배경 자산을 만들며 이전 배경도 전체 복원 백업과 시안 이력에서 참조합니다.
- 한 브라우저 저장 공간에서 쓰기 탭 하나를 Web Locks로 관리합니다. 두 번째 탭은 읽기 전용으로 기다리며 앞 탭 종료 후 편집권을 얻습니다.
- 저장 성공은 IndexedDB 트랜잭션 완료 후 표시합니다. 용량 초과 시 메모리의 작업과 기존 저장본을 유지합니다.
- 삭제/정리는 모든 시안·Before·개별 이력·이전 버전 기록·전체 복원 백업·자재 버전과 파생 자산의 원본 참조를 보존합니다. 미저장 업로드는 24시간 유예합니다. 로컬 재구성 모형은 모든 프로젝트·이력에서 사용하지 않는 내부 캐시만 24시간 후 정리하며, 일반 자재·개인 복제·수정 버전은 유지합니다.

브라우저 데이터 삭제 시 프로젝트가 사라질 수 있습니다. 이미지 내보내기는 다시 편집할 수 있는 프로젝트 백업이 아닙니다. 대용량 프로젝트 백업·이동 기능은 현재 제공하지 않습니다.

목록 썸네일과 비교 미리보기는 별도 브라우저 캐시에만 보관합니다. 시안 생성·복사·전환·비교는 AI를 호출하거나 합성 이미지를 서버에 업로드하지 않습니다. 사용자가 누른 다운로드만 PC에 파일을 만듭니다.

## Supabase 연결 준비

`.env.example`과 `supabase/README.md`, `supabase/migrations`에 설정 및 SQL이 있습니다. 이번 버전의 실제 검증은 로컬 모드를 기준으로 합니다. Supabase 계정 생성, 마이그레이션 적용, 이메일 인증 설정, 관리자 지정 및 실제 사용자 격리 검증은 설정 후 수행해야 합니다.

```dotenv
NEXT_PUBLIC_STORAGE_MODE=local
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
SUPABASE_SECRET_KEY=
```

서버 모드 사용 시 `NEXT_PUBLIC_STORAGE_MODE=supabase`를 명시하고 설정 후 개발 서버를 재시작합니다. 프로덕션 실행은 공개 환경변수가 빌드에 포함되므로 설정 변경 후 `npm run build`도 다시 실행합니다. 키가 있어도 자동으로 서버 모드가 되지 않으며, 실패 시 로컬로 조용히 전환하지 않습니다. 로컬 자료도 자동 업로드하지 않습니다. Secret key를 `NEXT_PUBLIC_` 변수나 브라우저 코드에 넣지 마세요.

서버 어댑터는 이메일/비밀번호 인증, 서버 사용자 검증, 소유권/RLS, 관리자 공용 목록 권한, 비공개 Storage, 이미지 재검증, 조건부 문서 저장, 실패 업로드 정리 경로를 포함합니다. `storage.objects`를 직접 SQL로 지우지 않고 Storage API를 사용합니다.

## 외부 기능과 한계

- AI 고화질 보정, 자동 배경 제거, 3D 모델 업로드/배치는 **후속 구현**입니다. 고화질 보정 버튼은 사진을 전송하거나 AI API를 호출하지 않습니다. 테스트용 결과를 실제 AI처럼 표시하지 않습니다.
- 벽·바닥 자동 찾기는 Google DeepLabV3 MobileNetV2 ADE20K 모델을 Web Worker의 TensorFlow.js WASM에서 실행합니다. 모델 약 2.3MB와 실행 파일은 앱에 포함돼 자격 증명이나 외부 다운로드 없이 동작합니다. 사진에 따라 문틀·작은 수전·모서리가 잘못 분류될 수 있습니다. 수동 경계 보정은 제공하지 않습니다. 벽의 꺾임은 사진 근거로 추정하고 실제 치수는 확정하지 않습니다.
- 재구성 Before는 사진의 대표색과 기구 배치를 추정한 비교 초안입니다. 기본 모형은 실제 상품 형상 복원이나 3D 모델 업로드 기능이 아닙니다. 사진에 보이는 깊이를 방 전체로 간주하지 않으며, 초기 깊이 구간과 기구 위치는 원본과 대조해 보정해야 합니다.
- 2D 제품의 평면 회전은 실제 3D 회전이 아닙니다. 새 기본 공간은 등록 가로·높이와 이미지의 투명 여백을 고려해 크기를 맞추지만 사진 속 제품의 실제 형상·깊이·설치 가능성을 확정하지는 않습니다. 사진 프로젝트의 제품은 기존 수동 크기 조절을 사용합니다.
- 명암 추출로 기존 무늬가 일부 남는 사진에서는 명암 보존을 0으로 낮추세요. 자동으로 완벽한 재질/광원 분리를 보장하지 않습니다.
- 접지 그림자와 색감은 사용자가 조절하는 합성 효과이며 물리 기반 광원 재현이 아닙니다.
- 데스크톱 Chrome/Edge와 WebGL2·Web Locks를 우선 지원합니다. WebGL 실패는 오류로 안내합니다. 모바일은 접이식 패널을 제공하지만 정밀 편집은 데스크톱을 권장합니다.
- 파일 출력은 가상 시공 결과입니다. 실제 색상·치수·설치 가능 여부는 실측과 현장 확인이 필요합니다.
- 기본 공간의 자재 면적은 적용된 벽·바닥 설정 치수와 명확한 하위 밴드 범위에서 계산합니다. 사진·충돌 영역은 순시공 면적을 직접 입력합니다. 제품 가림과 타일 픽셀은 구매 면적으로 환산하지 않습니다. 정보가 부족하면 확인된 자재비와 미계산/면적·포장 확인 필요 항목을 나눠 표시합니다. 타일 수량은 입력 면적 기준의 예상치이며 절단·현장 여유분은 자동 가산하지 않습니다.

## 검증

```powershell
npm run typecheck
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
npm run test:webgl
npm run test:images
npm run test:ui
npm run test:failure
npm run test:segmentation
npx playwright test e2e/material-usage.spec.ts e2e/material-usage-inputs.spec.ts e2e/designs.spec.ts e2e/design-failures.spec.ts
node --experimental-strip-types tests/design-preview-browser.ts
```

E2E와 UI 검증은 Playwright에서 시스템 Chrome을 사용합니다. 별도 WebGL·이미지·실패 검증도 시스템 Chrome을 사용하며 `npm run dev`가 실행 중이어야 합니다. UI 검증은 Playwright가 로컬 개발 서버를 재사용하거나 시작합니다. 테스트 장면은 외부 전송 없이 로컬에서 생성됩니다. 자세한 실행 결과·환경·미실행 항목은 [다중 시안 검증](docs/designs-verification.md) 및 [기존 검증 기록](docs/verification.md), 예시 자산 정보는 [자산 출처](docs/assets.md)에 기록합니다.
