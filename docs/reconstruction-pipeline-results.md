# 사진 재구성 후보의 실제 비교 평가

2026-09-13. 실제 사진 36장 순차 평가와 집계를 완료했다. 개선 후보의 자동 배치 개선 근거가 없어 일반 프로젝트에 채택하지 않았다.

## 동일 조건과 자료

- 실제 사진 36장: 개발용 24, 최종 평가용 12. 공개 라이선스·출처·입력 SHA256·주석을 고정했다. 별도의 사용자 사진 실험 및 합성 단위 테스트는 이 36장에 합산하지 않는다.
- 모든 사진의 비교용 공간 치수는 가로·깊이·높이 2400mm다. 현장 실측이 아니라 두 엔진에 같은 조건을 주는 통제값이다.
- 입력 JPEG는 긴 변 최대 1000px로 방향 정규화한 동일 파일이다. Qwen 전달 사진은 브라우저에서 JPEG 0.95로 다시 인코딩되며 크기를 늘리지 않는다. 원본 파일 지문과 분석 치수는 결과에 기록한다.
- 기준선은 DeepLab ADE20K와 기존 관측 규칙/표준 모형이다. 후보는 같은 기준선 관측을 재사용하고 Qwen 구조화 분석·촬영 시점·모형 배치 검사를 추가한다. 따라서 후보 전체 실행 시간은 DeepLab 재분석을 포함하지 않는 추가 실행 시간이다.
- 변경 없이 고정한 소스 hash: `5409cc3a037947c4319041f89b14238d8f9ec06cb36d90e60f7e12d44c82e562`.
- 자료/주석 manifest hash: `2848369591ebd854929ff94ff0f79b8a47f913e5fd8ef689a81ffcc7f86da4f6`.
- 모델 `qwen3-vl:4b-instruct-q4_K_M`, digest `ee4b975b58c17ce268cd19d40db35d5edc64603035d2ffc1fee1968eb0947f7b`, prompt revision 5, sampling/8192 context/4096 output 설정은 [구현 문서](reconstruction-pipeline.md)와 각 보고서에 보존했다. 기존 로컬 캐시를 사용했고 새 모델 다운로드는 하지 않았다.
- Windows 11 10.0.26200, Ryzen 7 7800X3D(16 논리 스레드), RAM 33,444,208,640bytes, RTX 4070 Ti 12,282MiB, driver 591.86, Ollama 0.34.0. Chrome 152.0.7977.83 headless/SwiftShader, DeepLab TFJS WASM 단일 스레드. GPU는 로컬 Ollama가 사용한다.
- 사진별 새 브라우저 context와 전용 Worker, 순차 추론. 후보 종료 시 모델은 메모리에서 내리고 디스크 캐시는 유지한다. OS 파일 캐시를 비운 냉간 실험은 아니다. 문서 작업/가벼운 검토가 병행된 개발 PC 측정이며 최소 기기 사양이나 독점 실험실 성능을 보장하지 않는다.

## 평가 해석

평가 주석은 후보 결과와 분리한 원본 사진에 대한 Codex 시각 검토다. 사람의 최종 다인 판정이나 실제 카메라/제품 mm 정답은 없다. 가시 영역 IoU 0.25 이상 일대일 대응 뒤 종류·속성·누락·오탐·반사 등을 따로 센다. 작은 설비·부분 가림·투명 유리의 영역 주석에는 오차가 있다. 제품 수가 많은 사진의 후보 수를 그대로 인식 성공 수로 쓰지 않는다.

기준선의 raw semantic 후보와 규칙을 거쳐 배치한 표준 모형을 구분한다. 후보의 원자동 관측과 적용 결과를 구분하고 사용자 수정은 AI 점수에서 제외한다. 스키마 거부는 실행 실패이며 ‘모델이 아무것도 보지 못했다’와 같은 의미가 아니다. 초기 원문에는 일부 맞는 설비와 반복·잘못된 속성이 함께 존재할 수 있다.

현재 스키마/표준 모형은 세면대의 wall/pedestal/vanity 지지 형태와 허용 설치 조합을 제한한다. 실제로 가능한 벽걸이 하부장과 같은 조합도 현재 후보 계약에서는 거부될 수 있다. 해당 거부를 곧바로 모델 자체의 시각 인식 오류라고 단정하지 않는다. 모든 실패를 더 큰 모델로 해결할 수 있다는 근거도 없다.

촬영 카메라가 보류되면 배치가 비어 있어도 빈 방을 성공적인 재구성으로 평가하지 않는다. 정해진 기본 카메라나 임의 위치로 몰래 대체하지 않는다. 기본 모형의 크기/형상/방향을 연속 최적화하지 않았으며, 재투영 잔차는 진단이지 실측 정확도가 아니다.

응답 길이 제한 실패는 일부 원문·모델 단계별 시간이 저장되지 않는다. 이 값은 미측정으로 유지하고 시간 통계의 표본 수를 명시한다. 스키마 검증 실패의 원문과 실제 모델 시간은 completion diagnostics에 저장한다. 테스트 응답 모킹과 녹화된 실제 보고서 재사용 검사는 기능 회귀로만 기록한다.

메모리: 페이지 JS heap에는 Worker/WASM/GPU가 포함되지 않는다. Ollama `/api/ps`를 약 1초마다 관측한 `size_vram`은 모델 런타임 보고 할당량으로 전체 GPU 사용량이나 CPU Working Set이 아니다. 시스템 RAM 용량과 사용량을 혼동하지 않는다. 전체 프로세스 RAM·저사양·OCI CPU·실제 모바일 기기 성능은 미측정이다.

## 개발 사진의 원인 대조

원본 JPEG와 최종 실행의 원문을 별도로 확인했다. 다음 세 사례는 후보 추출 이후 모형 배치 단계 이전인 구조/설치 계약 검증에서 전체 응답이 거부됐다.

| 사진 | 실제 관측과 응답의 차이 | 다음 개선에서 구분할 것 |
|---|---|---|
| bath-01 | 왼쪽 상판/벽 패널이 잘려 세면대 볼과 하부장 지지를 확인하기 어렵다. 모델은 wall+vanity와 visible vanity support를 단정했다 | 관측되지 않은 지지는 unknown으로 남겨야 한다. 이 사진을 정상 벽걸이 하부장 거부 사례라고 단정할 수 없다 |
| bath-06 | 긴 상판 아래 볼/배관과 별도의 낮은 선반이 보여 countertop 해석은 가능하다. 상판 전체의 지지는 불분명하다 | 볼의 상판 설치와 전체 조합의 방 지지 방식을 따로 기록하고 지지 구조의 불확실성을 유지해야 한다 |

2026-09-13에 36장 전체의 첫 완료 기록을 집계했다. 기존 분석은 36/36장, 후보는 10/36장에서 유효한 구조화 결과를 남겼다. 후보의 유효 결과 10장도 촬영 구도 판단이 보류되어 실제 설비 배치가 모두 0개다. 따라서 이번 후보를 일반 프로젝트의 기본 재구성 엔진으로 채택하지 않는다.

‘미대응 관측’은 고정된 평가기에서 `falseAdded`로 기록한 원관측의 bbox 미대응 수이며, unknown 종류·여러 semantic 연결 성분도 포함한다. 실제 앱에 그만큼 제품을 배치했다는 뜻이 아니다. 반사·중복은 일부가 겹칠 수 있어 별도 합산하지 않는다. 비교 대상이 아닌 주석 영역은 기존 개발 17개·최종 평가 16개 관측에서 제외했다. 실제 배치 기준 오추가는 기존 개발 22개·최종 평가 11개였고 후보는 0개지만, 후보가 전체 배치를 보류한 결과이므로 개선으로 평가하지 않는다.

개발 bath-07에는 원문상 변기 후보가 22개, bath-30에는 욕조 후보가 21개 반복됐다. 최종 평가 유효 3장에도 중복 4개와 반사 물체 오추가 1개가 있었다. 후보 수 증가를 설비 인식 개선으로 해석할 수 없다.

실제 모형의 원본 카메라 재투영 성공은 후보에서 0개다. 입력 후보 bbox의 중심 오차를 실제 3D 모형의 위치 정확도나 제품 mm 오차로 보고하지 않았다. 사용자가 몇 번 수정해야 하는지는 측정하지 않았다.

모델 단계별 평균은 개발 n18에서 로드 2.81초·이미지/프롬프트 평가 0.77초·텍스트 생성 21.82초, 최종 평가 n6에서 각각 4.19초·2.17초·33.75초였다. 일반 응답 실패 10장과 `fetch failed` 2장은 해당 시간 진단이 없어 평균에 포함하지 않았다. 모델 다운로드는 수행하지 않았다.

페이지 JS heap의 케이스별 관측 최대 범위는 기존 개발 n24 **19.59–51.47MiB**, 기존 최종 평가 n12 **16.46–41.54MiB**, 후보 유효 개발 n7 **32.80–51.47MiB**, 후보 유효 최종 평가 n3 **33.08–39.34MiB**다. 동일 페이지에서 기존 분석 후 후보를 실행하므로 후보 heap을 후보만의 증분 메모리로 해석하지 않는다. Worker·WASM·GPU는 포함하지 않는다. Ollama `size_vram`의 케이스별 최대 관측은 n36 모두 **4,235,345,264bytes(4039.14MiB)**였다. 약 1초 간격의 모델 할당 표본으로 전체 GPU 피크나 CPU 프로세스 RAM이 아니다.

### 실행 중단과 기록 검증

29개 완료 시점에 자원 경합과 앞선 통신 실패를 관측해 배치를 중단했다. 해당 작업 모델을 로컬 Ollama에서 해제한 뒤 미완료 7개만 같은 코드·모델·설정으로 재개했다. 완료된 실패는 다시 실행하지 않았다. [중단 기록](../test-results/reconstruction-corpus-final/batch-interruption.json)에 해제 후 GPU 관측과 재개 정책이 있다. `fetch failed`의 정확한 원인은 확인하지 못했으며, 중단 전후가 섞인 시간 표본을 통제된 단일 성능 실험으로 보지 않는다.

36개 입력 SHA256·manifest·완료 기록의 구현 hash와 정상 보고서의 엔진 설정 일치를 확인했다. 실제 요청 설정이 저장된 **24개 응답(정상 10+모순 거부 14)**도 모델 digest·prompt revision·sampling 값이 같았다. 진단이 없는 나머지 12개의 개별 요청 설정을 사후 측정한 것처럼 채우지 않았다. 동일 소스와 환경 기록으로 실행된 사실과 개별 진단의 부재를 구분한다.

평가에 사용한 19개 소스의 사본은 [고정 소스 manifest](../test-results/reconstruction-corpus-final/source-frozen/manifest.json)에 보존했다. 이 36장 평가는 위의 `5409cc…` 구현 기준이다. 이후 서버 실패·취소의 자원 해제 경로 보완과 그 기능 검사는 별개이며, 그 보완 후 모델 품질·처리 시간을 다시 측정한 결과는 아니다.

오프라인 비교표는 Chrome 152에서 36개 카드·82개 이미지·46개 PNG 다운로드 링크를 확인했다. 개발 24/최종 평가 12 및 실패 포함 26개 필터, 검색, 1440px 데스크톱·390px 모바일 표시를 검사했고 이미지/파일 응답 실패·브라우저 오류·외부 요청은 없었다. 모바일 집계표는 가로 스크롤한다. [UI 검사 기록](../test-results/reconstruction-corpus-final/report-ui-qa.json)에 범위를 남겼다.

### 채택 결론

**이 후보는 미채택이다.** 실패 26/36장, 유효 결과의 카메라 보류 10/10장, 실제 설비 재구성 0장은 기존 엔진을 교체하거나 품질 향상을 주장할 근거가 되지 않는다. 기존 엔진도 누락·오추가와 설치 불확실성이 남아 있으므로 충분한 품질이라고 판정한 것은 아니다.

다음 검증은 관측과 부품 조합의 설치 의미를 분리하는 계약, 반복 후보 출력, 방 코너·카메라 근거 확보를 각각 다뤄야 한다. 모델의 정확한 지원 형태와 보류 이유를 먼저 보완한 뒤 새 개발 평가를 수행하고 별도의 미사용 평가 사진으로 확인해야 한다. 현재 최종 평가 사진을 보고 맞춤 규칙을 만든 뒤 같은 12장을 새로운 독립 평가로 재사용하지 않는다. 더 큰 모델이나 다른 모델은 이번 결과만으로 추천하거나 채택하지 않는다.

외부 서비스 배포, 사용자 사진 외부 전송, 유료 API, Qwen의 브라우저 기본 다운로드, Supabase 사용자 격리 검증은 수행하지 않았다. TripoSR/BiRefNet과 일반 프로젝트 기본 엔진은 유지한다.
