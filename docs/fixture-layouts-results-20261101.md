# 기본 배치: 관리자가 만든 위생도기 세트를 눌러서 놓기 — 결과 (2026-11-01)

관리자가 놓은 제품을 "1번", "2번"으로 등록해 두면, 회원과 게스트가 눌러서 그대로 놓는다. 타일·벽 구조·SMC 천장은 건드리지 않는다. 놓인 제품은 보통 제품과 같아서 옮기고 지울 수 있다.

- **migration 0013:** 원격 적용은 사용자가 한다. **병합 전에 적용해야 한다**(9절).
- **원격 D1:** 쓰지도 읽지도 않았다. 실제 AI 호출도 없다.

## 2. 코드에서 다르게 확인한 것

요청서의 "지금 상태"는 확인한 범위에서 코드와 맞았다. 요청서에 없던 것과 계획과 다르게 만든 것은 다음과 같다.

- **탭 값:** 계획은 `tab`에 `'layouts'`를 더하는 것이었다. 하지만 `tab !== 'fixtures'`이면 타일로 보는 코드(`editorTabQuery`, 적용 위치 선택 등)가 여러 곳이라 잘못된 목록 요청이 나간다. 그래서 `tab`은 그대로 두고 `layoutsOpen`을 따로 뒀다. 기본 배치를 여닫아도 자재 목록을 다시 읽지 않는다.
- **표면 선택:** 표면을 고르면 탭이 그 종류로 바뀌는 동작을 유지하고, 기본 배치 화면도 닫는다.
- **유리 지지:** 유리 제품은 부모 제품을 가리킨다(`parentFixtureId`). 잠근 제품의 부모를 지우면 지지가 끊기므로 부모도 남긴다.
- **재시도 키:** 작업 이름이 정해진 목록(`create, save, update, remove` 등)에 있어야 작동한다. 위생도기 종류의 `delete`는 여기 없다. 기본 배치는 목록에 있는 이름만 쓴다.
- **서버 코드 위치:** 공개 목록은 계획의 `catalog/public.ts`가 아니라 `catalog/layouts-server.ts`에 뒀다. 관리 코드와 읽기 코드를 나누지 않으려고 한곳에 모았다.
- **Before 편집:** 사진 프로젝트에만 있다. 기본 공간 프로젝트에는 없다.
- **`tests/d1-material-kinds.test.ts`:** "0011 DB"를 목록의 마지막을 빼서 만들고 있어 0013을 더하자 깨졌다. 0012 앞까지로 고쳤다.

## 3. 쓰는 법

- **관리자**(11절에서 바뀜)
  1. 메뉴의 **기본 배치**(`/admin/layouts`) → **새 배치** → 공간 크기를 넣는다.
  2. 편집창과 같은 화면에서 위생도기를 놓고 끌어 자리를 잡는다. 벽을 먼저 누르면 벽 제품이 그 벽에 놓인다.
  3. 위쪽에 이름을 넣고 **저장**한다. 저장하면 바로 모든 이용자에게 보인다.
  4. 고칠 때는 목록에서 **열기**, 고친 뒤 **저장**. 목록에서 이름·순서·숨김·삭제를 한다. 번호는 저장 값이 아니라 순서에서 나온다. 숨기면 뒤 번호가 당겨진다.
- **이용자:** **기본 배치** 탭에서 번호를 누른다. 휴대폰에서는 패널이 닫힌다.
- **꺼지는 곳:** 방 없는 옛 사진 장면, 읽기 전용, Before 편집에서는 이유를 보인다. 관리자가 다른 회원의 프로젝트를 열었을 때는 탭이 없다.
- **알림:** 바꾼 개수, 빠진 제품, 방향 사진이 없어 대신 쓴 사진, 공간보다 커서 뺀 제품, 자리가 없어 겹친 제품.

## 4. 데이터 형식

- 새 표 `d1_fixture_layouts`: `id, name, display_order, active, items_json, room_json, revision, created_by, created_at, updated_at`. 기존 표는 다시 쓰지 않는다.
- 제품 항목(`src/lib/fixture-layout-contract.ts`): `materialId, face, u, v, scale, againstWall, rotation, direction, color, shadow`.
- 담지 않는 것: `occlusion`, `projectedQuad`, `position`, `id`, `locked`, `reconstruction`, 버전 id.
- 프로젝트의 저장 형식(Scene·fixture)은 그대로다. 렌더 코드를 바꾸지 않아 `ROOM_VIEWER_RENDERER_REVISION`도 그대로다.

## 5. API

| 경로 | 권한 | 내용 |
| --- | --- | --- |
| `GET /api/catalog/layouts` | 로그인 없음 | 사용 중인 배치를 순서대로, 자재의 공개 배치 정보(`placementsOf`), 빠진 제품 수 |
| `POST /api/d1/fixture-layouts` | 활성 관리자 | `list`, `create`, `save`(덮어쓰기), `update`(이름·순서·사용), `remove` |

- 쓰기는 `X-Idempotency-Key`로 재시도하고, `revision`이 다르면 409다.
- 등록과 덮어쓰기는 모든 자재가 지금 공개된 공용 자재인지 서버에서 확인한다. 개인 자재, 프로젝트 전용, 사진 분석 모형, 타일, 없는 자재는 400이다.
- 공개 응답에는 회원 정보, R2 키, 전체 payload, 만든 사람, revision이 없다.

## 6. 놓기 규칙 (`src/lib/fixture-layouts.ts`)

1. 현재 버전에서 저장한 방향의 사진을 고른다(옛 표기는 같은 방향으로 읽는다). 없으면 `getPlacementViewIndex`로 대신하고 알린다.
2. 방이 같으면 등록한 자리 그대로다. 다르면 u·v 비율을 유지하고, 벽 제품은 바닥에서 같은 mm가 되게 v를 다시 계산한다.
3. 벽에 붙은 제품은 그 방의 벽에 제품 깊이만큼 다시 붙는다. 어느 벽인지는 사진 방향이 정한다.
4. 벽을 넘거나 겹치면 `findFreeSlot`·`freeWallSlot`으로 비킨다. 벽 제품은 높이를 두고 가로로만 움직인다. 잠근 제품도 피한다. 큰 제품부터 자리를 잡아 결과가 늘 같고, 저장 순서는 등록 순서다.
5. 자리가 없으면 겹쳐 놓고 알린다. 공간보다 큰 제품은 빼고 알린다.

- **한 번의 기록:** 자재와 이미지를 모두 읽은 뒤 `st.change` 한 번으로 넣는다. 되돌리기 1번, 저장 1번이다.
- **벽에 바로 붙기:** 바꾸기 전에 `initializeUsage`로 store에 새 자재를 알린다. 안 그러면 벽 붙임이 다음 변경까지 미뤄진다.
- **나눠 쓰는 코드:** 새 제품의 시작 값은 `createPlacedFixture` 하나를 `applyMaterial`과 함께 쓴다.
- **게스트:** 목록을 받을 때 자재를 임시 저장소에 넣어 이미지 읽기와 초안 저장이 되게 한다. 초안에는 그 자재의 공개 정보만 남는다.

## 9. 적용

로컬 개발 DB는 `npm run db:dev:migrate`로 올린다. 올리기 전에는 준비 검사가 저장소를 막는다.

원격은 사용자가 병합 전에 한다.

```bash
npx wrangler d1 migrations apply sjn --remote
npx wrangler d1 migrations list sjn --remote
```

- 첫 명령의 목록에 `0013_fixture_layouts.sql` 하나만 있어야 한다. 둘째 명령은 `No migrations to apply`여야 한다.
- 순서: **원격에 0013 적용 → main 병합·푸시.** 반대로 하면 배포 직후 준비 검사가 표를 찾지 못해 저장소가 막힌다.
- 비용(시험 DB): 쿼리 1, 읽기 1행, **쓰기 3행**. 표만 만들고 행을 넣지 않는다. D1이 적용 기록을 남기는 `d1_migrations` 쓰기는 따로다.

## 10. 하지 않은 것과 한계

- 타일·벽 구조·천장을 담은 세트, 이용자 자기 배치 저장, 배치 안 제품 교체, 새 프로젝트에서 배치 고르기, 일반 회원에게 위생도기 탭 열기, 표준 모형 상태 저장, 사진 분석 표준 모형 등록.
- 벽 홈·젠다이와 제품의 충돌은 지금처럼 막지 않는다. 배치의 제품이 젠다이와 겹칠 수 있다.
- 바꾸기는 잠그지 않은 제품을 모두 지운다. 사진 분석으로 만든 프로젝트의 제품도 잠그지 않았으면 지워진다(Ctrl+Z로 돌아온다).
- 비례로 옮기므로 좁은 방에서는 벽 제품과 바닥 제품의 앞뒤 관계가 등록한 방과 달라질 수 있다.
- "표준 모형으로 보기" 안내와, 방 없는 장면·읽기 전용의 이유 문구, 다른 회원 프로젝트에서 탭이 없는 것은 e2e로 확인하지 않았다(앞의 문구 판단은 단위 시험만).
- AI 변환에서 놓인 제품이 어떻게 나오는지는 보통 제품과 같은 경로라 따로 시험하지 않았다.

| `/admin/catalog`의 표 | 새 탭으로 옮김 | 기본값(계획 승인) |
| 저장 방식 | 저장 버튼. 자동 저장 없음(저장이 곧 공개) | 기본값(계획 승인) |
| 숨긴 배치 | 열어서 고칠 수 있고, 저장해도 숨김 유지 | 기본값(계획 승인) |

**방식.** 편집 화면은 `Editor`를 그대로 쓰고, `layoutStudio` prop이 있을 때만 프로젝트 전용 버튼과 부분 타일·벽 구조·천장 도구를 숨긴다. 저장소는 체험 엔진을 메모리에 하나 더 만든 것(`createLayoutStudioSession`)이다. 그래서 프로젝트와 업로드가 생기지 않고, 공개 자재만 보이며, 게스트 초안과 섞이지 않는다.

**계획과 다르게 한 것.** 공간 크기 변경은 세션을 새로 만들지 않고 편집창의 기존 기능을 그대로 쓴다. 되돌리기 기록이 유지된다. 대신 벽 제품의 높이는 이 경우 mm가 아니라 비율로 따라간다(프로젝트의 공간 크기 변경과 같음). 이용자가 누를 때의 규칙(바닥에서 같은 mm)은 그대로다.

**API.** migration은 없다. **원격 D1 적용이 필요 없다.** `save`가 이름을 함께 쓰고(쓰기 1번), `list`가 `placements`를 함께 준다(이미 읽던 값이라 쿼리 수 그대로). 숨긴 배치를 공개 API 없이 여는 데 쓴다.

**화면 호출(`e2e/fixture-layouts.spec.ts`).** 놓기·끌기 중 서버 요청 없음(역할 확인 제외), 저장 1번에 `/api/d1/fixture-layouts` 1번, 프로젝트 저장 0, `d1_projects` 0행, 게스트 초안 없음.

**한계.**

- 전용 화면에는 공간 둘러보기·타일·벽 구조가 없다. 제품만 본다.
- 초안을 보관하지 않아 새로고침하면 저장 안 한 내용이 사라진다(브라우저 경고, 뒤로 버튼은 확인).
- 공개된 공용 제품만 놓을 수 있다.
- 벽 제품은 프로젝트처럼 처음에 첫 벽(왼쪽)에 놓인다. 다른 벽에 두려면 벽을 먼저 누르거나 속성에서 바꾼다.
- 두 관리자가 같은 배치를 함께 고치면 나중 저장이 409로 막힌다. 안내 뒤 목록에서 다시 열어야 한다.
