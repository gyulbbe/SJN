# 자재 목록 순서·관리자 우선순위 결과 · 2026-10-27

모든 자재 목록에서 순서를 고를 수 있다. 우선순위(기본)·최신 등록순·이름 오름차순·이름 내림차순이다. 관리자는 공용 자재에 우선순위 번호를 매긴다. 예를 들어 a·b·c·d 타일 중 a에 1, b에 2를 주면 a, b가 먼저 보이고 c, d는 이름순으로 이어진다.

- **원격 D1:** 쓰지도 읽지도 않았다.
- **0010:** 시험 DB(Miniflare)에 적용했다. **원격 `sjn`에는 2026-10-27 사용자가 적용했다**(사용자 보고: `migrations apply` 후 `migrations list`가 `No migrations to apply`). 작업 환경에서는 원격을 확인하지 않았다.
- **배포:** 하지 않았다.

## 1. 사용자 결정

- 순서 4가지: 우선순위(기본) / 최신 등록순(자재 `created_at` 내림차순) / 이름 오름차순 / 이름 내림차순. "등록순"은 최신 등록순 하나만 둔다.
- 오름·내림차순은 이름 기준만이다(가격 순서 없음).
- 우선순위 입력: `/admin/materials`의 공용 자재 카드에서 바로 한다. 새 버전을 만들지 않는다.
- 적용 범위: 자재가 나오는 목록 전부. 공개 `/materials`, 편집기 자재 서랍(회원·게스트 `/try`·관리자 프로젝트), 관리자 자재다.

## 2. 바꾼 것

| 화면 | 정렬 위치 | 기본 |
| --- | --- | --- |
| 공개 `/materials` | 결과 줄("전체 n개 중 m개") 오른쪽의 "정렬". 조건 초기화는 순서를 바꾸지 않는다 | 우선순위 |
| 편집기 서랍(회원·게스트·관리자 프로젝트) | 검색 칸 옆 작은 칸. 짧은 이름(우선순위·최신순·이름순·이름 역순)을 쓰고 전체 이름은 `title`이다. 새 줄을 만들지 않아 카드 두 줄이 그대로 보인다. 편집 화면 안에서는 탭을 바꿔도 유지된다 | 우선순위 |
| 관리자 `/admin/materials` | 카테고리 줄 오른쪽, "비활성 자재" 옆 | 우선순위 |

**우선순위 순서**
- 번호가 있는 공용 자재가 번호 작은 것부터 먼저 나온다. 같은 번호끼리는 이름순이다.
- 번호가 없는 자재는 그 뒤에 이름순이다.
- 개인 자재는 번호가 없는 것과 같다. 번호는 공용 자재에만 매길 수 있다.
- 이름은 앞뒤 공백을 빼고 영문 대소문자를 구분하지 않고 비교한다. 바이트 순서라 숫자 → 영문 → 한글(가나다) 순이다. 숫자는 글자로 비교한다(`타일 10`이 `타일 2`보다 앞).
- 이름이 같으면 자재 id 순서다.

**관리자 카드의 "우선순위" 칸**([priority-input](../src/components/materials/priority-input.tsx))
- 공용 자재 카드에만 있다. 1~9999 정수를 넣는다.
- Enter를 누르거나 칸을 떠나면 바뀐 값만 저장한다. 비우면 해제한다. Escape는 저장된 값으로 되돌린다.
- 1~9999 정수가 아니면 보내지 않고 칸을 빨갛게 표시한다.
- 저장은 한 번에 하나다. 실패하면 저장된 값으로 되돌리고 오류를 보인다.
- 저장하면 그 카드만 바꾸고 목록을 다시 받지 않는다. 여러 개를 이어서 매기는 동안 카드가 움직이지 않게 하려는 것이다. 순서가 우선순위일 때만 "새 순서 보기"가 나오고, 누르면 첫 쪽을 다시 받는다.
- 자재 정보 수정 뒤에도 카드는 제자리에서 바뀐다(예전에는 "가장 최근"이라 맨 앞으로 옮겼다). 우선순위는 유지된다.
- 우선순위는 `updated_at`을 바꾸지 않는다.

**쪽 사이에 바뀐 자재**
- 쪽을 받는 사이에 우선순위나 이름이 바뀐 자재는 다음 쪽에 다시 나올 수 있다. 이미 보이는 카드는 그대로 두고 다시 온 것은 버린다(`useMaterialPages`의 `identify`).
- 앞쪽으로 옮겨 간 자재는 처음부터 다시 받으면 보인다.

## 3. migration 0010 (`migrations/d1/0010_material_order.sql`)

**바뀌는 것**(추가만, 기존 표·열·인덱스·데이터 유지)
- `d1_materials.priority INTEGER`: `NULL` 또는 1~9999 정수(`CHECK`에 `typeof='integer'`).
- 요약 두 표(`d1_material_list`·`d1_material_list_facets`)에 정렬 열 3개를 더한다.
  - `prio`: 공용 자재면 `priority`, 없거나 개인 자재면 10000
  - `name_key`: 버전 이름의 `lower(trim())`(ASCII만 소문자, 공백만 제거) 앞 100자. 커서가 이 값을 담으므로 짧게 둔다. 앞 100자가 같은 이름끼리는 자재 id 순서다
  - `created_at`: 자재 등록 시각
- 기존 행은 UPDATE로 채운다. 인덱스보다 먼저 한다.
- 인덱스 15개: 0009의 다섯 모양(편집기 탭 lane·종류·전체·개인·분류 값) × 정렬 3계열.
  - `_prio`: `prio, name_key, material_id`
  - `_name`: `name_key, material_id`. 이름 내림차순은 거꾸로 읽는다.
  - `_new`: `created_at DESC, material_id DESC`
- 모든 부분 인덱스 조건을 두 개(`is_current=1 AND scope=…`)로 맞췄다. 0009의 `d1_list_lane`처럼 세 번째 조건(`active=1`)이 있으면 SQLite가 행마다 표를 다시 읽는다. 그래서 lane 인덱스는 `active`를 첫 열로 두었다.
- 트리거
  - 0009의 버전 INSERT·UPDATE 트리거를 지우고 새 열까지 채우게 다시 만든다. 본문은 0009와 같고 열만 더했다. 분류 행은 요약 행에서 복사한다.
  - `d1_material_list_priority`: `priority`·`scope`가 바뀌면 그 자재의 모든 버전 사본의 `prio`를 고친다. counts는 바뀌지 않는다.
  - `d1_material_list_created`: `created_at`이 바뀌면 사본을 고친다. 우선순위를 바꿀 때 등록순 인덱스까지 다시 쓰지 않게 나눴다.
- 0009 인덱스 5개는 지금 목록이 쓰지 않는다. 그래도 남겼다. 배포 전후에 옛 코드가 `INDEXED BY`로 읽고, `d1_list_recent`는 목록 이미지 일괄 생성이 쓴다.
- **준비 검사**(`checkD1Storage`): 새 열 probe와 인덱스 15개·트리거 2개의 이름을 확인한다. 메타 버전은 올리지 않았다. 0010 없이 새 코드가 배포되면 준비 검사가 실패해 저장소 전체가 503이 된다.

**원격 적용**(사용자가 한다)
```bash
npx wrangler d1 migrations apply sjn --remote
npx wrangler d1 migrations list sjn --remote   # No migrations to apply 확인
```
- 순서: 0010 적용 → 확인 → main 푸시(배포). 0010만 먼저 적용하는 것은 안전하다. 옛 코드는 새 열을 모르고, 트리거가 새 열을 맞춘다.
- 비용(시험 DB, 운영 모양 1배: 자재 986개·요약 987행·분류 3,115행): **읽기 50,414행, 쓰기 22,049행**(한 번). 하루 무료 쓰기 10만 행의 약 22%다. 같은 날 대량 등록을 함께 하지 않는다.
- 되돌리기: 0010 뒤에 옛 코드로 돌아가도 동작한다(옛 열·인덱스가 그대로다).

## 4. API

| 값 | 뜻 |
| --- | --- |
| `sort` | `priority`(기본)·`newest`·`name`·`nameDesc`. 모든 목록 질의(`materialPageQuerySchema`)와 공개 GET(`?sort=`)에 있다. 기본값이면 보내지 않는다(배포 전 서버의 strict 검사와도 맞음) |
| `materials({operation:'setPriority', id, priority})` | 관리자만. 공용·catalog 자재의 `priority`를 정하거나(`1~9999`) 지운다(`null`). 개인 자재는 400, 회원은 403, 관리자 프로젝트 범위는 403. 다른 값(0, 10000, 1.5, `'1'`, 빠짐)은 400. 새 버전·`updated_at` 없음. 관리자 batch(활성 관리자 확인)와 재시도 기록을 쓴다. 응답 `{ priority }` |
| 카드 `priority` | `MaterialCard.priority`(관리자 자재·편집기 서랍 카드). 번호가 없으면 `null` |

**커서**
- 마지막 항목의 정렬 값(`s`)과 질의 지문을 담는다. 지문에 정렬이 들어가므로 다른 정렬에 쓰면 400이다.
- 이름 키는 100자까지지만 분류 선택과 함께 담기므로 커서 길이 상한을 2,048자에서 4,096자로 올렸다.
- 배포 전에 연 탭이 들고 있던 옛 커서(`u`)는 400 "목록 순서가 바뀌었어요. 목록을 처음부터 다시 불러와 주세요."다. "다시 시도"를 누르면 첫 쪽부터 받는다. 옛 탭의 첫 쪽 요청은 그대로 된다(정렬이 없으면 기본값).
- 클라이언트(`cloud.ts`)는 `setPriority`도 `setActive`처럼 매번 새 요청 id를 쓴다. 그렇지 않으면 1 → 해제 → 1처럼 같은 값으로 돌아갈 때 첫 응답이 재생되어 저장되지 않는다.
