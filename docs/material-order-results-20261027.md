# 자재 목록 순서·브랜드 우선순위 결과 · 2026-10-27

모든 자재 목록에서 순서를 고를 수 있다. 브랜드 우선순위(기본)·최신 등록순·이름 오름차순·이름 내림차순이다. 브랜드 우선순위는 관리자가 **분류 관리의 브랜드 "표시 순서"**에 매긴 숫자다. 중요한 브랜드 몇 개에만 숫자를 넣으면, 그 브랜드의 자재가 숫자 작은 순서(0부터)로 먼저 나오고 나머지 자재는 이름순으로 이어진다.

- **원격 D1:** 작업 중 쓰지도 읽지도 않았다.
- **0010:** 원격 `sjn`에 2026-10-27 사용자가 적용했고(사용자 보고), 같은 날 main에 병합했다(`cf60e50`).
- **0011:** 시험 DB(Miniflare)에 적용했다. **원격 `sjn`에는 2026-10-27 사용자가 적용했다**(사용자 보고: `migrations apply` 후 `migrations list`가 `No migrations to apply`). 작업 환경에서는 원격을 확인하지 않았다. 그 뒤 main에 병합했다.

## 1. 사용자 결정

- 순서 4가지: 브랜드 우선순위(기본) / 최신 등록순(자재 `created_at` 내림차순) / 이름 오름차순 / 이름 내림차순. 가격 순서는 없다.
- 우선순위는 **자재마다가 아니라 브랜드마다** 정한다. 처음 만든 자재별 우선순위(자재 관리 카드의 칸)는 없앴다.
- 정하는 곳은 분류 관리의 "표시 순서"다. 같은 숫자로 자재 등록 양식의 브랜드 목록 순서도 정한다.
- 표시 순서는 **빈칸 또는 숫자만** 받는다. 지금 등록된 모든 분류(브랜드·색상·재질·마감·하위 카테고리)의 표시 순서는 빈칸으로 시작한다.
- 같은 브랜드 안은 자재 이름순, 순서 없는 브랜드의 자재는 브랜드와 상관없이 자재 이름순이다.
- 분류 관리에서 종류를 "브랜드"로 고르면 한 줄 설명이 나온다.

## 2. 화면

| 화면 | 바뀐 것 |
| --- | --- |
| 분류 관리 `/admin/catalog` | "표시 순서" 칸은 빈칸 또는 숫자(0~9999)만 입력된다. 글자를 치면 숫자만 남는다. 빈칸은 "순서 없음"이고 표에는 `—`로 보인다. 종류가 브랜드일 때 "브랜드 표시 순서는 자재 목록의 기본 순서예요. 숫자가 작은 브랜드(0부터)의 자재가 먼저 나오고, 순서가 없는 브랜드의 자재는 그 뒤에 이름순으로 나와요."가 보인다 |
| 공개 `/materials` | 결과 줄("전체 n개 중 m개") 오른쪽의 "정렬". 조건 초기화는 순서를 바꾸지 않는다 |
| 편집기 서랍(회원·게스트·관리자 프로젝트) | 검색 칸 옆 작은 칸. 짧은 이름(브랜드순·최신순·이름순·이름 역순)을 쓰고 전체 이름은 `title`이다. 새 줄을 만들지 않아 카드 두 줄이 그대로 보인다. 편집 화면 안에서는 탭을 바꿔도 유지된다 |
| 관리자 `/admin/materials` | 카테고리 줄 오른쪽, "비활성 자재" 옆의 "정렬" |

**표시 순서가 쓰이는 곳**
- 분류 관리 표: 숫자 있는 것(작은 것부터) → 빈칸(이름순).
- 자재 등록·수정 양식의 브랜드·하위 카테고리·색상·재질·마감 선택 목록: 같은 순서다.
- 자재 목록의 기본 순서: **브랜드의 표시 순서만** 쓴다. 색상·재질·마감·하위 카테고리의 표시 순서는 자재 목록 순서에 쓰지 않는다.

**자재 목록의 브랜드 우선순위 순서**
- 버전에 연결된 브랜드(자재 등록 양식에서 고른 브랜드)의 표시 순서가 작은 자재가 먼저다. 같은 숫자의 브랜드끼리는 자재 이름순으로 섞인다.
- 브랜드가 없거나 브랜드에 표시 순서가 없는 자재는 그 뒤에 자재 이름순이다.
- 이름은 앞뒤 공백을 빼고 영문 대소문자를 구분하지 않고 비교한다. 바이트 순서라 숫자 → 영문 → 한글(가나다) 순이다. 숫자는 글자로 비교한다(`타일 10`이 `타일 2`보다 앞). 이름이 같으면 자재 id 순서다.
- 브랜드 순서를 바꾸면 다음에 목록을 받을 때 바로 반영된다. 새 자재도 저장하는 순간 자기 브랜드 자리에 들어간다.

**쪽 사이에 바뀐 자재**
- 쪽을 받는 사이에 브랜드 순서나 이름이 바뀐 자재는 다음 쪽에 다시 나올 수 있다. 이미 보이는 카드는 그대로 두고 다시 온 것은 버린다(`useMaterialPages`의 `identify`).
- 자재 정보를 수정한 뒤 카드는 제자리에서 바뀐다(예전에는 "가장 최근"이라 맨 앞으로 옮겼다).

## 3. migration

### 0010 (`migrations/d1/0010_material_order.sql`, 원격 적용됨)

- 요약 두 표(`d1_material_list`·`d1_material_list_facets`)에 정렬 열 3개를 더했다.
  - `prio`: 0011부터 버전 브랜드의 표시 순서, 없으면 10000
  - `name_key`: 버전 이름의 `lower(trim())` 앞 100자(ASCII만 소문자, 공백만 제거). 커서가 이 값을 담으므로 짧게 둔다
  - `created_at`: 자재 등록 시각
- 인덱스 15개: 0009의 다섯 모양(편집기 탭 lane·종류·전체·개인·분류 값) × 정렬 3계열.
  - `_prio`: `prio, name_key, material_id`
  - `_name`: `name_key, material_id`. 이름 내림차순은 거꾸로 읽는다
  - `_new`: `created_at DESC, material_id DESC`
  - 모든 부분 인덱스 조건을 두 개(`is_current=1 AND scope=…`)로 맞춰 인덱스만으로 읽는다. 그래서 lane 인덱스는 `active`가 첫 열이다.
- `d1_materials.priority`(자재별 우선순위)도 더했지만 **0011부터 쓰지 않는다.** 열은 남기고 비웠다.
- 0009 인덱스 5개는 지금 목록이 쓰지 않지만 남겼다. 옛 코드의 `INDEXED BY`와 목록 이미지 일괄 생성(`d1_list_recent`)이 쓴다.

### 0011 (`migrations/d1/0011_brand_order.sql`, 원격 적용됨)

- `d1_catalog_options.display_order`, `d1_material_subcategories.display_order`: `NULL`(빈칸) 또는 0~9999 정수(`CHECK`에 `typeof='integer'`). 새 열이라 **지금 있는 모든 항목이 빈칸으로 시작한다.** 0003의 `sort_order`는 더 읽지 않는다(지우지 않음).
- 자재별 우선순위를 비우고 요약의 `prio`를 모두 10000으로 되돌린다.
- 트리거
  - 0010의 버전 INSERT·UPDATE 트리거를 다시 만든다. `prio`를 버전의 브랜드 표시 순서로 채운다.
  - `d1_material_list_brand_link`·`_unlink`: 저장이 버전 뒤에 브랜드를 연결하면(`catalogStatements`) 그 버전의 `prio`를 맞춘다. 연결이 지워지면 되돌린다.
  - `d1_material_list_brand_order`: 브랜드의 표시 순서가 바뀌면 그 브랜드의 모든 버전 사본(요약·분류 행)을 고친다(`d1_version_options_filter` 인덱스).
  - `d1_material_list_priority`: 0010의 이름을 그대로 둔다(배포 전 코드의 준비 검사가 이 이름을 찾는다). 그 코드가 자재별 우선순위를 써도 순서는 브랜드 순서로 남는다.
- **준비 검사**(`checkD1Storage`): `display_order` 열과 새 트리거 3개 이름을 확인한다. 메타 버전은 올리지 않았다.

## 4. API

| 값 | 뜻 |
| --- | --- |
| `sort` | `priority`(기본, 브랜드 우선순위)·`newest`·`name`·`nameDesc`. 모든 목록 질의(`materialPageQuerySchema`)와 공개 GET(`?sort=`)에 있다. 기본값이면 보내지 않는다 |
| 분류 `sortOrder` | `catalog` create·update와 `list`의 `sortOrder`는 `0~9999` 정수 또는 `null`(빈칸)이다. 다른 값(-1, 10000, 1.5, `'1'`, 빠짐)은 400. 목록은 숫자 있는 것(작은 것부터) → `null`(이름순) |

**커서**
- 마지막 항목의 정렬 값(`s`)과 질의 지문을 담는다. 지문에 정렬이 들어가므로 다른 정렬에 쓰면 400이다. 커서 길이 상한은 4,096자다.
- 정렬 이전 탭의 옛 커서(`u`)는 400 "목록 순서가 바뀌었어요. 목록을 처음부터 다시 불러와 주세요."다.

## 9. 하지 않은 것

- 숫자 자연 정렬(`타일 2` < `타일 10`): 이름을 글자로 비교한다.
