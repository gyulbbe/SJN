# 컷아웃이 실패한 도기 둘레 번짐 (2026-11-26, 결과: 컷아웃 구조 CUT_RESCUE 채택)

- 문제(백로그 10번, 열린 문제 9번): 지금 방식 다듬기는 AI가 그린 도기 윤곽을 컷아웃 모델로 찾는다. 렌더 제품과 겹침이 0.6(`MIN_IOU`)에 못 미치면 렌더 윤곽으로 다듬어, 둘레에 옅은 번짐·잔상이 남는다.
  - 11-16 시험에서는 70개 중 11개, 대부분 흰 벽 앞 흰 물탱크였다([아지랑이](fixture-haze-20261116.md)).
- 결론: 기준에 못 미친 컷아웃만 렌더 제품 둘레 12px로 잘라 다시 잰다. 겹침·덮음·윗부분·넓이 조건을 모두 넘을 때만 쓴다(`fixture-outline.ts` `CUT_RESCUE`, `current-refine.ts` 기본). 통과하던 컷아웃은 그대로 둔다.
  - AI에 보내는 그림·문장·호출 수는 그대로다. AI 답 뒤의 다듬기만 바뀐다.
- 감독(Codex)의 가린 평가와 개발 세션 측정이다. 등록 자재와 앱 규격 모형(욕조·얇은 세면대, 참고 장면)을 썼다.

## 1. 재현 (43단계, 저장 답 52장, 지금 main 다듬기)

- `refine.ts` 요약에 컷아웃마다 겹침(IoU)·사용 여부를 남겼다.
- **도기 컷아웃 70개 중 16개 실패**(같은 답 중복을 빼면 58개 중 13개)
  - 욕조 큰 방 측면(90°) 변기 5개: 0.17~0.23. 변기 크롭의 컷아웃에 뒤쪽 욕조까지 함께 잡혀 겹침이 낮다.
  - 흰 벽 앞 얇은 벽걸이 세면대 4개: 0~0.53
  - 샤워 장면 흰 벽 변기 2개(0.49·0.58), 올리브 측면 변기 1개(0.587), 흰 욕조 측면 욕조 1개(0.376)
- 최종 그림: 실패한 측면 변기는 반투명 몸체 잔상·이중 윤곽·바닥 번짐, 얇은 세면대는 계단 가장자리가 남는다. 잘 잡힌 정면 변기는 깨끗하다.

- CUT_RESCUE 조건: 자르기 12px, 겹침 ≥ 0.5, 렌더 제품 덮음(recall) ≥ 0.75, 렌더 제품 윗부분 1/4 덮음 ≥ 0.5, 넓이 ≤ 2.5배
  - 기준값은 44단계 점수로 정했다.
    - 측면 변기: 덮음 0.79–1, 윗부분 0.55–1, 넓이 1.0–1.95
    - 물탱크를 놓친 흰 벽 변기: 윗부분 0
    - 부푼 얇은 세면대: 윗부분 0.167, 넓이 1.83
  - 넓이로는 측면 변기와 부푼 세면대가 갈리지 않아, 세면대를 거르는 것은 윗부분 조건이다.

## 4. 남은 한계

- **흰 벽 앞 흰 물탱크와 얇은 세면대 둘레 번짐은 새 기본에서도 남는다.**
  - 컷아웃이 물탱크 윗부분이나 세면대 외형을 못 잡아 지킴 장치가 걸러, 예전처럼 렌더 윤곽으로 다듬는다.
  - 새 배치 시험에서도 같았다: 투피스 물탱크 윗부분 0, 얇은 세면대 윗부분 0.122
- **구조로 그림이 바뀐 Cloudflare 사례는 1장뿐이다**(큰 방 흰 벽 측면 변기).
  - 새 배치 측면(변기를 욕조 옆으로)에서는 변기가 원래 기준을 그대로 통과해 구조가 쓰이지 않았다.
  - 나머지 확인은 로컬 FLUX 답이다.
- 45단계 1패: 욕조 밑 짧은 잔상(올리브 측면 한 장)
- 두 방식 모두 측면 변기 앞면을 가로지르는 음영과 일부 솔통은 남는다.
