## 1차: 현재 계약을 유지한 의미 구분 실험

동일한 모델·format·좌표계·샘플링·최대 항목 수를 유지하고 다음 정의만 짧게 바꾼 비교군을 만든다. 기존 결과는 보존한다.

- physical은 사진에서 직접 보이는 실물 설비 자체다. 두께·깊이·설치벽·실제 규격을 몰라도 실물이 직접 보인다면 physical일 수 있다.
- reflected는 거울 안에 비친 설비 복사본이다. 거울 판 자체는 실물이다. uncertain은 실물과 거울 복사본을 구분하지 못한 경우에만 쓴다. 이를 강제로 physical로 치환하지 않는다.
- 추출 대상은 지정한 설비 종류다. 벽/바닥 타일, 조명 띠, 환풍기, 수건, 쓰레기통, 장식은 다른 설비 종류로 바꾸지 않는다. 미지원 설비가 중요하면 unknown과 짧은 이름을 별도 남기는 정책을 먼저 정한다.
- orthogonal false는 보이는 경계가 비직각 구조임을 실제로 뒷받침할 때만 사용한다. 모서리가 안 보이는 경우는 unknown이다.
- 이미 넣은 반복 금지 문장을 더 길게 늘리지 않는다. 지금도 해당 지시가 있으므로 그것만 다시 강조하는 것은 독립 대안이 아니다.

이 실험에서 reflection=physical 비율만 오른 것을 성공으로 평가하면 안 된다. 실제 거울 복사본 오배치와 직접 보이는 물체에 대한 보류가 함께 줄어드는지 본다.

## 2차: 짧은 inventory → 설치·기하 2단계

권장하는 본 실험은 먼저 설비 목록을 생성하고, 그 목록을 고정한 뒤 설치 정보를 묻는 방식이다. 새 모델을 추가하지 않는다. 1단계 성공 결과는 2단계가 실패해도 보존한다.

### A. 관측 목록

필수 필드는 종류, 2D 박스, 직접 보이는지/거울 복사본인지에 한정한다. 세면대만 필요한 형태·지지 방식·볼 개수를 선택적으로 받는다. 물체 ID는 모델에게 긴 이름이나 접미 숫자를 생성하게 하지 않고 검증된 배열 순서에 따라 앱이 발급할 수 있다. 이것이 중복 제거를 대신하는 것은 아니다.

다음은 입력·출력 형태를 설명하기 위한 빈 명세이며 실제 모델 응답이 아니다.

```text
{
  items: [{
    label: 지원 설비 종류 또는 unknown,
    bbox_2d: [x1, y1, x2, y2],
    view: direct | mirror_image | unclear,
    basin: null 또는 {shape: rectangular | round | unknown,
                       support: wall | pedestal | cabinet | unknown,
                       bowls: 1 | 2 | null},
    note: 짧은 관측 또는 구분 불가 이유 한 문장
  }]
}
```

설비 단위는 먼저 통일한다. 한 세면대+하부장 조합은 한 항목으로 출력하고, 두 볼이 보이면 그 조합의 bowls=2를 기록하는 계약을 우선 비교한다. 별도의 볼·하부장 부품 관계가 필요한 경우에는 다음 단계에서 원 항목의 부품으로 확장하며, 원 조합과 부품을 모두 독립 설비로 세지 않는다. 볼 두 개가 개별적으로 보이지 않으면 폭이 넓어도 bowls=null이다.

Qwen3-VL 공식 grounding 노트북은 기본 위치 좌표를 0–1000 상대 좌표로 설명하고 `bbox_2d` 배열 예시를 제공한다. 현재 프로젝트의 0–1 float 객체 대신 이 형태를 쓰는 것은 학습에서 익숙한 형식을 활용할 수 있다는 실험 가설이다. 좌표 변경만으로 정확도가 개선된다고 보장하지 않는다. 응답 검증 후 1000으로 한 번만 나눠 기존 내부 0–1 좌표에 맞춘다. 방향 정규화·리사이즈·좌표 변환을 독립 테스트하고 좌표계 변경 효과는 계약 축소 효과와 분리한다. [Qwen3-VL 공식 2D grounding notebook](https://github.com/QwenLM/Qwen3-VL/blob/main/cookbooks/2d_grounding.ipynb)

### B. 고정 목록의 설치·관계·방 관측

입력은 동일 사진과 검증된 A의 ID·박스 목록이다. 출력은 기존 ID에 대한 속성 보완만 받는다. 이 단계가 설비를 다시 나열하며 추가·복사하지 못하게 한다. A의 오류가 확인되면 해당 ID의 검토 필요 상태를 반환하고 A 원문은 보존한다. 새 설비 발견은 별도 진단으로 남겨 목록의 출처가 섞이지 않게 한다.

- 설치 방식과 설치 벽을 분리한다. 사진의 왼쪽에 있다는 이유로 left wall로 지정하지 않는다.
- 접점은 종류와 좌표, 짧은 가시 근거만 받는다. 바닥 접점·벽 부착점·상판 접점은 서로 바꾸지 않는다. 미관측 접점은 null이다.
- 관계는 관련 ID가 있을 때만 출력한다. 거울 복사본과 실물을 구분하지 못했다면 둘을 임의로 연결하지 않는다. 유리와 뒤 설비는 둘 다 유지한다.
- room geometry는 가능한 관측 선분/모서리와 근거만 받는다. 완전한 뒤 벽 quad를 기본 요구 항목으로 만들지 않는다. hidden corner를 만들어서 solver를 통과시키지 않는다.
- 직각 방 가정은 사용자가 제공한 설계 가정과 모델이 관측한 사실을 구분한다. 모서리가 안 보이는 것을 false로 바꾸지 않는다.
- B가 기하를 보류해도 A의 설비 목록과 종류·형태 관측은 유효한 별도 결과로 표시한다. 실제 자동 배치가 없으면 자동 재구성 완료로 표시하지 않는다.

두 호출은 이미지/프롬프트 준비가 두 번 들어갈 수 있다. 짧아진 생성 시간만 비교하지 않고 A+B 전체시간, 호출 수, 준비/사진평가/출력 시간과 실제 메모리를 합산한다. 동일 모델을 한 세션에서 재사용하더라도 준비 시간이 0이라고 가정하지 않는다. 실패·취소 처리도 각 호출에 적용한다.

## 반복 후처리의 역할

동일 bbox·종류·속성·관측 문장의 반복은 원문을 보존한 채 alias 관계로 표시할 수 있다. uncertain 항목끼리의 동일 주장도 중복 진단 대상이 될 수 있지만, 이를 합쳤다고 physical이나 배치 가능으로 승격하면 안 된다. 다른 물체, 실제 물체와 거울 복사본, 유리 앞뒤의 별도 물체를 합치지 않는 회귀가 필요하다. 정리 전 24개→정리 후 11개는 형식 중복의 감소일 뿐, 11개의 정확한 인식 성공을 뜻하지 않는다.

토큰/항목 상한은 자원 방어용으로 유지한다. 상한 도달, 반복 탐지 중단, 응답 절단은 각각 실패/불완전 진단으로 남긴다. 앞부분 N개만 채택해서 성공률을 계산하지 않는다.

## 검증 가능한 비교 순서

1. 평가 중인 prompt6의 8사진 결과를 그대로 동결한다. 다른 소스나 프롬프트 결과를 그 표에 덮어쓰지 않는다.
2. 개발용 네 사용자 사진에서 C0 현재 계약, C1 의미 정의만 구분, C2 짧은 inventory 계약을 비교한다. C2 첫 비교는 기존 0–1 좌표와 같은 샘플링을 유지해 계약 축소 효과부터 본다. 같은 seed의 한 번 실행 결과는 안정성 보장이 아님을 기록한다.
3. 반복이 심했던 서로 다른 두 사례에 대해 추가 고정 seed를 사용해 재현성을 본다. 네 사례에서 최소 한 번 좋아졌다는 이유로 전환하지 않는다. 모든 시도와 실패를 집계한다.
4. C2가 목록 품질을 유지하면서 출력·중복을 줄였을 때만 0–1000 `bbox_2d` 변경군 C3를 비교한다. 이후 선택한 inventory 결과에 B단계를 붙여 전체시간과 배치 품질을 검사한다.
5. 프롬프트 선택에 사용하지 않은 별도 사진을 한 번 더 평가한다. 이미 결과를 열어 보며 규칙을 수정한 사진은 엄격한 미사용 검증 집합이라고 부르지 않는다.

사진별 기록 항목은 다음과 같다.

- 원 관측 후보 수, 고유 주장 수, 반복 횟수, cap/출력제한 도달, 완료 사유, 유효 JSON 여부.
- 독립 정답과 대조한 실제 대상의 누락·오탐·종류·형태·지지 구조·볼 개수. 미지원 대상이 wallShelf/vanity로 바뀐 횟수.
- 직접 보이는 설비의 부당한 reflection unclear, 거울 복사본의 부당한 direct, unknown→사용자 확인 횟수. 모델이 자기 설명으로 쓴 근거를 정답으로 쓰지 않는다.
- 설치벽/접점/높이 보류, 자동 배치의 올바름과 틀림, 유리 뒤 물체 보존, 전체 수동 수정량. 배치 수가 많다는 이유로 성공하지 않는다.
- 원본 크기와 모델 입력 크기, bbox 좌표 오차/IoU, 모델 digest, prompt/schema/source hash, seed와 실제 설정.
- 호출별 모델준비·사진/프롬프트 평가·토큰생성·전체시간, 출력토큰, 측정 범위가 명확한 메모리. A+B 총시간과 사용자가 결과를 처음 확인할 수 있는 시간도 분리한다.

샘플링 변경은 위 계약 실험과 별도 축으로 둔다. Qwen 공식 Instruct 평가 설정은 temperature 0.7, top_p 0.8, top_k 20, presence_penalty 1.5이며 현재 코드와 대체로 일치한다. Ollama의 일반 structured-output 지침은 낮은 temperature를 제안한다. 목적이 다른 두 권고 중 하나를 무조건 정답으로 적용하지 않고, 현재 설정을 대조군으로 남긴 다음 필요할 때만 비교한다. 이전 greedy 반복 결과도 버리지 않는다. [Qwen3-VL 공식 평가 설정](https://github.com/QwenLM/Qwen3-VL#evaluation-reproduction), [Ollama 공식 구조화 출력 지침](https://docs.ollama.com/capabilities/structured-outputs)

이번 조사에서는 공식 문서와 로컬 원문만 읽었다. 사용자 사진을 외부로 보내지 않았고, 모델·소스·평가 결과를 변경하지 않았다. 현재 증거로 추천할 수 있는 것은 작은 계약 실험이며 모델 교체나 품질 개선의 확정 채택은 아니다.
