# 360° 제품 각도 편집

자재 등록·수정에서 **제품 이미지**만 올린 뒤 사진 옆 **AI 360° 입체화**를 연다. 투명 제품 사진이 필요하며 배경이 있으면 기존 **AI 배경 제거 테스트 → 360° 입체화** 흐름으로 시작한다. **입체화 시작**을 누르기 전에는 모델을 내려받거나 AI를 실행하지 않는다.

## 사용 방법

1. **입체화 시작**이 끝나면 입체화를 시작한 각도(사진 그대로인 각도)가 3D로 **자동 저장**된다. 정면이면 제품이 정면을 보는 자세로 저장되어 자재 폼의 정면이 사진에서 3D 캡처로 바뀐다(알림과 각도 썸네일로 확인, 자재를 저장해야 확정, 아래 "입체화한 각도 자동 저장"). 그다음 제품 주변이나 손잡이 이외의 영역을 드래그해 자유롭게 시점을 회전한다. 위아래 극을 넘어 뒤집어서 볼 수 있다.
2. 제품을 짧게 클릭하면 위·아래 손잡이가 나타난다. 위 손잡이를 오른쪽으로, 또는 아래 손잡이를 왼쪽으로 드래그하면 제품이 같은 방향으로 기울어진다. 현재 화면 평면을 기준으로 제품 자체를 세우는 조작이다.
3. 휠·핀치·확대 버튼으로 가장자리를 확인한다. 손잡이를 선택한 상태에서 좌우 키로 1°씩 보정할 수도 있다. 화면 맞춤, 시점 초기화, 기울기 초기화는 각각 독립적이다. 자동 수평 맞춤이 못 맞춘 제품은 **수평선 맞추기**(또는 **수직선 맞추기**)를 켜고 수평이어야 할 모서리를 따라 끌어 한 번에 맞춘다. 제품이 찌그러져 보이면 뷰어 아래 **제품 맞추기**에서 실제 크기·좌우 대칭을 켜고 앞쪽 방향이 맞는지 본다(아래 "결과 품질 보정").
4. **투명 PNG 다운로드**는 현재 각도의 1024×1024 PNG를 만든다. 검사 중 확대 배율과 무관하게 전체 제품을 여백 안에 넣고, 체크무늬·손잡이·선택 테두리는 넣지 않는다.
5. **새 각도 이름**을 목록(정면·왼쪽·오른쪽·위·아래·뒤)에서 고르면 제품이 그 방향을 보도록 자세가 바로 돌아간다. 직접 입력은 없다. **이 각도 추가**를 누르면 현재 자세의 PNG를 같은 자재에 추가한다. 이름을 고르지도 제품을 돌리지도 않았다면(입체화·자동 저장 직후의 첫 화면) 제안된 다음 이름의 방향으로 제품을 돌려 저장하고 알림에 그렇게 말한다. 이미 있는 이름은 고를 수 없고(목록에서 비활성), 한 자재는 방향마다 한 장씩 최대 6장이다. 추가한 뒤에는 아직 안 쓴 다음 이름이 골라지고 제품이 그쪽으로 돈다. 편집 창은 계속 열려 있으므로 한 번 입체화한 결과로 여러 각도를 연속 저장할 수 있다.
6. 뷰어 아래 저장한 각도 썸네일을 누르면 해당 자세가 복원된다. 자세를 조절한 다음 **선택한 각도 수정**을 누르면 그 각도 한 장만 바뀐다. 다른 각도는 유지한다.
7. 선택한 각도는 이름 변경·삭제를 할 수 있다. 이름 변경도 같은 목록에서만 고른다. 대표 이미지 지정은 없으며 목록에서는 정면 사진을 우선 표시한다. 원본 사진과 다른 각도는 각각 독립된 항목이다. 삭제한 각도가 과거 프로젝트의 불변 자재 버전에 사용됐다면 그 버전은 그대로 보존된다.
8. 각도 편집 창을 닫은 뒤 **자재 등록 / 새 버전 저장**으로 최종 확정한다. 각도 추가·수정은 자재 폼에 적용되며 자재 저장 전 취소하면 기존 저장 버전은 유지된다.
9. 저장한 사진의 **360° 각도 편집**을 다시 열면 메시와 자세를 불러온다. 같은 형상의 각도를 선택하거나 추가할 때 AI 재실행과 모델 다운로드는 발생하지 않는다.
10. 공간에 제품을 배치한 뒤 오른쪽 제품 속성의 **각도 썸네일**을 눌러 원하는 저장 이미지를 선택한다. 각도를 바꿔도 제품의 ID·위치·배치 개수·단가는 유지된다.

창을 닫으면 **이 각도 추가 / 선택한 각도 수정**으로 적용하지 않은 현재 자세만 버린다. 드래그 한 번은 실행 취소 한 번에 대응한다. 최근 50개 자세 편집 기록은 현재 각도 편집 창에서 사용한다.

각도 이름은 입력하지 않고 목록(정면·왼쪽·오른쪽·위·아래·뒤)에서만 고른다. 이름은 제품이 그 사진에서 바라보는 방향이고, 2D 편집기·3D 방·AI 변환이 모두 이 이름을 따른다([방 크기](./room-dimensions.md)). 정면 사진이 없으면 첫 사진을 표시한다. 상품 소개 이미지나 별도 대표 이미지는 등록하지 않는다. 타일은 텍스처만 올린다. 자세한 규칙은 [자재 이미지 표시 정책](./material-images.md)에 있다.

한 자재의 제품 사진은 방향마다 한 장, 최대 6장이고 타일 텍스처는 최대 100장이다. 직접 업로드한 사진도 같은 목록에 포함된다.

## 입체화한 각도 자동 저장

2026-10-04에 넣었다. 이전에는 입체화가 끝나도 폼의 정면이 원본 2D 사진 그대로였고 **선택한 각도 수정**을 따로 눌러야 3D가 됐다. 왼쪽·오른쪽만 추가하고 자재를 저장하면 3D 방에서 정면이 종이처럼 얇게 보이고(옆·위에서 볼 때) AI 변환 입력도 같은 납작한 사진이었다.

- **대상**(`planAutoSave`, `src/lib/product3d/auto-save.ts`): 입체화를 시작한 각도(지금 선택된 각도)가 `product3d` 없는 사진이고, 이름이 목록(정면·왼쪽·오른쪽·위·아래·뒤)에 있고, 저장 권한이 있을 때다. 이름은 그대로 둔다.
- **저장하는 자세**: 그 이름이 정하는 방향이다(`poseForDirection`). 정면이면 제품이 정면(0° ±2° 안)을 보고 카메라 높이 10°이며 윤곽 수평 보정이 끝난 모습이다. 새 모델은 처음부터 이 방향으로 열리고(`openingPose`), 뷰어가 열려 수평 보정까지 끝났다는 신호(`onReady`)가 오면 같은 방향을 한 번 더 맞춘 뒤 `capture()`(사진 색·광택 계산을 기다림)하고 **선택한 각도 수정**과 같은 경로(`apply('replace')`)로 저장한다. `shading`·`fit`·`gloss`·`photoCamera`도 같다. 수평 보정 전에는 저장하지 않는다.
- **저장 직후**: 알림 "“정면” 사진을 입체로 저장했어요. 자재를 저장하면 반영돼요. 이어서 다른 각도를 추가할 수 있어요.", 각도 썸네일이 3D 캡처로 바뀐다. 저장하는 동안 버튼이 잠기고 "입체로 저장하고 있어요…"가 보인다. 편집기는 방금 만든 모델을 저장본에서 다시 읽지 않고 그대로 이어서 쓴다(새 모델에만 있는 안내가 남는다: 윤곽 수평 안내, 입력한 크기와 사진이 많이 다를 때의 확인 질문, 앞쪽 방향이 불확실하다는 안내, 사진 색을 못 입힌 이유). 다음 각도를 추가할 때 메시·입력 자산은 다시 올리지 않는다.
- **자동 저장하지 않는 경우**
  - 입체화 도중 창을 닫았을 때(늦게 온 결과도 쓰지 않는다), 선택한 사진이 바뀌었을 때(`sameAngle`).
  - 선택한 각도가 이미 3D일 때. 사용자가 다듬은 각도를 "다시 입체화"가 말없이 덮어쓰면 안 되므로 "새 형상은 아직 저장되지 않았어요. ‘선택한 각도 수정’을 눌러 “정면” 각도에 반영해 주세요"라고 알린다.
  - 저장 권한이 없을 때(결과만 보여 준다), 각도 이름이 목록에 없을 때(이름을 고른 뒤 직접 저장), 뷰어를 열지 못했을 때(WebGL 실패).
- **실패하면**: 오류와 "입체 결과는 그대로 있어요. ‘선택한 각도 수정’을 눌러 직접 저장할 수 있어요"를 보이고 자동으로 다시 시도하지 않는다.
- **확정**: 자동 저장은 자재 폼 초안에만 반영한다. 자재 저장(`submit`)을 눌러야 확정되고 불변 자재 버전 규칙은 그대로다. 저장 전에 창을 닫아도 기존 저장본은 유지된다.
- **입체화 모델·맞춤·사진 색·광택 계산은 바꾸지 않았다.**
- **실제 4종 확인(2026-10-04)**: 곰 변기·스마트 변기·사각 욕조·벽걸이 세면대 사진을 실제 편집기로 등록→배경 제거→입체화했다(`tests/product3d-auto-save-real-browser.ts`, 개발 서버·로컬 D1·WebGPU Chrome). 4종 모두 "선택한 각도 수정"을 누르지 않아도 정면이 3D로 저장됐고(입체화 시작부터 24~27초), 저장된 정면의 방향은 0°(±0.01°)·카메라 높이 10°였다. 첫 화면에 이름 불일치 경고는 없고 안내가 떴으며, 이어 추가한 오른쪽·왼쪽·뒤도 이름의 방향(+90°·−90°·180°, 높이 10°)으로 저장됐다. 4종 모두 자재 등록까지 끝났다. 이미지: `test-results/product3d-auto-save/`(첫 화면 `*-10-first-screen.png`, 정면 `*-11-front.png`).
- **정면이 대각선 사진일 때(조사만, 바꾸지 않음)**: 사진이 제품의 대각선 앞에서 찍혔으면 진짜 정면은 사진에 없던 면이라 모델이 추측한다. 위 4종의 저장본을 다시 그려(`tests/product3d-front-compare-browser.ts`, 이미지 `test-results/product3d-front-compare/`: `sheet-poses.png`, `sheet-room.png`) 비교했다. 방향 이름의 뜻(이름 = 제품이 향하는 방향)은 바꾸지 않았다.
  - **사진을 찍은 쪽과 정면의 각도 차**: 곰 변기 39.4°, 스마트 변기 48.0°, 욕조 33.1°, 세면대 0.0°. 편집기의 40° 안내는 곰 변기(약 40°)·스마트 변기(48°)에서 떴다.
  - **지금(정면 이름에 맞춘 자세 = 제품의 앞) 대 대안(사진을 찍은 방향 쪽 자세)**: 곰 변기·스마트 변기는 지금 쪽이 네모난 덩어리로 보이고(곰 변기는 얼굴이 있는 몸통, 스마트 변기는 거의 상자) 대안 쪽이 사진처럼 탱크·변좌·몸통이 구분돼 자연스럽다. 욕조는 둘 다 직육면체 욕조로 읽혀 차이가 작고, 세면대는 같다(0°). 다만 대안은 제품이 이름("정면")에서 33~48° 돌아간 모습을 그 이름으로 저장하는 것이라 방에서 제품이 대각선을 향하게 되고(25° 넘는 어긋남이라 편집기의 이름 불일치 경고 대상이다), 방의 벽 규칙과 AI 변환이 이름을 방향으로 읽는 약속과 어긋난다. 그래서 바꾸지 않았다.
  - **3D 방 정면 시점에서 원래의 평면 정면 사진 대 자동 저장한 3D 정면**: 정면에서만 보면 평면 사진 쪽이 더 자연스러웠다(곰 변기·스마트 변기·욕조: 사진의 대각선 모습이 그대로 서 있고, 3D 정면은 얼굴 달린 네모 몸통·상자·밋밋한 직육면체로 나온다. 세면대는 비슷하다). 하지만 평면 사진은 카드 한 장이라 방을 옆·위에서 돌려 보거나 AI 변환의 시점이 바뀌면 종이처럼 얇아지고(이번에 보고된 문제), 대각선 모습의 제품이 방 정면을 보고 서 있는 모양이 된다. 3D는 그 점이 낫지만 정면 모습은 거칠다. 4종의 눈으로 본 비교이고 정량 지표는 없다.
  - **한계**: 자동 저장으로 정면이 3D가 된 뒤 사진 그대로로 되돌리는 버튼은 없다(자재 폼에서 **취소**하면 초안이 버려진다). 대각선 사진 제품은 3D 정면이 거칠다는 안내(위의 40° 문구)와, 정면에서 찍은 사진을 쓰면 더 정확하다는 말만 한다.

## 결과 품질 보정

모델(TripoSR)은 그대로 두고 입력·형상·색·자세 처리만 보정한다. 새 라이브러리 없이 직접 구현했다.

- **보기 모드: 혼합(권장) · 조명 보정 · 원본 색**: 뷰어 위쪽에서 고른다. 새로 입체화하면 **혼합**으로 시작하고, 저장한 각도는 저장한 모드 그대로 열린다(필드가 없는 과거 각도는 `원본 색`, `조명 보정`으로 저장한 각도는 `조명 보정`). 세 모드의 색은 [shading](../src/lib/product3d/shading.ts)의 `productSurface` 하나로 계산해 360° 편집기·투명 PNG·3D 방(공간 둘러보기)·AI 변환 입력이 같은 색을 쓴다. 메시마다 모드별로 한 번만 계산해 두고, 29만 정점에서 1~2초가 걸리므로 [surface](../src/lib/product3d/surface.ts)가 Web Worker에서 먼저 계산해 화면이 멈추지 않게 한다(Worker가 없으면 화면 안에서 계산한다). 모드를 바꾸는 동안에는 "색을 계산하고 있어요…"가 보이고, 그사이 PNG를 만들면 계산이 끝나기를 기다린다.
  - `조명 보정`은 사진의 명암이 묻은 꼭짓점 색 대신 재질별 기본색을 쓰고, 현재 시점 기준 좌상단 광원과 반구광으로 음영을 매번 계산한다. 그래서 정면이 아닌 각도에서도 사진의 그림자가 엉뚱한 쪽에 남지 않는다([albedo](../src/lib/product3d/albedo.ts), [renderer](../src/lib/product3d/renderer.ts)). 다만 색으로 그린 디테일(뚜껑 이음선·버튼·테두리)도 함께 지워져 둥근 덩어리처럼 보인다. 아래 재질·기본색 설명은 조명 보정과 혼합이 함께 쓴다.
  - 재질은 명암에 영향받지 않는 선형 RGB 색도로 최대 3개까지 나눈다(흰 도기·목재·색 패널 등). 어두운 부분은 그림자의 색 번짐일 수 있어 색도 계산에서 뺀다. 다만 자기 색도가 유색 재질과 뚜렷이 같으면(그늘진 목재, 호박색 병의 어두운 쪽) 그 재질로 본다. 흰 도기 그림자의 약한 따뜻한 번짐은 여기에 걸리지 않는다. 나머지는 표면을 따라 가장 가까운 밝은 부분의 재질을 따른다.
  - 이웃 대부분과 다른 재질로 분류된 꼭짓점은 이웃의 재질로 바꾼다. 어두운 병 위의 반사광 같은 점이 다른 색 얼룩으로 번지지 않게 하기 위해서다.
  - 흰 도기·크롬·검정처럼 밝기만 다른 무채색 부품은 한 장의 사진으로 그림자와 구분할 수 없어 같은 재질로 합친다. 카메라 쪽을 향한 어두운 부분을 검정 부품으로 보는 방법도 시험했지만, 부품 사이 틈의 그림자가 검은 균열로 나타나 쓰지 않았다. 이런 제품은 `원본 색`으로 본다.
  - 기본색 밝기는 사진 쪽(+x)을 향한 면의 높은 분위수로 정한다. 광량은 정면이 원본 사진 정면과 비슷한 밝기로 보이도록 맞췄다(흰 제품이 하얗게 날아가지 않게). 사진 자체가 어둡게 찍혔으면 그만큼 어둡게 보이며 임의로 밝히지 않는다.
  - 조명 보정의 음영은 이웃 법선을 40회 평균한 법선으로 계산한다([mesh-cleanup](../src/lib/product3d/mesh-cleanup.ts) `shadingNormals`). TripoSR 표면의 격자 몇 칸 크기 망치 자국 무늬는 Taubin 스무딩이 일부러 남기는 크기라, 위치 대신 법선을 고르게 한다. 윤곽과 저장 형상은 바꾸지 않는다. 공간 둘러보기의 `lit` 각도도 같은 법선을 쓴다.
  - **혼합의 원리**([mixed-color](../src/lib/product3d/mixed-color.ts), 2026-10-02): 입체 형상은 사진 한 장(TripoSR)에서 만들어서 사진에 찍힌 정면 쪽만 실제 정보이고 옆·뒤의 색은 모델의 추측이다. 그 추측이 그림자 쪽과 회색 배경 색에 끌려가 칙칙한 회갈색이 되고, 조명 보정은 이를 지우면서 디테일도 함께 지운다. 혼합은 꼭짓점마다 사진에 찍힌 정도 w(0~1)를 계산해 둘을 섞는다.
    - **w**: 매끈한 법선(12회 평균)이 사진 방향(+x)과 이루는 코사인을 0.25~0.65에서 smoothstep으로 0~1로 만든다. 찍힌 쪽과 안 찍힌 쪽은 이 곡선으로 이어져 경계가 보이지 않는다.
    - **w가 높은 곳(찍힌 쪽)**: 기본색 × (원본 색 ÷ 주변 평균 색). 주변 평균은 찍힌 표면을 제품 대각선의 약 3% 폭으로 평균한 색이라 큰 면의 사진 명암(그림자)은 상쇄되고, 그보다 작은 선·버튼·이음선은 그대로 남는다. 비율은 0.02~1.2로 제한하고, 가장자리의 무지개 같은 색 번짐은 절반만 남긴다. 단색이면 비율이 1이라 변하지 않는다.
    - **w가 낮은 곳(안 찍힌 쪽)**: 기본색만 칠한다. 모델의 추측 색은 쓰지 않는다. 형태는 색이 아니라 조명과 음영으로 읽히게 한다. 오목한 홈과 안쪽 모서리를 꼭짓점마다 두 크기(표면 이웃 평균 16회·48회로 둥글린 표면과의 거리)로 재서, 제품 크기의 0.1~0.5%·0.2~1.2% 깊이부터 최대 20%·25% 어둡게 한다. 음영용 법선은 조명 보정과 같은 40회 평균을 쓴다. 12회·24회는 표면의 망치 자국 무늬가 도드라져 쓰지 않았다.
    - **재질**: 안 찍힌 꼭짓점은 자기 색으로 재질(최대 3개)을 고르지 않는다. 사진 방향으로 투영한 화면에서 같은 자리에 찍힌 꼭짓점의 재질을 따르고(병의 뒷면은 병의 색), 가까이에 없으면 주 재질이다(받침 아래가 위에 선 병의 갈색이 되지 않게). 읽기에는 너무 어두운 찍힌 꼭짓점만 표면에서 가장 가까운 찍힌 꼭짓점을 따른다. 표면의 이웃 법선이 비슷한 조각으로 나누는 방법은 이 메시들이 너무 촘촘해(이웃 법선이 거의 같아 꺾인 곳에서도 끊기지 않음) 조각이 하나로 합쳐져 쓰지 못했다.
    - **구현은 실험으로 골랐다**(수치는 [검증 기록](./verification.md)). 원본 색을 주변 평균으로 나눈 비율과 평균을 뺀 차이를 비교하니, 차이 방식은 어두운 작은 부품(욕조의 수전)의 표시를 6%만 남겼고 비율 방식은 99~100%를 남겼다. 평균 폭을 1.5%로 하면 수전 같은 작은 부품이 평균에 묻혀 표시가 18%만 남고, 6%로 하면 큰 면에 사진 명암이 남아(10~90분위 L* 폭 6.3, 3%일 때 3.0) 3%로 정했다. 평균은 표면 위 이웃 평균(300회에 2.1초, 반경 약 17칸)이 아니라 법선 방향별 격자로 계산해 정점 수에 비례하고(변기 29만 정점에서 0.23초) 반경이 시간에 영향을 주지 않는다.
    - **성능**: 29만 정점(비데 변기)은 Worker 안에서 약 1.5초, 39만 정점(스툴)은 약 1.9초다(같은 환경에서 조명 보정은 0.8초·1.3초). 브라우저(소프트웨어 렌더링 PC)와 Node 한 스레드가 같은 속도였다.
    - **한계(숨기지 않는다)**: 안 찍힌 면의 **모양**은 모델의 추측이라 실제와 같지 않다. 혼합은 칙칙한 색과 뭉개져 보임을 줄이는 것이지 정확도를 높이는 것이 아니다. 더 정확하게 하려면 다른 각도의 사진을 추가로 올려야 한다(여러 각도 사진을 지원한다). 전체의 3% 미만인 부품(수전·병 뚜껑)은 한 재질로 합쳐져 흰색에 가깝게 나온다(조명 보정과 같다). 색이 다른 병이 선 받침은 병 밑에 병 색이 약간 번진다. 사진이 어둡게 찍혔으면 기본색도 그만큼 어둡다.
- **자동 수평 맞춤**(두 단계, 실행 취소 가능): 새로 입체화하면 한 번 적용하고, `기울기 초기화` 옆 버튼으로 다시 적용할 수 있다. 순서는 형상 추정 → 윤곽 보정이다.
  1. **형상 추정**([upright](../src/lib/product3d/upright.ts)): 위생도기는 바닥(-z)이나 벽(-x)에 평평한 면이 닿는다는 점을 이용해, 두 면에 얇게 붙는 점이 가장 많아지는 pitch·roll을 ±25° 안에서 찾는다. yaw는 바꾸지 않는다. 지금 상태보다 확실히 나을 때만(점 비율 30% 이상·2%p 이상 증가) 적용하고, 평평한 면을 찾지 못하는 모양(둥근 바닥 변기)이나 25°를 넘는 기울기는 못 맞춘다.
  2. **윤곽 보정**([outline-level](../src/lib/product3d/outline-level.ts), [silhouette-tilt](../src/lib/product3d/silhouette-tilt.ts), 2026-10-01): 3D 방이 보는 **수평 카메라(고도 0°)**로 현재 자세를 그려 제품 윤곽(알파)의 긴 직선 모서리가 수평·수직에서 화면 안에서 몇 도 돌아가 있는지 읽고, 그 카메라 축으로 제품을 돌려 맞춘다. 2회 읽는다. 편집기의 10° 내려다보는 카메라가 아니라 수평 카메라로 재므로 방에서도 똑바로 선다. 한계는 ±45° 미만이다(형상 추정은 ±25°). ±43°까지는 0.1° 단위로 읽히고, 44° 이상은 수평·수직의 접힘 경계라 답하지 않는다(틀린 답을 내는 것이 아니라 읽지 않는다).
     - **읽는 법:** 윤곽선의 알파 50% 교차점(화소 이하 정밀도)에 허프 변환을 걸어 방향마다 직선(±1px)에 놓인 점 수의 제곱(최소 길이 이상만)을 더하고, 수평·수직을 한데 모으는 90° 접기로 한 봉우리를 찾는다. 곡선과 짧은 직선은 봉우리가 안 된다. 기울기 방향 히스토그램은 둥근 바닥과 계단 화소에서 가짜 봉우리(변기에서 가짜 0°)가 나와 쓰지 않았다. 윤곽 면적의 제곱근으로 크기를 맞추고(제품이 돌아도 같은 값) 비스듬한 선이 격자에서 점이 더 많이 잡히는 편향은 방향 가중치로 없앴다.
     - **확신하지 못하면 그대로 둔다:** 긴 직선 점이 윤곽의 10% 미만, 봉우리가 직선 에너지의 45% 미만(윤곽의 절반 이상이 직선이면 35%), 다른 방향 봉우리의 1.6배 미만이거나 ±44° 밖이면 보정하지 않는다. 둥근 거울·덩어리 모양·원, 45° 돌린 정사각형이 이에 해당하고, 이미 수평·수직인 정사각형은 0°로 읽혀 손대지 않는다. 0.3° 미만은 "이미 맞아요"로 두고 돌리지 않는다.
     - **화면 안내:** 뷰어 아래에 결과를 적는다. "윤곽의 수평·수직선이 N° 오른쪽(왼쪽)으로 기울어 있어 바로잡았어요" / "…이미 맞아요" / "윤곽에서 기울기를 확신할 수 없어 형상으로만 맞췄어요. 어긋나 보이면 수평선·수직선 맞추기로 직접 맞춰 주세요". 새 입체화 직후에는 "새 입체 형상:"으로 시작한다.
  - 새 입체화 직후의 첫 자세에도 윤곽 단계를 적용한다(저장본을 열 때는 저장한 자세 그대로, 뷰어 다시 열기도 그대로).
  - **이전에 저장한 각도는 자동으로 바뀌지 않는다.** 360° 각도 편집을 열어 **자동 수평 맞춤**을 다시 누르고 **선택한 각도 수정**으로 저장해야 3D 방에 반영된다. 뷰어 아래 안내에도 적었다.
- **수평선·수직선 맞추기**(2026-10-01): 자동이 못 맞춘 제품을 손으로 맞춘다. 버튼을 켜고 수평이어야 할 모서리(탱크 윗변, 세면대 윗면 등)를 따라 끌면 그 선이 수평이 되도록 화면 roll을 돌리고(수직선도 같음), 도구는 꺼진다. 끈 방향에서 가까운 쪽으로 돌리며 45°를 넘는 선(다른 종류의 선)과 24px 미만의 짧은 끌기는 안내만 하고 돌리지 않는다. 한 줄이 실행 취소 한 번이고 카메라는 그대로다.
  - 키보드: 버튼을 켜면 포커스가 도구로 가서 좌우 방향키로 보조선을 1°(Shift 5°)씩 돌려 모서리에 맞추고 Enter로 적용, Esc로 끈다. 터치는 같은 끌기로 되고 레이어가 `touch-action: none`이라 화면이 같이 밀리지 않는다. 돌리는 기준은 편집기에 보이는 화면이다.
  - 켜 있는 동안 기울기 손잡이는 숨는다.
- **형상 정리**: WebGPU에서는 형상 격자를 160에서 TripoSR 기본값인 256으로 올렸다. CPU 대체 경로는 160을 유지한다. 추출 뒤 전체 삼각형의 5%에 못 미치는 떠 있는 조각만 지우고(가장 큰 덩어리는 항상 남긴다. 얇은 연결부가 복원되지 않아 따로 떨어진 휴지 롤 같은 부품은 남고, 사진 가장자리에 걸린 작은 소품은 빠진다. 소품이 남으면 자동 수평도 틀어진다), 표면 정밀화 후 Taubin 스무딩(λ 0.5, μ −0.53, 4회)으로 부피를 줄이지 않고 요철을 누른다([mesh-cleanup](../src/lib/product3d/mesh-cleanup.ts)). 결과가 25MB 저장 한도에 가까우면 같은 밀도 격자를 32씩 줄여 다시 추출한다.
- **작은 사진 안내**(2026-10-02, [image-size-hint](../src/lib/image-size-hint.ts)): 제품 사진의 짧은 변이 512px보다 작으면 "작은 사진은 흐리게 입체화돼요. 1000px 이상을 권해요"를 알린다. 자재 폼에서 제품 이미지를 고르거나 끌어 놓은 때(파일 머리글만 읽어 크기를 안다)와 360° 편집기에서 입체화를 시작하기 전에 보이고, 막지는 않는다. 타일 텍스처는 입체화하지 않으므로 안내하지 않는다. 한 장/여러 장 규칙(`file-drop.ts`)은 건드리지 않았다. 입체화 모델은 사진을 512px로 받아 제품을 크게 키우므로 작은 사진은 흐려진다.
- **제품 맞추기: 실제 크기 · 좌우 대칭 · 앞쪽 방향**(2026-10-02, [fit](../src/lib/product3d/fit.ts), [symmetry](../src/lib/product3d/symmetry.ts)): 사진 한 장으로 만든 형상은 찌그러져 보인다. 모델이 깊이를 짧게 추측하고(곰 변기는 가로 0.61·깊이 0.72, 실제 일체형 변기의 깊이는 높이의 0.9~1 안팎), 사진이 대각선이면 모델의 앞뒤 축이 제품의 앞뒤가 아니기 때문이다. 뷰어 아래 **제품 맞추기**의 항목으로 고친다. 사진 크기·자르기는 형상에 효과가 없어(원본 500px / 2배 1000px / 변기만 자른 1000px가 정점 수 164,932 / 159,856 / 161,828, 울퉁불퉁함 0.112 / 0.114 / 0.113) 이 작업에 넣지 않았다.
  - **실제 크기 맞추기**: 자재의 가로·깊이·높이에 맞춰 제품의 앞뒤·좌우·상하를 축별로 늘이고 줄인다(전체 크기는 그대로, 늘이는 비율의 곱이 1). 새로 입체화하면 자재 크기가 사진 비율과 40% 안에서 맞을 때 켜진 채 시작한다. 40% 넘게 다르면 켜지 않고 "입력한 크기와 사진의 비율이 많이 달라요(깊이 +61% …). 그래도 맞출까요?"를 묻는다(잘못 입력한 크기가 형상을 망치지 않게). 깊이가 비었거나 타일 기본값(9mm)이거나 10~5000mm 밖이면 항목이 꺼져 있고 이유를 쓴다. 자재 폼에서는 타일이 아닌 분류의 깊이 칸 아래에 "깊이를 꼭 입력해 주세요"를 보인다(막지는 않는다).
  - **좌우 대칭 다듬기**: 서 있는 제품의 좌우 대칭면(수직면)을 찾고(법선의 방향과 위치를 거칠게→세밀하게 탐색, 반사한 점과 표면의 평균 거리가 가장 작은 면) 확실할 때만 쓴다: 평균 거리가 제품 크기의 2% 이하이고 20° 넘게 다른 면보다 1.8배 이상 낫다. 둥근 제품·한쪽으로 치우친 제품은 면이 없다고 보고 그대로 둔다. 적용은 큰 모양만이다. 각 꼭짓점이 반사한 쪽 표면과의 거리(법선 방향)의 절반만큼 움직이고, 그 이동량을 이웃에 평균해 들쭉날쭉한 부분을 없앤다. 반사한 쪽에 표면이 없는 꼭짓점(수전, 한쪽 손잡이)은 움직이지 않고, 색은 건드리지 않는다. 변기·세면대·욕조·세면대장은 기본으로 켜지고 나머지(선반·수납장·거울 등)는 꺼져 있으며 직접 켤 수 있다. 직사각형 욕조처럼 면이 두 방향 다 대칭이면 입력한 크기의 비율에 더 잘 맞는 쪽을 좌우로 하고, 크기가 없으면 사진을 찍은 쪽에 가까운 쪽을 앞으로 한다.
  - **앞쪽 방향**: 대칭면을 따라 두 쪽 중 어디가 앞인지 두 단서로 정한다. 사진은 보통 앞쪽에서 찍는다. 변기·세면대는 앞(볼)이 뒤(물탱크·벽)보다 낮다. 높이 차이가 분명하면(한쪽 끝이 20% 넘게 낮으면) 낮은 쪽이 앞이고, 두 단서가 어긋나면 "제품의 앞쪽 방향을 확신하지 못했어요. 맞는지 확인하고 틀리면 앞쪽 뒤집기를 눌러 주세요"를 보인다. **앞쪽 뒤집기**로 반대로 돌린다. 앞쪽은 모델의 +x로 돌려 맞춘다. 그래서 각도 이름(정면 등)의 기준(제품의 +x)은 그대로이고 [방향 이름 규칙](../src/lib/product-direction.ts)·`poseForDirection`은 바꾸지 않았다. 정면 이름으로 보면 제품의 진짜 앞이 보인다. 사진을 찍은 방향은 모델의 +x에서 돌아가므로 "사진에서 40° 넘게 돌렸다" 안내는 찍은 방향 기준으로 센다.
  - **켜고 끄기와 실행 취소**: 항목은 체크 상자이고 **맞춤 실행 취소 / 다시 실행**이 한 번에 한 항목씩 되돌린다(20단계). 모두 끄면 만든 그대로의 형상이다. 항목을 바꿔도 지금의 자세는 유지된다(자세의 실행 취소 기록은 새로 시작한다).
  - **저장과 적용 범위**: 각도마다 `product3d.fit`(서 있는 자세, 앞쪽 각도, 대칭면 위치, 크기 사용 여부)을 기록하고 저장한 형상은 그대로 둔다. 불러올 때마다 같은 함수(`fitProductMesh`)로 맞추므로 360° 편집기, 투명 PNG 캡처, 3D 방, AI 변환 입력이 모두 같은 비율이다. 자재 크기를 나중에 고치면 3D 방과 편집기를 다시 열 때 따라간다(이미 만든 PNG는 각도를 다시 저장할 때 바뀐다). 맞추는 계산은 Web Worker에서 하고 결과를 메시와 맞춤마다 한 번만 둔다.
  - **한계(숨기지 않는다)**: 보이지 않는 면의 모양은 여전히 모델의 추측이라 실제 제품과 같지 않다. 이 작업은 비율과 표면 품질을 고칠 뿐이다. 대칭 가정이 맞지 않는 제품은 적용하지 않는다. 비율은 입력한 크기에 따라가므로 크기를 잘못 입력하면 그대로 따라간다(40% 넘게 다르면 묻는다). 대칭 다듬기는 큰 모양만 고르게 하므로 평균 거리가 크게 줄지는 않는다(측정값은 [검증 기록](./verification.md)). **기존에 저장한 각도는 자동으로 바뀌지 않는다.** 각도를 열어 **제품 맞추기**를 켜고 **선택한 각도 수정**으로 저장해야 한다(옛 저장본은 `fit`이 없어 그대로 열린다).
- **평평한 면은 펴고 모서리는 살리는 다듬기**(2026-10-02, [mesh-cleanup](../src/lib/product3d/mesh-cleanup.ts) `bilateralSmooth`): Taubin 스무딩은 어느 방향이든 똑같이 펴서 모서리도 둥글어진다. 그 뒤에 법선 양방향 필터(Zheng 등 2011)를 더했다. 면의 법선을 주변 면의 법선과 평균하되 면적·거리·법선이 닮은 정도(차 0.35에서 가중치가 60%)로 가중해 평평한 면의 망치 자국 무늬는 평균되고 이음선·시트 테두리는 법선이 크게 달라 섞이지 않으며, 꼭짓점은 걸러낸 법선에 맞게 움직인다(법선 6회·꼭짓점 20회). 새로 입체화하는 형상에만 적용한다(Worker, 29만 정점에서 2~2.5초). 인접한 면의 꺾임이 큰 모서리(60°)의 꼭짓점 수는 줄지 않고(35° 안팎의 잔 주름이 선 꼭짓점은 20~50% 줄어든다), 부피는 ±1.5% 안이다. 처음 시도한 꼭짓점 단위 양방향 필터(Fleishman 방식)는 1~2링 이웃이 망치 자국 무늬보다 좁아 효과가 적었고 꺾인 곳에 주름을 만들어 쓰지 않았다.
- **사진 색 입히기**(2026-10-03, [photo-camera](../src/lib/product3d/photo-camera.ts), [photo-color](../src/lib/product3d/photo-color.ts), [photo-refine](../src/lib/product3d/photo-refine.ts), [painted](../src/lib/product3d/painted.ts), [input-cutout](../src/lib/product3d/input-cutout.ts)): 입체 형상의 정점 색은 TripoSR가 예측한 값이라 해상도가 낮다(정점 약 16만 개). 곰 얼굴처럼 가는 선으로 그린 무늬(눈·코·입)가 점으로 흐려지고, `혼합`도 이 색에서 디테일을 뽑는다. 원본 사진이 훨씬 선명하므로, 사진을 찍은 방향에서 보이는 면은 원본 사진의 색을 정점에 직접 입힌다.
  - **카메라 맞추기**: 저장된 입력 사진을 모델이 본 그대로 512×512 그림에 놓는다(제품 전경이 긴 변의 0.85, 가장자리 정리. 모델 입력을 만드는 코드와 같은 함수 `drawCutout`을 쓴다). 이 컷아웃의 윤곽과 형상의 정점을 투영한 윤곽이 가장 많이 겹치는 카메라(방위·고도·거리·화각·화면 이동)를 찾는다. TripoSR의 정해진 값(+x, 수평, 화각 40°, 거리 1.9)을 가정하지 않고 실루엣 겹침(IoU)으로 맞춘다. 시작점은 그 값과 방위 ±25°·±45° 몇 곳이고, 거친 그림(96px)에서 찾은 뒤 256px에서 다듬는다(패턴 탐색, Worker 안에서 2~4초). 겹침(IoU)이 0.85 미만이면 이 기능을 쓰지 않고 지금의 색을 그대로 쓴다. 이유는 "사진과 입체 형상의 윤곽이 잘 겹치지 않아(NN%) …"로 알린다.
  - **정점 색 읽기**: 삼각형을 512² 깊이 버퍼에 그려, 정점이 자기 화소에서 가장 가까운 표면인지(이웃 3×3의 최소 깊이와 비교, 기울어진 면은 그만큼 허용) 가린다. 법선만 보지 않고 깊이를 비교하므로 뒷면·제품 안쪽·다른 부품 뒤에 가린 면에는 사진 색이 묻지 않는다. 보이는 정도는 `혼합`과 같은 곡선(법선과 카메라 방향의 코사인 0.25~0.65)이고, 컷아웃 가장자리 2px 안은 쓰지 않고 5px 밖은 모두 쓴다(회색 테두리가 칠해지지 않게). 사진에서는 이중선형으로 읽는다.
  - **가는 선은 어떻게 살렸나(비교)**: 정점 간격이 사진 화소 2개쯤이라 정점 샘플링만으로도 눈·코·입이 알아볼 만하지만 가는 선은 번진다. 곰 변기에서 사진 기울기가 강한 화소(선·윤곽)의 평균 색 오차가 모델 색 27.8 → 정점 샘플링 10.9로 줄었고, 사진 기울기가 큰 곳의 삼각형만 변을 반으로 나누고(최대 2회, 변이 사진 1화소 안팎이 될 때까지, 새 정점도 사진에서 읽음) 9.2까지 줄었다. 정점은 2%(3천여 개)만 늘고 모양은 그대로다(변의 한가운데에 점을 둔다). 사진 해상도의 텍스처(UV 추가)는 구현하지 않았다. 메시 저장 형식·25MB 한도·옛 저장본 호환을 모두 바꿔야 하고, 사진을 찍은 쪽에서만 이득이며 다른 각도에서는 형상 해상도가 한계라서다. 나눈 메시는 불러올 때마다 만들 뿐 저장하지 않는다.
  - **색 계산에 연결**: 모든 화면이 쓰는 한 곳([shading](../src/lib/product3d/shading.ts))에서 처리한다. 사진 색이 입혀진 메시는 별도의 객체이고(`painted.ts`), `원본 색`은 모델 색 위에 사진 색을 보이는 정도만큼 덮고, `혼합`은 기본색(base)은 그대로 두고 디테일 비율(색 ÷ 주변 평균)을 흐린 정점 색 대신 사진 색에서 뽑는다. `조명 보정`은 바뀌지 않는다. 편집기·투명 PNG·3D 방·AI 입력이 같은 색을 쓴다. 계산은 surface-worker에서 하고 메시마다 한 번만 한다.
  - **저장과 옛 저장본**: 각도의 선택 필드 `product3d.photoCamera`(찾은 카메라와 겹침 정도)가 있으면 켜진 것이다. 3D 방과 편집기는 저장된 입력 사진을 읽어 다시 맞추지 않고 그 카메라로 입힌다(방에서 약 0.5초 추가). 필드가 없는 옛 저장본은 바뀌지 않는다. 360° 각도 편집을 열어 **사진 색 입히기**를 켜면 그 자리에서 카메라를 찾고(2~4초), 저장하면 기록된다.
  - **편집기**: 뷰어 아래 **사진 색 입히기** 항목(체크 상자). 새로 입체화하면 겹침이 충분할 때 켜진 채 시작하고, 못 맞추면 꺼진 채 이유를 알린다. 켜고 끄기는 **맞춤 실행 취소 / 다시 실행**과 같은 기록에 한 단계로 들어간다.
  - **한계(숨기지 않는다)**: 사진에 보이지 않는 면의 모양과 색은 여전히 모델의 추측이다. 이 기능은 사진에 찍힌 면을 선명하게 할 뿐 안 찍힌 면을 정확하게 만들지 않는다. 얇은 귀 같은 작은 구조는 형상 자체가 접힌 판처럼 나오고 색을 입혀도 형상은 달라지지 않는다. 카메라 맞춤은 윤곽이 단순하거나 사진이 많이 잘렸을 때 실패할 수 있고, 그러면 지금 색을 쓴다. 겹침이 0.85를 넘어도 형상이 사진과 한두 화소 어긋난 곳에서는 선이 조금 번진다(강한 경계 화소의 평균 오차가 0이 되지는 않는다).
- **도기 광택**(2026-10-03, [glaze](../src/lib/product3d/glaze.ts)): 조명을 받는 모드(`혼합`·`조명 보정`)의 재질은 거친 회색이고 반사가 없어 찰흙 같았다. 유약을 입힌 하얀 도기는 은은하게 반짝여야 한다.
  - **재질**: 거칠기를 낮추고(0.25~0.35), 얇은 투명 코팅(clearcoat)과 코드로 만든 부드러운 스튜디오 환경 반사(three의 `RoomEnvironment`를 PMREM으로 렌더러마다 한 번 만들어 공유, 파일 없음)를 쓴다. 광택은 `약하게`(거칠기 0.35, 코팅 0.25)와 `보통`(거칠기 0.25, 코팅 0.8)이고 `광택 없음`은 지금까지의 재질이다. `원본 색` 보기는 조명을 받지 않는 색이라 광택이 없다.
  - **밝기를 다시 맞췄다**: 환경 반사를 그대로 더하면 하얗게 날아간다(실험: 흰 제품의 정면이 이미 거의 흰색이라 더한 빛이 곧 255). 그래서 환경 반사는 아주 약하게(0.06~0.12) 하고 정반사를 줄이고(0.4~0.5) 편집기의 주광·하늘빛을 광택에 맞게 다시 정했다(`GLAZE.editor`). 기준은 `tests/product3d-gloss-browser.ts`가 고정한다: 정면을 향한 흰 유약의 밝기가 무광과 ±3% 이내(측정 −2.0%·−2.6%), 255로 날아간 화소 비율이 무광보다 2%p 넘게 늘지 않을 것, 흰 구에 하이라이트가 생길 것, 도기가 아닌 분류는 무광과 화소까지 같을 것.
  - **적용 대상**: 도기 분류(변기·세면대·욕조)만. 세면대장(나무 수납장일 수 있음)·수전(금속)·거울·타일·그 밖의 분류, 분류를 모르는 경우는 지금의 무광 재질이다. 저장해 둔 광택이 있어도 분류가 도기가 아니면 쓰지 않는다.
  - **저장**: 각도의 선택 필드 `product3d.gloss`(`light`·`normal`, `none`은 필드 없음으로 저장). 필드가 없는 옛 저장본은 광택 없음으로 열린다. 새로 입체화한 도기는 `약하게`로 시작하고 뷰어 아래 **도기 광택**(광택 없음/약하게/보통)에서 바꾼다. 도기가 아니면 항목이 꺼지고 이유를 적는다.
  - **3D 방**: 광택 도기는 `MeshPhysicalMaterial`이고 방 자체의 환경(`createInteriorEnvironment`)을 반사한다. `onBeforeCompile`의 색 보정·톤맵과 프로그램 키, 그림자 설정은 무광 재질과 같은 코드를 지나므로 그대로 동작한다(`tests/room-viewer-fixtures.test.ts`). AI 입력도 같은 방을 그린다.
  - **성능**: 방 전체 내보내기(1000px) 한 장의 시간을 한 제품·네 제품에서 재 보니 GPU(Intel Iris Xe)에서 차이가 없었다(무광 19·33ms, 광택 16~18·26~33ms). 소프트웨어 렌더링(SwiftShader)에서는 코팅 셰이더 때문에 내보내기가 20~25% 느려졌다(1031 → 1248ms, 3246 → 4082ms). 한 번 컴파일하는 비용은 첫 내보내기에만 든다.
  - **한계**: 광택은 형상의 울퉁불퉁함도 같이 보여 준다. 매끈하게 보이게 하는 것이 아니라 하이라이트가 읽히게 하는 것이고, 형상을 고치지는 않는다. 흰 제품 전체의 평균 밝기는 정면 밝기를 맞추느라 무광보다 3~4% 낮다.
- **입력 정리**: 입체화 입력을 회색 배경에 합성하기 전에 반투명 가장자리 픽셀에 제품 쪽 색을 채우고 알파를 1px 줄여 회색 테두리가 색에 섞이지 않게 한다. 원본 사진 자산은 바꾸지 않는다.
- **사진 밖 각도 안내**: 사진 방향에서 40° 넘게 돌린 시점이면 저장 버튼 근처에 "사진에 없던 면이라 모양이 부정확할 수 있어요"를 보인다. 저장은 막지 않는다.
- **이름과 자세:** 이름은 제품이 향하는 방향이고 자세에서 읽는다(`src/lib/product3d/direction-pose.ts`). 정면 0°, 오른쪽 +90°, 왼쪽 −90°, 뒤 180°이고, 카메라가 위에서 내려다본 각도는 빼고 센다. 이름을 고르면 `poseForDirection`이 카메라만 돌려 제품이 그 방향을 보게 한다(제품의 서 있는 모양·기울기는 그대로, 카메라는 똑바로).
  - 위는 카메라를 60°로, 아래는 −45°로 올리고 내린다(옆으로는 그대로). 가로 이름은 카메라가 35°를 넘게 위·아래이면 기본 높이(10°)로 돌아온다.
  - 이름과 자세가 25° 넘게 어긋나면(직접 돌린 경우) 저장 버튼 근처에 경고와 **가장 가까운 이름으로 바꾸기**·**‘X’ 방향으로 돌리기** 버튼을 보인다. 막지는 않는다. 위·아래는 카메라 높이(35°)로 맞춘다.
  - 방은 저장한 자세를 똑바로 세워 놓으므로 편집기의 이름과 방에서 보이는 방향이 같다(`tests/product-direction.test.ts`의 "the room sees the same direction the name gives" 검사).
  - **첫 자세와 경고(2026-10-04)**: 새 모델은 입체화한 각도의 이름이 정하는 방향으로 열린다(`openingPose`). 그래서 입체화 직후 첫 화면에 "새 각도 이름(다음 이름의 기본값, 정면이 쓰였으면 왼쪽)과 제품이 바라보는 방향이 달라요" 경고는 뜨지 않고, 대신 "새 각도를 추가하면 제품이 ‘왼쪽’ 방향으로 돌아서 저장돼요"라는 안내가 보인다(`product3d-direction-hint`). 사용자가 이름을 고르거나 제품을 1° 넘게 돌린 뒤에는 위의 경고가 그대로 뜬다(`directionMoved`로 직접 돌렸는지 읽는다). 다음 이름 고르기는 그대로다.
  - **"사진 방향에서 약 N° 돌아가 있어요"(40° 넘으면)**: 사진이 대각선에서 찍힌 제품은 진짜 정면이 사진에 없던 면이라 사실이다. 뜻을 분명히 했다: "‘정면’ 모습은 사진에 없던 면이라 AI가 추측해요(사진 방향에서 약 40° 돌아가 있어요). 정면에서 찍은 사진을 쓰면 더 정확해요."
- **호환**: 각도의 `product3d.shading`은 선택 필드다. 기록하는 값은 `mixed`·`lit`이고 `원본 색`은 필드가 없는 것으로 저장한다(과거와 같다). 필드가 없는 과거 각도는 `원본 색`으로, `lit`은 `조명 보정` 그대로 열려 옛 값은 항상 읽힌다. 과거 메시·자세·PNG는 자동으로 다시 만들지 않는다. 공간 둘러보기도 `mixed`·`lit`으로 저장한 각도만 기본색과 공간 조명으로 그린다.
  - **`fit` 필드(2026-10-02)**: 각도의 `product3d.fit`도 선택 필드다. 없는 옛 저장본은 만든 그대로 열리고 새 앱은 있든 없든 읽는다. 이전 앱이 읽으면 저장된 자재는 읽을 때 검증하지 않아 무시하지만, 이전 서버로 되돌리면 쓸 때 스키마가 모르는 필드(`.strict()`)를 거부하므로 `fit`이 든 자재는 그 서버에서 다시 저장할 수 없다(맞춤을 모두 끄고 저장하면 필드를 쓰지 않아 풀린다). 새로 입체화한 각도는 맞춤이 켜진 채 시작하므로 새 저장분부터 `fit`이 쓰인다.
  - **`photoCamera`·`gloss` 필드(2026-10-03)**: 각도의 `product3d.photoCamera`와 `product3d.gloss`도 선택 필드다. 없는 옛 저장본은 만든 그대로(모델 색, 무광) 열리고 새 앱은 있든 없든 읽는다(`tests/product3d-storage.test.ts`). `fit`과 같은 이유로 이전 서버로 되돌리면 두 필드가 든 자재는 다시 저장되지 않는다(스키마 `.strict()`). 사진 색을 끄고 광택을 `광택 없음`으로 한 뒤 저장하면 풀린다. **기존 제품은 자동으로 바뀌지 않는다**: 각도를 다시 열어 **사진 색 입히기**를 켜고(도기는 **도기 광택**도 고르고) **선택한 각도 수정**으로 저장한 뒤 자재를 새 버전으로 저장해야 3D 방과 AI 입력에 반영된다.
  - **새 값 `mixed`의 범위**: 새 앱은 세 값과 필드 없음을 모두 읽고 쓴다(스키마는 이전 값의 상위 집합이고, `tests/product3d-storage.test.ts`가 확인한다). 이전 앱이 `mixed`를 읽으면 저장된 자재는 읽을 때 검증하지 않으므로 `원본 색`으로 보인다. 그러나 이전 서버로 되돌리면 쓸 때 스키마(`.strict()`)가 `mixed`를 거부하므로, `mixed` 각도가 든 자재는 그 서버에서 다시 저장할 수 없다(각도를 `조명 보정`·`원본 색`으로 바꿔 저장하면 풀린다). 새로 입체화한 각도는 기본이 `혼합`이라 새 저장분부터 `mixed`가 쓰인다.

## 구조와 저장

- 기존 TripoSR ONNX 추론과 Web Worker, GPU 우선·CPU 대체 실행, 표면 정밀화, 색상 처리를 재사용한다. 자동 정면 추정과 고정 세 방향 결과 생성은 제거한다.
- Three.js `TrackballControls`로 카메라를 회전하고, 제품 자체 회전은 별도 quaternion으로 보관한다. 조작 중에는 모델 다운로드·AI 추론·PNG 생성·서버 업로드를 하지 않는다.
- `MaterialVersion.views[].product3d`는 메시 자산, 실제 추론 입력 자산, 모델 ID·revision, 제품 회전, 카메라 자세·확대를 가리킨다. 기존 자재 버전과 프로젝트는 변경되지 않는다.
- 이미지와 `product-mesh` 자산을 구분한다. 메시의 바이너리는 형식 버전과 positions·indices·colors를 포함하며 25MB 이하, 유한 좌표·색상·유효한 인덱스를 검증한다.
- PNG·메시·입력 이미지의 자산 저장을 완료한 뒤 폼 사진을 추가하거나 바꾼다. 한 번 입체화해서 추가한 각도들은 같은 메시·입력 자산을 공유하고 각도별 PNG·자세·이름은 따로 보관한다. 실패하면 이전 사진과 현재 뷰어 결과를 유지해 재시도한다. 자산 정리는 불변 자재 버전과 메시의 원본 참조를 확인한다.
- 이전 세 방향 PNG는 그대로 사용할 수 있다. 과거 메시가 저장되지 않은 결과는 최초 360° 편집에서 재입체화해야 한다. 메시가 없거나 손상된 경우 이유와 재생성 버튼을 표시하며 자동으로 모델을 실행하지 않는다.
- Supabase의 바이너리 업로드 검증·참조 탐색과 MIME 정책도 준비한다. 이 작업에서는 서버 연결이나 배포를 수행하지 않는다.

## 검증 실행

```powershell
npx playwright test --config playwright.product3d.config.ts
```

기본 브라우저 검증은 실제 AI가 이전에 만든 변기 메시를 재생하되 Worker 응답은 제어한다. 테스트의 목적은 뷰어·PNG·저장·실패 처리이며 새 AI 추론의 성공 증거로 세지 않는다. fixture가 없는 환경에서는 해당 테스트가 명시적으로 건너뛰어지며 다음 환경변수로 별도 fixture를 지정할 수 있다.

- `SJN_PRODUCT3D_MESH`: `mesh-positions.bin`, `mesh-indices.bin`, `mesh-colors.bin` 폴더.
- `SJN_PRODUCT3D_SOURCE`: 실제 추론에 사용한 투명 PNG.

입체화 자동 저장을 실제 사진·실제 편집기로 확인하려면(개발 서버가 떠 있고 `test-results/e2e-flow/state.json`에 관리자 로그인 세션이 있어야 한다) 다음을 쓴다. 개발 서버는 1MB를 넘는 업로드를 vinext 기본 한도(`serverActions.bodySizeLimit`)로 413으로 막아 메시 저장이 실패한다. 이 확인에서만 `next.config.ts`에 `experimental: { serverActions: { bodySizeLimit: '40mb' } }`를 임시로 넣고 끝나면 반드시 되돌린다(커밋 금지, 운영에서도 그런지는 확인하지 못했다). 한도를 올리지 않으면 자동 저장이 413으로 실패해 "자동 저장하지 못했어요 … 직접 저장할 수 있어요"가 뜨고 결과는 유지된다. 두 번째는 저장된 4종을 다시 그려 정면 자세와 방 정면 시점을 비교한다.

```powershell
node tests/run-browser-test.mjs tests/product3d-auto-save-real-browser.ts bear-toilet
node tests/run-browser-test.mjs tests/product3d-front-compare-browser.ts
```

실제 제품 사진 여러 장을 앱과 같은 Worker로 한 번에 돌려 보려면 사진을 `test-results/product3d-batch/input`(또는 `SJN_PRODUCT3D_BATCH_INPUT` 폴더)에 넣고 실행한다. 배경 제거(BiRefNet) → 입체화(TripoSR, WebGPU) → 전후 캡처를 사진마다 `test-results/product3d-batch/<이름>/`에 쓰고, 원본·배경 제거·전후 6장을 모은 `<이름>-comparison.png`와 `summary.json`(단계별 시간, 정점 수, 거칠기, 자동 수평 각도, 재질 수, 밝기)을 남긴다. 이번 실행에 없는 사진의 기존 기록은 유지한다.

- 모델은 로컬 파일만 쓴다. TripoSR는 `tmp/multiview-model`, BiRefNet FP16은 `tmp/background-model/model_fp16.onnx`(98,484,532 bytes)다. 후자는 QA용 Chrome 프로필 캐시에서 `node tests/export-background-model.mjs`로 꺼낼 수 있다(`127.0.0.1:3000`에 개발 서버가 떠 있어야 한다). 프로필이 없으면 앱이 쓰는 고정 revision 파일을 직접 받아 같은 위치에 둔다.
- `SJN_PRODUCT3D_BATCH_CPU=<이름>`: 그 사진은 CPU(wasm, 격자 160) 시간도 잰다(수 분).
- `SJN_PRODUCT3D_BATCH_RERENDER=1`: AI를 다시 돌리지 않고 저장된 메시만 다시 캡처한다(렌더링·재질 추정을 바꿨을 때).
