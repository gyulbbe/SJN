# 관측 표면에 기반한 하부장 규격·자세 대안 실험 — 2026-09-13

`observed-product-proposal.ts`는 같은 종류로 분류된 하부장 몸체의 두 수직 면에서 **사용자가 검토할 임시 모형**을 만든다. 기존 `observed-product-pose.ts`의 고정 규격 검사와 자동 배치 경로는 변경하지 않았다. 이 작업은 현재 Lab에 관측 표면을 공급하거나 사용자가 대안을 선택하는 기능을 연결한 구현이 아니다.

## API와 경계

```ts
proposeObservedProductProposal(input: ObservedProductPoseInput, context: {
  room: RoomDefinition;
  expectedFingerprint: string;
  baseHeightMm: number;
  sources: {
    inputFingerprint: string;
    pointsSha256: string;
    labelsSha256: string;
    cameraSha256: string;
  };
}): ObservedProductProposal
```

반환값은 `held` 또는 `review-required`다. 자동 적용이나 사용자 수락 상태는 없다. `fixedCheck`에는 기존 함수를 같은 입력으로 호출한 결과를 보존한다. `proposalId`와 각 대안의 `id`는 입력·소스 SHA, 후보 ID, 원래 규격, 방, 설치 높이, 분류 근거로 구성한 결정적 식별자다. 해시는 호출자가 원자료 바이트와 검증해야 한다. 순수 함수는 해시의 형식·사진 일치만 검사하며 원파일을 읽지 않는다.

- `user`·`catalog` 규격은 대안으로 교체하지 않는다. `default` 규격의 폭·깊이에만 별도의 관측 proxy를 제공한다. 원래 규격은 반환 출처에 그대로 남고 입력 객체도 변경하지 않는다.
- 높이는 기존 기본값을 유지한다. 설치 높이도 호출자의 기존 가정으로 기록하며, 관측 점의 최저점을 바닥 접점으로 채택하지 않는다. 이번 실제 재생은 기존 바닥 설치 기준인 0을 사용했다.
- cabinet 라벨 11만 몸체 적합에 사용한다. 세면볼 48과 다른 종류의 점은 제외한다. 사진 bbox 전체를 물체 점으로 사용하지 않는다.
- 수평 축 하나의 길이는 그 축에 수직한 끝면의 픽셀 수가 아닌 **다른 면의 접선 방향 범위**로 계산한다. 각 면의 잔차·법선 검사 후 별도로 백분위를 계산하므로 큰 끝면의 투영 면적이 전체 점 분포를 지배해도 접선 길이를 단축하지 않는다.
- `sampleExtentSensitivityMm`은 p2–p98와 전체 점 범위의 민감도다. 실제 길이의 신뢰구간이 아니다. `completeDimension.minimumSupportedSpanMm`도 모델 스케일에서 관측된 지지 범위이며 실측 최소 치수가 아니다. 미관측 끝은 `unverified-may-be-occluded-or-clipped`, 전체 길이 상한은 `null`로 남긴다.
- 두 축 배정 × 앞뒤 두 개, 최대 네 가지 해석을 유지한다. 앞면 의미나 가장 가까운 벽을 근거 없이 선택하지 않는다. 방·관측 벽·몸체 적합 검사를 통과하지 못한 대안만 제외하며 위치/규격을 clamp하지 않는다.
- 한 면만 관측되거나 작은 부분, 잘못된 벽, 확인된 분류 혼입 또는 분리되지 않은 반사는 보류한다. `contamination: unassessed`는 동일 제품 여부를 확인해야 하는 `review-required`까지만 허용한다.

## 실제 저장 관측 재생

실행:

```powershell
node tests/run-browser-test.mjs tests/reconstruction-product-proposal-replay.ts
```

입력은 `test-results/reconstruction-product-pose-20260913/inputs/user-01..04.json`이다. 당시 실제 DeepLab/MoGe 표면과 당시 카메라 좌표계를 재생했다. 새로운 AI 추론이나 최신 카메라 추정 실행이 아니다. NPZ·semantic labels·원 카메라가 담긴 placement report 바이트의 SHA-256이 내보낸 소스와 일치함을 검사했다. 재생 전후 이 실험의 소스 해시도 일치했다.

| 저장 사례 | 실험 범위와 결과 |
| --- | --- |
| user-01 | 저장된 6개 후보 중 vanity 없음. 모두 이 상자형 하부장 실험 밖 |
| user-02 | 당시 저장 카메라 보류, 월드 표면 없음. 후보 4개 `held-frozen-camera` |
| user-03 | 당시 저장 카메라 보류, 월드 표면 없음. 후보 4개 `held-frozen-camera`. 이후 별도 카메라 개선의 결과를 부정하거나 다시 검증한 것이 아님 |
| user-04 | vanity item_04 실제 점 23,824개 중 몸체 20,909개. 기존 고정 검사 `held`, 별도 proxy는 `review-required` 4개 |

user-04의 두 수직 면은 원래 법선의 직교 오차 3.636°를 갖는다. 안정적인 각 면의 점 5,634개/14,054개에서 다른 면의 접선 지지 범위 약 1,837.81mm/527.55mm를 얻었다. 이 숫자는 모델 추정 공간의 길이이며 실측이 아니다. 전체 미관측 길이는 알 수 없다.

네 대안은 같은 물리 사각형에 대해 의미상 폭·깊이와 앞뒤를 달리한다. 관측 proxy의 수평 길이는 약 1,939.79 × 592.47mm, 높이는 유지한 기본값 850mm다. 중심은 모델 월드 (x,z)=(-875.30, 1187.68)mm, yaw는 1.19°/91.19°/181.19°/271.19°다. 좌표와 치수는 실제 저장 관측의 재생 결과이며 앱에 하드코딩되지 않았다. 관측 벽 두 개에 대한 최소 코너 부호 거리는 약 162.74mm/65.87mm로 침범은 없지만, 제품 뒤가 벽에 닿는다는 설치 관계까지 확인한 결과는 아니다.

### 규격 변경과 허용 오차 변화의 분리

| 검사 | 표면 포함률 | 수직 면 잔차 p95 | 허용 오차 | 판정 |
| --- | --- | --- | --- | --- |
| 기존 기본 규격 1200×550, 축 1 | 85.05% | 34.27mm | 33.0009mm | 고정 규격 보류 |
| 기존 기본 규격 1200×550, 축 2 | 90.63% | 33.87mm | 33.0009mm | 고정 규격 보류 |
| 관측 proxy, 기존과 동일한 상대 오차 공식 | 98.3309% | 31.4669mm | 50mm | 수치상 적합, 사용자 검토 필요 |
| **같은 proxy, 기존 고정 오차로 비교** | **94.9878%** | **31.4669mm** | **33.0009mm** | **포함률 97% 미달** |

따라서 규격 대안만으로 기존 고정 검사 기준을 통과했다고 주장할 수 없다. 상대 오차 공식은 같지만 대각선이 길어져 허용 오차가 증가한 효과가 포함돼 있다. 각 대안의 `fit.originalFixedTolerance`에 기존 오차에서의 포함률, 높이 포함률, 표면/높이 판정을 별도로 보존했다. 첫 재생의 proxy 계산 164.162ms는 이미 디코딩한 점을 순수 함수로 계산한 1회 시간이며 AI·파일 내보내기·렌더·전체 사용자 완성 시간을 포함하지 않는다.

## 검증 및 아직 연결하지 않은 범위

새 단위 22개와 기존 고정 자세 단위 21개, 총 43개 통과. scoped ESLint 통과. 실제 저장 입력 4개 재생 exit 0. 테스트는 임의 회전, 기본 규격 충돌, user/catalog 규격 보존, 입력 불변, 소스 ID, 미관측 끝, 분류 혼입/반사, 한 면, 면별 픽셀 불균형, 방·벽 침범, 기존 높이 불일치, 해시 오류를 포함한다. 이 범위로 전체 사진의 재구성 품질이나 새로운 사진의 정확도를 달성했다고 판단하지 않는다.

후속 UI 연결에는 (1) 실제 같은 사진의 표면·벽·카메라와 허용된 로컬 소스 공급 경로, (2) 원관측과 사용자 선택을 별도로 보존하는 수락 기록, (3) 모형 비교에서 폭 축·앞뒤·미관측 끝·같은 제품 여부를 확인할 표현이 필요하다. 기존 `ManualCandidatePlacement`의 숫자만 채우면 치수 출처가 `user`로 축약되므로 생성 근거와 소스 해시를 별도 기록해야 한다. 원시 점 수만 개를 Lab report마다 복제하지 않는 자산 참조도 필요하다. 이번 작업은 이 UI·공급 프로토콜·수락·프로젝트 저장을 구현하거나 실행하지 않았다.

개인 사진 기반 결과는 ignored `test-results/reconstruction-product-proposal-20260913/user-04.json` 및 `summary.json`에만 저장했다. 원사진 또는 원시 표면을 외부에 전송하지 않았다.
