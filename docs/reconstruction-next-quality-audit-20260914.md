## 현재 촬영 기하와 공통 카메라는 서로 다른 계산이다

- `src/lib/room-geometry.ts:5`의 기본 공간은 2400×2400×2400mm다. `createRoomCamera`는 화각50°, 중앙 x=0, 눈높이=방높이×0.55, 방 앞쪽에서 전체 공간이 들어오는 거리를 만든다. 이것은 **비교용 공통 카메라**이며 사진의 EXIF/소실점/촬영 위치를 복원한 값이 아니다.
- `source-camera.ts:493`의 `fitSourceCamera`는 실제 관측한 방 모서리/선분과 입력 방 크기를 받는다. 직각 여부 unknown, 근거 없는 모서리, 초점거리-거리 모호성, 잘린 관측을 보류한다. `createSourceCamera`는 수학용이며 공통 편집 카메라를 교체하지 않는다.
- 현재 Qwen inventory v2는 설비 종류/부품을 찾지만 `backWallQuad=null`, `orthogonal=unknown`, corners/lines=[]를 명시한다. 이 자료로 source-camera가 held인 것은 카메라 코드를 통과시키면 해결되는 형식 오류가 아니라 **기하 관측이 없는 상태**다.
- `observed-placement.ts`는 실제 `room-boundaries` 평면과 하나의 같은 설비 관측이 맞을 때만 위치를 추정한다. 보이는 바닥 영역의 임시 깊이 범위를 물리 바닥 전체로 승격하지 않는다. 설치방식만 독립적으로 보완하는 경로와 위치 재사용은 분리되어 있다.
- `observed-support-contact.ts`와 `source-camera.ts:813`은 기둥형 세면볼 bbox의 하단을 발 접점으로 쓰지 않는다. 같은 사진/설비의 연속 기둥 하단을 별도 `supportEvidence`로 유지한다. 그 하단 윤곽도 실제 발의 중심·제품 중심 실측은 아니다.
- `source-camera.ts:910`의 `validateSourceFixture`는 모형의 실제 local boxes를 변환해 world bounds와 실제 source-camera의 projectedBounds를 계산한다. 입력 bbox를 projectedBounds로 복사하지 않는다. source가 없으면 실제 방 내부 검사만 하고 bboxErrorPx를 만들지 않는다.

현재 Lab에는 ‘원본 촬영 구도: 확인 필요/추정됨’, ‘최종 Before/After 공통 카메라와 원본 사진 해석용 카메라는 별도’ 안내가 이미 있다. 이 문구만 다시 추가하는 것은 이번 목표의 실질 개선이 아니다.

## 기존 평면·접점 실험을 현재 사실로 잘못 바꾸지 않기

아래는 새 실행이 아니라 `test-results/reconstruction-plane-evidence-20260913/placement-hypotheses/summary.json`을 직접 읽은 결과다. 실제 저장 관측 재생 시간은 약0.052초, 새 모델/네트워크/사용자 보정0이었다. MoGe 추론 시간이나 사람의 완료 시간으로 해석하지 않는다.

| 사진 | 기하 없는 후보 배치 | 광학영역 제외 전→후 strict camera | 배치 전→후 | 선택하지 않은 후단 가설 |
|---|---:|---|---:|---|
| user-01 | 0 | estimated→held | 0→0 | 2개, 촬영 위치173.382mm/회전8.674° 차이 |
| user-02 | 0 | held→held | 0→0 | 0개, 관측한 옆벽 부족 |
| user-03 | 0 | held→held | 0→0 | 2개, 위치20.116mm/회전0.493° 차이 |
| user-04 | 1 | estimated→estimated | 3→3 | 1개, 창/거울/변기 |

수치의 mm는 서로 다른 모델 가설 간 차이이며 실제 카메라 오차가 아니다. user03에서 비슷한 가설 두 개가 나온 사실도 제외한 벽 조각의 모순을 없애지 않는다. 현재 `fitDepthRoomCamera`는 모호한 뒤벽/여러 옆벽/미관측 옆벽을 계속 보류한다.

광학 제외 실험은 원사진과 같은 Qwen 원문/관측 bbox를 검증한 뒤 거울·유리·창·문/반사 영역을 보수적으로 제외했다. 투명체 뒤 실제 벽 지지까지 일부 잃을 수 있고 bbox는 정확한 인스턴스 마스크가 아니다. 합칠 벽 조각을 모두 재적합했을 때 기준을 넘으면 병합하지 않았다. 이 경로는 일반 사용자 기본 분석에 채택되지 않았다.

추가 주의점: `depthObservedWallAtPoint`는 선택된 두 명목 벽과 광선의 가까운 교차를 구한다. 현재 API에는 관측 패치의 픽셀별 지지 범위가 없으므로, 교차가 된다는 것만으로 실제 부착 관계·거울/개구부 아님을 입증하지 못한다. 향후 이 경로를 확대한다면 동일사진 지지 픽셀/경계·가림 검사를 먼저 넣어야 한다. 현 목표를 이유로 이 미확정 기하를 자동 승인하지 않는다.

## 공통 개선 제안: 볼 모양과 기둥 단면을 분리

초기 감사 당시 `templates.ts:267`은 `basinShape=rectangular`여도 받침을 항상 `CylinderGeometry`로 만들었다. 사각 볼 아래의 넓은 사각 기둥이 원통이 되는 현상은 직접적인 모형 표현 누락이며 카메라 실패와 무관하다.

가장 좁고 근거 있는 후속 형태 개선은 **기둥 단면(모름/원형/사각)**을 볼 형태와 별도 옵션으로 두는 것이다. 원모델이 단면을 관측하지 않았으면 볼의 rectangular에서 기둥까지 사각으로 자동 결정하지 않는다. 사용자가 사각을 고르면 user 출처로 저장하고 표준 사각 기둥을 렌더한다. 기존 저장 데이터에서 옵션이 없으면 기존 원통 모형을 유지한다. 폭·깊이를 실측이라 부르지 않고 기존 기본/사용자 규격으로 분리한다.

초기 제안 이후 사각 기둥 단면을 명시 선택하는 `pedestalShape`가 승인·구현됐다. 볼 형태에서 기둥 단면을 자동 추정하지 않으며, 필드가 없는 기존 자료는 원통을 유지한다. `tests/reconstruction-pedestal-shape.test.ts`, 생성·설계 저장 단위 검사 및 `test-results/reconstruction-pedestal-shape-20260914/run-02-formatted/verification.json`의 실제 UI·모형 PNG 검사를 완료했다. 이는 선택 가능한 표준 형태 표현의 개선이며 실제 AI 단면 인식 성공이 아니다.

현재 근거로는 Qwen 기본 엔진 채택이나 깊이 모델의 일반 사용자 자동 연결을 권하지 않는다. 새 목표는 검증된 색상 원인을 수정하고, 설치 관계의 확인 입력을 줄이며, 필요한 형태를 사용자가 조절할 수 있게 하는 범위에서 끝낼 수 있다. 완전 자동 카메라 복원·숨은 형상·실측 정밀도를 추가 완료 조건으로 만들지 않는다.


## 후속 좁은 기하 수정과 현재 증거

초기 감사 뒤 baseline 추정, 모형 생성, 저장 후 재투영 세 곳에서 별도의 fit/clamp가 작동하며 원요청의 방 침범을 숨긴 경로가 확인됐다. 사진과 사용자 확정은 `placementPolicy: preserve`로 좌표·규격을 보존하고 실제 모형 bounds 위반을 보류한다. 일반 직접 추가의 기존 기본 위치 맞춤은 유지한다. 보류는 원래 제안·출처·넘침 이유를 유지하고 간단한 값 수정 UI에서 확인한다.

새 5사진 raw 재생의 배치 개수는 2/1/2/3/4 → 0/0/0/2/0이다. 자동으로 더 잘 배치한 결과가 아니라 그동안 숨겨진 추정 기하 실패 10개를 드러낸 결과다. 이 비교를 자동 인식·재구성 품질 향상으로 주장하지 않는다. 각 사진과 사용자 보정 후보의 현재 결과, 실제 보류 수정·저장 검사는 최종 보고에서 따로 구분해야 한다.

자세한 현재 소스·검증·제한은 [엄격 배치 결과](reconstruction-strict-placement-results-20260914.md)를 따른다. 이 추가 절은 위 초기 완료 기준을 대체하거나 과거 검증만으로 새 목표 완료를 선언하지 않는다.
