## 확인한 원인과 변경 파일

`analysis.reviewFromSegmentation`의 `visible-floor-region`은 실제 깊이를 측정한 평면이 아니다. `auto-surfaces.estimatePlaneQuad`는 텍스처의 원근만 정하는 네 점이며, 처음 점이 방 뒤쪽일 보장도 없다. 실제 user-03의 첫 점은 사진 전경인데 이전 baseline에서 물리 v=0으로 쓰였다. 기존 candidate 관측 재사용 경로는 이 임시 바닥을 이미 거부했으므로 baseline과의 계약 불일치도 있었다.

이제 `inspectReconstructionCandidateMapping`은 사용할 수 있는 물리 위치와 검토용 임시 제안을 나눈다. 후자는 `placementReview.requested`와 사유에 남고 원관측은 그대로 둔다. `room-boundaries` 또는 사용자 확인 평면도 선언된 구간을 사용한 근사이며, 카메라 캘리브레이션이나 실측 정답을 뜻하지 않는다.

## 사용자 확인 결과 — 자동 성공과 분리

[Review run-05 증거](../test-results/reconstruction-placement-quality-20260914/review-ui/run-05/verification.json)는 실제 user-03 raw 관측으로 생산 생성 함수를 실행한 후 생산 Review UI를 조작했다.

## 남은 한계와 다음 판단

촬영 카메라와 실제 바닥 범위가 불명확한 사진에서 자동 위치 복원은 여전히 병목이다. 표준 모형이 보인다는 것과 원사진의 종류·형태·상대 위치·높이·방향을 충분히 재현한다는 것은 다르다. 지금은 필요한 위치를 그림에서 확인해 추가할 수 있게 된 수준이다.

유리 파티션·거울장·선반처럼 원모델 관측 자체가 부족한 대상, 반사 속 설비와 실제 설비 구분, 가려진 접점, 제품 실측 규격은 별도 인식/기하 근거가 필요하다. 새 모델을 채택하려면 기존 로컬 Qwen 경로에서 같은 입력의 종류·설치 관계·거짓 양성·후속 생성까지 평가해야 한다. 이번 작업에서 그 실험은 새로 실행하지 않았으므로 모델 교체의 효과를 주장하지 않는다.

Supabase 실연결·외부 배포·유료 API·사진 외부 전송은 수행하지 않았다. 새 미사용 사진을 사전 기준으로 평가하는 일반화 실험, 실제 source-camera 재투영, 사용자 전체 메모리 피크 측정도 미실행이다. 기존 원본·불변 자재 버전·시안 저장 방식은 유지했다. 원본과 기존 수정 내용을 삭제하거나 초기화하지 않았다.

## 사용 위치

- 홈의 **사진 재구성 테스트** 또는 `/reconstruction-lab`: 사진 여러 장을 추가하고 기존 전체 실행 버튼을 사용한다. 결과의 **후보별 진행 근거**에서 관측→배치→모형 생성 단계를 펼친다.
- 사진으로 만든 프로젝트의 Before 설비 확인에서 보류된 설비의 설치 위치·규격을 연다. 필요한 설치 벽/방향을 선택하고 그림을 클릭한 뒤 **모형 추가**로 확정한다.
- 뒤/왼쪽/오른쪽 벽 쪽 미리보기는 조건이 맞는 바닥 설치 물체의 기본 대안이다. 실제 사진에서 파악한 위치로 표시하지 않는다. 벽 제품은 그림의 세로 위치로 설치 높이도 함께 조절한다.
- 기본안 선택·그림 미리보기만으로 저장 문서를 바꾸지 않는다. 실제 추가 후에는 기존 실행 취소·저장 흐름을 사용한다.

## 다음에 필요한 실험

다음 우선순위는 모형 종류 추가가 아니라 **관측 후보와 실제 방의 평면을 연결할 근거 확보**다. 같은 후보를 고정하고, 검증된 방 모서리·바닥 경계·촬영 기하를 주었을 때 보류가 올바른 자동 제안으로 바뀌는지 독립 비교해야 한다. 새 평가 사진과 종류·설치 벽·높이·가림의 판정 기준은 실행 전에 정한다. 실제 촬영 기하나 실측 정답이 없는 자료에는 mm 정확도를 만들지 않는다.

설비 자체가 관측에 없는 경우에만 기존 로컬 Qwen 경로로 종류·설치 관계·반사 오탐을 별도 비교한다. 정상 응답이나 후보 수 증가만으로 분석기를 교체하지 않는다. 이번 다섯 개발 사진의 자동 결과가 개선되지 않았으므로, 현 변경을 자동 재현 기능의 완성으로 간주하지 않는다.
