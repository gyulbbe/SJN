# 원본 시점과 후보 배치 실험 경로

이 모듈은 opt-in 후보 분석기의 기하 단계다. 기존 DeepLab 기준선과 최종 Before/After 공통 카메라는 변경하지 않는다. 원본 시점은 사진 좌표를 방의 mm 좌표로 옮기고 재투영 오류를 기록하는 데만 사용한다.

## 현재 후보와의 연결

prompt revision 8은 `fixture-inventory-v2`의 설비 목록만 관측한다. 방 모서리·접점이 없으면 아래 촬영 카메라는 미확정으로 남는다. `observed-placement.ts`는 같은 설비와 실제 방 경계의 독립 근거가 있는 경우에만 추정 위치를 재사용한다. 이 경우에도 카메라를 성공으로 표시하거나 재투영 오류를 만들어 내지 않는다. 위치 재사용이 기본 모형의 방 내부 검사를 통과한다는 보장은 없다. [현재 실제 사진 검증](reconstruction-improvement-results-20260913.md)에서 재사용 후 범위 보류까지 구분했다.

## 관측 계약

`src/lib/reconstruction/pipeline-contract.ts`의 `SceneUnderstanding`은 종류·설치 방식·벽·형태·반사 여부·근거·불확실성과 관계를 따로 둔다. `unknown` 후보를 삭제하거나 기본 종류로 바꾸지 않는다. 좌표는 방향 정규화한 전체 사진의 0–1 좌표다.

뒤 벽의 네 점은 실제 외곽 모서리를 TL/TR/BR/BL 순서로 관측한 경우에만 준다. 사진 크롭 경계와 욕조·가구의 경계를 방 모서리로 대신 사용할 수 없다. 부분 사진에는 실제 보이는 named corner만 준다. 앞 모서리도 실제 방 앞 모서리이며 사진 프레임의 끝을 의미하지 않는다. 완전한 뒤 벽 네 점에는 공간 관측 근거가, 개별 named 모서리에는 각 점의 관측 근거가 필요하다. 빈 배열이나 공백뿐인 근거를 실제 관측으로 받아들이지 않는다.

`reflectionOf`는 `frontId=반사된 복사본`, `behindId=실제 물체`다. 실제 물체가 보이지 않으면 `reflection=reflected/uncertain`만 보존한다. `visibleThrough`는 `frontId=유리`, `behindId=유리 뒤 설비`다. 유리 뒤 설비의 픽셀 분류를 유리 종류와 충돌한다고 간주하지 않는다.

## 카메라와 설치면 계산

`source-camera.ts`는 WebGL 없이 Three.js 수학만 사용한다.

- 완전한 뒤 벽: 입력한 방 가로·높이와 관측 네 점의 호모그래피를 만든 뒤 직교 회전과 핀홀 화각을 적합한다.
- 뒤 벽 일부 누락: 실제 관측한 서로 다른 깊이의 방 모서리 여섯 개 이상이 독립 제약을 제공하면 정규화한 선형 카메라 적합을 사용한다. 중복·특이 배치·잘못된 모서리는 보류한다.
- 일부 모서리와 직선: 두 축 이상의 실제 평행 방 경계·타일 선분을 축당 두 개 이상 관측하면 직교 소실점으로 회전·화각을 적합한다. 실제 named 모서리 두 개 이상이 만드는 거리 제약으로 촬영 위치를 푼다. 선분만 있거나 거리 기준이 부족하면 스케일을 임의로 정하지 않는다. 같은 선을 복제하거나 잘못된 축·짧은 선·근거 없는 선분은 보류한다.
- 정면 평행 뒤 벽 하나: 초점거리와 촬영 거리를 분리할 수 없으므로 보류한다. 실제 다른 깊이의 모서리 또는 명시적으로 제공한 수직 화각이 있을 때만 추가 계산한다.
- 주점이 사진 중심이라는 가정, 렌즈 왜곡을 무시하는 가정, 직사각형 공간·입력 방 치수를 사용하는 가정을 보고서에 명시한다. 이는 실측 카메라 보정이 아니다.
- 비직각 공간과 직각 여부를 모르는 공간, 모서리 면적 부족, 큰 재투영 오차, 비현실적인 촬영 위치를 자동 성공으로 표시하지 않는다.

설비의 관측 접점 또는 벽 부착점에서 원본 카메라 광선을 쏘아 floor/back/left/right 면과 만나는 위치를 얻는다. 바닥 설치와 벽 설치는 별도 면으로 역투영한다. 벽걸이는 바닥 접점을 요구하지 않는다. 명시한 접점/부착점은 비어 있지 않은 관측 근거와 올바른 설치 종류가 있어야 하고, 해당 설비의 사진 영역 안 또는 정규화 좌표 허용 오차 0.01 안에 있어야 한다. 다른 제품의 접점을 넣어 하단 잘림 검사를 우회할 수 없다. 면 밖 교차점을 clamp해서 정상 좌표처럼 만드는 경로는 없다.

명시한 기준점이 없으면 사진 범위 하단 중앙을 기하 추정 기준점으로 쓸 수 있지만 이 사실과 사용자 확인 필요를 기록한다. 하단이 잘린 경우에는 그 경로를 보류한다. 사진 범위의 폭·높이를 mm 규격으로 바꾸지 않으며 모형 규격은 계속 종류별 기본값 또는 사용자 입력값이다.

## 배치 전 검사와 보고서

`candidate-pipeline.ts`는 기본 모형을 고른 다음 `validateSourceFixture`로 실제 모형 상자를 검사한다. 바닥에 뜨거나 방 밖·벽 밖·천장 위로 나가는 모형은 축소나 이동으로 숨기지 않고 보류한다. 미지원 세면대 지지 형태, 반사 의심, 종류 근거 충돌, 중복 후보도 `plans=null`, `placements=held`, 검토 후보 `requiresReview=true`로 일치시킨다.

사용자 배치는 별도 출처다. 원본 카메라가 보류됐어도 사용자가 공통 방 좌표에 놓을 수 있지만 이때 `room-only` 물리 검사만 수행한다. 원본 재투영 값을 만들어 내지 않는다. 벽의 설치 높이 mm를 기준으로 세로 정규화 좌표를 동기화한다. 수동 위치만으로 종류 충돌이나 반사 여부가 확정되는 것은 아니다.

오차는 구분해 읽는다.

- `camera.reprojection`: 적합에 사용한 방 모서리 관측의 RMS/최대 px 오차. 독립 정확도나 물체 인식 성공률이 아니다.
- `placements[].reprojectionErrorPx`: 관측 기준점을 역투영한 뒤 다시 투영한 수치 왕복 오차. 실제 접점을 정확히 검출했다는 뜻이 아니다.
- `modelChecks[].result.bboxErrorPx`: 기본 모형의 원본 시점 외곽과 관측 물체 범위 차이. 규격·형태·방향이 기본값일 수 있으며 마스크 일치도가 아니다. 물리 범위 검사 성공과 별도로 기록하며, 이 값을 최소화하는 자동 규격·형상·방향 최적화는 구현하지 않았다.

사용자가 새로 추가한 설비는 원래 사진 관측 영역이 없다. 폼의 전체 화면 임시 범위를 관측 정답으로 사용하지 않으므로 `bboxErrorPx`를 기록하지 않는다. 원본 카메라가 있으면 실제 `projectedBounds`와 가시성·방 내부 검사는 유지한다. 기존 모델 후보를 수동 보정한 경우에는 같은 ID의 원래 자동 이해에 저장된 사진 범위로 비교한다. 수정된 범위나 사용자 추가의 임시 범위로 원분석을 대체하지 않는다.

모든 px 오차는 `camera.camera.image`에 기록된 기하 입력 해상도 기준이다. 좌표는 전체 사진에 대해 정규화되어 있지만 기하 입력은 방향 정규화 미리보기일 수 있으므로, 원본 이미지가 더 클 때 이를 원본 전체 해상도 픽셀 오차라고 부르지 않는다. 원본·미리보기·분석·출력 크기는 lab 보고서에서 구분한다.

자동 이해·수정된 이해·기준선 후보·기하 계획은 깊은 복사로 분리한다. 모델 및 사용자 사진을 바꾸거나 기존 프로젝트에 자동 저장하지 않는다. 실제 공통 장면 생성은 기존 템플릿과 동일한 저장·PNG 경로를 사용한다.

## 자동 검증과 한계

`tests/reconstruction-source-camera.test.ts`의 28개 검사는 Three.js로 만든 실제 합성 카메라를 사용한다. 완전/부분 모서리, 알려진 화각, 정면 모호성, 비직각/크롭/중복, 네 설치면 왕복, 벽 밖, 반사와 유리 공존, 부착점, 바닥 뜸, 모형 외곽 오차를 검사한다. 다른 물체의 접점으로 크롭을 우회하는 경우와 근거 없는 모서리를 거부하는 회귀도 포함한다. 일부 정확한 합성 사례의 재투영 오차는 0.000001px 미만이었다. 이 결과를 AI 모서리 인식 성능으로 보고하지 않는다.

`tests/reconstruction-candidate-pipeline.test.ts`의 23개 검사는 합성 구조화 후보로 종류 충돌·공존·반사·중복·지지 형태·수동 입력·규격 경계·원본 불변성·보류 상태 일치를 검사한다. 사용자 추가 설비의 임시 범위로 오차를 만들지 않고 기존 후보의 원래 관측 범위는 유지하는 회귀도 포함한다. 실제 모델 평가와 분리한다. 기하 28개와 후보 23개, 합계 51개의 단위 검사 통과를 확인했다. 최종 임시 범위 수정 뒤에는 후보 23개·통합 7개·lab 6개, 합계 36개를 실행해 통과했고 담당 파일 lint와 전체 TypeScript 검사도 통과했다. 이 수는 서로 겹치는 검사를 다시 합산한 전체 테스트 수가 아니다.

모델 또는 사용자가 관측한 직선에서 소실점 제약을 계산한다. 원시 영상에서 별도의 자동 선분 검출기를 실행하는 경로는 아니다. 선분은 실제 사진 경계에서 관측돼야 하며, 선분 방향만으로 거리·스케일을 복원할 수는 없다. 모서리가 충분하지 않은 사진, 광각 렌즈/왜곡, 잘못된 방 치수, 실제 비직각 공간에서는 자동 기하를 보류할 수 있다. 독립 실측 카메라·실제 제품 치수 정답을 가진 자료에 대한 정밀 위치 정확도는 아직 검증하지 않았다. 후보 분석 모델이 모서리를 잘못 관측하면 수치 적합이 양호해도 실제 구도가 틀릴 수 있어 사용자 확인과 별도 사진 평가가 필요하다.

통합 회귀 `tests/reconstruction-pipeline-integration.test.ts` 7개는 실제 프로젝트 생성·실험실·메모리 저장소 코드에 추론/GPU 경계만 모의 처리해 기본 DeepLab 유지, 후보 null 시 보류, 원분석 복사, 공통 카메라·빈 After, 사용자 교정의 AI 재호출 없음, 다른 사진/치수 재사용 거부, 늦은 취소 결과 폐기를 검사한다. 이는 실제 모델 인식 평가가 아니다.

세면대 이외의 shape 관측은 현재 기본 모형에 shape 옵션으로 적용하지 않는다. 예를 들어 round 거울을 관측해도 현재 직사각 기본 거울을 원형 인식·생성 성공이라고 표시하지 않으며, shape 출처를 default로 기록하고 차이 확인 안내를 남긴다. 실제 거울 원판/프레임 변형의 구현은 별도다.

2026-09-13 코드 고정 뒤에는 이 문서만 보완했다. 실제 사진 36장 비교(개발 24장 / 최종 평가 12장), 마지막 UI 회귀와 Next.js·vinext 최종 빌드는 진행 중이며 위 단위 결과로 완료를 대신하지 않는다.
