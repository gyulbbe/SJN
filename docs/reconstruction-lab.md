## 목적과 엔진

같은 사진과 공간 크기로 **기존 분석**, **개선 후보**, **사용자 교정**을 구분하는 개발용 화면이다. 여러 사진은 독립된 케이스이며 같은 방의 여러 촬영 사진을 합치는 기능은 아니다. 일반 프로젝트의 기본 분석기를 후보로 바꾸지 않는다.

- **기존 분석:** 브라우저 DeepLab ADE20K, 관측·설치 규칙, 표준 모형.
- **개선 후보:** 기존 관측과 로컬 Qwen3-VL-4B-Instruct의 간결한 설비 관측을 검증한 뒤 중복·부품·기하·설치·모형을 처리한다. 모델의 정수 0–1000 박스는 검증 후 내부 0–1 좌표로 한 번 변환한다. 방 기하를 임의로 채우지 않으며 기존 관측의 유일한 설비 대응과 실제 평면 근거가 있을 때만 추정 위치를 재사용한다. 실제 로컬 엔진 연결을 확인했을 때만 실행할 수 있다.
- **사용자 교정:** 원래 모델 관측과 기존 분석을 재사용하고 확인한 종류·형태·개수·설치·위치로 별도 PNG를 만든다. AI를 다시 실행하지 않는다.

후보 사진은 이 PC의 개발 서버와 고정 로컬 Ollama에만 전달한다. 새 대형 모델을 사용자 브라우저에 내려받거나 사진·응답을 외부 서비스에 전송하지 않는다. 유료 API·배포는 하지 않는다. 연결과 모델 준비는 [파이프라인 설명](reconstruction-pipeline.md), [감사 기록](reconstruction-pipeline-audit.md)을 참고한다. 엔진 연결 성공은 인식 품질 검증 또는 기본 분석기 채택을 뜻하지 않는다.

## 사용 순서

1. 사진을 선택하거나 끌어 놓는다. 최대 20개, 합계 200MB, 개별 25MB·40MP다. JPG/PNG/WebP의 실제 바이트와 치수를 확인하고, 선택 직후 읽은 바이트로 메모리 파일을 만든다.
2. 가로·깊이·높이를 입력한다. 기본값은 각각 2.4m다. 가능하면 결과를 보기 전에 **사용자 정답 설비**와 메모를 기록하고 **정답 고정**을 누른다. 사진으로 알 수 없는 설치 벽·형태·개수는 **모름**으로 둔다.
3. **기존 분석 실행** 또는 **기존 분석 전체 실행**으로 기준선을 만든다. 연결된 엔진의 **개선 후보 실행**을 누르면 호환되는 기존 분석이 있는지 먼저 확인한다. 전체 실행은 한 케이스씩 처리하고 실제 단계·경과 시간·취소를 제공한다.
4. 원본·기존·후보 세 열과 각 실행의 배치 상태를 비교한다. 모바일은 세로 배치다. 이미지를 눌러 확대하고, 실행 이력에서 이전 결과를 선택할 수 있다.
5. **관측 설비 → 종류·부품 관계 → 공간 기하 → 배치** 정보를 확인한다. 같은 물체 중복, 부품, 반사, 의미 오류, 종류 충돌은 서로 다른 상태다. 원출력·정리 후 검토 대상·실제 배치·확인 필요 수를 비교한다.
6. 후보의 **필드 확인 / 사용자 교정**에서 종류·지지 방식·설치 벽·볼 형태·볼 개수·실체 여부를 바꾼다. **선택값 확인**은 값이 같아도 사용자 확인 출처를 남긴다. 사진에 없는 항목은 **사진에 없는 설비 / 잘못 추가됨**으로 제외한다.
7. 위치가 보류됐으면 **위치·규격을 직접 지정**을 켜고 바닥/벽 그림을 누르거나 끌어 위치를 정한다. 바닥에서는 앞·왼쪽·오른쪽·뒤쪽 방향을 선택할 수 있다. 숫자로 하단 높이·규격을 보정할 수도 있다. 필요한 설비는 **교정 결과에 빠진 설비 추가**로 보완한다. 잘못된 `partOf`는 관계 목록의 **부품 연결 해제**를 누른 뒤 독립 설비의 설치 방식·위치를 확인한다. **연결 해제 취소**로 되돌릴 수 있다.
8. **확인값으로 교정 결과 생성**을 누른다. 자동 결과와 원문은 그대로 남고 새 교정 결과가 추가된다. 위치만 입력해 잘못된 종류·반사·부품 판단을 강제로 통과시키지는 않는다.
9. 엔진별/교정 PNG·JSON, 케이스 상세 또는 전체 보고서를 내려받는다. **새로고침·페이지 이탈 시 사진과 실행 기록이 사라지므로 먼저 다운로드한다.** PNG에는 확인 표시·패널·편집 도구가 포함되지 않는다.

모델 관측은 최대 24개, 사용자 교정 목록은 최대 64개다. 자동 관측 제한을 초과하는 생성과 수동 확인을 구분한다. 한도에 도달하면 잘못 추가된 설비를 제외하거나 케이스를 삭제해 공간을 확보한다.

## 완료와 배치 확인 필요

| 화면 상태 | 의미 |
|---|---|
| 분석 중 | 아직 이번 시도의 결과가 확정되지 않음 |
| 분석 완료 및 배치 완료 | 정리된 검토 대상이 모두 배치됨. 실제 치수·형태 정확도의 보증은 아님 |
| 분석 완료, 일부 배치 확인 필요 | 배치한 설비와 보류한 설비가 함께 있음 |
| 분석 완료, 전체 배치 확인 필요 | 관측은 남아 있지만 자동 배치는 없음 |
| 분석 완료, 설비 관측 없음 · 확인 필요 | 정리 후 독립 설비 후보가 없음 |
| 분석 실패 / 취소됨 | 실행 실패 또는 취소. 이전 결과와 실패 이력은 보존 |

**정리 후 검토 대상은 확정된 물리 설비 수가 아니다.** 중복·구성 부품·확인된 반사는 독립 수에서 제외하지만 충돌·미확인 관측은 확인 목록에 남긴다. 중복 10개를 10개 인식 성공으로 표시하지 않는다. 모두 보류된 빈 PNG를 정상 재구성으로 해석하지 않는다.

후보 한 개의 설치 의미가 잘못돼도 정상 후보는 남는다. 해당 항목의 오류 이유를 확인해 보정할 수 있다. 반면 JSON 손상·숫자 범위·중복 ID 등 응답 구조 자체가 잘못됐으면 임의로 복구하지 않고 분석 실패로 기록한다.

## 부품·형태와 간단한 보정

세면볼 형태는 사각/둥근 형태이며 지지는 벽걸이·기둥·하부장으로 구분한다. 전체 하부장 설비 하나 또는 `countertop` 세면볼+`vanity` 부모 관측을 표현할 수 있다. `partOf`의 앞 ID는 볼, 뒤 ID는 하부장이다. 연결된 볼은 별도의 바닥 제품으로 다시 배치하지 않는다.

볼 개수는 **모름/1개/2개**로 확인한다. 모델이 명시한 개수, 중복을 제거한 부품에서 계산한 수, 모형 기본값, 사용자의 확인은 별도 출처다. 하부장이 넓다는 이유로 두 볼을 관측했다고 기록하지 않는다. 서로 다른 형태의 두 볼은 현재 같은 형태의 볼 모형으로 자동 처리하지 않고 사용자 확인이 필요하다.

상판은 바닥 접점이 아니다. 잘못된 접점을 수정하려고 수동 위치를 켜면 이전 모델 접점을 제거하고 사용자 위치를 사용한다. 잘못 연결된 부품을 분리할 때는 연결만 해제하는 것으로 끝내지 말고 지지 방식·위치를 함께 확인한다. 현재 관계 UI는 기존 연결 해제/복구와 상판 세면볼의 부모 하부장 선택을 제공한다. 드로잉 방식의 복잡한 관계 편집기는 추가하지 않는다.

바닥 설비는 **벽 기준 거리로 배치**를 선택해 설치 벽·모서리에서 중심까지 거리·제품 뒤쪽과 벽의 간격을 mm로 입력할 수도 있다. 기본 규격에 근거한 임시 거리이며 직접 측정한 값과 구분한다. 깊이가 바뀌면 뒤쪽 간격을 유지하고 중심을 다시 계산한다.

수동 위치는 설치 면의 0–1 좌표다. 벽은 가로(u)·위에서 아래로 세로(v), 바닥은 가로(u)·뒤 벽에서 앞쪽으로 깊이(v)를 쓴다. 벽의 세로 위치와 하단 높이는 연동된다. 보류된 배치 제안이 있으면 해당 위치에서 보정을 시작하고, 없으면 임시 중앙값 0.5를 사용한다. 제안도 AI 확정 위치나 실측값이 아니다. 바닥 그림의 점은 모형 바닥 면의 중심이고 벽 그림의 점은 모형 하단 중앙이다. 왼쪽 벽의 가로 좌표는 앞쪽→뒤쪽, 오른쪽 벽은 뒤쪽→앞쪽이다. 방향키로 1%, Shift와 함께 10% 이동하며 터치도 지원한다. 벽 설비는 설치 벽 방향을 따르고 바닥 설비의 방향은 조정할 수 있다. 규격을 비우면 기본값을 쓴다.

관측하지 못한 제품 치수를 공간 크기에서 알아낸 것으로 표시하지 않는다. 거울에 원사진 반사 풍경을 붙이지 않으며 유리는 뒤쪽 타일·설비를 보여주는 반투명 모형이다. 실제 반사·굴절과 가려진 수납장 내부는 별도 한계로 남는다. 열린 변기 뚜껑은 기록된 DeepLab 조합 근거가 있을 때 규칙 추정하거나 설비 보정에서 사용자가 선택한다. 실험실 **변기 뚜껑**에서도 열림/닫힘을 선택하고 관측 결과·기본 모형 유지로 되돌릴 수 있다. 사용자 외형 보정은 `correctionSnapshot.input.toiletLidStates`에 따로 담는다. 단순히 모델 설명에 열림이 적혀 있다는 이유로 자동 확정하지 않는다. 복잡한 레이어·수동 마스크·다각형 편집은 추가하지 않는다.

## 비교 조건과 캐시

사진 바이트 SHA256, 공간 종류·버전·치수, 분석 처리 revision, 모델 revision, 코드와 실행 설정으로 호환성을 확인한다. Qwen 결과에는 prompt revision과 정확한 모델 digest도 포함한다. 파일명이 같아도 바이트나 치수·관련 처리 조건이 바뀌면 동일 캐시로 보지 않는다.

호환되는 기존 분석이 있으면 후보 실행에서 DeepLab을 다시 실행하지 않는다. **재사용 근거·실제로 실행한 단계**에서 캐시 키·원실행·새 실행 단계를 확인할 수 있다. 이번 실행 시간과 재사용 원본의 측정 시간은 따로 표시한다. 캐시는 이 페이지의 메모리 보고서 재사용이며 모델 파일의 브라우저 HTTP 캐시와 다른 개념이다.

이전 버전 보고서는 현재 자동 캐시로 섞지 않는다. 같은 사진·치수와 유효한 원래 관측이 있으면 **과거 결과의 사용자 교정**에는 쓸 수 있다. `historical-correction` 표시와 원래 모델·설정·원실행 ID·시간을 유지하고, 현재 모델이 새로 분석한 결과로 집계하지 않는다. 손상된 교정 자료를 발견해도 AI를 몰래 다시 실행하지 않는다.

실행 이력과 PNG는 다시 실행해도 덮어쓰지 않는다. 치수를 바꾸면 이전 조건은 기록에 남고 **저장된 비교 조건**으로 돌아갈 수 있다. 원사진 촬영 카메라와 Before/After 공통 카메라는 별도이므로 원사진과 표준 공간의 구도가 정확히 같다는 보장은 없다.

정답 항목·누락/오탐 메모는 AI 관측과 독립적이다. 각 실행은 시작 당시 정답 revision과 고정 시각을 복사한다. 결과를 보고 수정한 정답이나 사용자 교정 결과를 독립 AI 정확도 측정으로 취급하지 않는다.

## 실패·취소·저장

실패 보고서는 `failure`의 단계·분류·경과 시간, `completion`의 종료 여부·종료 사유·가능한 토큰 수·제한, 모델 원문과 런타임 오류를 보존한다. 길이 제한(`output-limit`)과 실행기 오류(`runtime-error`)를 구분한다. 손상된 런타임 JSON은 제한된 원응답을 남기고 정상 설비 목록으로 적용하지 않는다. 응답이 없어서 모르는 원문·토큰·시간은 추정해서 채우지 않는다. 화면에 나오는 원문은 텍스트이며 코드로 실행하지 않는다.

`attempts`에는 종료된 시도들이 쌓이고, 현재 진행 중인 시도의 시간·단계는 별도 `attempt`에 들어간다. 따라서 이전 실패 이력과 현재 `running`이 함께 있는 보고서는 재시도 중일 수 있다. 종료된 이전 시도와 내보내기 시점의 현재 시도를 구분하며, 현재 재시도의 결과가 없으면 성공·실패를 단정하지 않는다.

실험은 임시 메모리 저장소를 사용한다. 일반 프로젝트·불변 자재·IndexedDB·시안·자재비를 수정하지 않는다. 프로젝트를 만들거나 원본·합성 사진을 서버 자산으로 업로드하지 않는다. 개인 사진·원문 진단·다운로드 보고서는 비공개로 관리하고 공개 저장소에 추가하지 않는다.

새 기존 분석에는 전용 DeepLab Worker를 사용하며 완료·실패·취소 때 정리한다. 호환되는 관측을 재사용하면 Worker를 새로 만들지 않는다. 모델 파일 HTTP 캐시는 브라우저 정책을 따르며 케이스 사이에 전용 Worker의 모델 메모리를 계속 유지하지 않는다. 전용 분석 제한 시간은 15분이다.

동시 시작을 막고 삭제·전체 비우기·페이지 이탈 때 취소한다. 취소 불가능한 이미지 처리 단계는 끝난 뒤 결과를 버린다. 늦은 모델 응답이 다른 케이스를 덮어쓰지 않으며 렌더러는 `finally`에서 해제한다. 이력 이미지 URL은 이전 결과 조회를 위해 유지하다 케이스 삭제·전체 비우기·페이지 이탈 때 해제한다. 로컬 모델 해제 실패는 새 추론을 막고 **연결 다시 확인**으로 해제 여부를 다시 검사한다.

## 보고서와 측정 범위

| 필드 | 의미 |
|---|---|
| `runId`, `startedAt`, `engineMetadata` | 실행 식별·시각·엔진·실제 모델 revision/설정 |
| `inputFingerprint`, `input`, `room` | 바이트 지문, 원본/미리보기/분석 입력 크기와 공간 치수 |
| `execution` | 완료/보류 구분, 원출력·정리 후 검토 대상·배치·확인 필요 수 |

| `pipeline.model` | 원문, `outputContract`, 종료 진단, 실제 모델 측정·설정 |
| `pipeline.placements[].baselineEvidence` | 기존 위치 근거를 재사용한 경우 원후보·평면·접점·가정. 모델이 직접 관측한 벽이나 실측 위치가 아님 |

```powershell
$env:SJN_LAB_TEST_PHOTO = '로컬 욕실 사진.jpg'
npx playwright test e2e/reconstruction-lab.spec.ts
```

```powershell
$env:SJN_LAB_CANDIDATE_UI = '1'

npx playwright test e2e/reconstruction-pipeline-lab.spec.ts --grep 'actual local candidate'
```

저장한 실제 24개 후보 보고서의 AI 없는 교정 회귀:

```powershell
$env:SJN_LAB_REUSE_REPORT = 'actual-automatic-report.json의 절대 경로'
$env:SJN_LAB_CANDIDATE_PHOTO = '해당 보고서와 동일한 원본 사진.jpg'

```

보고서 파일은 해당 테스트가 저장한 케이스 형식(`runs[].analysis`)이다. 같은 사진의 바이트와 공간 치수가 맞아야 재사용할 수 있다. 모델 평가 시간 측정과 브라우저 검사를 동시에 실행하지 않는다. 개인 사진·결과는 Git에서 제외되는 `test-results` 안에 보관한다.


## 설치 보정과 경계 진단 보강

보류된 모형 검증에 `proposedPlacement`, `worldBoundsMm`, 방향별 `overflowMm`를 남긴다. 제안이 검증에서 실패하면 장면에 배치하지 않으며, 화면에는 초과한 벽·바닥·천장과 mm 값을 표시한다. 이전 보고서에 이 항목이 없으면 추정해 채우지 않는다. 숫자 자체가 유효하지 않은 모형에는 가짜 경계값을 넣지 않는다.

규격을 비우면 기본값을 유지하고 위치만 바꾸어도 기본 규격이 사용자 입력으로 바뀌지 않는다. 새 모형의 `provenance.width/height/depth`가 개별 규격 출처이며 기존 `dimensions`는 호환용 요약이다. 일부 규격만 입력하면 사용자 값과 기본값이 섞여 있다는 안내를 표시한다.

부분 후면벽은 기존 세 벽 전체 추정이 실패한 경우에만 천장선·좌우 벽 이음선·벽과 바닥의 접합선을 함께 검사한다. 가려진 코너는 관측선의 교차 추정으로 기록하며 카메라가 복원된 것으로 승격하지 않는다. 관측 근거는 `geometryEvidence`에 보존한다. 자동 배치 품질은 별도의 실제 사진 평가 결과로 판단한다.
