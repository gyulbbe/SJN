# 앱 그림의 빛 개선: 흰 유광 타일에서도 줄눈·무늬가 보이게 (2026-11-14~)

타일 시험([결과](tile-ai-trials-20261113.md))의 사용자 글 "빛이 너무 쨍해서 앱 그림에서도 줄이 잘 안 보인다, 이거 먼저 개선"에 따른 작업이다. AI는 부르지 않는다(3라운드의 AI 확인은 사용자가 원할 때만).

## 1. 사용자 결정

| 질문 | 결정 |
| --- | --- |
| 무엇을 | 앱 그림의 빛 개선 계획(11-14, "빛 개선 계획 세워줘"), 계획 승인 |
| 범위 | 3D 렌더러(AI 입력·둘러보기·벽 구조 장면)와 2D 합성(기본 방 편집 화면·다운로드) |
| 바꾸지 않는 것 | 11-05 결정 "작게 보일 때 타일 그림 속 줄무늬는 실제처럼 곱게(밉맵 −0.25)" |
| main 반영 | 끝나고 묻는다 |
| 3D 그림 | **B: 줄눈 최소 1px + 고른 빛**(그림을 보고 고름, 2라운드) |
| 2D 그림 | **줄눈 최소 1px**, 빛은 그대로 |
| 기준 2번 | 고친다(아래 2절, 사용자 승인) |
| AI 확인 | 한다(장면 8 × 1장, 약 880뉴런) |

## 2. 기준 (후보 결과를 보기 전에 적음)

결과를 본 뒤 낮추지 않는다. 바꿀 때는 이유를 적고 사용자에게 묻는다.

1. **줄이 보이는 정도:** 흰 유광(`scored`)·흰 무광(`white`)·엇갈림(`subway`) 벽에서 "면 안의 세밀한 밝기 차"(밝기와 그 3px 흐림의 차의 평균, 줄눈·무늬가 만드는 것)가 지금보다 **1.5배 이상**. 3D AI 캡처와 2D 편집 화면 크기 둘 다.
2. **잘림:** 2D 편집 화면·다운로드에서 흰 타일 벽(`scored`, `white`)의 254 이상 픽셀이 0.5% 이하.
   - **고침(11-14, 사용자 승인):** "타일 그림 자체의 254 이상 비율 + 0.5%포인트 이하"(그림보다 더 하얗게 잘리지 않는다).
   - 까닭: `scored`(HS 3654)는 타일 그림의 90.3%가 이미 순백(254 이상)이다. 지금 2D 그림은 벽의 약 40%만 255라 그림보다 더 잘리지 않는다. 처음 기준을 넘으려면 흰 타일을 일부러 어둡게 그려야 했고, 그렇게 한 후보(D1b)는 줄 보임이 0.6배로 떨어지고 색이 1.2 멀어졌다.
3. **색:** 벽 가운데 색(중앙값)의 ΔE2000(타일 그림의 평균색 대비)이 지금보다 1.0 넘게 나빠지지 않는다. 어두운 타일(`charcoal`)은 더 밝아지거나(평균 2 넘게) 색이 0.3 넘게 멀어지지 않는다.
4. **바뀌면 안 되는 것:** 타일 크기·배치·줄눈 위치·자재 색, 제품 모양. 바뀌는 것은 빛·반사·줄눈 굵기 표현뿐이다.
5. 위를 넘은 후보 중에서 사용자가 그림을 보고 고른다.

## 7. 앱에 넣은 것

- [tile-atlas.ts](../src/lib/render/tile-atlas.ts): `TILE_JOINT_MIN_PX = 1`, 타일이 화면에서 3px 이하면 지금처럼(물리 평균), 6px 이상이면 줄눈을 최소 1px로 그린다(사이는 서서히). 2D·3D 셰이더가 같은 `sjnJointWidth`를 쓴다. 줄눈 위치와 타일 그림은 그대로다.
- [realistic-lighting.ts](../src/lib/render/realistic-lighting.ts): 천장 조명 0.44 → 0.32, 반사광 0.58 → 0.66. 2D 표준 모형 조명(`createModelLights`)은 예전 반사광 0.58을 그대로 쓴다(2D 빛은 바꾸지 않음).
- 렌더 버전: `ROOM_VIEWER_RENDERER_REVISION` `room-view-v13-ledge-join` → `room-view-v14-light`, `DESIGN_RENDER_REVISION` 4 → 5.
  - 3D 시안 카드와 2D 시안 미리보기(IndexedDB) 캐시를 새로 만든다.
  - 부작용(09-25·11-05와 같음): 프로젝트가 다시 저장될 때까지 프로젝트 목록 조회 때 프로젝트마다 R2 문서를 한 번씩 읽는다(`PROJECT_SUMMARY_PREVIEW_REVISION`에 렌더 버전이 들어간다).
- 바꾸지 않은 것: 타일 그림 속 가는 선(11-05 "실제처럼 곱게"), 톤 곡선, 유광 반사, 2D 빛, 사진 효과, 저장 형식·D1·API.
- 앱 코드로 다시 재 보니(`app`) 1라운드의 B와 같은 숫자였다. 기준 1~4(2번은 고친 기준) 모두 통과.

## 8. 3라운드 — AI 확인 (2026-11-14 UTC, 두 번째 계정)

- 타일 시험의 개발 장면 8개를 새 렌더러로 다시 그려(`test-results/tile-ai-20261113/scenes-light/`, 시험의 원래 장면은 그대로) 지금 방식으로 seed 424242 한 장씩 불렀다. 8장 모두 200, 추정 877뉴런(타일 시험 장부에 함께 적음).
- 같은 장면·seed의 이전 결과와 나란히 봤다(장면마다 1장이라 참고용):
  - `subway` 엇갈림: 이전 그림에서는 AI가 민무늬로 그렸는데, 새 그림에서는 벽돌 배열을 그대로 그렸다.
  - `large` 600×1,200: 새 그림에서 세로 줄눈이 더 분명히 나왔다.
  - `scored`·`charcoal`·`accent`·`marble`: 타일 크기·배열은 이전처럼 맞고 줄눈이 더 또렷하다.
  - 유리 칸막이(물건 추가)는 이전 그림의 `patchwork`, 새 그림의 `patchwork`·`beige`에 생겼다. `patchwork` 새 결과는 세면대를 어두운 금속처럼 그렸다.
  - 지난 시험의 "줄눈 굵게"(입력 1.25px, 줄눈이 너무 굵다는 평가)와 달리 이번 줄눈은 입력에서 약 0.5px라 굵어 보이지 않았다.
- 줄눈 되돌리기는 새 앱 그림의 줄눈을 쓰므로 되돌린 면의 줄눈도 더 또렷해졌다.
- 그림: `test-results/light-tuning/sheets/ai-a.png`, `ai-b.png`

## 10. 한계와 남은 것

- **SMC 천장 조명을 끈 방:** 2D의 "조명 끔" 밝기(`CEILING_LIGHT_OFF_LEVEL` 0.53)는 3D의 끔/켬 비율을 재서 정한 값이다. 3D 빛이 바뀌어 이 비율이 0.65가 됐다(`smc-ceiling-browser.ts`). 2D 빛은 그대로 두기로 해서 값을 바꾸지 않았다. 조명을 끈 SMC 천장 방은 2D가 3D보다 조금 어둡다.
- 다운로드(2D 4,096px, 3D 사진 효과)는 줄눈이 이미 1px 이상이라 거의 바뀌지 않는다.
- 줄눈을 1px로 그리는 것은 실제 사진보다 줄눈이 조금 또렷하다는 뜻이다(사용자가 그림을 보고 골랐다).
- 타일 그림 속 가는 선은 작게 보일 때 지금처럼 옅다(11-05 결정).
- AI 확인은 장면마다 한 장이라 경향만 본 것이다.
