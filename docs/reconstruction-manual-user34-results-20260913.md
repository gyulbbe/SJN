# user03·04 저장 관측으로 수행한 실제 보정 UI 검사

2026-09-13. 코어 모델·분석·기하 코드는 변경하지 않았다. `tests/reconstruction-manual-user34-browser.ts`는 실제 `ReconstructionLab`을 독립 localhost에 표시한다. 최초 기준선·후보 실행 두 번만 기존 `after-partial-wall` 보고서/PNG로 재생한다. 이후 **확인값으로 교정 결과 생성**은 실제 앱 함수·입력 스냅샷·표준 렌더러를 사용한다. 이 첫 결과 재생을 새 모델 실행 성공으로 계산하지 않는다.

## 입력과 출처

- 실제 원관측: `test-results/user-reconstruction-improvement-20260913/after-partial-wall/user-03|04/candidate.json`, `baseline.json`
- 같은 입력: `inputs/user-03.jpg`, `inputs/user-04.jpg`. 파일 SHA256가 보고서 `inputFingerprint`와 일치한다.
- 시나리오: `test-results/reconstruction-manual-scenarios-20260913/scenarios.json`
- 최종 결과: `test-results/reconstruction-manual-ui-user03-04/run-04/`
- 비교 화면: 위 폴더의 `comparison.html`, 각 사진 폴더의 `comparison.png`
- 실제 출력·기록: 각 사진 폴더의 `corrected.png`, `corrected.json`, `records.json`, `verification.json`

각 기록은 원본과 후보 관측, 실제 수동 입력, 원출처와 보정 출처를 구분한다. 기본 2400×2400×2400mm 방과 모형 규격은 실측이 아니다. 아래 위치는 사진의 설치 관계를 확인하기 위해 평가자가 사용자 역할로 입력한 임시 값이다. 사진 정답 좌표를 의미하지 않는다.

## user03: 사각 기둥 세면대·열린 잘린 변기·거울·샤워 유리

기존 모델 관측은 세면대 `pedestal + rectangular + bowlCount=1`을 이미 제공했다. 이 세 필드는 수정하지 않고 보존했다. 잘린 변기 바닥 접점을 사진 bbox 하단에서 계산하지 않고 사용자 벽 기준 거리로 새 위치를 지정했다.

| 대상 | UI에서 지정한 값 | 결과 |
|---|---|---|
| 변기 item_01 | 왼쪽 벽, 벽을 따라 중심 1850mm, 뒤쪽 간격 50mm, 뚜껑 open | 생성. 뚜껑·설치 출처 user, 규격 default |
| 세면대 item_02 | 왼쪽 벽, 중심 1000mm, 뒤쪽 간격 40mm | 사각 기둥형 1볼 생성. 기존 형태/개수 관측 유지 |
| 잘린 거울 item_03 | 왼쪽 벽, u=1000/2400, 하단 1300mm | 은회색 표준 거울 생성. 사진 반사 풍경을 붙이지 않음 |
| 유리 item_04 | 바닥 면 u=0.65, v=0.34, 방향 0°, 샤워 턱 임시 하단 100mm | **보류**. 바닥 설치 제품 하단이 바닥에 닿지 않는다는 진단 |

핵심 설비 **3/4만 표현**됐다. 유리를 하단 0mm로 내려서 성공 수를 채우지 않았다. 샤워 턱/욕조 테두리 같은 별도 지지 높이는 현재 보정 파이프라인의 바닥 접지 규칙과 연결되지 않는 한계다. 별도 `unknown item_05` 수전 관측도 원본 목록에 유지하며 지원 설비로 강제 변경하지 않았다.

PNG에서 기둥형과 열린 변기·거울은 보이나 기본 카메라에서는 앞쪽 변기가 세면대 기둥 일부를 가린다. 임시 배치이며 원본 촬영 구도와 동일하다고 판단하지 않는다. 상단에서 잘린 거울의 전체 외곽도 기본 모형 추정이다.

| 하부장 item_04 | 형태 round, 왼쪽 벽, 중심 1200mm, 뒤쪽 간격 50mm | 둥근 볼 2개의 하부장 1개 생성 |

핵심 설비 **4/4가 보정 결과에 표현**됐다. 기존 후보 `bowlCount=2`는 model 출처를 유지하고 볼 형태만 user로 수정했다. 사각 하부장 몸체와 둥근 볼을 독립적으로 표현했다. 개별 볼 후보를 추가하거나 두 볼을 새로 검출했다고 보고하지 않는다.

물리 거울은 하나이고 거울 내부 반사·휴지통·가장자리 조각을 별도 설비로 늘리지 않았다. 원 `rawReview`와 모델 원문/자동 이해는 바뀌지 않았다. 거울의 둥근 상단, 창의 정확한 분할, 제품 치수·촬영 카메라·조명까지 일치하는 결과는 아니다. 별도 부품 두 개 추가/연결 시나리오는 이번 full Lab 최소 보정 경로에서 실행하지 않았다.

## 실제 기능 검사

Windows 10, Headless Chrome 152, SwiftShader 소프트웨어 WebGL. 실제 모델 Worker 시작을 차단했고 각 사진에서 Worker 0·AI POST 0·IndexedDB open 0을 확인했다. 프로젝트/자재에 영구 저장하지 않는 랩 모드다. 원본 사진은 외부로 전송하지 않았다.

- 기존 기준선/후보 보고서 두 개를 원 파일과 깊게 비교해 불변 확인.
- 실제 교정 결과의 `automaticUnderstanding`, 모델 `rawText` 불변.
- 수동 입력이 없는 width/height/depth는 모든 생성 모형에서 `default` 유지.
- user03 사각 1볼 관측 유지, user04 둥근 형태 user와 볼 2개 model 구분.
- 뚜껑 open user 출처와 적용 당시 `toiletLidStates` 입력 보존.
- PNG 다운로드가 화면에서 표시한 Blob과 SHA256 일치. 별도 패널·선택 핸들이 포함되지 않는 실제 렌더 PNG를 육안 확인.
- 적용 후 편집 칸의 볼 형태를 다시 변경하고 **이 교정 입력을 편집 칸에 복원**을 눌러 이전 값을 복원. 완료 스냅샷은 불변.
- 내려받은 상세 JSON/교정 JSON에 원실행과 완료 입력이 모두 보존됨. 새로고침 후 랩의 사진 목록을 영구 복원하는 기능은 이 검사 범위가 아니며 랩 자체는 메모리 모드다. 여기서 프로젝트 저장/재진입 통과를 주장하지 않는다.

실제 교정 구간은 user03 2.838초(PNG 1.708초), user04 3.025초(PNG 1.853초). 두 경우 기존 분석·추가 모델 시간은 0이다. 전체 자동 UI 순서는 각각 약 7.831초/6.965초이며 사람이 보정하는 데 필요한 시간 측정이 아니다. 입력/버튼 로그 32/27개는 하네스가 기록한 작업 이벤트이고, 펼치기 등을 포함한 완전한 인간 클릭 수로 쓰지 않는다. 다른 루트 검증 작업과 같은 PC를 사용한 조건이다.

## 재시도와 제한

초기 `user-03|04/failure.json`은 독립 esbuild 하네스에서 Next Image의 CJS 기본 export 연결 오류였다. Next의 실제 named Image export를 사용하는 하네스 어댑터로 해결했다. `run-02`는 테스트가 빈 `open` 속성을 닫힘으로 오판해 details를 닫은 오류였으며, 앱 코드를 수정하지 않고 테스트만 고쳤다.

`run-03`에서는 하부장 종류(`kind=vanity`)에 테스트가 세면대 전용 `basinStyle=vanity`를 추가해 의미 충돌로 보류됐다. `run-04`는 해당 전용 속성을 원래 unknown으로 유지하고 볼 형태·배치만 수정해 완료했다. 이전 자료를 덮어쓰거나 이 재시도를 숨기지 않았다. 현재 필드 편집 UI가 하부장에도 세면대 전용 지지 구조를 노출하는 점은 혼동 소지가 있다.

최종 브라우저 검사 exit 0, 담당 ESLint 통과. 전체 타입 검사는 동시 빌드 중 `.next/types`의 생성된 route export 오류로 종료됐고 생성파일을 수정하지 않았다. 최종 타입/빌드는 루트 검증 결과를 따른다.

```powershell
$env:SJN_MANUAL34_OUTPUT='test-results/reconstruction-manual-ui-user03-04/new-run'
node tests/run-browser-test.mjs tests/reconstruction-manual-user34-browser.ts
```

하네스는 개인 저장 보고서가 있어야 실행된다. 처음 두 실행의 모델 응답을 생성하거나 흉내 내지 않고 파일에 보존한 실제 결과를 재생한다. 이 UI 검사와 새로운 모델 품질 평가는 분리한다.
