# 위생도기 종류 칩: 마우스로 넘기기 · 문·창 빼기 · 관리자가 종류 관리 · 2026-10-28

- **사용자 보고:** 편집 화면의 위생도기 탭에서 칩 줄이 "…샤워 설비 수"에서 잘렸고, 오른쪽으로 넘길 수 없었다(`test-results/fixture-kinds/user-report/chips-cut-off.png`).
- **요청**
  - 마우스를 줄 끝 근처에 대면 그쪽으로 움직이게 한다.
  - 위생도기 종류를 관리자가 등록·관리하게 한다.
  - 목록에서 문·창을 뺀다.
- **원격 D1:** 쓰지 않았다. 읽기는 승인받은 SELECT 1회뿐이다(3절).
- **migration 0012:** 원격 적용은 사용자가 한다. **병합 전에 적용해야 한다**(4절).

## 1. 왜 못 넘겼나 (실제 크롬, 고치기 전)
Playwright `channel:'chrome'`(Windows)으로 편집 화면 위생도기 칩 줄을 시험했다. 줄은 227px, 내용은 1,079px이다.

| 동작 | scrollLeft |
| --- | --- |
| 마우스 휠(세로 120) | 0 → 120 (움직임) |
| 가로 휠·터치패드(가로 120) | 0 → 120 (움직임) |
| 칩을 누른 채 왼쪽으로 끌기 | 0 (안 움직임) |
| 오른쪽 끝에 마우스를 1초 대기 | 0 (안 움직임) |

- 휠로는 넘어갔다. 하지만 화면에 휠을 알리는 표시가 없다.
- 사용자가 기대한 끌기나 가장자리 hover로는 움직이지 않았다. 그래서 넘길 수 없다고 느꼈을 것으로 본다.

## 2. 사용자 결정
| 질문 | 결정 |
| --- | --- |
| Q1 새 종류의 동작 | 기타와 똑같이: 사진으로만 배치, 하위 카테고리·표준 모형·AI 방향 사진 없음, AI 내보내기 문장에서 빠짐(그림은 그대로) |
| Q2 기본 종류에서 바꿀 수 있는 것 | 표시 순서와 사용(숨김)만. 이름은 고정이고, 기타는 늘 마지막 |
| Q3 숨기기·지우기 | 숨기면 칩과 양식에서만 사라지고 '전체'와 기존 프로젝트에는 남는다. 지우기는 자재가 없는 새 종류만 |
| Q4 문·창 자재 | 그대로 둔다 |

## 3. 화면
- **칩 줄 가장자리 hover**(`src/components/editor/fixture-kind-chips.tsx`)
  - 마우스가 줄 끝 48px 안에 있고 그쪽에 칩이 더 있으면, 그쪽으로 계속 움직인다.
  - 끝에 가까울수록 빠르다(프레임당 1~10px, `requestAnimationFrame`).
  - 멈추는 때: 영역을 벗어날 때, 끝에 닿을 때, 버튼을 누를 때(누른 자리의 칩이 골라진다)
  - 마우스이고 hover가 되는 장치(`(hover: hover) and (pointer: fine)`)에서만 움직인다.
  - 그대로 둔 것: 터치·펜 밀기, 휠, 포커스, 고른 칩 보이기, 흐린 가장자리, 줄 높이와 자리
  - 움직이는 동안 서버 요청은 0회다.
- **문·창**
  - 고르는 목록에서 뺐다(샤워 커튼과 같은 방식). 타입, 저장 값, 사진 분석 표준 모형 종류는 그대로다.
  - 운영 문·창 자재(승인받은 SELECT, 읽기 4,611행, 쓰기 0): 창 2개뿐이고 둘 다 사진 분석 표준 모형(class 6, 개인, 목록에 안 보임)이다. 라이브러리 자재는 0개다.
- **위생도기 종류 관리**(분류 관리 → 종류 "위생도기 종류")
  - 새 종류 만들기: 이름, 표시 순서(빈칸 가능), 사용
  - 기본 종류: 이름 칸이 잠기고 "기본"으로 표시된다. 기타는 순서 칸이 없고 늘 마지막이다.
  - 표에는 구분(기본·추가), 순서, 상태(사용·숨김)를 보이고, 자재가 없는 새 종류에는 삭제 버튼을 둔다.
- **종류 목록을 쓰는 곳**
  - 편집기 칩, 공개 자재 종류 선택, 등록 양식, 관리자 자재 탭, 게스트 서랍
  - 숨긴 종류는 빠진다. 단, 양식은 그 자재에 저장된 종류를 계속 보인다(숨긴 종류, 문·창·샤워 커튼).
  - 카드·상세의 종류 이름은 목록의 이름이다. 모르는 새 종류는 '기타'로 보인다.

## 4. DB: migration 0012 (`migrations/d1/0012_material_kinds.sql`)
- **새 표 `d1_material_kinds`**
  - 열: `code` PK, `name`, `normalized_name` UNIQUE, `display_order`(NULL 또는 0~9999), `active`, `builtin`, `created_at`, `updated_at`
  - 기본 13행을 지금 순서로 넣는다: 변기~낮은 칸막이는 0~11, 기타는 NULL.
  - 타일·문·창·샤워 커튼은 넣지 않는다.
- **새 종류 코드:** `k-` + 무작위 10자(소문자·숫자)이고, 자재의 `category`에 저장한다.
  - 기존 자재와 목록 요약은 다시 쓰지 않는다(백필 없음).
  - 0009 트리거가 이미 타일이 아닌 종류를 위생도기 칸에 넣고, `category=?`로 거른다.
- **부분 인덱스 `d1_versions_added_kind`**
  - `d1_material_versions(category) WHERE substr(category,1,2)='k-'`
  - 새 종류를 지우기 전에 그 종류의 자재(모든 버전, 개인·공용, 사용 여부 무관)가 있는지 본다.
  - 목록 요약의 카테고리 인덱스는 현재 공용 행만 담는 부분 인덱스라 이 확인에 쓸 수 없다.
  - 만들 때는 비어 있다. 그 뒤에는 새 종류 자재의 버전마다 1행이다.
- **준비 검사**(`src/lib/d1/database.ts`): 새 표와 인덱스가 없으면 저장소 준비가 실패한다.
- **0012 전에 서버가 이 표를 읽는 경우:** 종류 목록은 기본 고정 목록으로 대신한다(`no such table`만 잡음).

### 원격 적용 (사용자가 한다, 병합 전)
```bash
npx wrangler d1 migrations apply sjn --remote   # 목록에 0012_material_kinds.sql 하나만 있어야 함
npx wrangler d1 migrations list sjn --remote    # No migrations to apply 확인
```
- 순서: **원격에 0012 적용 → main 병합·푸시.** 반대로 하면 배포 직후 준비 검사가 표를 찾지 못해 저장소가 막힌다.
- 비용(시험 DB): 쿼리 3, 읽기 5행, **쓰기 44행**(13행과 그 인덱스, 빈 부분 인덱스)이다. 운영에 `k-` 자재는 없으므로 같다.

## 5. 서버와 API
- `readKinds`
  - 종류 전부(숨긴 것 포함)를 순서대로 읽는다: 기타 마지막, 표시 순서, 이름.
  - 13~20행의 작은 표라 통째로 읽는다.
- **응답에 싣는 곳(화면 요청 수는 그대로)**
  - 분류 목록(`/api/d1/catalog` list, `readCatalog`)
  - 목록 첫 쪽(`options`가 있을 때, 회원 `page`·게스트 `/api/catalog/placement`·공개 `/api/catalog/materials`)
  - 관리자 자재 첫 쪽(`counts`와 함께)
  - 화면은 받은 목록을 탭 안 저장소(`useMaterialKinds`)에 두고 칩·선택·이름에 쓴다.
- **분류 관리 `kind:'materialKind'`**(관리자만)
  - 만들기 / 수정(`code`) / 지우기(`operation:'delete'`)
  - 이름이 다른 종류나 타일·문·창·샤워 커튼과 같으면 409다.
  - 기본 종류의 이름을 바꾸려 하면 400이다.
  - 자재가 있는 종류를 지우려 하면 409다. 커밋 batch에서 한 번 더 확인한다.
  - 기본 종류를 지우려 하면 400이다.
  - 새 종류는 하위 카테고리의 상위가 될 수 없다(0003 CHECK).
- **자재 저장 검사**
  - 관리 대상 종류는 사용 중이어야 한다. 그 자재가 이미 가진 종류면 숨겼어도 수정할 수 있다.
  - 타일·문·창·샤워 커튼은 예전처럼 통과한다.
  - 저장 검사의 `resolveCatalogInput`이 이미 부르던 `readCatalog`에 종류 목록이 실려서, 따로 요청하지 않는다.
- **새 종류의 동작**: 동작을 정하는 곳은 `kindBehavior()`(`src/lib/material-kinds.ts`)로 기타가 된다. 다음 동작이 모두 기타와 같다.
  - 제품 사진 문구의 영어 이름
  - 정면 문장
  - 방향 사진 추천
  - 견적 단위
  - 시작 크기(표준 모형 없음)
  - AI 내보내기(종류 목록에 없어 문장에서 빠짐)
  - `=== 'toilet'` 같은 기존 분기는 새 코드가 어느 것과도 같지 않아 바꾸지 않았다.
