# 자재 수량·금액 패널

2026-09-07 구현. 기존 견적서 작성·인쇄/PDF 화면을 제거하고 편집기 오른쪽에서 현재 시안의 **After**에 적용한 자재만 계산합니다. 프로젝트당 시안 생성·복제는 최대 5개, 동시 비교도 최대 5개입니다. 이전에 저장된 초과 시안의 보존 정책은 유지합니다.

## 사용 방법

1. 자재 등록에서 타일 규격, 판매 단위와 단가를 입력합니다. 타일은 박스·장·㎡, 제품은 개 단위입니다. 단가·포장 정보 없이도 등록할 수 있습니다. 0원은 명시적인 가격이며 빈 단가와 다릅니다.
2. 타일이나 제품을 적용하면 **시안 A의 사용 자재**에 상품 이미지·이름·모델·규격·위치·면적/개수·구매 수량·단가·금액이 나타납니다. 모두 제거하면 항목도 사라집니다.
3. 면별 면적을 직접 입력할 수 있습니다. 기본 공간은 설정 치수로 계산하며 직접 입력하면 수동 면적으로 바뀝니다. 근거가 있는 면은 **공간 기준**으로 되돌릴 수 있습니다. 사진 픽셀이나 자동 추정 원근을 구매 면적으로 환산하지 않습니다.
4. 타일 수량은 자동 계산하거나 **수동으로** 고정합니다. 수동 수량은 면적이 바뀌어도 유지되며 새 자동 계산값을 함께 보여줍니다. 제품 수량은 실제 After 배치 개수이므로 가격 계산용 숫자를 따로 수정하지 않습니다.
5. 유효한 숫자는 Enter/포커스 이동으로 한 번 확정하고 시안 복사·전환 전에 확정합니다. 음수·NaN·무한대·소수 박스/장·범위 초과는 거부하며 Escape로 입력을 되돌립니다. 수정은 해당 시안의 실행 취소·다시 실행에 포함됩니다.
6. **최신 단가 적용**에서 현재 시안과 최신 등록값을 비교한 뒤 적용합니다. 이미지와 배치는 그대로입니다. 판매 단위가 달라지면 수동 수량을 초기화하며, 규격·모델이 바뀌었으면 가격만 가져올 수 없습니다.
7. 비교 카드의 **자재 보기**는 해당 시안의 읽기 전용 상세를 엽니다. 확대·이동 포커스와 편집 중 시안은 바뀌지 않습니다. **이 시안 편집**으로 들어가 수정합니다. 작은 화면에서는 도구 막대의 **자재 수량·금액 및 속성**으로 드로어를 엽니다.

Before를 보고 있어도 패널은 현재 시안의 After를 집계합니다. 목록만 스크롤하며 합계는 하단에 고정됩니다. 기존 편집 속성은 접을 수 있는 영역에 있습니다. PNG/JPG·비교 PNG에는 금액, 패널, 선택 도구가 들어가지 않습니다.

## 계산 규칙

- 같은 불변 상품 버전·규격·판매 단위·단가·포장 조건의 타일은 면적부터 합칩니다. 상품명만 같은 다른 상품·규격은 합치지 않습니다.
- 박스는 `ceil(면적 / 박스면적)`, 장은 `ceil(면적 / (가로mm × 세로mm / 1,000,000))`, ㎡ 판매는 면적 그대로입니다. 올림에 부동소수점 오차 보정을 적용하며 면적은 표시할 때만 반올림합니다.
- **12㎡ / 1.44㎡ = 9박스**, **9 × 40,000원 = 360,000원**입니다. 박스당 4장이면 참고 36장·구매 면적 12.96㎡를 표시합니다.
- 박스당 등록 면적을 우선합니다. 없으면 규격×박스당 장수로 계산합니다. 등록값과 계산값 차이가 0.000001㎡를 넘으면 등록 화면에서 차이를 보여주고 등록 면적 사용을 확인받습니다.
- 전체 벽과 명확한 하위 밴드가 함께 있으면 하위 면적을 먼저 배정하고 전체 벽에는 나머지만 배정합니다. 불명확한 범위·충돌 면은 자동 면적을 보류합니다. 제품 가림·마스크 픽셀은 시공 면적에서 자동 차감하지 않습니다.
- 제품은 After의 배치 개수 × 개당 단가입니다. 이동·회전·가림·Before 전환으로 수량이 바뀌지 않습니다. 복제는 원본의 시안별 단가도 보존합니다.
- 판매 수량×판매 단가를 항목별 원 단위로 반올림하고 합산합니다. 세금·공임·배송비·추가비용·할인·자동 여유분은 계산하지 않습니다.
- 미입력 단가는 **계산 전**입니다. 모든 항목이 계산·확인 가능하면 **예상 자재비 합계**, 아니면 **확인된 자재비**, **미계산 자재 수**, **면적·포장 확인 필요 수**를 구분합니다. 면적·포장이 부족해도 유효한 수동 구매 수량과 단가가 있으면 그 금액은 포함하고 경고를 유지합니다.
- 가격 조건 변경으로 항목이 합쳐질 때 기존 수동 구매 수량을 보존합니다. 일부 면 삭제 등으로 수동 합계 수량을 분할할 수 없으면 재확인을 요구합니다. 타일을 완전히 제거한 뒤 새 자재를 적용하면 이전 수동 구매 수량을 재사용하지 않습니다.

타일 수량은 입력 면적 기준의 예상치입니다. 절단·배열·현장 여유분과 확정 발주 수량을 보장하는 기능은 아닙니다.

## 데이터와 복사 독립성

`DesignFrame.materialUsage?`에 다음 값을 저장합니다. 자동 수량·합계는 저장하지 않습니다.

- `assignments`: 면/제품 ID별 시각 상품 버전과 적용 가격·포장 스냅샷. 가격 출처 `sourceVersionId`는 시각 상품 버전과 별개입니다.
- `areas`: 면별 수동 면적. 값이 없으면 근거 있는 공간 치수에서 계산합니다.
- `quantities`: 연결 대상 집합별 수동 타일 구매 수량.
- `aggregateAreas`: 정확히 연결된 이전 견적의 여러 면 수동 총면적. 임의로 면별 분할하지 않고 연결 면 구성이 바뀌면 재확인합니다. 한 면을 새로 입력하면 나머지 면도 개별 확인하도록 안내합니다.
- `migratedQuoteId`: 이전 견적 이관 표시. 원본 `quote`는 보관하며 이후 편집에서 자동 변경하거나 새 합계에 사용하지 않습니다.

읽기 시 전체 시안·이력·공통 복원 백업을 메모리에서 전환합니다. 읽기만으로 저장하지 않고 정상 편집 후 기존 500ms 조건부 저장에 포함합니다. 정확한 상품 버전·판매 단위·연결 대상만 이관하며 제품의 이전 구매 수량과 견적의 세금·할인·추가 항목·자동 여유분은 제외합니다.

복사 시 모든 변경 가능한 데이터를 깊은 복사하고 면·제품 ID와 구매 수량 키·합계 면적 참조를 함께 변환합니다. 이미지와 불변 상품 버전은 공유합니다. 각 시안의 최근 50개 undo/redo 및 크기 변경 직전 전체 복원에도 자재 설정을 포함합니다. 공통 치수 변경은 자동 면적을 재계산하되 수동 면적·구매 수량·단가를 보존합니다.

`design.revision`과 `renderRevision`을 분리해 가격·수량 수정은 저장/이력만 변경하고 비교·목록 썸네일과 캔버스를 다시 합성하지 않습니다. 합성 이미지를 서버에 업로드하거나 AI를 호출하지 않습니다. 버전 참조 검사는 모든 시안·이력·공통 복원 백업의 시각 상품 버전과 가격 출처 버전까지 포함합니다.

실행 환경: Windows 11 Home, AMD Ryzen 7 7800X3D, Node.js 22.13.1, npm 10.9.2, Chrome 152.0.7977.76. 브라우저 테스트는 개인 데이터와 분리한 Playwright context에서 실행하며 WebGL은 재현 가능한 SwiftShader 설정을 사용합니다. 테스트 이미지는 직접 생성한 색상 타일/제품입니다.

- 전체 Vitest: **37개 파일, 341개 테스트 통과**. 새 순수 계산기 42개와 자재 상태·저장·공통 크기 회귀 테스트를 포함합니다. 양수 극소값도 구매 수량이 0으로 떨어지지 않는 경계값을 확인했습니다. 로그: `test-results/material-usage-unit-final.log`.
- TypeScript: 통과. ESLint: 경고/오류 없음.
- 전체 Playwright: 코드 변경을 멈춘 상태에서 **39개 테스트 모두 통과, 6.9분**. 로그는 `test-results/material-usage-full-browser.log`입니다. 자재 적용·가격/수량 수정·5개 비교·모바일·저장 실패·다중 탭·재진입·출력 및 기존 편집 회귀를 포함합니다.
- 프로덕션 빌드: **`npm run build` 통과**. Next.js 16.3.4 컴파일·TypeScript·9개 정적 페이지 생성 성공. 로그: `test-results/material-usage-build.log`.
- 경계값 보완 뒤 대표 360,000원 계산과 5개 비교 브라우저 테스트 **2개 추가 재실행 통과(27.6초)**. 5개 미리보기 로딩 완료 후 화면도 확인했습니다. 로그: `test-results/material-usage-detail-browser.log`.
