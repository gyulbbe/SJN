# 공간미리 핵심 화면 UI 개선 검증

확인일: 2026-09-18. 대상은 로컬 작업 트리의 UI 변경이며 운영 데이터 변경과 배포는 수행하지 않는다.

## 변경 내용

- 따뜻한 중립색 배경·흰 패널·민트 강조색을 공통 CSS 변수로 정리했다. 본문 14px, 편집기 라벨 13px, 보조 설명 12px을 기본으로 하고 금액은 숫자 폭을 맞췄다.
- 메인과 공개 자재 화면에 공통 탐색 메뉴를 적용했다. 기존에 제거한 상단 중복 메뉴는 복원하지 않았다. 큰 화면의 본문은 왼쪽 메뉴를 제외한 영역에 가운데 정렬하고 최대 너비를 제한한다.
- 620px 이하에서는 메뉴를 접어서 열며 일반 회원의 로그아웃과 관리자의 자재·분류·회원·전체 프로젝트 메뉴에 접근한다.
- 메인 시작 카드와 프로젝트 카드의 이미지·제목·날짜·작업 버튼을 정리하고, 프로젝트 로딩·빈 목록·검색 결과 없음과 검색 초기화를 구분했다.
- 공개 자재 전용 CSS를 분리했다. 검색·종류·개수·초기화, 로딩·빈 목록·검색 실패·연결 오류, 이미지 누락·로드 실패 대체 표시를 제공한다. 타일은 무늬를 채워 보여주고 제품은 전체 형태를 표시한다.
- 자재 상세 팝업은 PC에서 이미지/속성 2열, 모바일에서 세로로 배치한다. Escape로 닫고 기존 카드로 초점을 복귀한다.
- 편집기는 왼쪽 자재/가운데 공간/오른쪽 견적·속성 구조를 유지한다. 상단 기능을 묶고 1280px 이하에서 보조 기능을 더보기로 모았다. 1100px 이하에서는 패널을 필요할 때 열고, 620px 이하에서는 상단을 두 줄로 배치한다.
- 견적/편집 속성 바로가기는 같은 패널의 스크롤을 이동한다. 검증된 입력값을 먼저 반영하고 DOM과 펼침 상태를 유지한다. 활성 도구·자재는 테두리·체크·선택 상태로 구분한다.
- 로그인 화면과 팝업의 설명·버튼·진행·실패 표시를 맞췄다. 중앙 배치, 내부 스크롤, Escape와 초점 복귀를 유지한다. 키보드 포커스와 모바일 주요 조작의 44px 터치 영역, 동작 감소 설정을 지원한다.

## 구현 경계

서버 API·공개 DTO·DB 스키마·프로젝트 저장 형식·권한 정책은 변경하지 않았다. 실제 공간의 재질·조명·렌더링·출력 이미지 계산도 변경하지 않았다. 기존 캔버스 컴포넌트 변경은 도구 버튼의 aria-pressed 추가뿐이다. 외부 폰트·새 UI 라이브러리·이미지 생성 모델은 도입하지 않았다.

## 화면 비교

[너비별 개선 전후 보기](../test-results/ui-studio/index.html)

390·768·1024·1440·2560px에서 메인·자재·편집기·로그인 각각의 전후 화면을 캡처했다. 기본 비교 40장과 회원 프로젝트 목록·역할별 모바일 메뉴·많은 자재·상세 팝업·모바일 편집 패널의 추가 캡처를 남겼다. 비교 HTML에서 너비를 바꾸고 이미지를 눌러 원본 크기로 볼 수 있다.

- 이전 화면: test-results/ui-studio/before
- 개선 화면 및 추가 상태: test-results/ui-studio/after
- 자동화: e2e/studio-ui.spec.ts

캡처는 실제 브라우저 화면이지만 인증은 모의 Google/세션이며 D1/R2는 격리된 테스트 저장소다. 자재 카드는 테스트용 단색 이미지와 누락·실패 사례를 사용했으므로 실제 상품 이미지나 AI 인식 결과가 아니다. 실제 Google 로그인 및 운영 연결 검증과 구분한다.

새 UI 검사는 5개 너비의 화면 넘침, 검색·초기화·자재 상세, 모바일 메뉴와 권한별 항목, 중앙 팝업·Escape·초점 복귀, 이미지 실패·빈 목록·연결 오류, 긴 이름과 많은 목록을 확인했다. 격리 회원 프로젝트 9개와 자재 목록 28개를 사용했다. 모바일 편집에서는 더보기의 기존 로그인 제한, 견적/속성 이동, 입력값 유지와 비로그인 서버 쓰기·AI 모델 요청이 없음을 검사했다.

기존 회귀는 자재 등록/분류/권한, 자재 배치·견적 입력, 실행 취소/다시 실행·한글 입력, 2~5개 시안 비교·다운로드, 새로고침 복원, 로그인 취소·실패·응답 유실과 저장 재시도 등을 확인했다. 최종 간격 변수 정리는 계산되는 px 값을 바꾸지 않았으며 이후 두 빌드를 다시 성공시켰다.

vinext 빌드에는 도구체인의 punycode deprecation·glob 실험 기능·향후 Vite config loader 호환성 경고와 일부 경로의 정적 분류 한계 안내가 출력된다. 현재 빌드는 성공했고 격리 Workers 화면 검증에서도 기능 오류는 재현되지 않았다. 실제 Google 인증·운영 DB/R2 연결과 실배포 확인은 이번 검증에 포함하지 않았다.

## 재실행

기본 Playwright 설정은 개발 서버와 인증된 격리 테스트 헬퍼를 사용한다. 다른 로컬 서버와 충돌하지 않도록 이번 실행에서는 3011 포트의 임시 설정을 사용했다.

```powershell
npm test
npx playwright test e2e/studio-ui.spec.ts --workers=1
npx playwright test e2e/guest-workspace.spec.ts e2e/guest-promotion-recovery.spec.ts e2e/login-flow.spec.ts e2e/catalog-access.spec.ts e2e/material-usage-inputs.spec.ts e2e/editor-history-shortcuts.spec.ts e2e/designs.spec.ts --workers=1
npm run typecheck
npm run lint
npm run build
npm run build:vinext
```

화면 캡처 파일은 테스트 산출물이므로 저장소 커밋 대상은 아니다. 이후 UI 테스트를 실행하면 after 캡처가 갱신된다. before는 변경 전 실제 캡처이며 현재 코드로 재생성하면 변경 전 화면이 되지 않는다.
