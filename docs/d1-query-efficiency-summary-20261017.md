# D1 읽기 줄이기 · 한눈에 보기 (2026-10-17)

## 무슨 일이 있었나

- 2026-10-17, 운영 DB의 하루 무료 읽기 한도(500만 행)를 넘었다. 그날 1,885만 행을 읽었다.
- 원인은 "이 이미지를 이 사람이 볼 수 있나?"를 확인하는 쿼리 하나였다.
- 이미지 한 장을 확인할 때마다 **볼 수 있는 이미지 전체 목록**을 처음부터 만들었다. 그래서 자재가 늘수록 계속 비싸졌다.

## 무엇을 바꿨나

- 확인할 이미지 **한 장에서 출발해** 필요한 만큼만 읽게 했다.
- 로그인 없이 보는 공개 자재 이미지도 같은 방식으로 바꿨다.
- 누가 무엇을 볼 수 있는지는 **하나도 바뀌지 않았다.** 무작위 데이터 60세트로 옛 방식과 새 방식을 비교했고 판정이 다른 경우는 0건이었다.

## 효과

| 작업 | 이전 | 지금 |
| --- | --- | --- |
| 이미지 1장 열기 | 약 5,000~10,000행 | **5~11행** |
| 프로젝트 저장 확인 | 약 8,000행 | **약 330행** |
| 공개 이미지 1장 | 약 1,400행 | **4행** |
| 공개 배치 목록 전체 | 약 139만 행 (6.4초) | **약 6,000행 (0.1초)** |
| **하루 전체 (어제 사용량 기준)** | **약 5,600만 행** | **약 38만 행** |

자재가 5배로 늘어도 지금 숫자는 그대로다.

## 확인한 것

- 자동 테스트: D1·자재·관리자 테스트를 모두 통과했다.
- e2e: 59개 중 58개가 통과했고, 나머지 1개도 혼자 다시 돌리면 통과한다.
- 로컬 개발 서버에서 사람이 쓰는 흐름을 직접 확인했다.
  - 자재 목록·수정·저장
  - 프로젝트 저장·다시 열기
  - 공개 자재 이미지
  - 깨진 이미지나 권한 오류는 없었다.
- 운영 DB: 승인받고 읽기만 했다. 수정한 것은 없다.

## 결정이 필요한 것

1. **인덱스(0008) 운영 적용**: 10-17에는 그날 한도를 이미 다 써서 적용하지 못했다. **10-18 09:00 KST 이후** 적용한다.
   - 적용하면 하루 약 4만 행을 더 줄인다.
   - 적용하지 않아도 동작은 같다.
   - 명령: `npx wrangler d1 migrations apply DB --remote --config wrangler.jsonc`
2. **다음에 줄일 곳 (지금은 큰 문제 아님)**
   - 공개 자재 목록은 자재 수에 비례해 읽는다. 지금 1회 약 5,000행이다.
   - 한 화면에서 관리자 권한 확인이 여러 번 나간다.
3. **배포**: 2026-10-17 main에 병합·푸시해 자동 배포된다. 한도가 초기화되는 10-18 09:00 KST부터 새 쿼리로 읽는다.
