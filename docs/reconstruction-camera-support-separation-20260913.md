# 카메라 보류와 독립 설치·지지 관측 분리: 실제 저장 자료 재생

2026-09-13. 최신 네 개발 사진의 기존 Qwen/DeepLab/MoGe 관측을 현재 함수로 재생했다. 새 모델 실행, 사용자 좌표 입력, 카메라 가설 선택은 없었다. 이 검증에서는 생산 소스를 편집하지 않았고 루트가 통합한 변경을 검증했다.

## 검증한 변경과 결과

`candidate-pipeline.ts`가 카메라 보류 중에도 `inspectObservedInstallation`의 위치와 무관한 설치 방식·지지 형태를 보존한다. 깊이 광선으로 설치 벽을 추정하는 단계는 여전히 유효한 카메라가 필요하다. 기둥형 세면대는 원 사진 해시가 일치하는 `inspectObservedSupportContact`의 독립 기둥 하단 근거를 사용할 수 있으며, 볼 bbox 하단을 바닥 접점으로 대신 쓰지 않는다.

각 사진의 동일 원관측과 명목 방을 사용한 전후 비교에서 다음을 직접 assert했다.

- 일반 corner 카메라와 깊이 기반 카메라 결과 객체가 기준선과 정확히 같다.
- `automaticUnderstanding` 원문이 변하지 않는다.
- 일반 경로와 깊이 실험 경로의 `plans` 전체 객체가 기준선과 정확히 같다.
- 재생 전후 관련 소스 해시가 같다. 실제 `candidateInputFingerprint`와 `observationInputFingerprint`를 제공했다.

| 사진 | 보류 상태에도 review에 남은 독립 설치 근거 | 일반 배치 전→후 | 깊이 실험 배치 전→후 |
| --- | --- | ---: | ---: |
| user-01 | 변기·욕조의 바닥 설치 | 0→0 | 0→0 |
| user-02 | 변기의 바닥 설치, 세면대의 벽걸이 지지 | 0→0 | 0→0 |
| user-03 | 변기의 바닥 설치, 세면대의 기둥형·바닥 지지 | 0→0 | 0→0 |
| user-04 | 기존 변기·하부장의 바닥, 창·거울의 벽 설치 유지 | 1→1 | 3→3 |

user-01의 세면대 설치 충돌, user-02의 반사로 분류된 거울, 매칭되지 않은 신규 설비, 미확정 종류는 그대로 남았다. 독립 지지 검사만으로 명시한 종류·형태의 충돌을 덮어쓰지 않았다. 이 변경으로 자동 배치 수가 늘었다고 보고할 수 없다. 카메라 부족과 설치 의미 부족을 따로 보여주고 불필요한 지지 형태 재입력을 줄일 수 있게 된 것이 이번 검증 범위다. 실제 UI 입력 횟수 감소는 별도 UI 시험 범위다.

## user-03: 접점 이후에도 남는 범위 문제

카메라는 계속 보류한다. 선택하지 않은 벽 쌍 두 개를 각각 독립 실험 입력으로 넣었을 때에도 기존 카메라 결과는 정확히 같았다. 두 가설을 자동 선택하거나 평균하지 않았다.

같은 사진의 세면볼·연속 기둥 관계에서 얻은 하단 윤곽점 `(0.356823, 0.749441)`은 유효한 지지 관측으로 인정됐다. 원래 볼 bbox나 모델 anchor를 수정하지 않고 별도 `supportEvidence`로 기록했다. 이 점은 실제 발 접촉면 중심 또는 제품 중심의 실측값이 아니다.

새 접점으로 진행한 후단에서는 기존 기본 규격 `600×800×480mm`, yaw `0°` 모형의 왼쪽 방 범위 넘침이 각각 **45.539mm / 46.097mm**였다. 두 가설 모두 최종 배치는 0개로 유지된다. 모형을 줄이거나 방 안으로 옮겨 통과시키지 않았다. 제품 방향·설치 벽·윤곽점과 모형 중심의 관계가 다음 확인 대상이며, 카메라 가설만 선택해도 전체 배치가 해결된다고 볼 수 없다. 전체 기둥 모형을 볼만 있는 Qwen bbox와 비교한 86px 안팎의 bbox 차이는 같은 전체 객체 범위에 대한 정확도 검증이 아니다.

## 카메라 실패별 다음 경로

- **user-03의 가까운 두 가설:** 위치 20.12mm·회전 0.493° 차이, 공통 명목 격자의 투영 최대 차이 2.873px다. 그러나 벽 두 조각을 함께 적합하면 최대잔차 0.03789 모델m가 기존 0.01772 모델m 기준을 넘는다. 가설 차이가 작다는 이유로 제외된 벽의 모순까지 해결됐다고 하면 안 된다. 향후 가설별 같은 제품의 설치 면·접점·전체 모형 범위를 모두 검사한 대안/범위를 제공할 수 있으나 단일 카메라 자동 승격은 현재 근거로 지원하지 않는다.
- **user-02의 미관측 옆벽:** 직교 벽 쌍이 없고 뒤벽 후보도 둘이다. 각 후보를 뒤벽으로 보았을 때 추정 촬영 거리는 약 540mm/1857mm로 다르다. 바닥+선택한 물리 뒤벽의 부분 프레임에서 회전·높이·깊이만 보존하고 좌우 이동을 미정으로 남기는 새 계약이 필요하다. 사용자가 물리 뒤벽을 고르고, 의미가 명확한 관측 기준점의 벽을 따른 위치 하나를 제공하면 좌우 자유도를 정할 수 있다. 실제로 그러한 기준점이 없는 사진에는 이 2입력 경로를 약속할 수 없다. 현재 함수나 UI에 구현한 기능은 아니다.
- **user-01의 큰 가설 차이:** 위치 173.38mm·회전 8.67°·격자 최대 46.99px 차이다. 추가 근거 또는 사용자의 명시적 공간 가설 선택이 필요하다. user-03과 같은 안정성으로 취급하면 안 된다.
- **지금 사용할 수 있는 대안:** `placementFromWallReference` → `resolveManualDraft` → `ManualCandidatePlacement`는 카메라와 독립인 표준 공간 배치 경로다. 제품별 설치 벽·모서리에서 중심까지 거리·벽 뒤쪽 간격을 사용자가 정한다. 현재는 한 설비의 위치이며 공통 카메라 보정으로 전파하는 기능은 아니다.

## 기존 검증의 한계

가설 단위 테스트는 열거와 보류, 잘못된 입력을 검사한다. 물리 카메라 오차나 모든 가설을 빠짐없이 만들었다는 보장은 없다. 기존 격자 비교는 두 카메라 모두에 보이는 점만 평가하므로 향후 안정성 검사에는 한쪽에서만 보이는 경우, 수평선 부근 광선 불안정성, 제품 코너 전체의 차이도 포함해야 한다. corner-fit의 숫자 기준을 그대로 가족 가설의 정확도 통과 기준으로 사용해서는 안 된다.

`depthObservedWallAtPoint`는 현재 명목 방의 관측 벽 면과 광선을 교차시키며 실제 관측 패치의 영상 지지 범위를 입력으로 받지 않는다. 교차점은 부착 관계나 거울·개구부·돌출 표면 부재를 증명하지 않는다. 한 점의 역투영·재투영 왕복 오차가 작다는 것도 외부 정답에 대한 정확도 증거가 아니다.
