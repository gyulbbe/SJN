# 자동 배치 변경 후 실제 관측 재생

2026-09-14, 변경 전과 같은 다섯 사진·가정 방 치수·저장 관측을 새 생산 코드에 재생했다. **자동 배치 수와 이 사진들의 시각 재현 품질은 개선되지 않았다.** 이전 0/0/0/2/0에서 0/0/0/1/0으로 바뀌었다. 확인되지 않은 바닥 대응을 확정 설치 근거로 쓰지 않으면서 user-04 하부장도 보류됐다. 위치 확인 기능의 개선은 별도 사용자 UI 검증과 구분한다.

15장의 원본/이전 자동/변경 후 자동 이미지는 [로컬 비교표](../test-results/reconstruction-placement-quality-20260914/comparison.html)에 있다. user-04 전후를 직접 육안 확인했고, 나머지 네 PNG는 바이트 SHA가 동일함을 검사했다. 파란 제품의 색 메타데이터가 유지된 것을 파란 하부장 시각 재현의 개선으로 보고하지 않는다. 잘못된 자동 배치를 줄이려는 보류와 알아보기 쉬운 결과 완성은 별개다.

## 저장·출력·측정

각 결과에서 명시적 IndexedDB 저장·재로딩 후 검토 및 모형 데이터가 동일하고, 프로젝트 복사 시 모형이 보존되며, After의 설비·적용 자재가 비어 있음을 확인했다. 생산 합성기로 Before/After PNG를 만들었으며 편집 UI를 넣지 않았다. 페이지 예외·Worker 생성·외부 요청은 모두 0이다.

## 모델 교체에 대한 판단

이번 다섯 사진의 변기·세면대·욕조·하부장은 이미 관측됐는데 설치 벽/지지점/바닥 대응과 규격 가정 때문에 생성이 멈춘 경우가 많다. 이 부분은 모델 종류만 바꾸어 해결됐다고 볼 수 없다. 반면 user-01의 유리 파티션·거울 수납장·벽 선반을 별도 종류로 찾지 못한 부분은 같은 raw의 좌표 계산만으로 새 인식 성공을 만들 수 없다.

기존 [실제 Qwen 비교](reconstruction-evaluation-split-20260913.md)의 원 `execution.json`, `metric-summary.json`, `visual-audit.json`을 다시 읽었다. 2026-09-13에 캐시된 Qwen3-VL4B q4_K_M/prompt8과 DeepLab을 세 사진에 각 한 번 실제 실행했고, 알려진 종류 bbox 대응은 Qwen 9/9·DeepLab 6/9였다. 그러나 Qwen 결과의 실제 모형 생성은 0/0/0, 원사진 재투영 평가 가능 항목도 0이었다. 카메라·설치 충돌·원관측 대응 부족 등이 남았다. 9/9는 불확실한 스크린·거울장 종류를 제외한 작은 선택 표본이며 형태·설치 정확도가 아니다. 그 사진들은 결과를 본 이후 개발 회귀 자료다.

따라서 이 자료만으로 기본 엔진을 Qwen으로 바꿀 근거는 부족하다. 다음 모델 실험은 명확한 종류 누락과 관계 이해를 보조하는 범위에서 기존 로컬 Qwen 경로를 평가하고, 위치 확인 뒤 실제 표준 모형이 생기는지까지 함께 확인하는 것이 타당하다. 이번 작업에서는 새 추론·모델 다운로드·모델 라이선스 변경·제품 TripoSR/배경 제거 변경을 수행하지 않았다.
