# 바닥·벽 기하 실험과 독립 설치 근거 연결

2026-09-13. 사진 재구성 전체 목표는 미완료다. 이번 변경은 설치 근거와 위치 계산을 분리하고, 로컬 깊이 모델을 실제 관측 자료와 결합해 배치에 기여하는지 시험했다. 새 기하 모델을 일반 사용자 분석에 채택하지 않았다.

## 확인한 원인과 구현

현재 Qwen inventory는 종류·형태·부품을 관측하며 설치 벽·방식은 대부분 unknown이다. 기존 후보 파이프라인은 원본 카메라가 보류일 때에만 DeepLab 설치와 위치를 함께 재사용했다. 따라서 새로운 기하로 카메라를 얻어도 설치 방식이 unknown이면 배치가 멈췄다. 실제 user-04에서 기하를 연결한 첫 실험의 배치가 1→0으로 감소한 원인이었다.

`observed-placement.ts`의 공통 매칭 검사를 분리하고 `inspectObservedInstallation`을 추가했다. 같은 실물의 독립 관측에서 설치 방식·가능한 지지 형태만 가져온다. 기존 위치·접점·치수·가시 바닥 범위를 가져오지 않는다. 1:1 대응, IoU와 기둥 부품 근거, 반사·모순·약한 관측·사용자 보정 제외 검사를 공유한다. 설치 벽은 근거가 있을 때만 반환한다. 종류에 따른 설치 제안도 추정이며 실측이 아니다.

`candidate-pipeline.ts`는 카메라가 있는 경우 이 독립 설치 근거로 effective copy의 누락 필드만 보완한다. 원모델 응답·automaticUnderstanding은 유지하고 설치 검사 결과와 출처를 보고서에 남긴다. 카메라가 있더라도 특정 설비의 위치가 보류면 기존의 엄격한 평면 재사용 경로를 시도할 수 있다. 후보 처리 캐시는 `structured-scene-v7-independent-installation-1`로 변경했다.

이전 작업에서 새 DeepLab 바닥의 `geometrySource`를 `visible-floor-region`으로 구분했다. 사진에 보이는 바닥 영역을 방 전체의 물리 모서리로 자동 승격하지 않는다. 기존 저장 자료와 기본 분석의 과거 근사 배치를 일괄 덮어쓴 것은 아니다.

## 실제 로컬 기하 실험

[MoGe 실행 조건](reconstruction-moge2-probe.md), [평면 추출과 실제 육안 검토](reconstruction-geometry-plane-probe.md)를 함께 읽는다. 네 개발 사진과 기존 회귀 사진 네 장을 사용했다. 회귀 사진도 이미 사용한 자료이며 독립적인 새 평가 세트가 아니다. 새 모델 실행과 기존 Qwen 관측 재생을 구분한다.

- MoGe-2 vits-normal의 실제 로컬 추론에서 점군·깊이·법선·내부 카메라를 얻었다. 모든 mask=1이므로 유효 마스크를 의미 분할이나 신뢰도 필터로 사용하지 않았다.
- 실제 DeepLab 벽·바닥 마스크를 경계 침식하고 설비 사각 범위를 보수적으로 제외한 뒤 강건 평면을 추출했다. 원사진 해시와 전체 이미지 좌표를 검증했다.
- 반사·인접 공간·욕조가 벽으로 섞이는 사례가 확인됐다. 수치상 직각 평면 조합을 실제 방 모서리 검출 성공률로 사용하지 않는다.
- `depth-room-geometry.ts`는 바닥과 두 관측 벽의 지지·방향·거리·내부 카메라를 확인해 실험용 SourceCamera를 만든다. 가장 정면인 벽을 표준 뒤벽 축으로 정의하되 비슷한 축이나 여러 옆벽 후보는 보류한다. 주점·픽셀 비율 불일치, 입력 해시 불일치, 불충분한 지지, 방 치수와 충돌하는 촬영 위치를 거절한다.
- 단위는 모델이 추정한 metre→mm다. 사진별 스케일 튜닝이나 방 안으로 강제 이동은 하지 않았다. 이 카메라는 정확도가 검증된 보정값이나 실측값이 아니다. 최종 Before/After 공통 카메라는 그대로다.
- 선택된 관측 벽만 원사진 광선과 교차시켜 벽 설비의 설치 벽을 추정한다. 보이지 않은 벽을 새 근거로 만들지 않는다.

기하 입력은 현재 순수 배치 함수의 명시적 실험 옵션으로만 연결했다. 일반 UI에서 모델을 자동 실행하거나 추가 다운로드하지 않는다. 기하의 오인식과 위치 추정 한계가 남아 있어 기본 엔진 교체 근거로 삼지 않았다.

## 실제 자동 관측 재생·이미지

기존에 실제 실행한 Qwen prompt revision 8의 원관측, 이번 실제 DeepLab·MoGe 결과를 현재 배치 코드에서 재생했다. 새 Qwen 호출이나 사용자 위치 보정은 없다. 비교의 기준선은 **같은 후보 관측을 현재 배치 코드에서 기하 없이 처리한 결과**이며, 일반 DeepLab 단독 분석의 배치 수와 혼동하지 않는다.

| 사진 | 기하 없는 후보 배치 | 기하 실험 배치 | 상태 |
|---|---:|---:|---|
| user-01 | 0 | 0 | 카메라 후보는 생성, 잘린 변기·세면대 지지 충돌·불명확한 설치 등 보류 |
| user-02 | 0 | 0 | 뒤벽/옆벽 구분과 원점 미확정 |
| user-03 | 0 | 0 | 유리 뒤 깊이가 나뉜 여러 벽 후보로 기하 모호 |
| user-04 | 1 | 3 | 창·거울·변기 배치, 하부장 세면대는 보류 |

user-04의 표준 공간 PNG를 직접 확인했다. 원사진에 있던 창·거울·변기를 각각 표현하고 거울은 중립 표면이다. 하부장 세면대는 여전히 빠졌다. bbox 하단 중앙과 기본 방향으로 배치하면 기본 하부장 몸체가 왼쪽 벽 약159mm, 앞쪽 경계 약21mm를 넘었다. 이를 강제로 밀어 넣거나 축소하지 않았다. 제품 관측 표면·지지 관계로 기준점과 방향을 보완해야 한다.

실제 브라우저에서 `createReconstructionProject`와 `PhotoCompositor`를 사용해 네 사진의 두 결과를 각각 PNG로 출력했다. 별도 가짜 장면이나 사진 평면을 붙이지 않았다. 새 Worker 0, 외부 요청 0, pageerror 0, 각 After 설비 0을 확인했다. 1200×800 출력이며 표준 공간 구도가 같고 확인 도구가 포함되지 않는다. 이 하네스는 전체 앱 UI·새 모델 추론·독립 인식 정확도 시험이 아니다.

계산 결과: 같은 루트의 `placement/{id}/report.json`, 입력·코드 해시 포함.

## 관련 검증과 남은 일

순수 기하 테스트는 기울어진 카메라, 좌/우벽 부호, 역투영, 불충분한 평면, 사진 불일치, 치수 충돌, 사용자 입력 없는 설치 보완과 원관측 보존을 검사한다. 처음 역투영 테스트가 카메라 밖의 점을 사용해 실패했고 실제 보이는 점으로 정정했다. 실제 배치 재생의 첫 실행은 입력 보고서 해시 필드 이름 오류로 실패했으며 `inputSha256` 필드로 고쳤다. 실패를 모델 품질 실패 또는 성공으로 집계하지 않는다.

이 변경 당시 전체 검사 결과는 `test-results/reconstruction-depth-installation-20260913/checks.json`과 각 로그에 있다. lint·타입 검사·Vitest(91개 파일, 1,091개 테스트)가 통과했다. Next.js 53.971초, vinext 19.853초로 순차 빌드했고 각각 종료 코드 0이다. 첫 전체 타입 검사는 새 브라우저 테스트의 DOM null 처리 두 곳 때문에 실패했으며, 수정 후 통과했다(`checks-initial.json`, `typecheck-initial.log`). 이전 별도 검사에서 나온 오래된 Next 생성 타입 경고와 이 실패를 구분한다. 후속 제품 표면·Lab 연결 변경의 검증을 이 과거 검사로 대체하지 않는다.

이와 별개로 실제 욕조를 선택하는 [유리·욕조 테두리 연결](reconstruction-bath-rim.md)을 구현했다. 해당 기능은 사용자 보정이며 자동 욕조 지지 관계 검출 성과가 아니다.

남은 핵심은 잘린 제품·가려진 접점·방향을 한 점에 의존하지 않고 보완하기, 반사와 실제 벽 구분, 최소 사용자 확인을 실제 테스트 화면에 연결하기, 네 사진 및 새로운 평가 사진의 재현 품질 검증이다. 원본과 충분히 닮은 전체 공간이 완성됐다고 보고하지 않는다.
