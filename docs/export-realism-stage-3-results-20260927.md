## 3-2 FLUX 설비 보호

### 3-2a 두 방식 시제품 (호출 없이)

- **방식 1: 설비 되돌리기(클라이언트 합성)**
  - 마스크
    - 3D는 `RoomViewerRenderer.fixtureMask`다. 내보내기와 같은 카메라로, 설비를 ID 단색으로 그린다. 방 면은 가리고 유리는 가리지 않는다.
    - 2D는 합성기의 설비 ID 패스다. 제품 알파·가림·표준 모형을 쓴다.
    - 실제 WebGL 시험에서 설비 3개 모두 실루엣이 설비 상자 안에 있었고, 상자의 15~55%를 채웠다.
    - 기존 렌더는 그대로였다(render-realism 45장·room-viewer-render 9장 픽셀 차 0).
  - 정렬
    - 전체 구도: 윤곽(밝기 기울기) 상관을 ±3% 이동 범위에서 구한다.
    - 설비: 자기 윤곽의 상관을 전체 이동 근처 ±1%에서 구한다.
    - 합성: 정렬된 불투명 설비만 원래 1024 캡처로 덮고, 경계 2px를 섞는다.
  - 2026-09-25 결과 6장(상자 마스크)
    - 전체 구도 상관: 구도를 지킨 A·B 0.34~0.61, 구도를 바꾼 C 0.11. 기준을 0.22로 정했다.
    - 설비 상관: 그대로인 설비 0.33~0.58, 조작 사례(변기→원통 0.22, 세면대 지움 0.11). 기준을 0.28로 정했다.
- **방식 2: Gemma 확인(서버)**
  - `POST /api/export/photoreal/check`([서버](../src/lib/ai-export/check-server.ts), [계약](../src/lib/ai-export/check-contract.ts))
  - 결과 이미지(JPEG, 1.5MB·1024px 이하)와 설비의 종류·상자만 받는다. 서버가 영어 질문을 만든다. 응답은 설비마다 `present`(yes/no/unsure)·`seenAs`(종류/other/none)인 엄격한 JSON이다.
  - 기존 Gemma 규칙을 따른다: 동일 출처·로그인, `sjn-gateway`, 재시도 1회 제한, 진단에는 크기·개수만.
  - 스키마 밖 입력은 추론 전에 400이다(단위 14개).
- **조작 사례**(양성 대조, 호출 없이 만듦): 2026-09-25 B-424242에서 변기 자리를 회색 원통으로 덮은 것, 세면대를 옆 벽으로 지운 것

### 3-2c 채택과 화면 연결 (`f95b255`)

- **동작**
  - FLUX 결과가 나오면 곧바로 보이고, 이어서 배치한 제품의 종류·상자로 Gemma 확인을 한 번 부른다.
  - 확인 중에는 "AI 제품 확인"으로 경과·보통 시간(1.4초)을 보인다.
  - 모두 보이면 "AI 제품 확인: 배치한 제품 N개가 모두 보여요."를 보인다.
  - `no`인 제품은 결과 아래 경고로 알린다. 예: "세면대가 가운데에서 보이지 않거나 다른 물건으로 바뀌었을 수 있어요. 다시 만들어 보세요. 자동으로 다시 만들지는 않아요."
  - 확인이 실패하면(한도 등) 결과는 그대로 두고 "AI 제품 확인을 하지 못했어요."와 이유를 보인다.
  - 배치한 제품이 없으면 확인을 부르지 않는다.
- **호출 수:** 한 클릭에 FLUX 1회와 확인 1회다. 자동 재시도나 재변환은 없다. 안내 문구에 두 요청의 사용량이 생긴다고 적었다.
- **다운로드:** PNG는 FLUX 결과 그대로다(보호 합성 없음).
