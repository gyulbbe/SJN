# 제품 관측색과 표면색 분리 — 2026-09-14

따뜻하고 어두운 사진의 도기를 갈색 재료로 굳히던 경로를 수정했다. 사진의 실제 RGB와 제품 고유색을 완전히 분리한 것은 아니다. 애매한 따뜻한 도기색은 원 관측색을 보존하고 **중립 기본색·확인 필요**로 표시하며 사용자가 실제 색을 확인한다. 파란 도기와 하부장은 관측색을 유지했다.

## 확인한 원인

`candidates.ts`의 기존 색 추정은 bbox 전체 평균이 아니라 연결된 semantic 분류 영역에서 약256개 픽셀을 뽑고 밝기70–95%의 채널 중앙값을 사용했다. 따라서 이번 사진만으로 bbox 평균 오염을 원인이라고 보고하지 않는다. 다만 마스크 가장자리의 혼합 픽셀을 따로 제외하지 않았으므로 새 관측에서는 실제 semantic 마스크를1픽셀 침식해 내부만 사용한다.

문제의 `prospective-03` 원사진 `commons-155847010.jpg`를 직접 확인했다. 저장 세면대색 `#978370`, 변기색 `#8a7767`이며 해당 원사진 bbox의 밝기70–95% RGB 중앙값도 각각 `[149,130,110]`, `[133,115,99]`였다. 이 bbox 계산은 원인 확인용 비교이며 새 제품 색 선택에 bbox를 쓰지 않는다. 원사진 자체가 따뜻하고 어두워서 관측 RGB를 새 중립 조명의 재료색으로 재사용하면 갈색 재료처럼 보인다.

별도 원인으로 `candidate-pipeline.ts`와 `index.ts`가 관측색을 복사하면서도 `provenance.appearance`를 항상 `default`로 기록했다. 이제 실제 재료 선택의 `colorEvidence.source`와 `provenance.color/appearance`가 일치한다.

색공간 경로는 원사진 sRGB 바이트 → `Color`/`MeshStandardMaterial`의 선형 변환 → `StandardModelRenderer`의 LinearSRGB 표적 → compositor 최종 sRGB 인코딩이다. 독립 템플릿 PNG는 Three의 SRGB 출력이다. 이 조사에서 중복 감마 변환은 확인되지 않았고 감마 보정 코드를 추가하지 않았다. `Color` sRGB 왕복 단위 검사와 같은 모형·카메라·조명의 브라우저 PNG로 확인했다.

## 변경 코드와 의미

- `src/lib/reconstruction/product-color.ts`: 실제 마스크 내부 관측, 색상군/밝기 극단 선택, 중립 반사·투명 표면, 조명색이 모호한 도기의 기본색 선택, 사용자 색 확인을 한 경로로 처리한다.
- `candidates.ts`: 원 연결 영역을 전달한다. bbox 배경이나 다른 설비 픽셀을 새로 채워 넣지 않는다.
- `types.ts`, `candidate-pipeline.ts`, `index.ts`: 관측색·최종색·이유·확인 필요·샘플 수와 필드 출처를 후보 및 모형에 저장한다. 원모델 응답과 과거 저장 자료는 변경하지 않는다.
- `src/lib/supabase/validation.ts`: 선택적 색 증거와 필드 출처를 검증·보존한다. 색 증거에는 이미지/자재 ID 참조가 없으므로 자산 참조 관계를 추가하지 않는다.
- 사용자 색 보정은10번째 파이프라인 인자 `userColors`로 받고 원관측과 별도로 저장한다. 미지정은 관측 정책, `neutral`은 사용자 기본색 확인, `custom`은 사용자 sRGB 색이다. 중립 기본색 자동 선택은 `default`, 사용자가 중립색을 확인하면 `user`다.

색 증거의 `method`는 `semantic-interior`, `legacy-observation`, `neutral-optics`, `default`, `user`를 구분한다. `observedColor`는 보존할 사진색, `color`는 선택된 모형색이다. semantic 픽셀 선택은 모델의 종류 분류를 사용한 **규칙 추정**이므로 `inferred`이며 고유색 모델 관측/실측이라고 부르지 않는다. 이전 분석에 마스크 선택 기록이 없으면 `legacy-observation`과 확인 필요를 명시한다.

거울·거울장·유리·창의 반사/배경색은 고유색으로 사용하지 않으며 기존 중립 표면·투명도를 유지한다. 따뜻한 어두운 세면대·변기·욕조는 중립 기본색으로 보류하지만 목재 하부장이나 파란색·중립 회색·검정 제품을 일괄 흰색으로 바꾸지 않는다. 실제 베이지 도기도 같은 조명 모호성에 걸릴 수 있어 사용자가 색을 확인해야 한다.

## 실제 관측 검증

원사진 네 장과 기존 평가 후 회귀로 분류된 `prospective-03`을 사용했다. 새 Qwen 요청이나 외부 사진 전송은 없었다. 첫 정책에서 중간 밝기35–80%를 사용하자 `user-03`의 기둥 그림자가 과도하게 반영되는 회귀를 발견했다. 그 결과와 소스 사본을 보존하고, 작은 밝은 하이라이트 덩어리는 제외한 뒤 남은 몸체의 밝기70–95%를 쓰도록 수정했다.

첫 정책의 실제 DeepLab 전체5회 기록은 [actual-baseline](../test-results/reconstruction-product-color-20260914/actual-baseline)에 있다. 각 사진당 한 번 실행했다. UI/렌더를 포함한 실행 시간은22.282/12.213/22.389/27.668/27.520초이며 이를 최종 정책 결과로 바꿔 부르지 않는다.

최종 정책은 네 장의 **이미 저장된 실제 primary semantic 마스크와 RGBA**를 재생했다. `prospective-03`은 당시 마스크가 없어 primary 관측1회를 실제 실행해4.739초에 캡처한 뒤 재생했다. 이 단일 primary 캡처는 전체 flip/crop 분석과 다르다. 각 입력·마스크 SHA256을 확인했고 기존 모델 출력·사진·정답 기록은 덮어쓰지 않았다. ## 검사와 한계

제품 색 신규19개를 포함한 마지막 관련 검사68개가 통과했다. 내부 마스크·갈색 경계 제외·따뜻한 도기 보류·파란/회색/검정 유지·검정 위 작은 하이라이트·혼합색 확인·중립 광학 표면·사용자 베이지 확인·원문 보존·파이프라인 출처·Supabase 스키마를 검사했다. 회색·검정의 보존은 합성 단위 검사이며 실제 회색/검정 제품 사진의 정확도 검증으로 보고하지 않는다. 담당 구현/테스트의 ESLint도 통과했다. 전체 타입/빌드/저장·UI 회귀는 루트 최종 검증 기록을 따른다.

환경은 이 저장소의 Windows/Chrome152 headless·SwiftShader·TFJS WASM이다. 실제5장 실행의 [환경 기록](../test-results/reconstruction-product-color-20260914/actual-baseline/environment-all.json)에 하드웨어·브라우저·소스 해시를 남겼다. 새 전체 RAM/VRAM 최고점 측정은 하지 않았다. 이번 모델은 기존 DeepLab이며 모델 교체/라이선스 변경/큰 모델 추가 다운로드가 없다.

한 장의 사진으로 조명과 도기 고유색을 구분할 수 없으므로 베이지·색조명·다중 재질·깊은 그림자는 사용자 확인이 필요하다. semantic 모델이 물체 내부 자체를 잘못 분류하면 침식만으로 오탐을 해결할 수 없다. 세면볼·하부장 여러 재질을 한 개 색으로 나타내는 기존 표준 모형의 한계도 남아 있다. 이번 결과는 색 표현과 출처의 개선이며 종류·설치·카메라·숨은 형상의 자동 복원 성공률 개선이 아니다.
