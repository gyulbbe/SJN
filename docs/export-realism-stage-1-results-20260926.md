## 1-1 방 안 시점

### 구현

- **시점 모델** ([view-state](../src/lib/room-viewer/view-state.ts))
  - `projection: 'room-eye'`와 `eye { position(mm), yaw(도), shift, fov(수평 도) }`를 추가했다.
  - 저장 스키마는 `'room-eye'`와 `eye`를 받는다. 둘은 함께 있어야 한다. 이전 형식은 그대로 통과하고, 깨진 `eye`는 정규화에서 버린다(프로젝트를 거부하지 않는다).
- **카메라**
  - 기본값은 눈높이 1,500mm, 피치 0, 수평 화각 74°(풀프레임 24mm 상당)다.
  - 세로 구도는 피치 대신 렌즈 시프트(`setViewOffset`)로 맞춘다. 그래서 세로선이 늘 곧다. 기본 시프트는 −0.2(바닥이 조금 더 보이게)다.
  - 위치는 벽에서 150mm 이상, 높이 300mm ~ 천장−150mm로 제한한다. 화각은 60~90°다.
- **앞벽을 보지 않는 범위**
  - 앞면(z = 방 깊이)에는 자재 정보가 없다.
  - 수평 시야 가장자리 광선이 앞면 쪽으로 향하지 않으려면 |yaw| + fov/2 < 90°여야 한다. 여기에 여유 3°를 두어 |yaw| ≤ 90° − fov/2 − 3°로 제한한다. 74°에서는 ±50°다.
  - 모든 프리셋과 화각 60·74·90°, yaw −한계·0·+한계·179°(제한됨)에서 앞면 격자 169점이 프레임 밖인지 단위 테스트로 확인한다.
- **프리셋과 조작** (공간 둘러보기)
  - "방 안 · 가운데 / 왼쪽 모서리 / 오른쪽 모서리"는 입구(깊이−150mm)에서 뒷벽 쪽을 본다.
  - 방 안에서는 방향 버튼이 "왼쪽 15° / 오른쪽 15° / 위로 보기 / 아래로 보기(시프트 ±0.1)"로 바뀐다.
  - 이동 버튼 "앞으로 / 뒤로 / 왼쪽으로 이동 / 오른쪽으로 이동"은 150mm씩 움직인다.
  - 드래그는 가로 yaw, 세로 시프트다. 휠·핀치는 화각이다. "바깥 시점으로"는 궤도 보기로 돌아간다.
- **천장** ([ceiling](../src/lib/room-viewer/ceiling.ts))
  - 무광 흰 천장(`#f3f2ee`, 구석 차폐)과 600×600mm 발광 평판 등을 기존 SpotLight 자리에 둔다.
  - 선택·견적·설비 상자에는 들어가지 않는다(`userData` id 없음, 그림자 안 드리움).
  - **방 안 시점에서만 보인다.** 카메라가 방 안에 있는지로 켜면, 방 안에 카메라가 있는 저장 사진 시점의 기존 렌더가 바뀐다. 그래서 시점 방식으로 정했다.
  - 방 안에서는 SpotLight가 천장을 비추지 않아 천장이 어둡다. 그래서 반사광 근사로 자체 발광 0.5를 더했다.

## 1-2 여러 장 겹쳐 찍기

### 구현

- **대상:** `export(view, { quality })`에서만 동작한다. `quality`가 없는 기본 `export()`(시안 미리보기, FLUX 입력)와 실시간 `render()`는 이전과 같다.
- **흔들기** ([accumulate](../src/lib/room-viewer/accumulate.ts))
  - 0번 장은 흔들지 않은 원래 프레임이다. 이후 장은 고정 Halton 수열을 쓴다. 카메라는 기수 2·3, 등은 5·7이다. 같은 장면은 늘 같은 결과가 나온다.
  - 카메라: 투영 행렬 3열에 서브픽셀 이동을 더한다. 카메라 위치는 그대로다.
  - 등: SpotLight와 target을 600×600mm 판 안에서 함께 옮긴다. 그림자 맵은 매 장 다시 그린다.
- **평균:** 면(Before/After)마다 half-float 타깃에 가중치 1/(k+1)로 이동 평균한다. 쓰는 면만 할당한다(After만 받으면 하나).
- **그림자 보정(내보내기에서만)**
  - 천장 등 원뿔이 90°라 three.js 그림자 카메라 화각이 2·angle·focus = 180°가 되어 실제로는 그림자가 드리우지 않았다.
  - 겹쳐 찍는 동안에만 focus 0.8(144°)과 2048² 맵을 쓴다. 끝나면 되돌리고 맵을 새로 만들게 해 실시간 렌더는 이전과 같다.
  - 실시간 화면의 그림자 문제는 그대로 남는다(사용자 결정 2026-09-26: 내보내기에서만 고침).
- **GPU 완료 대기:** 매 장 뒤에 1픽셀을 읽어 GPU가 끝날 때까지 기다린다.
  - WebGL 호출은 작업이 끝나기 전에 돌아온다. 그래서 대기가 없으면 진행률과 시간 예산이 제출 시점을 셌다.
  - 소프트웨어 렌더링에서는 취소가 쌓인 장 뒤로 10초 가까이 밀렸다. 대기를 넣은 뒤에는 진행 중인 한 장이 끝나면 멈춘다(SwiftShader 1024에서 0.3초).
  - Iris Xe 4096 32장 기준 비용은 2.47초 → 2.69초다.
- **장 사이 양보**
  - 첫 장 전에 0%를, 각 장 뒤에 진행률을 그리도록 다음 그림 그리기(`requestAnimationFrame`)까지 기다린다. 숨은 탭은 100ms 타이머로 넘어간다.
  - 마지막 장 뒤에도 한 번 양보하고 취소를 확인한다. 공간 둘러보기는 파일을 받기 직전에도 취소 여부를 본다.
- **시간 예산**
  - 첫 장(흔들지 않은 프레임)의 실제 시간으로 예산 안에 들어가는 장 수를 정한다.
  - 16장 미만이면 등을 600mm 판 전체가 아니라 100mm 안에서만 옮긴다. 등 위치가 몇 개뿐이면 그림자가 여러 겹으로 보이기 때문이다.
  - 등을 아예 고정하지 않는 이유: three.js PCF 그림자는 화면 좌표 기반 디더링이라 카메라 흔들기로는 평균되지 않는다. 8장 고정에서는 변기 받침에 점무늬가 남았다. 100mm면 설비 그림자 이동이 수 픽셀이라 겹침은 없고, 그림자 경계의 점무늬는 줄어든다. 받침 위쪽의 약한 점무늬는 남는다. 비교: `final-d3d11-quality/spread-compare.png`(8장 고정 · 8장 100mm · 32장 600mm).
  - 첫 장만으로 예산을 다 쓰면 그 한 장(그림자 보정 포함)을 내보낸다.
- **대체와 해제**
  - float 타깃이 없거나 도중에 GPU 오류가 나면 한 장으로 내보내고 `diagnostics().lastExport.fallbackReason`에 이유를 남긴다.
  - 취소·창 닫기·렌더러 해제·컨텍스트 손실은 다음 장 전에 멈춘다. 누적 타깃과 1픽셀 타깃을 해제하고 등·그림자 설정을 되돌린다.
  - 내보내는 동안 들어온 실시간 `render()` 요청은 끝난 뒤 마지막 것 하나만 그린다.
- **진행률 UI**
  - [ModelLoadingProgress](../src/components/model-loading-progress.tsx)의 표시부를 [ProgressMeter](../src/components/progress-meter.tsx)로 꺼내 함께 쓴다.
  - 공간 둘러보기 다운로드와 편집기 내보내기(3D 경로)에 "고화질로 만드는 중 · n/N장 · %"와 "다운로드 취소"를 둔다.
  - 공간 둘러보기를 닫거나 편집기 내보내기 창을 닫아도 멈춘다.

### FLUX 입력에 적용할지

- 1024 캡처에 8장은 +140ms 정도다(65 → 203ms). 496px로 줄였을 때 픽셀의 1.9%가 휘도 6 이상 바뀐다(평균 0.61). 대부분 새로 생긴 설비 그림자다.
- 적용하지 않았다. 입력이 바뀌면 FLUX 결과가 바뀌는데, 좋아지는지는 유료 호출 없이 확인할 수 없다. FLUX 비교를 할 수 있을 때 다시 판단한다.

## 1-3 사진 효과

### 구현

- [photo-effects](../src/lib/room-viewer/photo-effects.ts)는 `export({ effects })`에서만 쓰는 별도 post 프로그램이다.
  - 기본 post 셰이더 소스에서 마지막 출력 줄만 바꿔 만든다. 색 조정·배치 계산은 같고, 기본 프로그램은 그대로다.
  - 첫 사진 다운로드 때 한 번 컴파일하고 렌더러를 닫을 때 해제한다.
- **빛 번짐**: 선형 값이 1을 넘는 부분(천장 평판 등, 강한 반사)만 쓴다. 1/4 해상도에서 4×4 평균 후 넓어지는 가우시안 3단(가로·세로)으로 흐린다. 번짐 반경은 이미지 폭의 약 2%라 크기와 관계없이 같아 보인다. 세기 0.35다. 내보낼 때마다 만들고 바로 해제한다.
- **가장자리 어두움**: 사진 영역 반대각선 기준 반경 0.6부터 1.05까지 서서히 최대 22% 어두워진다. 가운데 60% 상자 안(반경 0.6 이하)은 0이다.
- **입자감**: 고정 씨앗 해시로 중간 톤에서 ±1.5/255, 검정·흰색에서는 0이다. 같은 장면은 같은 파일이 나온다.
- **톤 곡선**: 표시값 10% 아래는 최대 +0.012 올리고, 85% 위는 최대 −0.03 누른다. 가운데 톤은 그대로다.
- **UI**
  - 공간 둘러보기 출력 줄과 편집기 내보내기 창(3D 경로일 때만)에 "사진 효과" 체크박스를 둔다. 기본은 켬이다.
  - 선택은 브라우저에 기억한다(`localStorage` `sjn-photo-effects`). 견적용 원본을 받으려고 끈 사람이 다음에도 같은 선택을 유지하게 하려는 것이다. 저장소를 못 쓰면 그 화면에서만 유지한다.
  - FLUX 입력 캡처는 효과를 넘기지 않는다.

### 판단 기준

조건: 겹쳐 찍기 16장, 2048×1365(`final-d3d11`)와 1024×683(`final-swiftshader`).

## 남은 한계

- **실시간 그림자:** 원뿔 90° 때문에 실시간 화면에는 설비 그림자가 여전히 없다. 내보내기에서만 고쳤다(사용자 결정). 실시간도 고치면 편집 화면·시안 미리보기 기준선이 바뀐다.
- **소프트웨어 렌더링:** GPU 없이 4096을 받으면 한 장에 수 초가 걸린다. 예산 때문에 1~2장으로 끝나고, 그동안 페이지는 장 사이에만 반응한다. 취소도 진행 중인 장이 끝난 뒤 반영된다.
- **윤곽 계단:** MSAA 4×가 이미 기하 모서리를 0.05px 안으로 맞춰, 겹쳐 찍기로 줄어든 폭은 측정 오차 수준이다. 효과는 주로 그림자다.
- **앞벽 방향 시점:** 앞면에 자재 정보가 없어 방 안 시점은 앞벽 쪽을 볼 수 없다.
- **대상 밖:** 벽 구조가 없는 사진 합성(2D) 프로젝트의 내보내기는 이번 작업과 무관하다. 방 안 시점·겹쳐 찍기·사진 효과는 3D 렌더러 경로에서만 동작한다.
- **FLUX 입력:** 겹쳐 찍기와 사진 효과를 넣지 않았다. 겹쳐 찍기의 효과는 유료 FLUX 비교로 확인해야 한다.
