# 4방향 고정 시점과 시점별 사진 결과 (2026-10-05)

제품이 방향별 평면 사진이 되어, 자유롭게 도는 3D 대신 **정면·오른쪽·뒤·왼쪽 네 방향(90° 간격)**으로만 보고 시점마다 맞는 사진 한 장(2D)을 보여 주도록 바꿨다. 규칙은 [방 크기](room-dimensions.md)의 "네 방향 시점", [FLUX 변환](flux-export.md)의 "돌리기"·"제품 방향", 검증 요약은 [검증 기록](verification.md)에 있다. 이 문서는 결과를 한곳에 모은 것이다.

## 1. 바뀐 것

| 구분                     | 이전                               | 이후                                                                                                         |
| ------------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| AI 입력 시점             | 끌기(방위·높이), 위에서/옆에서, ↑↓ | 왼쪽/오른쪽 90°, ←→, 정면으로만. 끌어도 안 바뀜                                                              |
| 공간 둘러보기            | 위·아래 90°, 방 안 시점            | 왼쪽/오른쪽 90°만. 확대·이동은 그대로                                                                        |
| 편집기 가운데 3D 방 화면 | 위·아래 90° 포함                   | 왼쪽/오른쪽 90°만. 저장된 시점은 가장 가까운 방향으로 그려 보이고, 사람이 돌리기 전에는 저장값을 바꾸지 않음 |
| 저장된 다른 시점         | 그대로 열림                        | 가장 가까운 방향으로 열림(저장 데이터·스키마는 그대로)                                                       |
| 사진 선택                | 뷰어 25°·AI는 같은 발자국 사진만   | 한 함수(`choosePhotoForView`): 고른 사진 방향 − 카메라 방위                                                  |
| 사진 크기                | 모든 사진을 가로×높이              | 정면·뒤=가로×높이, 왼쪽·오른쪽=깊이×높이                                                                     |
| AI 방향 문구             | 방 기준 벽 이름                    | 카메라 기준(the camera / the right side of the picture / …)                                                  |

**되돌리는 방법:** `FOUR_DIRECTION_VIEWS`(`view-state.ts`)를 `false`로 하면 공간 둘러보기의 위·아래 90° 버튼·방 안 시점·↑↓ 키, 편집기 가운데 3D 방 화면의 위·아래 90° 버튼, 시점 맞춤(`snapRoomView`·`snapFluxOrbit`)과 `turnFluxOrbit`의 위·옆 동작이 돌아온다. AI 입력 시점 선택기(`ai-view-picker.tsx`)의 끌기·위에서/옆에서 버튼·↑↓ 키는 코드를 지웠으므로 상수로는 돌아오지 않는다. 커밋 `df9880f`에서만 되살릴 수 있다(`git show df9880f:src/components/editor/ai-view-picker.tsx`).

## 2. 사진 선택 표

| 고른 사진 | 정면 화면 | 오른쪽 화면 | 뒤 화면 | 왼쪽 화면 |
| --------- | --------- | ----------- | ------- | --------- |
| 정면      | 정면      | 왼쪽        | 뒤      | 오른쪽    |
| 오른쪽    | 오른쪽    | 정면        | 왼쪽    | 뒤        |
| 왼쪽      | 왼쪽      | 뒤          | 오른쪽  | 정면      |
| 뒤        | 뒤        | 오른쪽      | 정면    | 왼쪽      |

없는 방향은 등록된 사진 중 가장 가까운 것(같은 거리면 고른 사진)을 쓰고 알린다. 좌우 뒤집기와 위·아래 사진은 쓰지 않는다.

## 3. 검증 결과

- **단위:** vitest 239개 파일·3,468개 통과(이전 3,433개; 마무리 작업에서 1개 추가). typecheck·eslint·바꾼 파일 Prettier 통과. 병합한 main에서도 다시 확인.
- **e2e:** flux-export 8, room-viewer 7, four-view-photos 1(새), editor·flux-refine·standard-model-switch·guest-workspace·material-images·room-fixtures 36개 모두 통과. 의도한 변경으로 깨진 기존 e2e(위·아래·방 안 시점, 끌기)는 새 규칙에 맞게 고침.
  - 마무리 작업(편집기 가운데 3D 방 화면 제한): 새 `editor-four-view` 1개(위·아래 버튼 없음, 위에서 본 저장 시점을 열어도 저장값·수정 번호 그대로, 오른쪽 90°를 네 번 누르면 네 방향을 한 번씩 돎)와 기존 wall-features-ui 2(제품 선택·끌기·90° 포함), room-fixtures 1, room-viewer 7(1 건너뜀), editor 10, flux-export 8, four-view-photos 1 모두 통과. 네 방향마다 제품을 끄는 e2e는 따로 만들지 않았고, 기존 e2e의 앞쪽 시점 끌기·90° 회전 확인으로 갈음했다.
- **실제 화면(AI 없음):** 제품 4종 방(Q1)과 방향별 사진 4장짜리 시험 변기 방(S1)을 네 방향으로 캡처. 시점마다 표의 사진이 보이고, 옆 사진은 깊이(640mm)만큼 넓게(정면 370mm보다) 그려지며, 바닥 제품은 네 화면 모두 바닥에 닿고 벽 세면대는 벽에 붙음. 사진이 모자란 제품은 대체 사진과 알림이 나옴.
  - 이미지(git 제외): `test-results/product-representation/report/11-four-views-Q1.png`, `12-four-views-S1.png`
- **AI 변환(승인: FLUX 4·Gemma 4, 모두 사용):** S1을 '지금 방식'으로 정면·오른쪽에서 seed 2개씩.
  - 방 윤곽·제품 위치·크기가 입력대로 유지됨.
  - 오른쪽 시점: Gemma 확인이 두 번 모두 "제품 5개가 모두 보여요".
  - 정면 시점: 두 번 모두 "배치한 제품이 바뀌었을 수 있어요"가 나왔다. 근거(`ai/F1-front-s1·s2/지금_방식-정면-call2-answer.json`, git 제외)를 보면 Gemma는 제품 5개 중 직접 그린 시험 변기 2개(2번·3번)를 `present: no, seenAs: other`로 읽었고, 곰 변기(1번)는 "변기가 있음"이었다. 욕조는 첫 seed에서 `no/other`, 두 번째 seed에서는 "있음"이다. 이미지(`13-ai-four-view-S1.png`)에서 AI는 직접 그린 변기를 거의 그대로 뒀고(파란 띠·빨간 점이 남음), 눈에 띄게 바뀐 것은 맨 왼쪽 곰 변기 실제 사진(일반 흰 변기로)이다. 즉 이 경고는 그림이 변기답지 않아 Gemma가 변기로 못 읽은 시험 자료의 영향이 크고, 이번 기능이 만든 문제로 볼 근거가 없다.
  - 이 AI 4회가 말해 주는 것은 "방 윤곽이 유지되고, 오른쪽 시점은 Gemma가 제품 5개를 모두 확인했다" 정도다.
  - 이미지(git 제외): `test-results/product-representation/report/13-ai-four-view-S1.png`
  - 첫 요청 1회는 개발 서버에 AI 연결이 없어 앱이 503으로 막음(모델 미호출, 청구 없음).

## 4. 한계와 남은 일

- 2D 편집기는 고른 사진을 등록한 가로로 그린다. 옆 사진을 고른 제품은 2D와 3D 폭이 다를 수 있다.
- 면 이름(타일 면 문장, "on the back wall", 결과 확인의 벽 이름)은 방 기준 그대로라 정면 외 시점에서는 그림 위치와 다를 수 있다.
- 뒤 화면에서 벽걸이 세면대가 벽에서 떨어져 허공에 떠 보인다(판이 카메라를 향해 벽과의 접촉이 안 보인다). 이미지: `12-four-views-S1.png`, `11-four-views-Q1.png`.
- 정면 화면의 욕조는 3/4 각도 사진 때문에 비스듬하게 떠 보인다(이전 비교와 같다). 사용자가 기준점을 손봐야 한다.
- 방향별 사진이 없으면 대체 사진을 쓰므로 뒤 화면의 변기는 앞모습이다(알림이 나온다).
- 편집기 가운데 3D 방 화면(`RoomCanvasWorkspace`)도 네 방향으로 제한했다(`room-canvas-workspace.tsx`, 같은 `FOUR_DIRECTION_VIEWS`를 따른다).
- 사진이 한 장뿐인 제품은 어느 방향에서도 그 사진이고 방향마다 안내가 나온다.
- 돌리지 않은 것: room-viewer의 user01 실제 보고서 e2e(`SJN_VIEWER_REAL_REPORT=1`일 때만 실행), `tests/*-browser.ts`의 `exportAngles` 비교 스크립트(옵션은 호환용으로 남았고 비교 결과의 뜻이 달라짐).
- AI 변환은 4회뿐이라 품질 결론이 아니라 "입력 구도가 유지되고 제품이 보이는지" 확인으로만 본다.
