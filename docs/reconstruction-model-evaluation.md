# Before 재구성 모델의 로컬 비교 검증

> 이 문서는 초기 CLI 3장·6회 실험의 당시 구현과 기록이다. 현재 개발 전용 테스트 화면에는 별도 후보 연결이 추가됐다. 현재 스키마·설정·UI 연결은 [새 파이프라인](reconstruction-pipeline.md), 36장 평가 결과는 [최종 평가](reconstruction-pipeline-results.md)를 따른다. 아래 초기 실험 수치를 새 구현 결과와 합산하지 않는다.

## 적용 범위

Qwen은 **개발용 비교 도구**로만 추가했다. 앱의 기본 사진 분석은 기존 DeepLab ADE20K Worker를 사용한다. TripoSR 제품 입체화와 BiRefNet 배경 제거는 변경하지 않는다. 앱에서 Qwen을 내려받거나 Ollama를 호출하는 진입점은 없다.

사진은 명시적으로 지정한 로컬 파일을 읽어 `127.0.0.1` 또는 `[::1]`의 Ollama에만 전달한다. 원격 호스트, 리다이렉트, 클라우드 모델 이름을 거부한다. 외부 모델 레지스트리 접근은 개발자가 `--pull`로 모델 다운로드를 요청할 때만 필요하며 사진을 포함하지 않는다. 로컬 Ollama 자체가 신뢰할 수 있는 설치본이어야 한다.

재현 명령(PowerShell):

```powershell
node tests/qwen-reconstruction-evaluation.mjs --photo 'C:\사진\욕실.jpg' --pull
node tests/qwen-reconstruction-evaluation.mjs --photo 'C:\사진\욕실.jpg' --output test-results/reconstruction-qwen-evaluation/my-photo --expected-digest ee4b975b58c17ce268cd19d40db35d5edc64603035d2ffc1fee1968eb0947f7b
npx vitest run tests/qwen-reconstruction-evaluation.test.ts
```

Ollama가 먼저 실행되어 있어야 한다. 첫 명령의 `--pull`은 캐시가 없을 때만 다운로드한다. `--runs`는 기본 2회이며 첫 실행 전에 모델을 메모리에서 내리고 이후 실행은 재사용한다. 모든 실행이 끝나거나 실패·취소하면 선택한 모델을 내린다. 디스크 캐시는 삭제하지 않는다. 기본 요청 제한 시간은 600초이며 `--timeout-seconds`로 조정할 수 있다.

`--baseline`으로 기존 재구성 테스트의 로컬 `result.json`을 함께 기록할 수 있다. 원본 파일을 복사하지 않으며 파일 해시·치수, 원시 응답과 메모리 샘플은 Git에서 제외한 `test-results` 하위에만 저장한다. 서버 어댑터나 프로젝트 저장소에 테스트 결과를 적용하지 않는다.

[Qwen 공식 모델 카드](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct), [정확한 Ollama 모델 태그](https://ollama.com/library/qwen3-vl:4b-instruct-q4_K_M), [Ollama 라이선스](https://raw.githubusercontent.com/ollama/ollama/main/LICENSE), [구조화 출력 문서](https://docs.ollama.com/capabilities/structured-outputs)를 확인했다. Apache-2.0 및 MIT는 상업적 사용을 허용하며 재배포 시 해당 라이선스와 고지를 지켜야 한다. 이번 변경은 Qwen 가중치를 앱 배포 자산으로 포함하지 않는다.

별칭 `qwen3-vl:4b`를 사용하지 않고 Instruct와 양자화를 명시한다. 양자화 모델의 결과를 원본 BF16 모델의 정확도로 보고하지 않는다. 이 구성은 브라우저 실행용이 아니며, 이번 측정으로 저사양 PC나 OCI CPU 환경의 실행 성능을 보장하지 않는다.

모델 출력에는 설비 종류, 좌표, 설치 방식과 벽, 세면대 형태, 반사 여부, 근거·불확실성, 후보 사이의 가림 관계를 요구한다. 공통 스키마 외에 검증 사진의 정답·좌표·기대 개수는 프롬프트에 넣지 않는다.

- 모델 좌표 계약은 `bounds1000`의 0–1000 정수다. 스키마 검증 후 앱과 같은 0–1 좌표로 변환한다. 치수를 mm로 추정하지 않는다.
- Zod로 종류·숫자 범위·유효한 사각형·ID 중복·가림 참조를 검사한다. 유리/창 이외의 물체에 `visibleThrough`가 지정되면 거부한다.
- 바닥 설치와 특정 벽이 함께 반환되면 부착 벽인지 인접 벽인지 확인하라는 경고를 남긴다. 값을 임의로 수정하지 않는다.
- `valid: true`는 데이터 계약 통과만 뜻한다. 인식 정확도, 후보 중복 제거, 설치 벽 확정 또는 자동 적용 가능 여부를 뜻하지 않는다. 모델이 붙인 `physical`도 사실로 검증된 값이 아니다.
- 코드·명령 형태의 텍스트는 실행하지 않는다. 원시 응답은 평가용 파일로만 저장한다. 토큰 제한에 걸린 응답과 잘못된 JSON은 실패로 기록한다.

## 측정 조건과 해석

Windows 11(10.0.26200), Node.js 22.13.1, Ryzen 7 7800X3D(16 논리 스레드), RAM 약 31.15GiB, RTX 4070 Ti 12,282MiB, NVIDIA 드라이버 591.86에서 실행했다. 입력은 EXIF 방향만 정규화하며 원본 픽셀 수를 유지했다. Ollama 내부 이미지 토큰화 해상도는 측정하지 않았다.

최종 공통 설정은 prompt version 2, temperature 0.2, seed 42, top_p 0.8, top_k 20, repeat_penalty 1.05, presence_penalty 1.5, context 8192, 출력 상한 4096토큰이다. 같은 seed라도 GPU와 캐시 상태에서 문장·후보가 완전히 일치한다고 보장하지 않는다.

첫 다운로드는 별도 기록에서 **93.756초**였다. 아래 냉간은 *런타임 모델을 내린 뒤 다시 읽은 실행*이며 OS 파일 캐시를 비운 실행은 아니다. 재실행은 동일 사진의 모델·프롬프트 캐시를 재사용한다. 모델 준비·입력 평가·문장 생성은 Ollama가 보고한 시간을 구분해 기록한다.

메모리는 약 1초 간격의 표본 최대값이다. 장치 VRAM과 시스템 RAM에는 다른 앱이 포함되며, 정밀한 모델 할당 최대값이나 필요 최소 사양이 아니다. Ollama 서버와 `llama-server` 프로세스의 Working Set 합계는 공유 페이지를 중복 셀 수 있고, Private Memory는 실제 상주 RAM이 아니라 커밋된 메모리다. `api/ps`의 `size_vram`은 모델 런타임이 보고하는 할당량으로 별도 기록한다.

기존 기준선은 후보 15개에서 변기·욕조·일반 거울 3개를 배치했고 전체 재구성은 23.659초였다. 주 세면볼의 semanticPixels=3629, meanMargin≈2.338과 미배치 사유가 저장되어 있어 인식 단계 누락이 아니라 배치 단계 제외임을 확인했다. 규칙 개선 후 자동 Before는 해당 세면대를 추가한 4개다. 이 수정이 유리·거울장·선반의 신규 AI 검출을 뜻하지 않는다. DeepLab의 전체 재구성 시간에는 여러 차례 분할 추론, 모형 생성, 저장이 포함되어 Qwen 추론 시간과 직접적인 속도 승패로 비교하지 않는다.

민트 욕실에서는 세면볼 2개와 하부장을 따로 반환하고 같은 basin ID를 사용해 두 실행 모두 거부됐다. 원시 응답에는 바구니·휴지통을 bath로, 커튼을 glassPartition으로 붙인 항목과 반복 후보도 있었다. 응답을 임의로 정정해 성공으로 집계하지 않았다.

공용 예시에서는 기둥형 세면대, 변기, 일반 거울, 오른쪽 창, 왼쪽 문을 올바른 종류로 반환했다. 작은 수건 걸이·휴지 걸이는 unknown이었다. 예시에서 맞춘 기둥형과 검증 사진에서 맞춘 벽걸이형의 구분은 실제 모델 결과지만, 세 장으로 일반적인 정확도를 추정할 수는 없다.

평가 산출물은 다음 ignored 폴더에 있다. 개인 사진과 원시 응답을 커밋하지 않는다.

- `test-results/reconstruction-qwen-evaluation/user-bathroom-measured`: 검증 사진 최종 2회, 상세 시간·메모리·정규화 후보.
- `test-results/reconstruction-qwen-evaluation/mint-bathroom`: 기존 민트 사진 2회와 검증 거부 이유.
- `test-results/reconstruction-qwen-evaluation/example-bathroom`: 직접 제작한 기존 회귀 예시 2회.
- `test-results/reconstruction-planning-baseline`: 수정 전 실제 DeepLab 결과.
- `test-results/reconstruction-improved`: 수정 후 실제 DeepLab 결과. 사용자 보정 결과와 혼동하지 않는다.
- `test-results/reconstruction-qwen-evaluation/pull.json`: 최초 모델 다운로드 시간.

사전 실험도 보존했다. Prompt version 1에서는 모델이 0–1 대신 0–1000 좌표를 반환하고 설명을 반복해 두 번 모두 4096토큰 상한에 도달했다(91.491초/37.487초). JSON 스키마를 프롬프트에도 명시하고 짧은 근거와 좌표 단위를 정리한 공통 version 2로 재평가했다. 또 초기 메모리 관측이 ollama 서버만 포함한 것을 확인해 최종 측정은 실제 `llama-server`도 포함했다. 최종 표에는 이 수정 이후의 측정만 사용한다.

## 한계와 채택 판단

**이번 설정의 Qwen으로 기본 분석기를 교체하지 않는다.** 검증 사진에서 세면대 설치 방식과 유리 존재를 파악한 장점은 있으나, 거울 수납장 구분·반사 중복·설치 벽·가림 구조·다른 사진의 오분류와 반복이 해결되지 않았다. 최대 후보 수 16개까지 불필요한 후보가 채워지는 경우도 있었다.

필요하다면 후속 작업에서 Qwen을 사람이 확인할 후보 제안 용도로 평가할 수 있다. 먼저 더 넓은 정답 자료와 동일한 평가 계약에서 프롬프트/출력 제한/양자화별 재현성을 검사해야 한다. 이번 결과만으로 더 큰 모델이 문제를 해결하거나 더 좋은 정확도를 제공한다고 주장하지 않는다. 사용자 PC에 기본 모델을 추가 다운로드하는 근거로도 사용하지 않는다.

실제 CPU 전용 추론, 저메모리·비 NVIDIA 기기, OCI/Cloudflare 배포, BF16·다른 모델과의 비교는 수행하지 않았다. 3개 사진의 2회 측정은 일반 정확도·최소 사양 검증이 아니다. 최종 `api/ps`의 모델 목록이 빈 상태인 것을 확인하여 GPU 점유를 해제했다.

개발 도구 검증은 단위 테스트 **7개 통과**, 해당 파일의 ESLint·Node 구문 검사 통과다. 단위 테스트의 인공 JSON은 검증기 동작만 검사하며 AI 인식 성공에 포함하지 않는다. 앱의 렌더·편집·저장 및 전체 빌드 결과는 재구성 기능의 별도 검증 기록을 따른다.
