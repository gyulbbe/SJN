# 부분 벽 추정·설치 보정 검증 — 2026-09-13

전체 자동 재구성 목표는 아직 완료되지 않았다. 같은 8장 실제 모델 재실행에서 후보의 자동 배치는 0개에서 1개로 늘었지만, 나머지 주요 설비의 설치 근거와 형태 문제는 남는다. 후보를 기본 분석기로 채택하지 않는다.

## 실제로 달라진 동작

- `partial-wall-geometry.ts`, `analysis.ts`: 세 벽 전체 추정이 실패해도 천장·두 벽 이음선·벽과 바닥 접합선이 관측되면 후면 벽 하나를 보존한다. 가구 앞 윤곽을 방 모서리로 쓰지 않으며, 가려진 코너는 관측선의 교차 추정으로 기록한다. 물리 카메라를 복원했다고 표시하지 않는다. `geometryEvidence`는 문서와 Supabase 검증에서도 유지한다.
- `toilet-observations.ts`, `templates.ts`, 설비 보정 폼: 실제 DeepLab 뚜껑·볼 조합 근거가 있으면 열린 뚜껑을 규칙 추정한다. 선택적 `toiletLidState`가 없는 이전 모형 외형은 유지한다. 사용자가 열림/닫힘을 선택할 수 있고 바꿀 때 다른 치수 출처가 덮어써지지 않는다.
- `source-camera.ts`, `candidate-pipeline.ts`: 보류한 계획을 `modelChecks[].proposedPlacement`에 남기고, 모형의 실제 공간 경계와 방향별 초과 mm를 기록한다. 거부된 계획을 장면에 넣거나 강제 이동·축소하지 않는다.
- `placement-picker.tsx`, 실험실 보정 폼: 바닥/벽 그림의 클릭·드래그, 방향키, 터치로 설치 위치를 정한다. 바닥 방향은 버튼으로 선택한다. 설치 방식·벽 선택과 수동 위치의 값이 연동된다. 원래 제안이 없으면 기본 위치임을 표시한다.
- 치수 출처: 새 `provenance.width/height/depth`는 각 규격의 기본값/사용자 입력을 구분한다. 위치만 바꿔도 기본 규격이 사용자 입력으로 바뀌지 않는다. 기존 `dimensions`는 호환용 요약이다.
- `lab-correction.ts`, 실험실 실행/내보내기: 결과 생성 직전 입력을 복제·고정해 완료 PNG에 연결한다. 이후 입력을 수정해도 이전 결과의 필드·위치·규격·원실행 기록은 바뀌지 않는다. 당시 입력을 원래 편집 칸으로 복원할 수 있다.

## 실제 사진 재실행

원본 4장과 기존 평가 자료의 4장을 같은 설정으로 순차 실행했다. 뒤의 4장도 과거 평가에서 사용된 사진이므로 새로운 미관측 평가 집합으로 주장하지 않는다. 이번 실행에는 강제 설비·수동 위치·정답 좌표를 넣지 않았다.

후보 추가 흐름은 직전 기존 분석을 재사용한 뒤의 추가 모델·배치·렌더 시간이다. 첫 실행 전체 비용은 기존 분석 시간을 더해야 한다. 원출력 합계 43개와 정리 후 42개는 정확도나 실제 설비 개수의 정답이 아니다.

`images.jpg`의 창 하나가 후면 벽에서 배치된다. 설치 높이 약 1163mm는 관측 벽과 기본 창 크기로 계산한 추정이다. 변기와 하부장은 여전히 공간 범위 검증에서 보류된다. 기준선은 창을 추가로 배치하지만, 두 볼이 있는 하부장은 기본 한 볼 모형으로 남는다.

`test 화장실3.jpg`의 기준선은 실제 조합 관측을 사용해 열린 변기를 표현한다. 기둥형 세면대는 여전히 둥근 볼 기본값이며 원본 사각 볼을 제대로 재현하지 못한다. 세면대 모형이 사각형을 지원하는 사실과 실제 분석이 그 형태를 관측했다는 사실을 구분한다.

## 검증 상태

- 전체 ESLint 및 `next typegen && tsc --noEmit` 통과.
- Vitest 80개 파일, 915개 테스트 통과.
- 실제 Chrome 위치 선택기: 클릭·드래그·키보드·잠금·터치·벽 하단 기준점·모바일 폭 검사 통과. AI 정확도 검사가 아니다.
- 실제 앱 Playwright 2개 통과(약 1.5분): 실제 DeepLab 사진 생성→빈 After→저장/새로고침→비교 PNG, 실제 Qwen 실행→형태/설치 보정→위치 그림→추가 AI 없이 교정→완료 입력 불변→당시 입력 복원→JSON/PNG.
- 위 실제 UI 실행 이전 한 번은 실행 허용 환경 변수가 빠져 스킵됐다. 성공 검사로 세지 않았고, 변수를 설정한 별도 실제 실행을 완료했다.
- 비교 보고서의 8개 케이스·32개 이미지 로딩과 확대 검증 통과.
- 뚜껑 모형의 기존 몸체 좌표 보존, 실제 보정 폼과 IndexedDB 저장/재진입, Before undo/redo, 불변 자재 버전 보존은 별도 모형 검증 문서에 기록했다.
- 실제 Supabase 연결, 외부 배포는 실행하지 않았다.
- `npm run build`(Next.js 16.3.4) → `npm run build:vinext`(Vite 8.2.2) 순차 빌드 모두 종료 코드 0. 기존 punycode/glob 및 Vite native config loader의 확장자 안내가 남았으며 배포하지 않았다.

## 시간·메모리 범위

Windows 10.0.26200, Ryzen 7 7800X3D, 16 논리 CPU, Chrome 152.0.7977.83 headless, 렌더러 SwiftShader, DeepLab TFJS WASM 단일 스레드다. 로컬 Qwen 모델은 `qwen3-vl:4b-instruct-q4_K_M`, digest `ee4b975b58c17ce268cd19d40db35d5edc64603035d2ffc1fee1968eb0947f7b`, prompt revision 8, `fixture-inventory-v2`다. 개발 작업을 병행했으므로 엄격히 격리된 성능 벤치마크는 아니다.

런타임이 보고한 모델 VRAM의 샘플 최대값은 4,235,345,264바이트다. 전체 프로세스 RAM이나 전체 GPU의 최고 사용량을 측정한 값이 아니다. 설치 RAM 용량을 사용량으로 보고하지 않는다. 모델 다운로드 크기와 실행 메모리도 구분한다.

## 아직 필요한 개선

자동 결과만으로 네 사진의 주요 설비를 충분히 재현하지 못한다. 확인된 창 하나와 열린 변기 표현, 사용자 위치 보정의 개선을 전체 자동 복원 성공으로 보고하지 않는다.

- 사진 하단 픽셀은 제품 전체 앞끝·받침 접점·가려진 바닥점 중 무엇인지 불명확하다. 후면 벽을 얻어도 가시 바닥 깊이의 기본 65%를 실측값으로 바꿀 수 없다. 통과하도록 깊이·방향을 조절하지 않았다.
- 설치 벽·방향과 벽으로부터의 거리, 또는 사진에 대응하는 실측 바닥 거리 등 최소 기준 확인이 더 필요하다.
- 사각 기둥 세면대의 볼 분리는 이미 시도하지만 이후 어떤 형태 검사에서 실패하는지 확인할 원시 세면대 성분과 단계 진단이 부족하다. 동일 픽셀을 보존해 다음 형태 비교의 근거로 사용해야 한다.
- 잘못된 반사 관계 해제, 상판 세면볼과 하부장 연결 추가, 원본 사진의 후보와 보정 목록을 직접 연결하는 UI는 추가 개선 대상이다.
- 새 위치 선택기와 결과 입력 복원을 실제로 검사했지만, 네 사진 전체를 소수의 확인만으로 완성했다는 사용성 검증은 아직 아니다.

빌드 후 로컬 홈·재구성 실험실·자재 화면은 모두 HTTP 200으로 확인했다. 홈은 개발 서버 첫 응답에 33.48초, 이후 두 화면은 42ms/59ms였다. 마지막 Ollama 실행 목록은 비어 있어 테스트 모델 세션은 해제됐다.
