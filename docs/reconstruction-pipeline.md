## 구조 검증과 항목 격리

현재 모델 응답은 간결한 `fixture-inventory-v2` 계약이다. `bbox_2d` 네 좌표는 정수 0–1000으로 검증하고 내부 사진 좌표 0–1로 **한 번만** 변환한다. 종류·박스·실물/거울 복사 구분·세면볼 형태/지지/개수·짧은 근거를 관측한다. 모델이 방 기하와 ID까지 반복 생성하지 않도록 앱이 안정적인 항목 ID를 부여하며, 반복 관측 자체는 원문과 목록에 남긴다.

손상된 JSON, 지원하지 않는 필드/enum, 정수가 아니거나 범위를 벗어난 좌표, 배열 길이·응답 크기 초과는 구조 오류다. 값 크기로 좌표계를 추측하거나 잘못된 출력을 자동 복구하지 않는다. 명시적 v1 계약은 이전 0–1 좌표로 읽고, 계약이 없는 이전 전체 장면 보고서는 기존 구조 검증기로 읽는다. 알 수 없는 계약은 거절한다. 기존 전체 장면의 중복 ID도 계속 거절한다. 원문과 구조 오류는 보존한다.

이는 [Qwen3-VL 공식 grounding 좌표 규약](https://github.com/QwenLM/Qwen3-VL/blob/main/cookbooks/2d_grounding.ipynb)에 맞춘 입력·출력 연결 수정이다. 올바른 좌표 형식이 올바른 설비 인식을 뜻하지는 않는다. 종류·형태·반사 판단의 오답은 별도 품질 한계로 기록한다.

읽을 수 있는 구조 안에서 설치 방식·지지 구조·접점·부품 관계가 모순되면 정상 후보는 유지한다. 문제 후보에는 `validation.status = needs-review`와 코드·이유를 붙이고 자동 배치를 보류한다. 잘못된 관계는 `validation.quarantinedRelations`에 원래 관계와 함께 남긴다. 방 관측의 의미 오류는 `roomLayoutIssues`로 분리하므로, 촬영 기하를 확정하지 못해도 설비 목록이 사라지지 않는다.

사용자 교정은 원래 관측을 깊은 복사한 별도 결과다. 의미 검증을 다시 수행하여 해결된 항목만 보류를 해제한다. 위치만 지정해서 잘못된 종류·반사·부품 관계를 강제로 통과시키지 않는다. 필드별 `model`, `geometry`, `default`, `user` 출처를 구분하며 모델의 근거 문장 자체를 독립 검증된 사실로 취급하지 않는다.

## 중복·충돌과 세면대 부품

같은 종류·영역의 호환되는 반복 관측은 대표 ID에 연결한다. 원후보·관계 ID는 삭제하지 않는다. 같은 위치의 일반 거울/거울 수납장/창/문처럼 종류가 충돌하면 확인 대상으로 남긴다. 유리 뒤 욕조, 세면볼과 하부장, 거울 반사는 각각 다른 관계다. 단순 중첩만으로 뒤쪽 물체를 지우지 않는다.

세면볼의 사각/둥근 형태와 벽걸이/기둥/하부장 지지 방식을 분리한다. 표현 경로는 다음과 같다.

- 전체 설비 하나: `basinStyle = vanity`, 전체의 `mounting = floor | wall`, 관측한 경우에만 `bowlCount`.
- 부품별 관측: `mounting = countertop`인 세면볼과 `vanity` 부모를 `partOf`로 연결한다. `frontId`는 세면볼, `behindId`는 하부장이다. 볼을 다시 독립된 하부장 모형으로 그리지 않는다.
- 같은 하부장이 여러 ID로 반복됐으면 호환되는 동일 영역의 실물 부모에 한해 canonical ID로 정리한다. 다른 위치·벽·지지 방식·형태·개수·반사 상태의 부모를 임의로 합치지 않는다.

`floor-contact`는 전체 설비의 실제 바닥 접점이다. 세면볼의 `countertop-contact`를 바닥에 투영하지 않으며, 상판 좌표를 `floor-contact`로 잘못 지정한 항목은 보류한다. 부품 연결에는 관측 근거가 있어야 하고, 멀리 떨어지거나 알려진 설치 벽이 다른 세면볼·하부장은 확인이 필요하다.

볼 개수는 명시된 관측/사용자 값 또는 중복을 제거한 부품 개수에서 나온 규칙 추론으로 기록한다. 넓은 하부장이라는 이유로 두 볼을 인식했다고 표시하지 않는다. 새 모형에서 미확인 개수는 기본값으로 표시한다. 이전 저장 모형의 폭에 따른 두 볼 표현은 기존 외형 호환을 위해 유지되며 새로운 AI 관측으로 소급하지 않는다.

하부장 부모의 원래 형태 응답과 자식 세면볼 형태는 구분해 보존한다. 볼 형태·개수의 출처도 각각 집계한다. 서로 다른 형태의 두 볼은 현재 공통 볼 모형으로 자동 단순화하지 않고 확인 대상으로 남긴다. 사용자가 공통 형태를 선택하면 원래 관측과 다른 사용자 선택임을 기록한다.

## 기하와 모형의 실제 범위

촬영 카메라는 사진 좌표를 공간 좌표로 옮길 때만 사용한다. 최종 Before와 After는 같은 공간 치수와 기존 `createRoomCamera`를 공유한다. 실제 관측된 뒤 벽 네 모서리, 충분한 비평면 방 모서리, 또는 평행선의 소실 방향과 실공간에 대응되는 모서리로 촬영 시점을 추정한다. 조건과 수치 안정성이 부족하면 보류한다. 사진 테두리나 타일 모서리를 방 모서리로 대체하지 않는다.

촬영 카메라를 해결하지 못해도 기존 픽셀 분석의 **동일 설비·유일한 대응·실제 방 경계 평면**이 있으면 독립적인 위치 근거로 재사용한다. 설치 방식 모순·반사·의미 오류·화면 밖 잘림·모호한 대응은 재사용하지 않는다. 모델이 기둥형이라고 관측한 볼 부분은 기존 분석의 좁고 연속된 지지대 근거가 함께 있을 때만 전체 기둥과 연결한다. 모델 원래 박스를 늘리거나 카메라를 성공으로 표시하지 않는다.

재사용 위치에는 `baselineEvidence`로 원후보 ID·평면 ID·IoU·접점과 역할·범위·기본 방향 가정을 남긴다. 미정 설치 방식과 벽만 `geometry` 출처로 보완하며 사진 속 좌우를 설치 벽으로 변환하지 않는다. 바닥 앞쪽 접점에서 기본 깊이의 절반만큼 중심을 옮기고, 최종 공간 범위를 벗어나면 보류한다. 실제 깊이·높이를 알아낸 것이 아니므로 확인 안내를 유지한다. 사용자 보정은 이 자동 추정과 별개로 기록한다.

기존 분석의 영역은 `room-boundaries`와 `appearance-region`을 구분한다. 타일 색·무늬를 추출한 작은 영역을 방 전체의 실측 기준으로 쓰지 않는다. 모델이 `roomLayout`을 비웠다고 직각 공간이나 미관측 좌표를 채우지 않는다. 중심 주점·왜곡 없는 핀홀·직사각형 방이라는 가정과 재투영 잔차를 기록한다.

접점은 해당 설비 영역 안에 있고 근거가 있어야 한다. 벽 부착점이 설비의 윗부분에 있을 수 있으므로 그 점과 제품 하단 높이를 구분한다. 사진 범위 하단을 벽에 투영한 높이는 돌출 깊이·가림 영향을 받는 추정값이다. 실제 부착점이나 기준점이 없을 때 사용하는 영역 기반 보완값도 관측 접점과 구분한다.

표준 모형은 사각/둥근 세면대, 기둥/벽걸이/하부장, 한 개/두 개의 볼을 지원한다. 규격은 기본값 또는 사용자 값이며 사진으로 자동 실측한 값이 아니다. 모형 영역의 재투영 오차는 진단이고 연속적인 형상·규격·방향 최적화가 구현된 것은 아니다. 미지원 종류의 형태는 기본 모형과 차이 안내로 남긴다. 열린 변기 뚜껑 상태는 현재 후보 계약/모형 옵션에 없으므로 일반 변기를 찾았다는 결과와 해당 개폐 상태의 재현을 구분한다.

거울은 은회색 표면과 프레임/문 경계를 사용하고 사진 속 반사 풍경을 붙이지 않는다. 유리는 독립 반투명 모형이다. 보이지 않는 수납장 내부나 정밀한 반사·굴절을 복원하지 않는다. 자동 기하가 부족하면 사용자가 종류·설치 벽·지지 방식·높이·크기·위치를 확인한다. 복잡한 레이어·마스크·다각형 편집 UI는 추가하지 않는다.

## 로컬 모델과 실패 진단

- 개발용 Next 서버의 loopback 주소에서만 활성화한다. 프로덕션·Cloudflare에서는 미연결 상태다.
- 브라우저 → 같은 출처 `/api/reconstruction-lab/engine` → 고정 `127.0.0.1:11434` Ollama로 연결한다. 사진과 응답을 외부 AI 서비스에 보내거나 영구 저장하지 않는다.
- 미리 설치된 `qwen3-vl:4b-instruct-q4_K_M`만 사용한다. 모델 자동 다운로드·교체·유료 API 호출은 없다. TripoSR와 제품 배경 제거 모델도 변경하지 않는다.
- 방향 정규화 후 긴 변 최대 1024px JPEG를 전달한다. 모델 내부 이미지 토큰화 해상도는 측정하지 않는다.
- prompt revision 8은 짧은 설비 관측과 명시적 좌표 규약을 사용한다. JSON 스키마를 런타임 `format`과 프롬프트에 함께 제공한다. 특정 모양·개수가 채워진 예시는 모델이 따라 쓰는 현상이 관측되어 제거했다. 자동 재시도는 없으며 사용자가 재시도한다.
- 설치·방 기하를 같은 모델의 두 번째 호출로 보완하는 개발 실험도 실행했으나, 기둥/벽 설치 모순과 유리 경계를 방 모서리로 쓰는 오답이 남아 채택하지 않았다. 현재 후보 버튼은 Qwen 추론 한 번만 실행한다. 기존 관측 근거 또는 사용자 확인으로 배치를 진행한다.
- temperature 0.7, top_p 0.8, top_k 20, presence_penalty 1.5, repeat_penalty 1, seed 17, context 8192, 최대 생성 4096 토큰은 유지한다. 실제 실행 설정과 digest를 보고서에 복사한다.

완료된 런타임 응답에서도 출력 길이 제한, 런타임 오류, 분석 JSON 구조 오류를 분리한다. 실패 전에 `rawText`, 제한된 크기의 `rawRuntimeResponse`, HTTP 상태, `completion.done/doneReason/runtimeError`, 가능한 입력/출력 토큰 수와 출력 제한, 단계·경과 시간을 수집한다. `failure.category`는 `output-limit`, `runtime-error`, `runtime-http`, `runtime-response-json`, `analysis-structure` 등을 구분한다. 응답이 도착하지 않아 없는 값은 추정해 넣지 않는다. 부분 JSON을 완성된 분석으로 적용하지 않는다.

동일 서버 프로세스에서 후보 추론 하나만 허용한다. 앱 제한 시간은 15분이며 전송 계층 제한이나 네트워크 오류가 더 먼저 발생할 수 있다. 미완료 요청은 전용 AbortController로 종료하고 고정 모델 해제를 최대 3초 시도한다. HTTP와 `done: true`가 확인되지 않으면 새 추론을 막고 **연결 다시 확인**에서 읽기 전용 모델 목록으로 부재를 확인한 뒤 회복한다. 원래 오류·cause code·정리 상태는 `transport`에 보존한다. 취소 후 늦은 응답은 다른 결과에 적용하지 않는다. 다른 프로세스나 디스크 모델 캐시를 지우지 않는다.

라이선스 확인 기록은 Qwen3-VL Apache-2.0, Ollama MIT다. 가중치를 앱 배포물에 포함하지 않는다. [공식 모델 카드](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct), [Ollama 라이선스](https://raw.githubusercontent.com/ollama/ollama/main/LICENSE), [구조화 출력](https://docs.ollama.com/capabilities/structured-outputs)을 참조한다. native Ollama 실행 조건과 이번 개발 PC의 결과를 사용자 PC·OCI 성능 보장으로 해석하지 않는다.

## 캐시·보정·저장과 평가

현재 자동 실행의 기존 분석 재사용 키는 사진 바이트 SHA256, 공간 종류/버전/치수, 분석 처리 revision, DeepLab 모델·코드 revision과 설정을 포함한다. 후보 모델 재사용은 추가로 Qwen 모델 digest·prompt revision·응답 계약·실행 설정과 코드 revision을 검사한다. 파일명이 같다는 이유로 재사용하지 않는다. 현재 버전과 맞지 않는 과거 결과는 자동 실행 캐시로 인정하지 않는다.

이전 버전 보고서도 같은 사진·치수이고 원래 관측이 남아 있으면 사용자 교정의 출발점으로 사용할 수 있다. 이 경우 `compatibility = historical-correction`, 원실행 ID·원모델 설정·원시간을 별도로 보존한다. 현재 버전의 새 AI 분석으로 집계하지 않는다. 교정은 모델 재호출 없이 새 모형과 PNG만 만들며, 검증 불가능한 과거 보고서를 자동 재추론하여 대체하지 않는다.

실험은 임시 Map 저장소와 메모리 보고서만 사용한다. 일반 프로젝트·불변 자재 버전·IndexedDB·시안·금액을 수정하지 않는다. 사진 기반 Before와 같은 치수·카메라의 빈 After, 사진 없는 프로젝트의 양쪽 빈 공간을 유지한다. 기본 벽·바닥 보호와 기존 저장·실행 취소·비교·다운로드 흐름도 유지하며 임의 상품 가격이나 견적 수량을 추가하지 않는다.

보고서는 원출력 후보, 정리 후 검토 대상, 실제 배치, 확인 필요를 구분한다. 정리 후 수는 확정된 물리 설비 수가 아니다. 중복·부품·확인된 반사는 독립 설비 수에서 제외하고 충돌·미확인 관측은 검토 목록에 남긴다. 분석 호출이 끝났어도 전부 보류면 **분석 완료, 전체 배치 확인 필요**로 표시한다.

`timing`은 이번 실행의 전체·기존 분석·추가 모델·배치/기타 준비·PNG 시간을 나눈다. 기존 분석 또는 모델을 재사용하면 그 단계의 이번 비용은 0이고 원측정값은 `reuse.*.sourceDurationMs`에 따로 남긴다. 모델의 준비·이미지/프롬프트 평가·텍스트 생성 시간은 전체 요청 시간과 구분한다. 페이지 JS heap, Ollama 모델 VRAM 할당, 장치 RAM 용량은 서로 다른 범위이며 미측정 메모리를 채우지 않는다.

[평가 프로토콜](reconstruction-corpus.md), [기하 상세](reconstruction-source-camera.md), [테스트 화면 사용법](reconstruction-lab.md)을 함께 본다. 개발 사진과 별도 회귀 사례, 실제 모델 관측과 규칙 추론·기본값·사용자 보정, 모의 통신 검사와 실제 추론을 분리한다. 코드 고정 이후 얻은 같은 조건의 결과만 합산한다. 개인 사진·실행 원문·비교 이미지는 Git에서 제외된 로컬 `test-results`에 보관하고 공개 저장소에 추가하지 않는다.

## 이전 버전 기록: 36장 평가 뒤 통신 자원 정리

이 절은 prompt revision 5 평가와 그 직후의 통신 수정 기록이다. 아래의 “모델·스키마·프롬프트를 바꾸지 않았다”는 설명은 당시 통신 수정 범위에 한정된다. 이번 prompt revision 6·항목별 검증·부품 정리 변경의 평가 결과와 합산하지 않는다.

36장 품질 평가는 소스 hash `5409cc3a037947c4319041f89b14238d8f9ec06cb36d90e60f7e12d44c82e562`로 끝냈고, 해당 19개 소스를 `test-results/reconstruction-corpus-final/source-frozen`에 해시 검증 후 보존했다. 이후 `local-engine-server.ts`의 종료 처리만 보완했다. 모델·스키마·프롬프트·샘플링·촬영 기하·모형 배치는 바꾸지 않았다.

종전에는 일반 fetch/body 실패가 caller/deadline signal을 abort하지 않으면 명시적 모델 해제 없이 잠금을 풀 수 있었다. 현재는 전용 AbortController로 미완료 upstream을 종료하고, 해제 시도 동안 잠금을 유지한다. 실패 경과 시간·원래 오류 이름/원인 코드·해제 확인 상태를 별도 진단에 남긴다. 완료된 스키마 거부의 원문·모델 시간은 그대로 보존한다. 해제 실패 뒤에는 새 추론을 차단하고 연결 재확인으로 회복한다.

이 수정은 전송·자원 수명 관리 수정이며 인식 품질 향상으로 집계하지 않는다. 36장 전체 시간은 수정 전 기록이고, 전송 오류 원인 코드를 과거 실패에 소급해 채우지 않는다. runtime 해제는 제한 시간 안의 요청/응답 확인이며 OS나 GPU 작업을 강제 종료하는 보장은 아니다. 다른 앱·프로세스의 추론 잠금을 제공하지 않는다.
