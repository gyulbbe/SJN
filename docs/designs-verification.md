# 다중 시안 관리·복사·비교

현재 시안 생성·복제 한도는 **5개**이며 비교도 **5개**다. 이전 10개 한도에서의 측정·시험 기록은 아래에 보존했다. [5개 한도 변경과 기존 자료 호환](five-design-limit.md) 참고.

2026-09-07 로컬 구현 및 검증 기록. 실제 Supabase 연결·배포는 이번 작업에 포함하지 않는다.

## 사용 방법

1. 프로젝트를 열고 상단 **시안 관리**를 누른다. 새 프로젝트는 **시안 A**로 시작한다.
2. **새 시안**은 공통 기준 공간에서 빈 조합을 만든다. 카드의 **복제**는 현재 구성과 견적을 가져오고 `원본 이름 복사본`을 바로 활성화한다. 썸네일 옆 버튼으로 이름을 바꿀 수 있다.
3. 카드의 비교 체크박스로 최대 5개를 선택하고 **선택한 시안 비교**를 누른다. 데스크톱 2/3개는 한 줄, 4개는 2×2, 5개는 위 3개·아래 2개다. 모바일은 세로 스크롤한다.
4. **이 시안 편집**에서 수정한 뒤 **시안 비교로 돌아가기**로 돌아온다. 선택은 유지하며 수정된 카드만 다시 합성한다. 동기 확대·이동은 기본 활성화, **모두 화면 맞춤**은 모든 위치를 초기화한다.
5. 기존 **Before/After**는 공통 Before와 현재 시안을 비교한다. **내보내기**는 활성 시안의 PNG/JPG 또는 공통 Before/활성 After 좌우 비교다. 비교 카드의 PNG는 그 카드 시안, 비교 화면의 PNG는 선택 시안 배치를 내보낸다.

삭제는 시안 이름을 보여 주고 확인한다. 활성 시안을 삭제하면 다른 시안을 선택하고, 마지막 시안 삭제 시 새로 만들 수 있는 빈 상태를 표시한다. **비교에서 제외**는 시안을 삭제하지 않는다. 기본 벽·바닥 삭제 방지와 수동 영역·레이어 UI 제거는 유지했다.

`ProjectDocument`는 v3만 편집한다. 프로젝트 공통 기준 공간·Before는 `shared`, 각 After/견적/실행 취소는 `designs`에 있으며 최상위 `scene` 별칭을 중복 저장하지 않는다. v1/v2는 읽을 때 메모리에서만 변환하고 다음 정상 조건부 저장 때만 새 형식을 기록한다. 현재 치수와 호환되지 않는 과거 이력은 별도 프로젝트 복원용으로 보존한다.

복제는 진행 중인 초안부터 확정한 최신 메모리 문서를 `structuredClone`하고, 새 시안·면·제품·견적/견적행 ID와 내부 참조를 발급한다. 이미지 및 불변 자재 버전 ID는 공유한다. 타일 seed, 배열, 원근, 마스크, 제품 위치·가림·그림자·색감을 보존하며 복사본 undo는 빈 상태로 시작한다. 수동 단가·수량·할인·메모와 미반영 견적 상태도 유지한다.

`MAX_DESIGNS = 5`, `MAX_COMPARISON_DESIGNS = 5`, `HISTORY_LIMIT = 50`을 공통 규칙으로 사용한다. 생성/복제는 비동기 생성 단계 없이 중앙 명령에서 최신 상태를 원자적으로 추가하므로 빠른 연속 호출도 이미 추가된 시안을 포함해 검사한다. 화면 버튼뿐 아니라 저장/서버 검증 경계에서도 한도를 검사한다.

## 이력과 공통 크기 변경

- 일반 실행 취소는 현재 시안의 장면과 견적에만 적용한다. Before 수정은 공통 Before 기록만 사용한다.
- 크기 변경은 영향받는 시안 수와 초기화 항목을 안내하고 새 배경을 한 번 준비한다. 모든 시안·Before·기준 공간·연결 견적을 한 번에 바꾸며 수동 단가·수량은 유지한다.
- 치수 변경 직전 전체 작업 공간과 각 이력을 최근 1회 백업한다. 일반 undo는 새 치수에서 시작한다.
- **크기 변경 직전 전체 복원**은 이후 시안 편집·생성·삭제·견적 수정까지 되돌린다는 확인을 받고 실행한다. 복원 직전 최신 상태는 **전체 다시 실행**으로 회수한다. 중첩 백업을 만들지 않으며 revision은 되돌리지 않는다.

## 저장·렌더링·출력

확정 편집 뒤 500ms 자동 저장, 단일 쓰기 탭, `storageRevision` 조건부 저장을 유지한다. IndexedDB 트랜잭션 완료 뒤에만 “이 브라우저에 저장됨”으로 표시한다. 저장 실패 시 현재 메모리 문서와 이전 저장본은 보존한다. 시안 선택·비교 선택·줌은 장면 revision을 바꾸지 않는다.

이미지는 Blob 자산으로 저장하고 모든 시안·Before·각 이력·전체 복원 백업·이전 기록의 참조를 확인한 뒤 정리한다. 복제·비교는 원본 자산을 중복 저장하거나 AI를 호출하지 않는다. 브라우저 캐시 `gongganmiri-design-previews-v1`의 썸네일/비교 PNG는 서버 업로드 경로와 분리했다.

비교는 하나의 공통 PhotoCompositor에서 순차 합성한다. 작업 키에 프로젝트/시안 ID, 장면 및 공통 revision, 자재 버전 내용, 출력 크기를 포함하고 오래된 결과는 폐기한다. 썸네일은 360px, 비교 미리보기는 표시 크기와 DPR에 맞춘 최대 2048px다. 다운로드는 같은 스냅샷·합성기를 사용하고 원본/GPU 한도 안에서 전체 긴 변 최대 4096px다. 편집 핸들은 렌더러 밖 DOM/SVG이므로 PNG/JPG에 들어가지 않는다.

테스트 브라우저는 실제 사용자와 분리된 프로필을 사용한다. 시험용 타일/분홍 직사각형 제품/단색 WebGL 자산은 테스트에서 직접 제작했으며 앱의 기본 상품으로 등록하지 않는다.

## 미실행과 한계

- 실제 Supabase SQL 적용·인증·RLS 사용자 격리·비공개 Storage 및 서버 실패 재시도는 미실행이다. 준비 코드와 mock 통과를 서버 검증 통과로 표시하지 않는다. OCI/R2 배포나 자동 업로드도 수행하지 않았다.
- 브라우저 로컬 저장은 다른 PC 동기화 또는 영구 서버 백업이 아니다. 데이터 삭제 시 손실될 수 있으며 PNG는 편집 가능한 문서 백업이 아니다.
- 비교 확대는 캐시 이미지의 표시 좌표만 바꾸므로 큰 확대에서 미리보기가 흐릿할 수 있다. 개별 다운로드는 더 높은 해상도를 사용한다.
- 합성과 PNG 인코딩은 메인 스레드 작업이다. 큰 첫 사진 디코딩·4096px 출력에는 입력 지연이 발생할 수 있다. 성능 수치는 기록한 장면/브라우저/하드웨어 조건의 실측이며 임의 사진·모바일 기기의 속도를 보장하지 않는다.
- 기존 2D 원근·자동 영역 감지·재구성 품질의 한계는 유지한다. 이 기능에서 AI 보정이나 자동 영역 기능을 추가 실행하지 않는다.
