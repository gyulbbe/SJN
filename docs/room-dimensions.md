# 공간 크기로 기본 공간 만들기

사진을 업로드하지 않아도 가로·깊이·높이를 입력해 빈 방을 만들 수 있습니다. 새 기본 공간의 배경, 타일 면, 제품의 원근 크기와 자재 면적은 같은 설정 치수를 사용합니다. 외부 AI나 이미지 생성 서비스는 호출하지 않습니다.

## 시작과 크기 변경

1. 홈의 **기본 공간으로 시작** 또는 **새 프로젝트**를 누릅니다. 홈은 로그인 전에도 서버에서 먼저 그려지므로, 화면이 준비(하이드레이션)되기 전까지 이 버튼들은 잠시 비활성으로 보입니다. 준비 전 클릭이 아무 반응 없이 사라지지 않게 하기 위해서입니다.
2. **가로 (m)·깊이 (m)·높이 (m)**를 입력합니다. 기본값은 각각 **2.4m**입니다. 가로·깊이는 0.5–20m, 높이는 1–6m를 지원합니다. 입력 중 빈 방 미리보기와 바닥 면적을 확인할 수 있습니다.
3. **공간 만들기**를 누릅니다. 바닥·왼쪽 벽·정면 벽·오른쪽 벽이 독립 면으로 준비됩니다. 천장은 중립색 배경으로 보이며 타일 적용 면은 아닙니다. 도기·문·창·예시 자재는 추가하지 않습니다.
4. **내 자재 등록하기**에서 실제 규격과 가격·포장 정보을 등록하고 원하는 면에 적용합니다.
5. 편집 중에는 상단 **공간 크기** 또는 오른쪽 속성의 **공간 크기 변경**에서 치수를 다시 입력하고 **크기 적용**을 누릅니다.

입력 단위는 m이고 문서에는 정수 mm로 저장합니다. 기본값과 입력값은 공간 설정값이며 자동으로 실측 확인 상태가 되지 않습니다. 기존 프로젝트를 열거나 사진을 업로드하는 과정에서 치수 입력을 강제하지 않습니다.

## 타일과 제품 크기

| 대상    | 치수 기준                                                   |
| ------- | ----------------------------------------------------------- |
| 바닥    | 가로 × 깊이                                                 |
| 정면 벽 | 가로 × 높이                                                 |
| 좌우 벽 | 각각 깊이 × 높이                                            |
| 제품    | 등록한 가로·높이, 촬영 이미지 비율, 설치 면 위치, 제품 배율 |

타일은 면 전체의 mm 좌표에서 등록 규격·줄눈·배열·회전·시작점으로 반복합니다. 같은 방에 600mm 대신 1200mm 타일을 적용하면 타일이 더 크게, 적게 보입니다. 방 전체가 화면에 들어오도록 카메라 거리를 조정하며 수직선과 정면 방향은 유지합니다. 카메라를 자유롭게 회전하는 3D 편집은 제공하지 않습니다.

새 기본 공간의 제품은 **설치 면**을 바닥·정면 벽·왼쪽 벽·오른쪽 벽 중에서 선택합니다. 드래그하거나 **면 가로 위치 (%)**와 **면 깊이 위치 (%) / 면 세로 위치 (%)**로 위치를 조정합니다. 바닥의 깊이 0%는 정면 벽 쪽, 100%는 앞쪽입니다. 벽의 세로 0%는 위쪽, 100%는 아래쪽입니다. 같은 제품을 앞으로 옮기면 크게, 안쪽으로 옮기면 작게 표시합니다.

**제품의 방향**은 따로 고르지 않습니다. 자재 등록에서 사진마다 붙인 **각도 이름**이 곧 방향입니다([자재 이미지](material-images.md)). 2D 편집기, 3D 방(공간 둘러보기), AI 변환 입력이 모두 이 이름을 따릅니다. 속성 패널의 "보는 방향" 선택(벽 안쪽 / 앞쪽)은 없앴습니다(2026-10-01).

- **이름의 뜻:** 그 사진에서 제품이 바라보는 방향을, 방의 열린 앞면에서 볼 때로 정합니다. 정면은 앞(보는 사람 쪽, +z), 오른쪽은 방의 오른쪽 벽 쪽(+x), 왼쪽은 왼쪽 벽 쪽(−x), 뒤는 뒤 벽 쪽(−z)입니다.
  - 위·아래는 위나 아래에서 찍은 사진이라 가로 방향이 없습니다. 카메라가 35° 넘게 내려다보거나 올려다볼 때만 AI 내보내기의 사진 후보가 됩니다.
- **방에서의 모양:** 쓰는 각도 사진이 보여 주는 방향 그대로 섭니다. 벽에 맞춰 돌리지 않습니다(옛 방식의 왼쪽 벽 +90°·오른쪽 벽 −90° 곱하기는 없앴습니다). 그래서 정면 카메라에서는 2D 편집기의 그 사진과 같은 모양이고, 3D 방과 AI 입력도 같습니다. 방 기준으로 고정돼 카메라를 따라 돌지 않으므로 오른쪽에서 돌려 보면 옆에서 보이고, 위에서 보면 사진 제품은 얇은 판입니다.
  - 사진 제품의 평면은 항상 정면(+z)을 봅니다. 다른 각도 사진은 이름 차이만큼 돌려 둡니다.
- **벽과 이름이 안 맞을 때:** 막지 않고 알립니다. 어울리는 이름은 왼쪽 벽=오른쪽, 오른쪽 벽=왼쪽, 뒤(정면) 벽=정면, 바닥=아무거나입니다.
  - **놓을 때 자동으로 고릅니다.** 제품을 처음 놓을 때 면을 먼저 정하고, 그 면에 어울리는 이름의 사진이 있으면 그 사진으로 놓습니다(없으면 정면 → 첫 사진으로 놓고 "‘오른쪽’ 각도 사진이 없어 ‘정면’ 사진으로 놓았어요."라고 알립니다). 속성 패널에서 **설치 면을 바꾸면** 지금 사진이 새 벽에 안 맞고 맞는 사진이 있을 때 면과 함께 한 번에 바뀝니다(실행 취소 한 번으로 둘 다 되돌아가고, 바닥으로 바꿀 때는 사진을 건드리지 않습니다). 직접 고른 사진은 면을 바꾸는 순간이 아니면 덮어쓰지 않습니다.
  - 속성 패널이 "각도 ‘X’ · …을 봐요"를 보이고, 직접 고른 사진이 안 맞으면 경고와 **맞는 각도로 바꾸기** 버튼을 둡니다. 어울리는 이름의 사진이 없으면 그렇게 알립니다.
  - 3D 방(공간 둘러보기)의 안내 문구에도 "이 면에는 어울리는 각도가 아니에요"가 붙습니다.
- **접촉:** 보이는 평면의 경계로 맞춥니다. 왼쪽 벽 제품은 가장 왼쪽이 벽 안쪽 면에, 오른쪽 벽은 가장 오른쪽이, 뒤 벽은 가장 뒤가 벽에 닿습니다(사진 평면은 1mm 앞).
  - 옆 벽과 바닥에서는 배치 위치(벽을 따라간 값)가 제품의 가운데입니다.
  - 바닥에 놓는 사진(평면) 제품은 앵커가 바닥에서 max(20mm, 높이의 5%) 안일 때만 바닥에 붙이고 그보다 크면 앵커가 시킨 대로 둡니다. 벽 제품은 앵커의 높이를 그대로 따르고 벽에만 닿습니다. (예전에는 저장한 360° 입체 제품이 앵커와 상관없이 가장 낮은 점을 바닥에 댔지만, 입체 제품은 없어졌습니다. [제거 기록](product3d-removal.md))
  - 3D 방(공간 둘러보기)·AI 변환 입력·내보내기는 같은 함수(`buildViewerFixtures`의 `seatProduct`)를 거치므로 어디서나 같습니다.
  - 그렇게 해도 방 밖으로 나가면 공간 둘러보기 안내에 알립니다.
- **저장:** 방향은 사진의 각도 이름 하나뿐입니다. `roomPlacement.facing`은 더 쓰지 않습니다. 옛 저장본에 남은 값은 읽기만 하고(스키마는 그대로 허용) 화면·렌더에서는 무시합니다.
- **옛 이름:** 읽을 때만 너그럽게 읽습니다(오른쪽 측면→오른쪽, 뒤에서·후면→뒤, 위에서→위, 사선→가까운 옆, front·left·right·back→이름). 목록에도 옛 이름에도 없으면 정면으로 읽고 자재 수정에서 다시 고르도록 안내합니다. 쓸 때는 목록의 이름만 받습니다.
- 옛 360° 자재의 각도는 저장된 캡처 사진(평면)으로 보이고, 위와 같은 규칙으로 놓입니다.

**새 제품의 자리.** 제품을 놓을 때는 같은 면의 다른 제품(잠긴 제품 포함)과 겹치지 않는 가장 가까운 빈 자리를 찾습니다(`src/lib/room-slot.ts`). 제품은 면 위의 상자로 잽니다: 바닥은 가로 × 깊이(자재의 깊이, 표준 모형은 모형의 깊이), 벽은 가로 × 높이이고 둘 다 제품 배율을 곱하며, 기준점이 사진 안 어디인지에 따라 기준점 둘레에 놓습니다. 기본 자리(면 가로 50%, 세로 55%)가 비어 있고 면 안에 들어가면 거기에 놓고, 아니면 50mm 격자로 기본 자리에서 가까운 순서로 훑어 상자가 면 안에 완전히 들어가고 다른 제품과 50mm 이상 떨어진 첫 자리를 고릅니다. 면 좌표는 `roomFacePoint`가 정하는 면 길이로 환산하므로 왼쪽 벽의 u가 뒤집힌 것을 따로 다루지 않습니다. 빈 자리가 없으면 기본 자리에 두고 "놓을 자리가 없어 겹쳐 놓았어요. 위치를 옮겨 주세요."라고 알립니다. **복제**도 같은 함수로 원본에 가장 가까운 빈 자리에 놓습니다(예전의 고정 +4% 이동은 없습니다). 다른 면의 제품끼리(벽걸이 세면대와 바닥 제품), 끌어서 옮길 때, 방이 없는 옛 2D 장면은 겹침을 따지지 않습니다.

**제품 배율**은 기본 100%, 조절 범위는 10–500%입니다. 등록한 가로·높이 외곽 안에 제품 이미지의 보이는 영역을 맞추고 이미지 비율을 유지합니다. 투명 여백은 제외하며 불투명 이미지는 전체 이미지를 기준으로 합니다. 불투명한 흰 배경이나 홍보 여백은 자동으로 제거하지 않으므로 필요하면 제품 등록 시 수동 배경 지우기를 사용합니다. 전체가 투명한 이미지는 배치할 수 없습니다.

촬영 방향을 바꾸면 해당 이미지의 비율과 투명 영역으로 다시 맞춥니다. 등록 규격, 사용자가 정한 배율, 설치 면과 상대 위치는 유지합니다. 제품은 2D 이미지이므로 실제 3D 회전·깊이·충돌·설치 가능성을 계산하지 않습니다. 그림자와 가림은 별도로 조절합니다.

## 기본 면 보호와 이전 저장 자료

기본 벽·바닥은 유지하며 자재·색감·줄눈을 변경하거나 적용 자재를 해제할 수 있습니다. 경계·원근점·면 크기를 직접 편집하거나 면을 삭제하는 도구는 제공하지 않습니다. 전체 가로·깊이·높이는 공간 크기에서 변경합니다. 이전에 저장한 수동 면은 기존 모습대로 읽어 합성합니다.

이전 프로젝트의 공간 크기를 바꿀 때 저장된 수동 보정이 있으면 초기화할 항목과 개수를 보여줍니다. 안내를 읽고 **수동 보정 초기화 확인**을 체크한 뒤 **크기 적용**을 누릅니다. **취소**하면 현재 장면을 바꾸지 않습니다.

- 바닥과 벽 3면은 새 치수로 다시 만듭니다. 기존에 남아 있는 기본 면의 ID·이름·자재·줄눈·배열·회전·시작점·색감은 유지합니다.
- 직접 추가한 면은 제거하고 기본 면의 수동 경계·원근 보정, 전체 보호 영역, 제품 가림 영역, 복원 배경은 초기화합니다.
- 제품의 등록 규격·설치 면·상대 위치·배율·촬영 방향·평면 회전·잠금·순서와 그림자 설정은 유지합니다. 위치와 표시 크기는 새 방에 맞춰 다시 계산합니다.
- 배경을 한 번 준비한 뒤 공통 Before와 모든 시안·자재 수량·가격을 함께 변경합니다. 일반 **실행 취소**는 새 크기의 현재 시안 또는 Before 안에서만 동작합니다. **공간 크기 → 크기 변경 직전 전체 복원**은 이전 크기·장면·자재 설정·각 시안 이력까지 복원합니다. 이후 시안 생성·삭제·자재 설정 변경도 함께 되돌리므로 적용 전 확인합니다. 복원 직전의 최신 작업은 **전체 다시 실행**으로 회수합니다. 백업은 최근 한 번만 보관합니다.

Before는 **현재 치수의 빈 방**입니다. After와 같은 이미지 위치·확대율에서 비교하며, 전체 복원으로 방 크기를 되돌리면 Before도 해당 치수의 배경으로 돌아갑니다. PNG/JPG 출력에는 편집용 손잡이가 들어가지 않습니다.

## 자재 수량·금액 연결

오른쪽 패널은 현재 시안의 After에 적용된 자재를 집계합니다. 기본 공간의 벽과 바닥은 설정 치수를 사용하고 명확한 하위 밴드가 있으면 그 면적을 먼저 배정합니다. 전체 면에는 나머지만 배정하며 보호 영역이나 도기 가림은 자동 차감하지 않습니다.

면별 직접 입력과 타일 수동 구매 수량·단가는 시안별로 보존합니다. 자동 면적과 수량은 공간 크기 변경에 맞춰 갱신하고 전체 복원/다시 실행에도 자재 설정을 포함합니다. 불명확한 사진/수동 영역은 순시공 면적 확인을 요구합니다.

2.4×2.4m 바닥 5.76㎡는 600×600mm 타일 16장 또는 박스당 1.44㎡ 기준 4박스입니다. 가로 3.6m로 바꾸면 8.64㎡, 24장 또는 6박스입니다. 자동 여유분은 가산하지 않습니다. [자재 수량·금액 안내](material-usage.md)를 참고하세요.

## 저장과 기존 프로젝트

선택 필드인 `Scene.room`은 `kind: 'parametric'`, 생성 버전 1, 가로·깊이·높이 mm를 저장합니다. 면은 기본 면 식별자와 자동 연결 여부를, 제품은 설치 면·상대 위치·규격·이미지 비율·투명 영역·배율을 보관합니다. 사진 좌표와 편집 화면의 확대·이동은 분리합니다.

Three.js로 배경 PNG를 만든 뒤 기존 자산 저장소에 원본과 2048px 미리보기를 저장합니다. 생성 원본은 기본 4096×2731px이며 GPU 한도에 따라 축소할 수 있습니다. 실제 출력 비율을 면 투영에도 사용합니다. 크기 변경은 기존 이미지 Blob을 덮어쓰지 않고 새 자산 ID를 사용합니다. 이전 배경은 전체 복원 백업·각 시안 이력과 다른 프로젝트 참조가 있는 동안 정리하지 않습니다.

생성 오류나 취소는 기존 장면을 바꾸지 않습니다. 저장 오류는 현재 작업과 기존 저장본을 유지하고 오류를 표시합니다. 로컬 자료는 해당 브라우저의 IndexedDB에만 저장되므로 브라우저 데이터 삭제에 대한 외부 백업은 아닙니다. 읽기 전용 탭은 생성·크기 변경을 할 수 없습니다.

기존 사진 및 고정 배경 프로젝트에는 `Scene.room`을 자동 추가하지 않습니다. `public/backgrounds/empty-room.png`는 홈 예시 이미지와 이전 프로젝트 호환을 위해 남기며 새 기본 공간 생성에는 사용하지 않습니다. Supabase 경로의 공통 타입·검증은 준비하지만 실제 연결, 사용자 격리와 배포 검증은 별도 항목입니다. 실행 결과는 [검증 기록](verification.md)을 참고하세요.
