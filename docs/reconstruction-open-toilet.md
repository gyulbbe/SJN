# 열린 변기·기둥형 세면대 사진 회귀 보완

이번 검증은 사용자가 제공한 447×447 PNG를 실제 DeepLab ADE20K 분석으로 처리했다. 사진은 로컬 테스트에서만 읽으며 저장소·배포에 포함하지 않는다. 모델과 배경 제거·TripoSR 기능은 교체하지 않았다.

## 실제 원인

변경 전 28.838초 실행에서 후보16개 중 거울1개만 배치됐다. 그 거울은 사진 상단의 실제 거울이 아니라 **열린 변기 뚜껑 내부**를 mirror로 잘못 분류한 영역이었다. 상단의 실제 거울 후보는 없었다.

- 주 세면대: 모델이 기둥을 포함한14,046픽셀을 basin으로 분류했다(meanMargin3.531). 하지만 바닥 접점을 가진 세면볼에서 설치 방식을 전부 unknown으로 남기는 규칙 때문에 미배치됐다.
- 변기: 뚜껑 테두리3,235픽셀은 toilet(meanMargin1.487), 뚜껑 내부는 mirror(2.372), 아래 볼10,879픽셀은 basin(2.963)으로 분열됐다. 단순히 기존1.5점 기준을 낮추면 잘못된 거울과 추가 세면대도 배치된다.
- 재분석: 한 번 연결한 설비의 일부가 뒤집기·확대 분석에서 다시 독립 후보로 돌아오고, 작은 조각의 보류 상태가 전체 설비에 전파되는 문제가 있었다.
- 타일: 이번 실제 재실행에서는 줄눈 반복을 찾았지만 밝은 줄눈 대신 그림자 쪽 색을 선택한 면이 있었다. 엇갈림 배열도 격자로만 전달됐다. “줄눈을 전혀 감지하지 못했다”는 것이 이번 사진 전체의 확인된 원인은 아니다.

## 변경

`candidates.ts`는 같은 세면대 분류 영역의 행별 폭·지지대 연속성을 관측한다. `installation.ts`는 좁고 긴 지지대와 바닥 접점이 함께 있을 때만 기둥형을 제안한다. 바닥에 가까운 볼 하나만으로는 기둥을 생성하지 않는다. 기둥 유무는 규칙 추정이며 모델이 설치 방식을 직접 출력한 것처럼 표시하지 않는다.

열린 변기는 내부 영역 둘레의 toilet 분류와 연결된 아래 볼이 모두 관측되는 경우에만 하나로 묶는다. 실제 원점수는 그대로 두고 별도의 관측 근거와 부품 범위를 기록한다. 일반 벽 거울·거울 속 제품·별도 세면대·휴지통 경쟁 분류를 무시하지 않는다. 관측한 부품 범위는 뒤집기/확대 좌표 변환과 후속 병합에서도 유지한다. UI에서도 직접 분류와 **형태 관계로 추정**을 구분한다.

세면대의 사진 바운딩 박스를 실제 규격으로 확대하지 않는다. 벽걸이·기둥형 등 각 형태의 편집 가능한 기본 규격을 사용하고 기본값임을 기록한다. 실제 사각/둥근 볼 모양, 치수, 설치 벽을 정확히 측정한 것은 아니다.

타일은 실제 줄눈 피크 위치의 색과 양축 반복 근거로 줄눈색을 정한다. 여러 단의 줄눈 위상이 반장씩 교대하는 근거가 있을 때 엇갈림 배열을 기록하며, 자재 생성·저장·렌더링에 같은 배열을 전달한다. 우측 벽의 엇갈림을 직접 관측했고, 좌측·정면은 그 면 자체에 반복 줄눈이 있으며 색과 줄눈 마감도 비슷할 때만 보완한다. 이러한 보완은 경고로 구분한다. 한 축 줄무늬만 있거나 다른 마감·강한 기존 격자·하위 밴드가 있는 면에는 전파하지 않는다. 관측하지 못한 무늬를 원본 사진 조각으로 붙이지 않는다.

## 재현

```powershell
$env:RECONSTRUCTION_PHOTO = '로컬 검증 사진.png'
$env:RECONSTRUCTION_OUTPUT = 'test-results/reconstruction-roomup-final'
npm run test:reconstruction:quality
$env:OPEN_TOILET_PHOTO = '로컬 검증 사진.png'
npx playwright test e2e/reconstruction-open-toilet.spec.ts
```

분석용 브라우저 실행기는 파일 확장자나 고정 JPEG 선언을 신뢰하지 않고 실제 JPG/PNG/WebP 헤더를 읽는다. 이미지에는 실제 모델 추론 및 일반 규칙 결과만 포함한다. 이 테스트를 위해 수동으로 설비를 추가하거나 좌표를 주입하지 않았다.

## 남은 한계

현재 분할 모델이 상단의 실제 거울과 유리 파티션을 감지했다고 보고하지 않는다. 표준 모형의 볼 형태와 설치 벽·방 모서리·실제 크기도 추가 확인이 필요하다. 확인되지 않은 거울이나 샤워 설비를 정답 위치에 자동 추가해 성공으로 집계하지 않는다. 원본 사진·기존 저장 프로젝트·불변 자재는 보존되며, 기존 프로젝트의 새 분석은 명시적인 재분석 흐름을 이용한다.

## 최종 실제 검증 결과 (2026-09-13)

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 자동 배치 | 잘못된 거울 1개 | 변기 1개, 기둥형 세면대 1개 |
| 열린 변기 | 테두리·뚜껑·볼 분리 | 관측 부품 관계로 한 설비를 제안 |
| 세면대 | 인식 후 설치 판단에서 보류 | 좁고 연속된 기둥과 바닥 접점으로 기둥형 추정 |
| 실제 상단 거울·샤워 유리 | 미검출 | 여전히 미검출; 수동 추가를 AI 성공으로 집계하지 않음 |
| 벽 타일 | 어두운 줄눈, 격자 | 밝은 줄눈, 우측 직접 관측 엇갈림 + 좌측·정면 보완 |
| After | 빈 공통 공간 | 빈 공통 공간 유지 |

최종 실행은 **29.3275초**였다. 사진 가져오기, 여러 분석 패스, 기본 공간과 모형 자산 생성을 모두 포함한다. Windows 10 계열, Headless Chromium 152, 16 논리 스레드 노출, DeepLab ADE20K / TFJS WASM 단일 스레드, 입력 447×447, 렌더러 SwiftShader 조건에서 한 번 측정했다. 동시에 개발 검증이 진행돼 변경 전 28.838초와의 차이를 속도 개선/저하로 판단하지 않는다. 모델 다운로드 시간이나 순수 추론 시간만을 뜻하지 않는다.

메인 페이지 JS heap 관측 최대는 **12,845,449바이트**였다. Worker·WASM·GPU·전체 프로세스 RAM은 포함하지 않으므로 앱 전체 메모리 사용량으로 해석하면 안 된다. 이 실행에서 브라우저 오류와 외부 요청은 모두 0이었다.

## 자동 검사

- 전체 Vitest: **61개 파일, 574개 테스트 통과**.
- 실제 사진 Playwright: **1개 통과**. 자동 변기·세면대, 가짜 거울 제외, 기본 치수 표기, 빈 After, 저장·새로고침, 4096px 비교 PNG 다운로드 확인. 제품·후보 수동 주입이나 모델 모의 응답은 사용하지 않았다.
- ESLint: `npm run lint` 통과, 오류·경고 0.
- 타입 검사: `npm run typecheck` 통과.
- Next.js 빌드: `npm run build` 통과(16.3.4).
- Cloudflare용 vinext 빌드: `npm run build:vinext` 통과. 기존 Node punycode/glob 및 Vite native loader의 확장자 없는 import 안내는 남아 있으며 배포는 하지 않았다.
- 빌드 후 로컬 `/`, `/materials` HTTP 200 확인.
- 관련 음성 테스트: 벽 거울·반사·별도 세면대·휴지통 경쟁 후보 보류, 지지대 없는 볼·좁은 배수관·벽 줄무늬 제외, 양방향 줄눈·그리드·엇갈림 및 무근거 벽 전파 제외.

주요 변경 파일은 `candidates.ts`(관측·후보 병합), `installation.ts`(설치 판단·배치), `analysis.ts`(타일 관측), `index.ts`(기본 치수·배열 전달), `segmentation/worker.ts`(완성된 부품 묶음의 재분리 방지), `types.ts`와 Supabase 검증(선택적 근거 필드), 재구성 검토 화면(추정 표시)이다. 저장 포맷의 필드는 선택적이며 원본 자산·불변 자재 버전은 덮어쓰지 않는다. 실제 Supabase 연결·배포는 실행하지 않았다.

기존 프로젝트에서 다시 적용하려면 재구성 검토 화면의 **사진 다시 분석 → Before 다시 만들기**를 사용한다. 기존 Before는 실행 취소로 되돌릴 수 있고 After 시안은 유지된다.
