## 현재 사실과 목표

현재는 관측 후보, 중복/충돌/부품/반사, 설치 판단, 공간 기하, 표준 모형 생성을 분리했다. 세면볼 형태와 벽걸이/기둥/하부장 지지, 두 볼, 열린 변기, 중립 거울, 반투명 유리, 설치 위치 보정과 저장 흐름도 있다. 현재 코드로 확인해서 해결된 기능을 중복 구현하지 않는다.

하지만 자동 재구성 품질은 충분하지 않다. 특히 다음 문제가 남아 있다.

1. 별도 회귀 사진에서 흰 세면대와 변기가 갈색으로 표현됐다. 조명·주변 벽·그림자 색이 제품 색에 섞였는지와 색상 출처가 잘못 기록됐는지 조사해야 한다.
2. 설치 벽·방향·높이·제품 중심과 실제 지지 접점이 불명확해 후보 배치가 자주 보류된다. 보류를 줄였다는 이유만으로 잘못 배치한 결과를 개선으로 세면 안 된다.
3. 사각 기둥의 단면, 유리 파티션 방향·폭, 거울장의 전체 폭, 하부장 길이, 가려진 제품의 형태는 근사에 머문다.
4. 공통 기본 공간과 원사진의 좁은 구도가 다르다. 방 실측값과 원사진 촬영 카메라를 구분해야 한다.

목표는 사용자가 원래 설비를 알아볼 수 있고, 적은 확인으로 필요한 위치와 형태를 맞출 수 있는 Before다. 완전 자동 복원·사진과 똑같은 숨은 형상·실측 정밀도를 이번 완료 조건으로 임의로 확대하지 않는다.

## 1. 제품 색과 재료 표현을 먼저 고친다

실제 문제가 나온 사진에서 픽셀 선택 → 제품 색 추정 → provenance → 재료 설정 → 색공간 변환을 추적한다. 배경이 섞인 bbox 평균, 반사·그림자 픽셀, 잘못된 색상 공간 변환 등을 각각 확인하고, 확인된 원인만 수정한다.

확실한 제품 내부 관측을 사용하고, 거울·유리에는 그 뒤 배경이나 반사 풍경의 색을 제품 고유색으로 적용하지 않는다. 흰 도기의 어두운 그림자를 갈색 제품으로 굳히지 않도록 하되, 실제 파란색·회색·검은색 제품을 전부 흰색으로 바꾸는 규칙은 금지한다.

사진의 조명과 제품 고유색을 한 장으로 완전히 분리했다고 주장하지 않는다. 근거가 부족하면 중립 기본색/확인 필요를 표시하고 기존 간단한 설비 속성에서 사용자가 색을 확인할 수 있게 한다. 모델 관측·규칙 추정·기본색·사용자 색을 필드별로 저장한다. 거울은 중립 은회색, 유리는 독립 반투명 표면을 유지한다.

## 2. 개별 좌표보다 설치 관계를 활용한다

세면대와 거울/거울장, 욕조와 유리, 세면볼과 하부장의 현재 관계 처리를 조사한다. 이미 있는 ‘세면대·하부장 위에 맞추기’는 선택 시점의 위치 복사다. 이 동작을 사용자에게 알리지 않고 동적 연결로 바꾸지 않는다.

설치 후보에는 관측 근거, 벽 부착 또는 바닥 지지, 제품 앞뒤 방향, 기준점 역할, 기본 치수를 구분해 유지한다. 세면볼 bbox 하단을 기둥 접점으로 쓰거나, 사진 왼쪽 물체를 무조건 왼쪽 벽에 붙이지 않는다.

관계와 공간 범위가 확실하면 이를 이용해 위치 확인 입력을 줄인다. 복수 배치가 가능하면 2~3개 대안과 차이를 보여주거나 필요한 벽/방향/높이만 묻는다. 사용자 선택 전에는 추정값이며, 선택한 경우 사용자 확인으로 기록한다. 원사진별 좌표·파일명·해시를 사용하는 특례, 벽 침범을 숨기는 강제 이동/축소는 금지한다.

## 3. 촬영 기하는 별도로 평가한다

기존 source-camera, 관측 벽·바닥, 접점, 오프라인 depth/평면 실험을 먼저 확인한다. 기존 실험의 낮은 배치 성공률과 미확정 가설을 자동 승인하지 않는다.

추가 기하 개선을 구현하면 관측된 경계·소실 방향·가림을 이용하고, 거울·유리·열린 창짝을 방 경계로 오인하지 않는지 검사한다. 실제 모형을 원사진 시점으로 재투영할 수 있을 때 위치/윤곽 차이를 평가한다. 입력 bbox를 그대로 출력해 재투영 오차가 작다고 보고하지 않는다.

정보가 부족한 부분은 보류하고 간단한 사용자 확인을 제공한다. Before와 After의 공통 카메라·치수는 유지한다. 촬영 카메라 추정의 개선과 공통 공간 렌더링의 개선을 별도로 보고한다.

## 4. 모델 교체는 증거가 있을 때만 제안한다

DeepLab의 픽셀 관측, 로컬 Qwen의 설비/관계 이해, 표준 모형 렌더러의 역할을 구분한다. Qwen이 응답을 정상 종료하거나 후보를 많이 찾은 것만으로 기본 엔진으로 채택하지 않는다.

필요하면 현재 로컬 엔진과 추가 후보를 같은 평가 자료에서 비교한다. 추가 모델의 현재 라이선스·실행 환경·메모리 조건은 공식 자료로 확인한다. 새 대형 모델을 사용자 브라우저에 기본 다운로드하지 않는다. TripoSR와 제품 배경 제거 모델은 변경하지 않는다. 유료 API, 외부 사진 전송, 배포는 하지 않는다.

## 5. 테스트 화면에서 결과와 수정량을 비교한다

홈의 ‘사진 재구성 테스트’와 `/reconstruction-lab`을 그대로 사용한다. 동일 사진·실측 또는 동일 기본 방 크기·관측 입력을 고정하고 변경 전후를 별도로 보존한다.

검증 사진은 `C:\Users\H\Downloads\TEST 화장실.jpg`, `TEST 화장실2.jpg`, `test 화장실3.jpg`, `images.jpg`와 앞서 기록한 별도 회귀 사례를 사용한다. 네 사용자 사진과 이미 결과를 본 사례는 개발 회귀로 분류한다. 새로운 평가가 필요하면 결과를 보기 전에 선정과 판정 기준을 고정한다.

표시·보고 항목은 제품 색, 종류/형태, 설치 벽/지지, 상대 높이/방향, 누락/오탐, 중복/반사, 사용자 보정량, 처리 시간이다. 사진에 실측 정답이 없으면 mm 정확도라고 부르지 않는다. 자동화 스크립트의 이벤트 수를 사람의 최소 클릭 수로 보고하지 않는다.

실제 AI 실행, 저장된 실제 관측의 재생, 사용자 입력, 모의 실패 검사를 분리한다. 모델/관측이 바뀌지 않은 UI 수정은 저장 관측 재생으로 검증하고 불필요한 모델 재실행은 하지 않는다. 실행 중에는 기존 핸들을 따라가며 timeout만으로 같은 추론을 중복 시작하지 않는다.

## 완료와 보존 조건

- 실제 원인 수정, 흰 제품 및 유색 제품 비교, 주요 설치 관계/형태 확인, 사용자 수정 가능 여부를 검증한다.
- 저장→새로고침→undo/redo→시안 복사→비교 PNG를 확인한다. 사진 기반 Before/빈 After, 사진 없이 양쪽 빈 공간을 유지한다.
- 기존 자재 수량/금액에 가짜 가격·상품 수량을 추가하지 않는다. 원본/불변 자재 버전, 기본 벽·바닥 보호, 간단한 설비 UI를 유지한다.
- 관련 단위·브라우저 검사, lint·타입 검사, Next.js 다음 vinext 순차 빌드를 실행한다. 확인되지 않은 기능을 통과로 표시하지 않는다.
- 보고서에 전후 이미지, 수정 원인과 파일, 자동/규칙/기본/사용자 값, 실제 시간과 측정 환경, 남은 오판을 기록한다. 메모리는 실제 측정 범위만 보고한다.
- 위 범위의 구현·검증을 마치면 완료한다. 완전 자동 생성이나 모든 사진의 정밀 일치를 새로운 완료 조건으로 계속 추가하지 말고, 남은 한계와 다음 실험을 분리해서 인계한다.
