### 공간 구조 관측

- 현재 DeepLab 픽셀 관측, 로컬 Qwen 설비 관측, 기존 코너·선·깊이·평면 실험과 캐시를 조사한다.
- 실제 실행 가능한 기존 경로부터 연결한다. 개발용 실험만 존재한다면 정상 호출에 연결하기 위한 인터페이스·실패 처리·지원 환경을 구현한다.
- 벽/바닥 경계, 관측 가능한 모서리·소실 방향, 신뢰할 수 있는 깊이/평면 정보 등 어떤 근거를 쓰는지 기록한다.
- 렌즈 왜곡, 좁은 시야, 가려진 바닥, 일부만 보이는 방, 낮은 벽·단차 때문에 정보가 부족한 경우를 구분한다.
- 상대 깊이를 근거 없이 mm 절대 깊이로 해석하지 않는다. 이미지 전체나 보이는 바닥 일부를 방 전체 면적으로 간주하지 않는다.
- 거울 속 방, 유리 뒤의 실제 벽, 창 밖 풍경과 문틀을 구분한다.
- 직사각형 기본 공간에 표현하기 어려운 단차나 구조는 한계를 표시한다. 모형 몇 개가 보인다는 이유로 원본 구조가 정확히 재현됐다고 보고하지 않는다.

### 설비 배치

- 바닥형 제품: 실제로 관측 가능한 접지·지지 정보, 바닥 평면, 방향, 제품 기준점을 사용한다.
- 벽걸이 세면대·거울/거울장·선반: 설치 벽과 부착 높이 기준으로 계산한다. 바닥 접점이 없다는 이유로 삭제하지 않는다.
- 기둥형·벽걸이형·하부장형 세면대, 사각/둥근 세면볼을 구분한다.
- 세면볼 bbox 하단을 기둥 접지점으로 쓰지 않는다. 화면 왼쪽 위치를 실제 왼쪽 설치 벽으로 단정하지 않는다.
- 유리: 방향·두께·폭·지지 관계를 가진 독립 반투명 설비로 취급한다. 유리 뒤 욕조·변기·벽은 함께 존재할 수 있다.
- 세면대–거울장, 세면볼–하부장, 욕조/샤워–파티션 관계를 이용하되, 관측되지 않은 제품을 관계만으로 생성하지 않는다.
- 물체 중심·앞면 접점·벽 부착점의 정의, 축·단위·회전·정규화 좌표 변환을 공통 계약으로 맞춘다.
- 방 밖 위치를 숨기기 위한 강제 이동·축소는 금지한다. 유효한 대안이 있으면 근거와 불확실성을 가진 새 제안으로 기록한다.

### 두 카메라 분리

- 원사진 촬영 카메라는 사진 좌표를 공간 위치로 해석하는 용도다.
- Before/After 공통 표시 카메라는 시안을 같은 구도로 비교하는 용도다.
- 실제 생성 모형을 추정 원사진 카메라로 재투영할 수 있을 때만 위치·윤곽 차이를 평가한다.
- 입력 bbox를 그대로 그려 재투영 정확도라고 하지 않는다. 원사진 카메라가 미확정이면 해당 정확도는 평가 불가로 표시한다.
- 확인되지 않은 촬영 자세를 Before/After 공통 카메라에 덮어써 비교 구도를 깨뜨리지 않는다.

## 5. 결과 표현과 간단한 확인 흐름

- 주요 설비가 자동 배치되는 경로를 먼저 개선한다. 종류별 모형이나 수동 입력창 추가만으로 품질 개선을 완료하지 않는다.
- 충분한 근거가 있는 추정 배치는 추정값임을 표시하고 제안한다. 증거가 없는 위치는 확정하지 않는다.
- 위치가 미확정인 후보도 보존하고 구체적 이유를 표시한다. “설비를 찾지 못함”과 “찾았지만 설치 위치 미확정”을 구분한다.
- 여러 설치 대안이 가능하면 근거 있는 소수 대안 또는 설치 벽·방향·높이 중 필요한 값만 확인하는 기존 간단한 UI로 연결한다.
- 확인·수정은 user 출처로 기록하고 자동 결과를 별도 보존한다. 사용자 확인 이전 결과가 자동 성능 평가의 대상이다.
- 복잡한 레이어 목록·수동 마스크·다각형 편집 UI를 다시 추가하지 않는다. 기본 벽·바닥 삭제 방지를 유지한다.
- 거울과 거울 수납장은 원사진 반사 풍경을 잘라 붙이지 않는다. 중립 은회색 표면·하이라이트·프레임·문 경계로 표현한다.
- 거울 속 중복은 제외하되, 유리 뒤 실제 설비는 중복이나 충돌로 제거하지 않는다.
- 흰 도기에 배경색·어두운 그림자가 묻어 제품 고유색이 바뀌는지 확인한다. 실제 노란/하늘색 제품을 모두 흰색으로 바꾸지 않는다.
- 사진으로 시작하면 재구성 Before와 같은 치수·공통 카메라의 빈 After, 사진 없이 시작하면 양쪽 빈 기본 공간을 유지한다.
- 재구성용 표준 설비에 임의의 판매 가격이나 견적 제품 수량을 추가하지 않는다.

## 6. 모델 변경과 실행 환경

- DeepLab은 픽셀 관측, 로컬 Qwen은 설비·관계 이해, 기하 계산은 공간 추정, 표준 모형은 표현이라는 역할을 구분한다.
- 우선 현재 모델과 코드로 연결·좌표·설치 규칙 문제를 수정한다. 모델 교체만으로 해결된다고 가정하지 않는다.
- 인식 또는 공간 구조 관측의 품질이 실제 병목으로 남으면 현재 로컬 Qwen3-VL 실험 경로와 가능한 추가 후보를 동일 입력·조건에서 비교한다.
- 신규 모델/라이브러리 도입 전 공식 자료에서 최신 라이선스·상업 이용 조건·지원 환경·메모리 요구를 확인하고 출처를 남긴다.
- 사용자 브라우저에 대형 모델을 기본 추가 다운로드하지 않는다. 개발용 로컬 모델이 필요한 경로는 실행 가능 조건을 명시하고, 해당 모델이 없는 배포 환경에서 조용히 다른 결과를 반환하지 않는다.
- TripoSR 제품 360° 입체화와 제품 배경 제거 모델은 이번 작업에서 변경하지 않는다.
- 유료 API·외부 사진 전송·외부 배포는 하지 않는다.
- 실행 환경이 부족하면 어떤 실험이 미실행인지 기록한다. 가능한 코드 개선·실제 검증은 계속 완료하고 모델 성공을 꾸며내지 않는다.
- 긴 추론은 진행 상태·취소·실패·재시도를 처리한다. 단순 timeout으로 실행 중인 추론을 중복 시작하지 않는다.
- 사진·기하·후보 입력의 hash, 모델 revision, 전처리 설정, 방 치수와 관련된 캐시 키를 검증한다. 다른 사진·설정·과거 응답이 섞이지 않게 한다.

## 7. 내가 다음 작업을 맡기기 쉽게 진단을 남길 것

기존 진단 JSON·IndexedDB 보관·새로고침 후 다운로드를 확장한다.
후보 ID는 원관측부터 생성 설비까지 추적 가능하게 유지한다. 통합·분할 시 부모 후보 ID를 남긴다.

다음 정보를 명확한 필드로 기록한다.

- runId, caseId, 입력 hash/치수/방향 정규화, 방 치수와 measured/default 출처.
- 코드 버전/변경 상태, 엔진·모델 ID/revision, 분석 설정, 캐시 사용 여부.
- 원모델 후보, 종류 정규화, 반사/부품 병합, 설치 방식, 지지면/접점, 위치, 범위 검증, 모형 생성의 단계별 입력·출력·소요 시간.
- 실제 공간 구조 분석이 실행됐는지, 관측값이 어느 함수로 전달되고 사용됐는지, 근거 부족·실행 실패·캐시 재사용·미실행 중 어느 상태인지.
- rawMounting / effectiveMounting / mountingSource와 실제 최종 배치 보류 원인을 분리한다. 'unknown' 문자열 때문에 보완 후 상태가 가려지지 않도록 한다.
- 물리적 설비 / 반사 / 부품 / 중복 / 미지원 종류 / 인식 누락 / 기하 미확정 / 배치 오류 / 렌더 누락을 다른 사유로 기록한다.
- 각 필드 출처를 model / geometry-derived / rule-inferred / default / user 등 검증 가능한 형태로 구분한다.
- 자동 결과, 사용자 확인 결과, 저장된 실제 관측 재생, 모의 실패 테스트를 분리한다.
- 첫 원인과 후속 연쇄 실패를 함께 연결한다. 하나의 카메라 실패가 여러 제품에서 반복된 것을 여러 독립 인식 실패로 세지 않는다.
- 실패·취소·늦은 응답에도 이미 확보한 근거를 보존한다. 삭제되거나 다른 실행으로 바뀐 화면에 늦은 결과를 적용하지 않는다.

기계가 읽을 summary.json과 사람이 읽을 원인표를 함께 만든다.
민감정보·바이너리·이미지 본문을 불필요하게 JSON에 중복하지 않는다. 상세 근거는 상대 파일 경로와 JSON 경로로 연결한다.
기존 용량 한도와 저장 실패 시 이전 로그 보존을 유지한다.

## 8. 실행 순서와 실제 검증

1. 현재 상태와 원본 9장을 보존하고 케이스 manifest를 만든다.
2. 동일한 기존 설정으로 변경 전 결과를 확보한다. 이전 실제 결과를 재사용하면 hash·설정·코드 상태의 일치 여부를 확인하고 재사용 사실을 기록한다.
3. 원후보부터 모형까지 추적하여 연결 문제와 실제 인식/기하 품질 문제를 분리한다.
4. 작은 단위로 수정하고 좌표·기하·설치 규칙은 저장된 실제 관측 재생과 단위 테스트로 검증한다.
5. 최종 후보 경로는 9장 모두 실제 분석부터 렌더링까지 실행한다. 테스트 모의 응답을 최종 평가에 사용하지 않는다.
6. 원본과 자동 결과를 직접 보며 케이스별 판정표를 작성한다. 요청한 비교 이미지를 실제 생성 이미지로 조합한다.
7. 미확정 후보의 간단한 확인 흐름도 시험하되, 결과와 점수는 자동 결과와 분리한다.
8. 정상 사용자 진입 경로에서 사진 → Before / 빈 After 생성, 저장·재진입·출력까지 연결되는지 확인한다. Lab에서만 동작하는 별도 우회 구현으로 끝내지 않는다.
9. 각 수정 이후 새 우려가 없으면 같은 고비용 추론을 의미 없이 반복하지 않는다. 최종 실행에 쓴 코드와 보고서·스크린샷이 같은 상태여야 한다.

### 케이스별 평가

- 사진에서 확인 가능한 주요 설비와 실제 인식한 설비.
- 올바른 종류·형태·설치 방식의 개수, 누락·오탐·반사 중복 수.
- 인식 후보 중 위치 제안 가능/자동 배치/사용자 확인 필요/명확한 제외의 수와 이유.
- 설치 벽·상대 높이·앞뒤 방향·설비 사이 상대 위치의 시각적 적합성.
- 벽걸이 세면대가 기둥형이 되는 오류, 휴지통이 변기로 되는 오류, 유리 뒤 설비 삭제.
- 재구성 모형의 색과 거울·유리 표현.
- 실제 사용자 확인이 필요한 항목. 자동화 이벤트 수를 사람의 최소 클릭 수로 보고하지 않는다.

배치 개수만 늘어난 것은 통과가 아니다. 잘못된 위치·오탐·중복이 늘었는지도 함께 본다.
remote-05에서 설치된 주요 설비가 0개인 결과를 실패로 분류하지 않는다.
표준 모형 근사와 원본 형태 정밀 복원을 구분한다. 측정 정답이 없으므로 mm 정확도 점수는 만들지 않는다.
일부 사진이 개선되지 않으면 해당 케이스를 실패/부분 개선으로 남기고 실제 병목을 설명한다. 이를 전체 통과로 묶지 않는다.

### 비교 이미지

- 9행 × 3열의 비교표를 만든다: 원본 / 변경 전 자동 결과 / 변경 후 자동 결과.
- 각 행에 caseId, 사진 이름, 주요 누락·배치 상태를 짧게 표시한다.
- 한 장으로 볼 수 있는 PNG와 확대 가능한 HTML, 개별 원본/전후 결과 PNG를 제공한다.
- 모든 재구성 전후 결과는 동일한 공통 표시 카메라·방 치수·출력 크기를 사용한다.
- 생성 결과를 비교용으로 손으로 보정하거나 생성형 이미지 도구로 개선하지 않는다.
- 수동 확인 결과가 있으면 별도 비교 자료로 제공하며 자동 결과 열에 섞지 않는다.
- 미리보기와 다운로드는 동일한 스냅샷·렌더링 결과를 사용한다. 편집 핸들·선택선·확인 UI는 출력에 포함하지 않는다.

## 9. 자동·브라우저 회귀 검사

- 기하 입력이 실제 생성되어 정상 호출에 전달되는 통합 테스트.
- 미확정 기하, 비직각/부분 공간, 잘못된 코너, 데이터 유한성, 좌표 왕복, 기준점·단위·회전 검증.
- 벽걸이/기둥/하부장 세면대, 일부 잘린 제품, 거울 속 중복과 유리 뒤 실제 제품의 처리.
- 원후보·보완 후 상태·실제 최종 보류 원인의 진단 일치.
- 사진 간 캐시 격리, 설정 변경 무효화, 취소·재시도·늦은 응답·WebGL 실패.
- 저장·새로고침·Before undo/redo·시안 전환/복사·Before/After 비교·PNG 다운로드 회귀.
- 로그 저장 실패·한도 정리·새로고침 후 진단 JSON 내보내기.
- 대표적인 정상 사용자 생성 흐름을 실제 브라우저에서 검증한다.
- 관련 Vitest/Playwright, lint, 타입 검사, Next.js 빌드, vinext 빌드를 실행한다. 실제 package.json의 명령을 확인해 사용하고 두 빌드는 충돌하지 않도록 순차 실행한다.

## 10. 완료 보고와 결과 보존

새 보고서를 docs 아래에 작성하고 결과 경로를 연결한다. 최소 다음 내용을 포함한다.

- 확인한 근본 원인, 수정한 코드 파일/함수, 실제 연결 전후 차이.
- 9장 케이스별 변경 전후 평가와 남은 실패.
- 실제 모델이 관측한 값 / 규칙·기하 추정 / 기본값 / 사용자 확인의 구분.
- 실제 생성 비교 이미지와 재현 명령, 입력 manifest, 모델/코드/설정 버전.
- 모델 다운로드·모델 준비·추론·기하 계산·렌더링·전체 처리 시간. 캐시가 준비된 실행과 최초 실행을 구분.
- CPU/GPU, RAM, OS, 브라우저와 WebGL 백엔드, 실행 장치, 동시 작업 조건.
- 메모리는 실제 측정한 프로세스/RAM/VRAM 범위와 방법만 보고한다. 측정하지 못한 값은 미측정으로 표시한다. 소프트웨어 WebGL 시간을 사용자 GPU 성능처럼 보고하지 않는다.
- 통과한 테스트 수와 실패/미실행 항목. 외부 서버 연동·배포 검증은 수행하지 않는다.
- 모델 추가/교체가 필요하면 9장 비교 증거와 실행 비용·메모리·라이선스를 근거로 다음 실험을 제안한다. 구현 실패를 모델 교체 제안으로만 대신하지 않는다.

완료는 “코드 연결 수정·검증 가능한 위치 제안·정상 생성 흐름 통합·9장 실제 평가·기존 기능 회귀·증거 자료”를 갖춘 상태다.
9장을 전부 정밀 복원했다고 과장하지 않는다. 남은 자동 인식·기하 추정 한계는 케이스별로 구체적으로 남긴다.
