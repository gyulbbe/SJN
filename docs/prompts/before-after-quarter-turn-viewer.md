# Before/After 공간을 상하좌우 90°씩 둘러보기 — 구현부터 실제 검증까지

SJN 프로젝트에서 Before와 After 공간을 위·아래·왼쪽·오른쪽으로 90°씩 돌려 확인하는 기능을 구현해줘. 저장소는 `C:\dev\SJN`이다.

목표는 **동일한 공간을 여러 방향에서 비교**하는 것이다. 타일·벽·바닥·설비가 공통 공간 좌표에 있고, 보는 방향만 바뀌어야 한다. 평면 이미지에 CSS 회전이나 좌우 반전을 적용하는 것으로 구현하지 않는다. 구현에 필요한 시간이 오래 걸려도 괜찮다. 조사·계획 설명에서 멈추지 말고 개발, 실제 브라우저 검사, 회귀, 빌드, 결과 보고까지 완료한다.

## 1. 기존 구조와 작업 내용 보존

먼저 `AGENTS.md`, 설치된 `node_modules/next/dist/docs/`의 관련 문서, 현재 git 상태와 다음 코드를 읽는다. 이미 수정된 파일을 초기화하거나 기존 사용자 자료를 덮어쓰지 않는다.

- `docs/reconstruction-current-status-20260913.md`
- `docs/reconstruction-placement-quality-results-20260914.md`
- `src/lib/room-geometry.ts`, `room-types.ts`, `types.ts`
- `src/lib/render/compositor.ts`, `standard-model-render.ts`
- `src/lib/reconstruction/projection.ts`, `templates.ts`
- `src/components/editor/canvas-workspace.tsx`, `editor.tsx`
- `src/lib/comparison.ts`, `editor-store.ts`
- 기존 자재의 `product3d`, 메시 검증·로딩, 시안 비교·다운로드·저장·자산 참조 코드

작성 시 확인한 구조를 실제 코드에서 다시 검증한다.

- `createRoomCamera`는 현재 정면에 고정돼 있다.
- 기본 방의 면은 `floor/left/back/right`이고 앞벽·천장이 독립 시공 면으로 등록돼 있지 않다.
- 벽·타일은 기존 카메라로 투영한 quad/mask를 사용한다.
- 재구성 표준 모형은 3D로 렌더링하지만 일반 제품은 PNG/투영 quad를 쓰는 경로가 있다.
- `RenderSnapshot`에 공통 자유 시점 계약이 아직 없고, Before 캐시도 기존 구도를 전제로 한다.
- `projectReconstructionFixture`는 표시 좌표뿐 아니라 배치 보정·앵커 등도 갱신한다. 이를 회전 이벤트마다 원본에 적용하지 말고 파생 투영을 분리해야 한다.
- compositor는 표준 모델이 연속한 묶음마다 깊이를 렌더링하는 경로가 있다. 중간에 PNG 제품이 끼면 깊이 관계가 분리될 수 있다.

따라서 카메라 함수 하나만 바꾸고 나머지를 그대로 두는 구현은 피한다. 공간 좌표·표면·제품·그림자·가림·캐시·다운로드가 어떤 경로에서 같은 시점을 사용할지 정리한 뒤 구현한다. 이번 목표는 **보기 기능**이며 재구성 인식 품질이나 제품 배치를 임의로 변경하지 않는다.

## 2. 사용자 흐름과 정확한 조작 규칙

기존 Before/After 도구 근처에 **공간 둘러보기** 버튼을 추가한다. 기존 편집 상태를 확정한 현재 스냅샷을 읽는 보기 모드로 열고, 큰 화면에서는 충분히 넓게, 작은 화면에서는 전체 화면에 가깝게 표시한다.

필수 도구:

- 왼쪽 90° / 오른쪽 90° / 위로 90° / 아래로 90°
- 기본 시점 / 화면 맞춤 / 확대·축소
- Before / After / 비교 전환
- 현재 방향 표시와 닫기
- 현재 시점 이미지 다운로드

조작은 다음 의미로 통일한다.

1. 한 번 누를 때 정확히 90° 이동한다. 제품의 배치나 방 자체의 좌표는 바꾸지 않는다.
2. 기본 정면에서 위로 누르면 위쪽에서, 아래로 누르면 아래쪽에서, 왼쪽/오른쪽은 각각 해당 쪽에서 공간을 본다. 방향과 화면 움직임이 헷갈리지 않도록 툴팁·간단한 방향 표시를 제공한다.
3. 공간 중심을 기준으로 카메라 위치와 방향을 함께 회전한다. 회전 축은 현재 카메라의 화면 오른쪽 축/위쪽 축으로 정하고, 이후 혼합 조작에서도 같은 규칙을 적용한다. 기본 상태에서의 부호와 축을 도식·테스트로 고정한다.
4. 위→아래, 왼쪽→오른쪽은 원래 상태로 돌아온다. 같은 버튼 네 번도 원래 상태로 돌아온다. 위·아래에서 멈추지 않고 반복해 180°/270°/360°를 확인할 수 있다.
5. 정규화 quaternion 또는 정확한 90° 회전 상태를 사용해 누적 오차·극점 뒤집힘·up vector 특이점을 방지한다. 카메라 position만 돌리고 up/방향을 방치하지 않는다.
6. 전환 애니메이션은 필수가 아니다. 추가한다면 빠른 연속 입력을 순서대로 처리하고, 중간 시점의 오래된 결과가 최종 시점을 덮지 않게 한다. reduced motion을 존중한다.
7. 보기 영역에 포커스가 있을 때만 방향키 조작을 지원한다. 입력칸이나 기존 제품 이동 키를 가로채지 않는다. 터치는 같은 버튼으로 조작한다.
8. 확대·이동은 양쪽에 동일하게 적용한다. 화면 맞춤은 방향을 유지하며 확대·이동만 초기화하고, 기본 시점은 방향·확대·이동을 모두 초기화한다.
9. 보기 모드 안에서는 제품 이동·삭제·레이어 편집을 하지 않는다. 닫으면 원래 편집 화면과 선택 상태로 돌아간다. 기존 숫자/그림 배치, 제품 360° 자재 편집과 충돌하지 않는다.

## 3. Before/After의 완전한 시점 동기화

Before, 활성 After, 비교는 **하나의 공통 ViewState/카메라 계산**을 사용한다. 별도로 시점을 누적해 비슷하게 맞추지 않는다.

- 회전 중심, quaternion, 투영 방식, 시야각, near/far, 화면 비율, 확대·이동, 잘라 보기 정책이 양쪽에서 동일해야 한다.
- 화면 맞춤은 공통 방 치수와 양쪽 콘텐츠를 함께 고려한다. Before와 After를 각각 제품 크기에 맞추면 비교 구도가 달라지므로 금지한다. 방 밖 이상 데이터가 화면을 무한히 축소시키지 않도록 검증한다.
- 동일한 방의 벽 모서리·바닥 줄눈은 Before/After 버튼 전환과 비교 슬라이더에서 같은 위치에 있어야 한다.
- 비교 레이아웃을 바꿔도 두 패널의 투영 기준을 맞춘다. 가로세로 비율과 DPR 차이 때문에 한쪽만 더 확대되지 않아야 한다.
- 활성 시안을 바꿔도 공통 시점은 유지한다. 시안별 자재·제품·색감·조명·수량은 그대로다.
- 기존 다중 시안 비교를 망가뜨리지 않는다. 새 90° 도구를 모든 비교 카드에 추가하는 것은 필수 범위가 아니지만, 공유 카메라 API 변경 때문에 기존 카드 구도·캐시·출력이 틀어지면 안 된다.
- 사진 시작은 재구성 Before + 빈 After, 사진 없이 시작은 양쪽 빈 기본 공간이라는 의미를 유지한다.

## 4. 공간 전체를 같은 좌표계에서 렌더링

기본 공간·재구성 공간을 위한 공통 3D 보기 렌더 경로를 구현하거나 기존 경로를 확장한다. Three.js와 자산 캐시를 재사용하고, 패널마다 WebGL context를 무제한 생성하지 않는다.

### 벽·바닥·타일

- `roomFace`, 실제 방 치수, 명확한 하위 밴드/면 범위를 기준으로 면을 생성한다.
- 타일 규격(mm), 줄눈, 배열, 시작점, 회전, 저장된 seed, 여러 무늬, 면별 색 보정이 보는 각도와 무관하게 같은 자리에 유지된다.
- 기존 정면용 quad·화면 마스크를 회전한 사진 좌표처럼 재사용하지 않는다. 면 좌표/UV로 표현 가능한 것은 변환하고, 불가능한 기존 사진 기반 편집은 별도 제한 상태로 다룬다.
- 모서리 틈, 겹치는 면의 깜빡임, 옆면 타일 반전·늘어남, 위쪽에서 줄눈 방향이 바뀌는 오류를 검사한다.
- 정확히 옆에서 보는 90°의 면적 0에 가까운 투영, 카메라 뒤의 면, near plane을 가로지르는 면은 clip/cull로 처리한다. 퇴화한 quad를 homography에 넣어 NaN·무한 확대·화면 전체 타일이 나오지 않게 한다.
- 기존 타일 명암 역시 원사진의 화면 좌표에서 추출한 텍스처임을 고려한다. 면 좌표로 근거 있게 변환할 수 없으면 보기 모드의 공간 조명으로 처리하고, 사진 명암을 보존한 것처럼 표시하지 않는다. 기존 정면 편집의 사진 명암은 유지한다.

### 바깥에서 내부를 보는 규칙

카메라가 방 주위를 돌면 가까운 벽이나 바닥이 내부를 가린다. **내부 확인을 위한 잘라 보기(cutaway)** 규칙을 구현한다.

- 실제 시점과 방 면 방향으로 가까운 외피를 숨기거나 잘라 내부가 보이게 한다. 이 처리는 보기용이고 시공 면을 삭제하지 않는다.
- 아래쪽에서는 바닥 외피가 내부 전체를 가리지 않게 하고, 위쪽에서는 천장 때문에 아무것도 안 보이는 화면을 만들지 않는다.
- Before와 After에 동일한 외피 정책을 적용한다. 벽에 설치된 거울·선반 등은 지지 벽을 보기용으로 숨겼다고 같이 삭제하지 않는다.
- 앞벽·천장 등 없는 면을 새로운 시공 면·자재·수량으로 임의 추가하지 않는다. 필요하면 명시적인 보기용 외피만 만들고 저장/견적에서는 제외한다.
- 기본 벽·바닥 삭제 방지를 유지한다. 사용자가 복잡한 레이어 목록을 조작해야 돌아가는 방식은 사용하지 않는다.

### 설비·반사·투명도

- 기존 재구성 표준 모형은 동일한 mm 위치·설치 벽·높이·회전·지지 관계로 렌더링한다. 보는 방향 변경이 사용자 출처나 배치 수치를 바꾸면 안 된다.
- 불투명 모형 간 가림은 벽·바닥·제품의 공통 깊이를 기준으로 계산한다. 정면의 화면 z-order나 마스크가 다른 방향에서 설비를 잘라먹지 않아야 한다. 특히 3D–PNG–3D 순서의 혼합 배치에서 별도 렌더 묶음 때문에 앞뒤 관계가 끊기는지 검사한다.
- 유리는 독립적인 반투명 모형으로 유지하고 뒤쪽 타일·욕조가 보이게 한다. 거울은 기존 중립 표면을 유지하며 원사진의 반사 풍경을 다시 붙이지 않는다.
- 그림자와 광원은 방 좌표에 고정한다. 카메라와 함께 회전하거나 정면 그림자가 공중에 붙어 있으면 안 된다. 새 각도에서 변환 불가능한 사진 그림자를 그럴듯하게 재사용하지 않는다.
- 한 번의 색공간 변환을 유지하고 Before/After의 원래 색감 설정을 서로 덮어쓰지 않는다.

## 5. 일반 제품 이미지·과거 사진 편집의 지원 범위

현재 제품이 모두 3D라는 가정은 금지한다. 다음 순서로 실제 자산에 근거해 표시한다.

1. 재구성 표준 모형은 기존 형상을 사용한다.
2. 현재 배치한 자재 버전·선택 사진에 유효한 저장 `product3d` 메시가 있으면 이를 읽어 3D 보기에 사용한다. mm 크기·중심·기준점·제품 자세와 선택 PNG의 관계를 확인하고 이중 회전/이중 스케일을 방지한다. 저장 메시가 있다는 이유로 새 AI를 실행하지 않는다.
3. 방향별 PNG만 있으면 방향 메타데이터가 명확할 때만 대응 이미지를 사용한다. 사진의 각도 편집값을 제품 전체의 재질/형상으로 오인하지 않는다. 방향 정보가 불명확한 이름을 자의적으로 해석하지 않는다.
4. 사진 한 장뿐인 제품은 입체 뒷면을 만들 수 없다. 설치 기준을 가진 평면 표현으로 보여주고 **2D 제품·각도 표현 제한**을 화면에서 명시한다. 이미지가 사라지거나 카메라를 항상 향하는 것을 완전한 입체 결과로 보고하지 않는다. 제한 제품 목록과 사용한 표현 방식을 제공한다.
5. `roomPlacement`가 없거나 사진 좌표 마스크·수동 복원 배경만 있는 자료는 임의 깊이를 부여하지 않는다. 지원 불가 항목과 이유를 알리고 기존 정면 보기로 돌아갈 수 있게 한다. 지원 가능한 표준 공간 전체를 이유 없이 막지는 않는다.

메시 손상·자산 누락·해독 실패 시 해당 원인을 보여주고 원본 사진·기존 자재 버전을 보존한다. 전체 장면을 빈 방으로 바꿔 성공 처리하지 않는다. 제한 항목이 포함된 내보내기는 같은 표현을 사용한다는 안내를 사전에 제공하되 이미지 안에는 진단 UI를 넣지 않는다.

새 모델, 사진 외부 전송, AI 호출, 자동 입체화, 유료 API, 외부 배포는 추가하지 않는다. 이번 기능을 단일 사진의 보이지 않는 뒷면 복원 품질 개선으로 설명하지 않는다.

## 6. 상태·저장·캐시·비동기 처리

- `ComparisonState.cameraVersion`의 기존 검증과 viewport의 zoom/pan만 있는 이전 구조를 함께 확인한다. 새 보기 상태를 제품·면·시안 장면 편집과 분리한다. 프로젝트 공통 보기 설정으로 마지막 확정 시점을 로컬 저장하고 재진입 시 복원한다. 과거 문서에 값이 없으면 기본 시점으로 읽는다.
- 회전·확대·이동은 장면의 edit/render revision, 자재 수량, 제품 개수, 기존 undo/redo 기록을 변경하지 않는다. 보기 결과용 키/revision은 따로 둔다. 저장 충돌용 revision은 실제 저장 정책대로 갱신한다.
- 읽기 전용 탭도 둘러볼 수 있지만 저장본에 쓰지 않는다. 정상 쓰기 탭의 500ms 저장, 충돌 감지, 저장 실패 시 현재 작업 보존을 유지한다.
- 시안 전환·프로젝트 복제·공통 방 크기 변경/전체 복원에서 보기 상태가 어떤 방식으로 유지·복원되는지 명시하고 테스트한다. 잘못된 과거 수치는 기본값으로 안전하게 처리하되 읽기만으로 원본을 덮어쓰지 않는다.
- 캐시 키에는 프로젝트·Before/시안·장면 revision·공통 공간 revision·시점·해상도·표현 정책이 포함돼야 한다. 비용만 바뀌었다고 메시·타일을 재생성하지 않는다.
- 빠른 연속 회전, 시안 전환, 창 닫기 중 늦게 도착한 결과를 폐기한다. 이전 각도 이미지가 최신 각도를 덮지 않게 한다.
- 메시/텍스처/자재 디코딩은 재사용한다. 회전마다 자산 업로드·PNG 생성·새 모델 다운로드를 하지 않는다. 닫을 때 listeners·bitmap·URL·GPU 자원을 정리한다.
- 타입·로컬 저장·참조 검사와 필요한 Supabase 검증을 함께 맞춘다. 실제 서버 연결·배포는 이번 범위가 아니다.

## 7. 이미지 다운로드

새 보기 창에서 현재 시점의 After PNG/JPG와 Before/After 비교 이미지를 내보낼 수 있게 한다.

- 미리보기와 같은 렌더 경로·공통 ViewState·불변 RenderSnapshot을 사용한다.
- 원본/GPU/전체 긴 변 4096px 제한 등 기존 출력 규칙을 유지한다. 좌우 비교의 양쪽은 같은 방향·배율·비율이다.
- 패널·회전 버튼·선택 테두리·축 표시·확인 문구·cutaway 진단은 출력 이미지에 포함하지 않는다. 보기용 외피 생략 결과는 미리보기와 동일하게 반영한다.
- 버튼을 누르는 순간의 시안을 출력한다. 출력 중 화면에서 회전/시안 변경이 일어나도 파일에 다른 결과가 섞이지 않는다.
- 출력 해상도 변경 뒤 미리보기 크기·시점이 유지돼야 한다. 기본 정면의 기존 다운로드도 회귀 검사한다.

## 8. 구현 순서와 검증

작업 전 기존 변경 상태와 재현 자료를 기록한다. 핵심 카메라·면/모형 투영 → 공통 비교 → 2D/legacy 제한 → 상태/캐시/저장 → 출력 → 실패·성능 순으로 완성한다. 마지막에 미완성 경로를 숨긴 채 버튼만 제공하지 않는다.

### 단위·통합 테스트

- 90° 회전 부호/축, 네 번 복귀, 반대 조작 복귀, 혼합 회전 뒤 역순 복귀, 반복 100회 후 오차
- 위·아래 극점, quaternion 유한성/정규화, 큰/좁은/낮은 방의 clipping·화면 맞춤
- 공통 카메라로 같은 방 기준점이 양쪽에서 같은 픽셀로 투영됨
- 모든 방향에서 면 UV·줄눈·seed·밴드 범위 유지, 지지면 위치와 모형 기준점 일치
- cutaway가 장면·수량을 바꾸지 않음, 유리 뒤 물체와 불투명 가림
- 3D/방향 PNG/단일 PNG/손상 메시/위치 없는 제품 분기
- 보기만 변경했을 때 장면 revision·undo/redo·가격·원본 참조 불변
- 시점 저장/구버전 기본값/읽기 전용/저장 실패/충돌/시안 전환·복제/전체 복원
- 캐시 분리·늦은 결과 폐기·닫기 후 처리·출력 시점 스냅샷 고정

테스트용 장면은 기능 검사로 표시한다. 모의 응답을 실제 제품 메시나 AI 성공으로 보고하지 않는다.

### 실제 브라우저 검사

기존 기본 공간, 실제 저장된 재구성 Before, 타일·제품이 있는 After를 사용한다. 개발 회귀 사진과 기존 프로젝트는 복제 또는 격리한 저장소에서 검증하고 사용자의 원본을 변경하지 않는다.

1. 좌/우/상/하 각각 네 번과 혼합 조작. 정면·양옆·뒤·위·아래에서 내부가 보이는지 실제 이미지 확인.
2. Before/After 전환·비교 슬라이더·확대·화면 맞춤 중 벽 모서리/줄눈 정렬.
3. 중립 거울, 벽걸이 세면대, 욕조·유리, 선반의 설치 높이·가림·색상 유지.
4. 실제 저장 메시 제품, 방향 사진 제품, 단일 PNG 제품이 각자의 지원 범위대로 표시되는지 확인.
5. 여러 시안 전환·가격 패널·닫고 재진입·새로고침·기존 편집 undo/redo.
6. 390px급 모바일·터치 버튼·키보드 포커스와 입력칸 충돌 없음.
7. 같은 순간 미리보기와 PNG/JPG·비교 출력의 방향·설비·타일·잘라 보기 일치, 편집 UI 제외.
8. 빠른 연속 입력·출력 중 전환·창 닫기·WebGL 실패·자산 실패·저장 실패에서 상태 보존.
9. 반복 열기/닫기와 회전 시 모델/AI/이미지 업로드 요청이 없는지 네트워크 기록으로 확인.

원본 정면과 새 방향별 이미지, 비교 PNG를 보관하고 직접 시각 검사한다. DOM 버튼 존재나 파일 다운로드 성공만으로 렌더링 검증을 대신하지 않는다. 기존 사진 기반 정면 편집과 다중 시안·수량/금액 회귀도 실행한다.

### 성능과 최종 검사

- 브라우저·기기·GPU 또는 소프트웨어 렌더링 여부·방 크기·설비 수·출력 크기·캐시 상태를 기록한다.
- 대표 장면의 최초 준비 시간과 캐시 준비 후 90° 전환 지연을 따로 측정한다. 애니메이션이 있으면 30fps 이상을 목표로 실제 측정한다. 순간 전환 구현이면 fps 수치를 꾸며 쓰지 말고 클릭→완성 프레임 지연을 보고한다.
- 50회 회전과 10회 열기/닫기에서 자원 수·메모리 추이를 확인한다. JS heap만 측정했다면 RAM/VRAM 전체로 보고하지 않는다. 좋은 개발 PC 한 대의 결과를 모든 사용자 성능으로 일반화하지 않는다.
- 관련 전체 단위·브라우저 회귀, lint·타입 검사, **Next.js → vinext 순차 빌드**를 마지막 생산 코드에서 실행한다. `.next`를 공유하는 개발 서버/빌드 검사를 충돌하게 병렬 실행하지 않는다.
- 실패하면 원인을 수정하고 관련 검사를 다시 실행한다. 성공 후 코드가 바뀌면 필요한 검사를 다시 수행한다. 이전 성공 로그를 최종 성공으로 소급하지 않는다.

## 9. 완료 보고

다음 내용을 결과 문서에 남기고 사용자에게 핵심만 설명한다.

- 버튼 위치와 사용법, 방향 조작 규칙
- 실제 조사한 원인·변경 파일·카메라와 렌더 경로
- 기본/90°/180°/270°/위/아래의 Before·After 비교 이미지
- 3D·2D·과거 사진 자료별 지원 범위와 제한, 미실행 항목
- 데이터 보존·저장·재진입·현재 시점 출력 검증
- 실제 테스트 수와 명령·종료 상태·성능 측정 조건

완료 기준은 **사용자가 Before와 After를 같은 각도로 상하좌우 90°씩 돌려 안정적으로 비교하고, 재진입과 출력에서도 같은 결과를 얻는 것**이다. 알려진 2D/사진 자료의 한계는 숨기지 않는다. 시간 때문에 핵심 동작을 생략하지 않되, 이번 범위 밖인 AI 재인식·보이지 않는 형상 추정·완전한 포토리얼 구현을 계속 새 완료 조건으로 추가하지 않는다.
