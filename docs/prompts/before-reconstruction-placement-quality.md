# 사진 → Before 자동 배치와 재현 품질 개선

SJN 프로젝트의 사진 → Before 재구성을 개선해줘. 저장소는 `C:\dev\SJN`이다.

목표는 사진 속 설비의 종류·형태·설치 관계를 파악하고, 공간미리의 표준 모형으로 알아볼 수 있게 재구성하는 것이다. 사용자가 모든 설비의 좌표를 직접 입력해야 하는 상태에서 벗어나, 근거 있는 배치를 제안하고 불확실한 부분만 간단히 확인하도록 개선한다. 계획 설명에서 끝내지 말고 원인 조사, 구현, 실제 사진 검증까지 수행한다.

## 1. 현재 상태를 확인하고 기존 기능을 재사용한다

먼저 `AGENTS.md`, 설치된 `node_modules/next/dist/docs/`의 관련 문서, 실제 코드와 다음 기록을 읽는다.

- `docs/reconstruction-current-status-20260913.md`의 최신 인계
- `docs/reconstruction-next-quality-results-20260914.md`
- `docs/reconstruction-strict-placement-results-20260914.md`
- `docs/reconstruction-strict-review-verification-20260914.md`
- `test-results/reconstruction-strict-placement-20260914/run-02-provenance/summary.json`
- `test-results/reconstruction-next-quality-20260914/comparison.html`

관측과 배치 분리, 반사·부품 관계, 벽걸이/기둥/하부장형 세면대, 거울장, 유리, 선반, 사각 기둥, 색상 보정, 설치 참고 추천, 보류 후보 수정·저장 기능은 이미 있다. 실제 연결 상태를 확인하고 중복 구현하지 않는다.

현재 실제 관측 재생에서 자동 배치는 사진별 `2/1/2/3/4 → 0/0/0/2/0`으로 줄었다. 이는 잘못된 위치를 방 안으로 강제 이동·축소하던 처리를 제거해 오류가 드러난 결과다. 자동 재현 품질이 좋아진 것으로 해석하지 않는다. 기존 비교 이미지의 사용자 보정 결과도 자동 인식 성공으로 집계하지 않는다.

이번 우선순위는 **인식한 설비가 올바른 위치 제안과 실제 모형 생성으로 이어지도록 상류 계산을 고치는 것**이다. 기본 모형 종류와 수동 입력 UI를 계속 늘리는 것만으로 완료하지 않는다.

## 2. 누락 단계를 실제 데이터로 추적한다

각 후보를 다음 흐름으로 추적한다.

`원모델 관측 → 후보 통합·반사/부품 판단 → 설치 방식 → 설치 벽·지지점 → 위치·규격 제안 → 물리 범위 검증 → 모형 생성`

후보 ID별 입력·출력·근거·출처·보류 이유를 기존 Lab 보고서에 연결한다. 아래 실패를 구분한다.

- 모델이 설비를 찾지 못함
- 찾았지만 중복·반사·부품 판단에서 잘못 제외됨
- 종류는 맞지만 설치 방식·벽·높이가 불명확함
- 접점·좌표 변환·규격 가정 때문에 위치가 방 밖으로 계산됨
- 유효한 후보가 렌더링·저장 단계에서 누락됨

세면대 등 실제 후보가 어느 단계에서 사라졌는지 확인한다. 모델 교체 필요성이나 좌표 오류를 추측만으로 확정하지 않는다. 원사진·원응답·기존 실행 결과는 그대로 보존한다.

## 3. 설치 위치 계산을 우선 개선한다

사진 좌표, 정규화 좌표, 벽/바닥 평면 좌표, mm 공간 좌표 사이의 변환을 점검한다. 축 방향·원점·단위·앞뒤 부호·회전·제품 기준점이 생성과 재투영에서 일치하는지 확인한다.

특히 다음 가정을 실제 사례로 검증한다.

- 사진에 일부만 보이는 바닥/벽을 방 전체 범위로 환산하고 있지 않은가?
- 세면볼의 bbox 하단을 기둥의 바닥 접점으로 쓰고 있지 않은가?
- 앞면 접점·벽 부착점·제품 중심을 혼동해 제품 깊이가 두 번 적용되거나 반대 방향으로 더해지지 않는가?
- 사진 왼쪽 물체를 근거 없이 실제 왼쪽 벽 설비로 판단하지 않는가?
- 가려지거나 화면 밖인 접점과 불확실한 기본 규격을 확정 관측처럼 사용하지 않는가?

확인된 원인을 일반적인 규칙과 좌표 계약으로 수정한다. 원래 위치·규격·근거를 보존하고, 방 밖 제안을 강제로 끼워 넣는 이동·축소를 다시 넣지 않는다. 관측에 근거한 새로운 추정과 단순 범위 맞춤을 구분한다. 사진별 좌표·파일명·해시 특례는 금지한다.

세면대–거울장, 욕조–유리, 세면볼–하부장 관계를 이용해 설치 대안을 좁힌다. 가림과 유리 뒤 중첩은 충돌로 일괄 제거하지 않는다. 이미 있는 위치 복사는 선택 시점의 복사이며, 알리지 않고 동적 부모 연결로 바꾸지 않는다.

여러 배치가 가능하면 이유가 있는 2~3개 대안을 미리보기로 제시하거나, 설치 벽·방향·높이 중 필요한 값만 확인받는다. 확인한 값은 사용자 출처로 저장한다. 개별 설비를 숫자로 전부 다시 배치해야 하는 흐름의 개선 여부도 평가한다.

## 4. 카메라와 모델의 역할을 분리한다

원사진 촬영 카메라와 Before/After 공통 표시 카메라는 별개다. 기존 source-camera·깊이·평면 실험을 조사하되, 보류된 가설을 자동 승인하지 않는다. 거울·유리·반사 공간을 실제 방 경계로 사용하지 않는다.

촬영 기하가 검증됐을 때만 생성 모형을 원사진 시점으로 재투영해 위치·윤곽을 비교한다. 원래 입력 bbox를 그대로 그린 결과를 재투영 정확도로 보고하지 않는다. 기하가 불명확하면 원사진 정확도는 평가 불가로 표시하고 필요한 사용자 확인을 제공한다. 공통 표시 공간에서 만든 근사 배치를 원사진 위치 복원으로 표현하지 않는다.

DeepLab의 픽셀 분류, 로컬 Qwen의 설비·관계 이해, 기하 계산, 표준 모형 렌더러를 나눠 평가한다. 인식 누락이 실제 병목이면 기존 로컬 Qwen3-VL 비교 경로부터 같은 입력으로 검증한다. 후보 개수나 정상 응답 종료만으로 기본 엔진을 바꾸지 않는다.

새 모델이 필요하면 공식 라이선스·상업 이용 조건·실행 환경·메모리 요구를 확인한다. 대형 모델을 사용자 브라우저에 기본 추가 다운로드하지 않는다. TripoSR와 배경 제거 기능은 변경하지 않는다. 유료 API, 사진 외부 전송, 배포는 하지 않는다. 실행 환경이 없으면 미실행으로 기록하고 모델 변경 없이 가능한 개선은 완료한다.

사용자가 준 최초 보고서 `C:\Users\H\.codex\attachments\adaf9967-71b3-4b36-9426-f89f27aceced\pasted-text.txt`는 과거 실행 기록이다. 최신 결과로 바꾸거나 현재 revision을 소급해서 붙이지 않는다. 다섯 사진은 이미 개발에 사용했으므로 일반화 성능을 입증하는 새 평가 자료로 부르지 않는다. 추가 평가를 할 경우 결과를 보기 전에 사진과 판정 기준을 정한다.

같은 사진·방 크기·관측 입력에서 변경 전후를 보존한다. 기본 방 크기는 실측값과 구별한다. 다음 결과를 별도 표시한다.

1. 사용자 수정 없는 자동 결과
2. 불확실한 항목을 사용자 확인한 결과
3. 추가 수동 배치로 완성한 결과

사진별로 실제 존재 설비, 관측 후보, 올바른 자동 배치, 잘못된 배치, 누락·오탐·반사 중복, 보류 이유, 종류·형태·상대 위치·높이·방향, 사용자가 바꾼 필드를 비교한다. 단순 배치 수 증가나 보류 감소를 성공 기준으로 사용하지 않는다. 실측 정답이 없는 사진에 mm 정확도를 보고하지 않는다.

실제 AI 실행, 저장 관측 재생, 사용자 입력, 모의 실패 테스트를 구분한다. 관측이 바뀌지 않은 계산/UI 수정은 저장 관측으로 재검증하고, 모델·전처리·프롬프트가 바뀌면 실제 새 추론으로 확인한다. 오래된 관측 캐시는 호환성 검증 없이 최신 분석에 사용하지 않는다. 실행 중 timeout만으로 같은 추론을 중복 시작하지 않는다.

## 6. 보존·검증·완료 조건

- 흰색·유색 제품의 기존 색상 개선, 중립 거울, 독립 반투명 유리와 필드별 출처를 유지한다.
- 사진으로 시작하면 재구성 Before와 같은 치수·카메라의 빈 After, 사진 없이 시작하면 양쪽 빈 기본 공간을 유지한다.
- 복잡한 레이어·수동 마스크 UI를 다시 추가하지 않는다. 기본 벽·바닥 보호, 원본 사진과 불변 자재 버전, 시안별 편집·수량/금액을 유지한다.
- 좌표 정·역변환, 기준점과 방향, 경계, 부분 관측, 가림·반사, 사용자 확인과 저장 출처를 단위 테스트한다. 모의 관측은 기능 검사에만 사용한다.
- 실제 브라우저에서 다중 사진 실행, 자동/확인 결과 비교, 보류 수정, 저장→새로고침→undo/redo→시안 복사→비교 PNG를 검사한다. 미리보기와 다운로드가 같은 장면을 사용하고 출력에 편집 UI가 없는지 확인한다.
- 관련 회귀와 lint·타입 검사·Next.js→vinext 순차 빌드를 실행한다. 이전 성공 로그를 변경 후 검사처럼 인용하지 않는다.
- 결과 보고서에 원인과 변경 파일, 원본/이전/개선 자동/사용자 확인 이미지, 실제 개선과 퇴행, 단계별 시간·환경·실제로 측정한 메모리 범위, 미실행 항목을 기록한다.

완료는 확인된 원인 수정과 실제 검증 결과로 판단한다. 자동 배치가 개선되지 않았다면 그 사실과 다음에 필요한 실험을 명시한다. 수동 결과를 자동 성공으로 바꾸거나, 모든 사진의 완벽한 복원·보이지 않는 형상·실측 정밀도를 새로운 완료 조건으로 계속 추가하지 않는다.
