# SJN 사진 → Before 재구성 개선 작업 프롬프트

아래 내용을 새로운 구현 작업에 그대로 전달한다. 기존 재구성 테스트 화면을 기준선 측정과 개선 검증에 사용하며, 이미 있는 화면을 중복 구현하지 않는다.

---

SJN 프로젝트의 사진 → Before 재구성 기능을, 사진별 예외 규칙을 계속 추가하는 방식에서 설비 이해·공간 추정·표준 모형 맞춤을 분리한 구조로 개선해줘.

- `docs/reconstruction-v2.md`
- `docs/reconstruction-open-toilet.md`

- 독립 테스트 화면 `/reconstruction-lab`과 `src/lib/reconstruction/lab.ts`

## 목표와 범위

사진에서 실제로 보이는 욕실 설비의 종류·형태·설치 벽·상대 위치·가림 관계를 파악하고, 사용자가 수정할 수 있는 공간미리 표준 모형으로 재구성한다. 사진 조각을 모형에 붙여 그럴듯하게 보이게 하는 방식은 쓰지 않는다.

Before와 After는 같은 공간 크기와 공통 카메라를 유지한다. 사진의 촬영 각도 추정은 사진 좌표를 공간 좌표로 옮기는 데 사용한다. 최종 Before와 After에 서로 다른 카메라를 적용하지 않는다. 사진으로 시작하면 Before만 재구성하고 After는 빈 기본 공간, 사진 없이 시작하면 양쪽 모두 빈 공간으로 시작하는 기존 동작을 유지한다.

기존 편집기·자재·시안 최대 5개·자재 수량/금액·저장·undo/redo·비교·PNG/JPG 출력과 호환한다. 기본 벽·바닥 삭제 방지, 복잡한 레이어·수동 마스크·다각형 편집 UI 제거 상태를 유지한다. 재구성 모형에 실제 상품 가격을 임의로 붙이지 않는다.

## 먼저 기준선을 고정한다

기존 DeepLab ADE20K 분석을 `baseline`으로 명시하고, 사용자 사진과 기존 회귀 사진을 같은 입력·방 치수로 실제 실행한다. 분석 원본과 적용된 모형 목록을 분리해 기록한다.

최근 확인된 문제는 다음과 같다. 실제 코드/결과를 다시 확인하고, 이미 해결된 버그를 반복 구현하지 않는다.

- 기둥형 세면대는 인식 후 설치 규칙에서 제외됐었다.
- 열린 변기의 테두리·뚜껑·볼이 toilet/mirror/basin으로 나뉘었다.
- 벽걸이 세면대의 설치 벽이 잘못 추정된다.
- 유리·거울 수납장·선반은 현재 분석기에서 누락되거나 다른 종류로 분류된다.
- 기본 모형의 형태와 사진 속 제품 형태가 다르고, 사진 원근과 임의 기본 치수가 혼합된다.
- 타일 규격과 배열은 실측 결과가 아니라 관측/추정/보완값이다.

## 구현 구조

다음 단계를 독립된 타입과 모듈로 구성하고 각 단계의 실패·보류 사유를 보존한다.

`사진 분석 → 설비 및 관계 후보 → 촬영 시점·공간 배치 추정 → 표준 모형 선택·맞춤 → 사용자 확인`

### 1. 설비와 관계 후보

종류만 출력하지 말고 후보 ID, 사진 속 영역, 설치 방식, 설치 벽, 형태 속성, 앞/뒤/유리 너머/거울 속 관계, 판단 근거와 불확실성을 구조화한다.

범위: 변기, 세면대(벽걸이/기둥/하부장 + 사각/둥근 볼), 욕조, 샤워 유리, 거울, 거울 수납장, 선반, 문, 창. 없는 제품을 채워 넣거나 후보 개수를 강제로 맞추지 않는다. unknown과 확인 필요를 허용한다.

픽셀 분류와 사진 내용을 이해하는 모델은 역할이 다르다. 한쪽 결과를 무조건 정답으로 삼지 말고, 영역 근거와 관계의 일관성을 검증한다. 모델이 인식한 값, 기하 규칙으로 추정한 값, 기본값, 사용자가 수정한 값을 필드별로 구분한다. 모델이 출력한 confidence를 검증된 확률로 표시하지 않는다.

거울 속 물체를 독립 설비로 중복 배치하지 않는다. 유리 뒤 설비는 삭제하지 않는다. 한 장의 이미지에서 관측할 수 없는 문 내부·뒷면·실측 치수를 알아낸 것으로 표시하지 않는다.

### 2. 촬영 시점과 공간 배치

방 치수, 관측 가능한 벽/바닥 경계와 소실 방향, 설비의 접지점/벽 부착점을 사용해 사진 좌표를 공통 공간 좌표로 변환한다. 사진 바운딩 박스 크기를 곧바로 실제 mm로 간주하지 않는다.

공간과 설비의 배치가 맞는지 다시 사진 좌표로 투영해서 검증한다. 사진 일부만 보이거나 벽 경계가 불명확하면 확정하지 않고 이유를 남긴다. 지원하지 않는 비직사각형 공간을 직사각형으로 정확히 복원했다고 보고하지 않는다.

벽걸이 제품은 바닥 접점 없이 설치 벽과 높이로 배치한다. 기둥형·하부장형은 지지 구조를 고려한다. 설비가 벽 뒤로 들어가거나 바닥에서 뜨는지 검사하되, 맞추기 위해 실제 후보를 조용히 삭제하지 않는다.

### 3. 표준 모형 선택과 맞춤

현재 모형 라이브러리를 재사용하고 부족한 형태만 확장한다. 사각 기둥형 세면대를 둥근 모형 하나로 대체하지 않도록 형태 선택을 분리한다. 물체별 위치·방향·폭·깊이·높이·설치 높이를 조절하고, 불확실한 치수는 편집 가능한 기본값으로 표시한다.

거울은 중립 은회색 표면과 외곽/문 경계를 사용한다. 유리는 독립 반투명 모형으로 뒤쪽 설비와 타일을 보여준다. 원본 사진의 반사 풍경이나 유리 뒤 벽을 불투명 제품 텍스처로 가져오지 않는다.

표준 모형 렌더링의 개선과 실제 인식 정확도 개선은 별도 평가한다. TripoSR 제품 360° 기능과 BiRefNet 배경 제거 모델은 이번 이유로 바꾸지 않는다.

### 4. 간단한 사용자 확인

종류·설치 벽·설치 방식·형태 등 불확실한 항목만 짧게 확인하도록 한다. 누락된 설비 추가와 위치/크기 수정은 기존 간단한 설비 UI를 활용한다. 사용자 확인 전 결과와 확인 후 결과를 각각 보존하고, 수동 보정을 AI 성공으로 집계하지 않는다.

## 모델 선택과 실행 제한

Qwen3-VL-4B-Instruct의 기존 로컬 비교 기록부터 읽어라. 이전 실험에서 유리 존재와 벽걸이형 구분에는 도움이 됐지만 거울장·설치 벽·반사·반복 후보 문제도 있었으므로 즉시 기본 분석기로 교체하지 않는다.

추가 후보 모델은 공식 모델 카드·라이선스·런타임 문서로 상업적 사용 조건, 입력/출력, 브라우저/CPU/GPU 지원과 메모리 조건을 확인한 뒤 개발 환경에서 비교한다. 더 큰 모델이나 새로운 모델이 더 정확하다는 가정을 결과처럼 보고하지 않는다.

유료 API·외부 서비스 배포·사용자 사진의 외부 전송은 범위 밖이다. 사용자 브라우저에 큰 새 모델을 기본 다운로드하지 않는다. 로컬 실험 환경이 없으면 해당 모델 실험을 미실행으로 기록한다. 기존 분석기를 가짜 대체 응답이나 단순 규칙으로 흉내 내어 신규 AI 성공으로 표시하지 않는다.

모델 출력은 검증된 구조화 데이터로만 사용한다. 텍스트를 코드/명령으로 실행하지 않는다. 잘못된 JSON, 유효하지 않은 좌표, 중복 ID, 존재하지 않는 관계 참조, 모순된 설치 값을 검증한다.

## 독립 테스트 화면 확장

홈의 **사진 재구성 테스트**(`/reconstruction-lab`)를 재사용한다. 일반 프로젝트 생성과 분리하고, 테스트 사진·결과로 사용자 프로젝트/자재를 덮어쓰거나 서버 업로드하지 않는다.

- 여러 사진을 넣고 사진별 방 크기를 설정해 순차 분석한다. 이미지는 각각 독립 케이스이며 다중 시점 복원 입력과 혼동하지 않는다.
- `기존 분석`과 `개선 후보`는 실행 엔진/모델/revision/설정을 명시한다. 실제 연결되지 않은 엔진은 실행 가능하게 보이지 않게 한다.
- 같은 사진·치수의 기존 결과와 개선 결과를 원본 옆에서 비교한다. 결과 교체 시 이전 기준선을 잃지 않게 한다.
- 진행 단계·현재 케이스·실제 경과 시간, 취소, 실패 이유, 재시도, PNG·상세 JSON 다운로드를 제공한다. 가짜 진행률이나 예상 시간을 만들지 않는다.
- 감지 후보/배치 후보/보류 후보·판단 근거·설치 정보·모형 기본값을 구분한다.
- 사용자가 정답 설비와 설치 벽·형태, 누락·잘못 추가됨을 기록할 수 있게 한다. 사용자 평가를 모델 출력과 분리한다.
- 긴 실행을 허용하되 동시 모델 추론으로 메모리를 폭증시키지 않는다. 취소·페이지 이탈·실패·늦은 응답에서도 URL, bitmap, WebGL과 임시 자산을 정리한다.
- 사진 크기, 분석 입력 크기, 출력 크기, 모델 준비/다운로드/추론/모형 생성/렌더 시간을 실제 측정 가능한 범위에서 나눈다. 분리 측정하지 못한 시간은 합산 단계 시간으로 표시한다.
- 메모리는 측정 범위(페이지 JS heap/Worker/WASM/GPU/전체 프로세스)를 명시한다. 관측하지 못한 항목을 0으로 표시하지 않는다.

## 검증과 채택 기준

사진 몇 장에서 맞은 결과만으로 채택하지 않는다. 먼저 사용 권한이 확인된 다양한 욕실 사진을 확보하고, 확보 가능한 수와 조건을 기록한다. 목표는 30장 이상이며 개발에 사용하는 사진과 최종 평가에만 사용하는 사진을 나눈다. 사진이 부족하면 그 수를 숨기거나 가짜 자료로 채우지 않는다.

기둥/벽걸이/하부장 세면대, 열린/닫힌 변기, 작은 설비, 가림, 거울 반사, 유리, 다른 조명과 촬영 각도를 포함한다. 테스트 사진별 정답과 실패 정의를 개선 전에 고정한다. 특정 사진 파일명·해시·좌표로 결과를 맞추지 않는다.

평가 항목을 분리한다: 설비 누락, 잘못 추가한 설비, 종류, 설치 방식, 설치 벽, 형태, 중복/반사, 사진 재투영 위치 오차, 사용자 수정량, 시간, 메모리. 설치 위치의 실제 정답이 없는 항목은 사진상 정렬 오차와 추정으로 표시한다. 임의의 종합 정확도나 근거 없는 목표 달성률을 만들지 않는다.

기존 기준선과 같은 사진/치수로 비교하고, 평가용 사진에서 개선되는 근거가 있을 때만 기본 경로 채택을 제안한다. 결과가 나쁘면 실패를 그대로 기록하고 기존 분석기를 유지한다.

관련 단위·실제 브라우저 회귀, lint·타입 검사·Next.js 및 vinext 빌드를 수행한다. 테스트 응답 모킹은 검증기·실패 복구 검사에만 사용하며 실제 AI 품질 결과와 분리한다.

완료 보고에 변경 구조와 파일, 사진별 전후 이미지, 실제 모델 출력/규칙 추정/사용자 수정의 구분, 측정 조건과 수치, 평가 사진 수, 개선되지 않은 항목, 미실행 실험·서버 항목을 포함한다. 테스트 통과 수를 인식 정확도로 설명하지 않는다.
