- **3-1 서버 AI 대기 표시**: 비용이 없다.

## 0. 배경과 범위

- 실사 변환은 **프로젝트 하나 기준**이다. 여러 장 사진 입력은 하지 않는다(2026-09-26 사용자 결정).

- **FLUX가 설비를 바꾸는 문제**
  - 2026-09-25에 배치 제품 정보를 문장으로 전달하도록 바꿨다([FLUX 문서](../flux-export.md)).

  - 이번에는 결과를 **되돌리거나(합성)** **검사해 경고한다(Gemma)**.
- 3-2의 부수 질문: 1단계 "겹쳐 찍기"(부드러운 설비 그림자)를 FLUX 입력에 넣으면 결과가 좋아지는가. 지금 FLUX 입력은 한 장 렌더다.

## 5. 3-2a 설비 보호 두 방식 시제품 (호출 없이)

### 방식 1: 설비 영역 되돌리기 (클라이언트 합성)

- FLUX 결과를 받은 뒤, **설비 자리만 원래 렌더로 덮어** 설비 종류·모양·색을 보장한다.
- **설비 마스크**: 상자가 아니라 실루엣을 쓴다.
  - 3D 경로: `RoomViewerRenderer`에 설비를 ID 색으로 그리는 마스크 메서드를 추가한다. 방 면에 가려진 부분은 뺀다.
  - 2D 합성 경로: 설비 레이어의 알파나 투영 형상으로 만든다.
  - 경로별로 방법과 한계를 적는다.
- **정렬 검사**: FLUX 결과는 원본과 조금씩 어긋날 수 있다(2026-09-25 C는 구도가 크게 바뀜).
  - 설비 주변에서 원본과 결과의 위치 차이를 추정한다(예: 윤곽 기반 상관, 이미지 폭 ±3% 탐색).
  - 어긋남이 기준보다 크거나 상관이 낮으면 **그 설비는 덮지 않고 "보호하지 못함"으로 표시**한다.
- **합성**
  - 경계는 2~4px로 부드럽게 섞는다.
  - 설비 색은 원본을 유지한다(설비 영역 ΔE2000 ≤ 2).
  - 밝기만 주변에 맞출지 시험하되, 색이 바뀌면 쓰지 않는다.
  - AI가 만든 그림자·반사는 설비 밖이라 그대로 남는다.
- 좌표 변환은 `fluxInputLayout`의 여백·배율을 반영한다. 출력은 입력의 두 배다.

### 방식 2: Gemma 검수 (서버, 호출당 소량 비용)

- 새 서버 경로를 만든다. 예: `POST /api/export/photoreal/check`.
  - 입력: FLUX 결과 이미지(크기 제한)와 장면 정보(`fluxSceneSchema`의 설비 종류·상자만)
  - 서버가 영어 질문을 만든다. 예: "image 0의 x 56–64%, y 61–81%에 toilet이 있는가"
  - 출력: 엄격한 JSON 스키마. 설비마다 `present: yes | no | unsure`, `seenAs`: 종류 enum 또는 `other`
  - 사용자 자유 문장은 보내지 않는다.
- 기존 Gemma 서버의 동일 출처·로그인·게이트웨이·재시도 1회 제한·진단(크기만) 규칙을 그대로 따른다.
- 화면 경고 예: "변기가 다른 물건으로 바뀌었을 수 있어요. 다시 만들어 보세요." **자동 재시도는 하지 않는다.**

### 오프라인 개발과 단위 검증

- 2026-09-25 결과 6장과 `scene.json`, `input.png`로 방식 1의 정렬 검사와 합성을 만든다.
  - 기대: B는 모든 설비가 정렬되어 덮이고, C는 어긋남을 감지해 덮지 않는다.
- 마스크가 필요하면 그 장면을 `tests/flux-grounding-browser.ts` 방식으로 다시 만든다. 장면 설정은 `docs/flux-export.md`의 비교 설명과 `scene.json`을 따른다. 어렵다면 상자 기반 대체 마스크로 먼저 개발하고 이유를 적는다.
- **조작 사례**(Gemma 양성 대조)
  - B 결과에서 변기 자리를 회색 원통 같은 다른 물건 그림으로 덮은 이미지를 만든다.
  - 세면대를 지운 이미지도 만든다.
  - 호출 없이 만들 수 있다.
- 단위 테스트: 좌표 변환, 정렬 판정, 합성 경계, 서버 요청 검증(스키마 밖 입력 거절, 추론 전 400)

## 6. 3-2b 실제 비교 (사용자 승인 뒤에만)

- **먼저 사용자에게 호출 수와 예상 뉴런을 알리고 승인을 받는다.** 승인 없이 호출하지 않는다.
- **호출 계획**(예상, 필요하면 줄인다)
  - **FLUX 4회**
    - 방 안 시점 3D 장면(벽 구조가 있어 3D 경로를 쓰는 욕실, 2단계 측정 장면 재사용 가능)
    - 입력 두 가지: 한 장 렌더 / 겹쳐 찍기 8장
    - seed 두 개
    - 약 440뉴런
  - **Gemma 검수 12회**
    - 2026-09-25 결과 6장, 새 FLUX 결과 4장, 조작 사례 2장
    - 약 300뉴런
  - 합계 약 740뉴런(약 $0.008), 하루 무료 한도 안
- **실행 방법**
  - 운영 `AI` 바인딩을 쓰는 로컬 임시 Worker로, 서버와 같은 요청을 보낸다(2026-09-25 방식).
  - Worker는 127.0.0.1에서만 열고 **호출 수 상한**을 코드에 둔다.
  - 도구 권한 검사로 실행이 막히면 우회하지 않는다. 사용자에게 실행할 명령(한 줄씩)을 주고 결과 파일을 받아 분석한다.
  - `wrangler whoami`로 로그인 상태를 먼저 확인한다. 로그인은 사용자가 직접 한다.
- **판정표**
  - FLUX 결과마다: 설비별 종류 유지, 위치, 모양, 색
  - 방식 1: 덮은 결과의 경계 품질(눈 확인 + 경계 지표), 설비 ΔE, 정렬 판정
  - 방식 2: 검수 판정(참/거짓 양성·음성), 실제 토큰·뉴런(응답의 usage가 있으면 그 값)
  - 부수 질문: 겹쳐 찍기 입력이 결과를 좋게 하는지
- 결과 이미지는 `test-results/export-realism-stage-3/`에 나란히 저장하고 직접 확인한다.

## 7. 3-2c 채택과 연결

- **채택 기준**(비교 뒤 판단)
  - 방식 1: 정렬된 결과에서 경계가 눈에 띄지 않고, 설비 ΔE ≤ 2이며, 어긋난 결과(C류)를 덮지 않고 걸러 낸다.
  - 방식 2: 조작 사례를 모두 잡고(2/2), 정상 결과의 거짓 경고가 드물다(정상 10장 중 1장 이하).
  - **둘 다 통과하면** 권장안은 "방식 1로 덮고, 덮지 못한 설비가 있을 때만 방식 2로 검수"다. 검수 호출은 필요할 때만 생긴다.
  - 기준이 애매하면 **사용자에게 결과와 선택지를 보고하고 결정을 받는다.**
- **화면 연결**
  - 기본은 보호된 결과를 보인다. "AI 원본 보기" 전환을 둘지는 판단해 제안한다.
  - 보호하지 못한 설비나 검수 경고는 결과 칸 아래에 알린다.
  - 안내 문구에 검수 호출이 생긴다는 사실(비용 발생)을 적는다.
  - 다운로드 PNG는 보이는 결과(보호된 결과)다.
- **겹쳐 찍기 입력**: 비교에서 좋아졌다면 FLUX 입력 캡처에 적용한다. 장 수와 시간을 적는다. 아니면 지금처럼 한 장으로 둔다.
- 한 클릭에 FLUX 한 호출(+필요할 때 검수 한 호출)이다. 자동 재시도는 하지 않는다.

## 8. 반드시 지킬 조건

- **AI 호출은 6절의 승인 뒤에만 한다.** 상한을 넘기지 않는다. 실패해도 자동으로 다시 부르지 않는다.
- 토큰·자격 증명을 채팅·소스·브라우저에 넣지 않는다. 로그인과 비밀 등록은 사용자가 한다.
- 사용자 자유 문장(제품명 등)을 모델에 보내지 않는다. 진단에는 크기와 개수만 남긴다.
- 편집 화면, 시안 미리보기, 일반 내보내기 출력은 바꾸지 않는다. 마스크용 새 메서드가 기존 렌더에 영향을 주면 안 된다(기준선 픽셀 차 0).
- 시스템 설정과 Chrome 전역 플래그는 바꾸지 않는다.
- Tailwind를 우선 쓴다. `globals.css`의 `p{margin:0}` 때문에 여백이 필요한 표시 요소는 `<div>`로 만든다.
- 줄바꿈은 작업 사본 CRLF, 저장소 LF다. Prettier는 쓰기에 `--end-of-line crlf --write`, 검사에 `--end-of-line auto`를 쓴다. typecheck 뒤 `next-env.d.ts`를 되돌린다.
