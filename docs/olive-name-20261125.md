# 올리브 벽 이름 시험 (2026-11-24–25, 결과: 앱 그대로, 회색화 미해결)

- 문제(백로그 5번, 열린 문제 4번 남은 것): AI 원본이 올리브 유광 벽돌(SI ROMAN OLVIE-G)을 회색 돌처럼 그린다.
- 원인: 프롬프트가 올리브 평균색 #6a6b51(채도 0.138)을 "grey"라고 부른다. 무채색 기준은 채도 0.14다.
  - 거기에 "Keep this exact grey …; do not warm, yellow or tint it."까지 붙는다.
- 결론: 앱은 main 그대로다. 두 이름 문장을 앱에 넣었다가 Cloudflare 평가에서 욕조 정면이 나빠져 모두 되돌렸다.
  - 작업 줄기 `task/olive-name`
    - 넣었다 되돌린 것: 32269f8 → 6d21e28, 3208c5a → c5a53cb
    - main과 다른 것은 시험 도구 `tests/olive-name/`뿐이다.
- 감독(Codex)의 가린 평가와 개발 세션 측정이다. 등록 자재 장면만 썼다(규격 욕조는 참고용 규격 모델).

## 1. 지금 규칙이 주는 이름

- 시험 장면에 나온 타일 색 가운데 잘못 불리는 것은 올리브 하나다.
  - #86847c·#868686·#bdbdb9·#c2c2c0(회색 계열), #151515·#fbfbfb, 베이지 #d0b190은 맞게 불린다.
- 기준을 그냥 낮추면 따뜻한 회색(#8c8478 → "brown", 그레이지 #a39e93 → "beige")도 색 이름을 받는다.
  - 0.14 기준은 모델이 회색을 따뜻하게 만드는 것을 막으려고 생겼다.

## 2. 로컬 FLUX (무료, klein 4B)

- 27–28단계
  - 오늘 앱 입력 6장면 × seed 2로 벽 문장만 바꿔 48장을 만들었다.
  - AI 원본 벽 채도(설계 14.8)

| 문장          | 원본 채도            |
| ------------- | -------------------- |
| 지금 "grey"   | 1.0 (12/12장 무채색) |
| "olive grey"  | 6.3                  |
| "olive"       | 10.4                 |
| "olive green" | 10.7                 |

- 앱 다듬은 뒤는 모두 14.1–14.3이다. 다듬기가 이미 색을 되돌린다.
- 가린 평가(원본): "olive"가 "grey"와 "olive grey"를 각각 6 / 0 / 0으로 이겼다.
- 30단계
  - "olive"를 Cloudflare에서 버린 뒤 대안 40장을 만들었다.
  - "dark olive": 원본 벽 밝기가 설계와 같아지고(L\* 58.9 → 42.0, 설계 42.4) 최종 벽 반사가 절반이 됐다(5.8 → 2.9%).
  - "어두움 유지·넓은 반사 없음"을 붙인 문장은 로컬에서 효과가 없었다.
  - 가린 평가: dark olive 12 / 0 / 0(원본 6, 최종 6)
  - 로컬은 Cloudflare의 욕조 정면 문제를 재현하지 못했다.

## 3. Cloudflare (같은 입력·seed 424242)

- 장면: 오늘 앱 입력 4장면(등록 변기 정면 0°·측면 90°, 규격 욕조 큰 방 정면·측면)
- 저장 답은 입력·문장 해시가 같을 때만 다시 썼다.
- 벽 반사 = 벽에서 L\* 92 위 %

### 29단계: "olive" (7회)

- 원본 벽 채도 5.2 → 10.3(4/4), 원본 반사 4.3 → 3.6%
- 앱 최종 채도 14.2 → 14.3, 밝기 53.1 → 51.9
- 감독 4 / 2 / 2
  - 진 두 쌍은 욕조 정면이다(원본·최종). 세 문장 모두 베이지빛 돌이 되고, "olive"는 넓은 노란빛 반사와 욕조 앞면 명암 경계가 더 컸다.
- 버림

### 31단계: "dark olive" (4회, main·olive 답 8장 재사용)

- 앱 규칙은 색조 40–65°, 밝기 ≤ 0.45, 채도 0.10–0.14만 "dark olive"로 불렀다.
  - 저장 장면 155개 중 94개가 올리브 문장 하나만 바뀌었고, 예상 밖 차이는 0이었다.
- 감독 6 / 2 / 2

| 장면               | 판정(dark 대 grey)  | 숫자(grey → dark)                                                                          |
| ------------------ | ------------------- | ------------------------------------------------------------------------------------------ |
| 변기 정면·측면     | 4승(원본·최종 각 2) | 원본 벽 L\* 61.1·64.8 → 43.6·46.2, 최종 벽 반사 5.56·3.86 → 2.91·2.76%                     |
| 욕조 정면          | 2패(원본·최종)      | 세 문장 모두 원본 베이지(색조 74–81°). 최종 반사 3.25 → 5.33%, 앞판 어두운 얼룩 2.0 → 8.9% |
| 욕조 측면          | 2같음               | 최종 반사 5.58 → 6.27%, 앞판 얼룩 22.3 → 19.6%                                             |
| 욕조 정면 대 olive | 2승                 | 앞판 얼룩 13.6 → 8.9%                                                                      |

- **변기 장면은 좋아지고, 욕조 정면은 벽 반사와 앞판 명암이 나빠졌다.**
- 전체 적용은 버렸다(감독 step-31).

## 4. 남은 것

- **AI 원본이 올리브 벽을 회색(또는 욕조 장면에서 베이지) 돌로 그리는 문제는 해결하지 않았다.**
  - 앱 최종은 다듬기가 색을 되돌려 올리브로 보인다. 다만 설계보다 밝다(L\* 약 +10).
- 이름만 바꾸는 방법은 장면에 따라 갈린다.
  - 변기 장면: 원본 색·밝기와 최종 반사가 좋아진다.
  - 큰 욕조 정면: Cloudflare가 어느 문장에서도 올리브로 그리지 않았고, 반사·앞판 명암이 나빠졌다.
- 한계: Cloudflare는 seed 하나다. 욕조는 규격 모델(등록 욕조 사진 없음)이다. 회록·청회색처럼 채도 낮은 다른 색조는 시험하지 않았다.
