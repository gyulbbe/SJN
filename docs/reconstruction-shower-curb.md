# 사용자 확인 샤워 턱 표준 모형 — 2026-09-13

이 작업은 [높은 유리 지지 배치](reconstruction-raised-glass-support.md)에 남았던 `유리가 떠 보이는` 문제를 사용자 보정 경로에서 개선한다. 사진에서 턱의 규격을 인식하거나 측정한 결과가 아니다. 욕조 테두리의 실제 욕조 연결 문제는 이번 변경으로 해결했다고 주장하지 않는다.

## 형식과 호환

`RaisedGlassSupport.curb?: {widthMm, depthMm, provenance:{width:'default'|'user',depth:'default'|'user'}}`를 추가했다. `shower-curb`의 명시적 사용자 선택·적용에서만 생성한다. 높이는 기존 `support.heightMm`이다. 새로운 기본 제안은 폭 `유리 폭 + 40mm`, 깊이 `max(120mm, 유리 깊이 + 40mm)`이며 UI에 기본값 출처를 보인다. 폭·깊이를 직접 바꾸면 해당 축만 `user`가 된다. 바탕 회색/윗면 밝은 회색 마감은 기본 표현이다.

이전 저장 자료에 `curb`가 없으면 자동으로 채우지 않으며 기존 높이만의 모습이 유지된다. UI의 `확인한 샤워 턱 모형 추가`를 눌러 명시적으로 추가할 수 있다. `bath-rim`에는 턱 형식을 허용하지 않고 기존 독립 지지 높이와 한계 안내를 유지한다. 실제 욕조나 부모 자산을 생성/수정하지 않는다.

## 물리 좌표와 출력

- 유리 본체를 기존과 똑같이 정규화한 후 턱 본체와 얕은 상판 두 메시를 추가한다. 유리 좌표는 `y=0..유리높이`이며 턱은 `y=-지지높이..0`이다. 실제 배치는 기존 유리 하단 원점 `baseHeightMm`를 적용하므로 턱 아래가 바닥 0, 상판 위가 유리 하단에 맞는다.
- 턱은 유리와 같은 중앙·방향을 쓰는 하나의 표준 설비 구성이다. 이동·회전 시 함께 움직인다. 턱 폭·깊이가 유리 규격보다 작으면 자동 확대하지 않고 거절한다. 별도 스케일링은 바닥 접촉을 바꾸므로 턱이 있는 경우 배율 1만 허용하고 규격 입력으로 변경한다.
- 전체 경계는 유리와 턱의 별도 물리 상자들을 회전해 계산한다. room 검증과 화면/투명 PNG 크롭이 같은 상자를 쓴다. 명시 지원 배치를 화면 투영 단계에서 임의로 자동 이동/축소하지 않는다.
- 턱은 불투명하고 유리는 기존 반투명 표현을 유지한다. 표준 렌더 캐시에 지지 유형·높이·폭·깊이를 포함하고, 변경 시 기존 메시/재질을 해제한다. 템플릿 revision은 9이며 이전 자재 버전과 이미지 자산을 덮어쓰지 않는다.
- 견적용 제품을 별도로 만들거나 임의 가격·자재 수량을 추가하지 않는다.

## 실제 기능 검증

전체 Lab UI에서 보존된 실제 user-03 관측 보고서를 읽고, 사용자 역할로 `샤워 턱`을 선택했다. 기본 840×120mm 표시를 확인한 뒤 폭900·깊이160·높이100mm로 보정했다. 유리는800×1800×8mm를 유지했다. 표준모형4개(열린 변기, 사각 기둥 세면대, 거울, 유리+턱)를 렌더했고 종류가 미확정된 추가 수전 후보는 보류로 남았다. 원 모델 원문·자동 관측·기준선 보고서는 동일하며 Worker0·AI POST0·외부전송0이다. 표시 이미지와 PNG 다운로드 해시 일치, 교정 스냅샷 복원 시 지지·턱 규격 유지도 통과했다. user-04 두볼 하부장 사례의 동일 전체 UI 회귀도 통과했다.

실제 PNG를 확인했을 때 기존의 유리 아래 빈 공간이 턱으로 연결됐다. 턱은 바닥에 닿고 유리 하단을 받치며, 뒤쪽 타일은 여전히 유리를 통해 보인다. 모형4개가 있다는 사실은 사진 전체 배치/카메라/마감까지 복원 완료했다는 뜻이 아니다. 기존 표준 공간과 사용자가 입력한 설치 위치를 유지했다.

처리 조건은 Chrome headless + SwiftShader, 다른 통합 작업과 경합 가능성이 있는 개발 PC다. user-03 이번 보정 총3.034초(사진·모형 준비1.344초, PNG1.690초), 기존 분석/추가 모델 시간은 각각0이다. 모델 성능 수치나 인간의 최소 보정 시간으로 사용하지 않는다. 새 메모리 수치는 측정하지 않았다.

## Before 편집·저장 및 단위

실제 Before 속성 UI의 합성 테스트 설비로 다음도 통과했다: 턱 폭790mm(유리800) 거절 및 이전840 보존 →900×160 수정→각 축 user 출처→실제 브라우저 IndexedDB 저장/재읽기→필드 복원→턱을 포함한 투명 자산 PNG 저장→바닥 직접 설치/종류 변경 시 지원 해제. 높이 기본600/default→500/user 및 undo/redo 회귀도 유지했다. 저장 PNG의 좁은 옆모습에서도 턱이 포함됐으며 잘리지 않는 것을 확인했다. 첫 테스트는 정확한 전체 오류문장 locator가 이어진 메시지를 찾지 못해 실패했고, 실제 거절은 정상임을 확인한 후 contains 검사로 고쳤다. 덧붙던 접지 오류는 제거해 원인 안내를 줄였다. 재시도 성공만 남기지 않고 `validation-notes.json`에 첫 실패를 기록했다.

관련 7파일 **107개 단위 통과**: 새 샤워턱11, 지원21, 생성9, 표준렌더4, 카메라40, 수동위치9, 저장13. 유리 정점 불변, 물리 접촉, 기본값/사용자 출처, 크롭 범위, 회전 후 방 경계, 잘못된 폭·깊이/출처/종류/배율, 과거 형상 보존, 캐시 재사용/변경/자원 해제를 검사했다. 관련 소스/테스트 ESLint 통과. 전체 타입 검사와 Next/vinext 빌드는 상위 통합 작업에서 실행한다.
